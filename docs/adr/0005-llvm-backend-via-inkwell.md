# 0005. LLVM backend via inkwell

- Status: Accepted
- Date: 2026-10-12

## Context

Bare-metal targets (e.g. `thumbv7m-none-eabi`, `riscv32imac-unknown-none-elf`)
need a backend with embedded target support, volatile accesses, atomics,
inline assembly, custom sections and interrupt calling conventions.
Cranelift does not support 32-bit embedded targets.

## Decision

Generate LLVM IR through the `inkwell` crate, emit object files, and link with
`ld.lld` using a linker script generated by the compiler.

The codegen layer only consumes MIR (ADR 0003); no other layer depends on LLVM.

## Consequences

- Access to every LLVM target and optimization.
- Building requires an LLVM **development** installation that provides
  `llvm-config` and static libraries, matching an LLVM version supported by
  the chosen `inkwell` feature (e.g. `llvm18-1`). The official Windows LLVM
  installer ships neither, so a dev build of LLVM (or WSL) is required.
  The exact version and setup must be documented in `CONTRIBUTING.md`.
- LLVM does not implement C ABI lowering of aggregates for frontends; see
  ADR 0006.

## Alternatives considered

- **Cranelift** — no embedded 32-bit targets.
- **Emitting C** — loses control over volatile/layout semantics and inherits
  C's undefined behavior.
- **Own backend** — out of scope for the foreseeable future.
