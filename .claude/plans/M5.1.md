# Plan: M5.1 MIR validation

ADRs: 0094, 0095
Base: 8ce05fa
Program on QEMU: no new program; every program of the tests, e2e on both
targets at `-O0` and `-O`, ui, the generated programs of ADR 0068 and the
snippets of ADR 0069, passes the validator at its three points (ADR 0095,
"When it runs"), since it runs in every build.
Out of scope:
- any change to the language: moves and `#[copy]` are M5.2, linear values
  M5.3, references M5.4, methods M5.5, peripherals M5.6, the move to
  references M5.7 (roadmap, "M5 steps"; ADR 0094 is accepted with this step
  so that M5.1 decides nothing the later steps must break, and implemented
  from M5.2);
- running the analyses of one body before evaluation: ADR 0094, from M5.2,
  which adds the first such analysis;
- new passes over MIR: none exists besides `leave_out`.

Before step 1: the `docs(adr)` commit that accepts ADR 0094 and 0095 also
sets the status line of the ADR 0094 amends, in its file and in the index
(`docs/adr/README.md`):
- 0033: `Accepted; amended by 0063 (the evaluator names HIR items by their
  ids only; `query` reaches every layer of the front end), 0094 (the
  analyses of one body run before that body is evaluated)`; index
  `Accepted, amended by 0063, 0094`.
The same commit holds the roadmap's edits written while planning: the M5
steps table, the decisions agreed for M5.2 to M5.7, the M5 pending decisions
per step, the work owed (the validator) removed, the deferred ideas on affine
and linear values and on typestate updated, and the status line.

Order: the rules of one body come first, wired at the end of MIR building
(1); the types (2) and the depth of `critical` blocks (3) add rules to the
same function; the program's rules and the two later points (4) need the
whole MIR. Each step runs the validator over every existing test through the
build, so a rule today's MIR breaks shows at that step.

A rule that today's MIR breaks (ADR 0095, last paragraph of "The rules of the
program"): if MIR building is wrong, the step fixes it, with a test that
fails without the fix, and records it in `Decisions`; if the MIR is right and
the rule is stated wrong, the step stops and the user is asked, since the
accepted ADR then needs an amending one.

## 1. feat(mir): validate the shape of each body
- Status: todo
- Implements: ADR 0095, "What it is", "When it runs" (point 1), "How it
  fails", and rules S1 to S9.
- Changes:
  - `src/mir/validate.rs` (new): a `Violation` (the body's name, the block,
    the statement's index or the terminator, the rule's id such as `S5`,
    and a short text naming what is wrong); `check_body(&Body) ->
    Vec<Violation>`, which finds every violation without panicking and
    computes nothing through `Body::place_ty`; and the one function that
    panics with the list when it is not empty, the only `panic!` of the
    file. The rules match every variant of `Statement`, `Terminator`,
    `Rvalue`, `Operand`, `PlaceElem` and `AsmOperandKind` without `_`, so
    that a new variant fails to compile there (ADR 0095, "Consequences").
    No cascade and the fixed order of violations (ADR 0095, "What it is").
    Under `#[cfg(test)]`, a thread-local count of the bodies and programs
    checked, which the wiring tests read; nothing outside tests sees it.
  - `src/mir/mod.rs`: `mod validate;` and what the other layers call.
  - `src/mir/build.rs`: `Builder::finish` validates the body it returns,
    which covers `build_body` and `build_expr_body`, before `query` stores
    or evaluates it.
  - `tests/architecture.rs`: `PANICS` gains `src/mir/validate.rs` with 1,
    the panic ADR 0095 decides.
- Tests:
  - unit tests in `src/mir/validate.rs`: a helper makes a small valid body
    (two blocks, a parameter, an assignment and a `return`), which reports
    nothing; one test per rule S1 to S9 changes it to break that rule only,
    and checks that the violations are exactly one, naming the rule; S2 and
    S3 on an external and a naked body, S8 on a constant local written by
    an assignment, a call's destination, an `asm` output and `&raw mut`,
    and not written through a `Deref`;
  - a test that the panic lists every violation of a body that breaks two
    rules, in the fixed order (`#[should_panic]` with the expected text);
  - no cascade: a place naming a local that does not exist reports S7 only;
  - wiring of point 1: a unit test in `src/query.rs` builds a small program
    through `Queries` (`check_all`, `lower_all`) and checks that the count
    of bodies checked grew by the number of bodies built, `comptime` ones
    included;
  - every existing test, which now builds every body through the
    validator.

## 2. feat(mir): validate the types of places, operands and rvalues
- Status: todo
- Implements: ADR 0095, "Types": "fits", volatile places, and rules T1 to
  T9.
- Changes:
  - `src/mir/validate.rs`: the validator's own type of a place, which
    stops at the first projection that does not apply (T1) instead of
    panicking; whether a place is volatile, as `Builder::is_volatile`
    computes it; the type of an operand and of each rvalue; T2 to T9 in
    `check_body`. The type of a call's arguments and destination needs the
    callee, and waits for step 4 (P3).
- Tests:
  - unit tests per rule: T1 for each projection, applied to a type it does
    not apply to and out of range (`ConstIndex` at the length, a `Field`
    past the last, a `Payload` of a variant that does not exist, `Field`
    on a peripheral entry that is an array); T2, T3 and T6 to T9 each
    with one case, T9 with a `u64` input too; T4 rejecting a struct read
    through a volatile pointer, and accepting `*(*p).q` with `p` volatile
    and `q` not; T5 with one case per rvalue kind, and with ADR 0024's
    conversion accepted (`*mut T` assigned to a `*const T` place) and its
    reverse rejected, a pointer of another pointee rejected, a `Use` of a
    `*mut [u8]` into a `*const volatile [u8]` place and a `Slice` from a
    `*const [u8; 4]` into a `*mut [u8]` place accepted (as `Builder::cast`
    builds them), and a `Cast` of a slice rejected;
  - every existing test.

## 3. feat(mir): validate the depth of `critical` blocks
- Status: todo
- Implements: ADR 0095, "`critical` blocks", rules C1 to C3.
- Changes:
  - `src/mir/validate.rs`: a walk from `bb0` giving each block reached the
    stack of `critical_enter` locals open at its start, compared at every
    edge into it; blocks nothing reaches are skipped.
- Tests:
  - unit tests: valid bodies with nested blocks, a `break` leaving two
    blocks, a `return` inside one, a panic inside one, and an unreachable
    block with an unmatched exit; invalid ones for C1 (a block entered at
    depth 0 and 1, and a block entered at depth 1 through two different
    locals), C2 (an exit at depth 0, and an exit naming the outer local
    while the inner is open) and C3 (a `return` at depth 1);
  - every existing test, among them the ui and e2e programs of M4.3 and
    M4.5 with `critical` blocks.

## 4. feat(mir): validate the program after it is assembled and after `leave_out`
- Status: todo
- Implements: ADR 0095, "When it runs" (points 2 and 3), and rules P1 to P8.
- Changes:
  - `src/mir/validate.rs`: `check_program(&Mir) -> Vec<Violation>`, running
    `check_body` on every body (P1) and the rules P2 to P8, with violations
    of a body named by its name and of the program by what they concern (a
    static, a data, a handler).
  - `src/query.rs`: `Queries::into_mir` validates the MIR it returns.
  - `src/mir/mod.rs`: `Mir::leave_out` validates the MIR it leaves, so that
    every caller gets the check, the unit tests that call it included; the
    MIR those tests build by hand is fixed where it breaks a rule.
- Tests:
  - unit tests per rule P2 to P8 on a small valid program built by hand:
    a callee, a `sym`, `entry` and a handler out of range, a static whose
    id is not its index, an operand holding a static's definition from
    before a renumbering (same id, another definition), a peripheral not
    in `Mir::peripherals`, a data id out of range, and `reset` and
    `critical_enter` set to `None` accepted (P2); a call with one
    argument too many, an argument of the wrong type, a `*mut T` argument
    for a `*const T` parameter accepted, a destination the return type
    does not fit (P3); a runtime body calling a `comptime` one (P4); an
    entry that returns `u32`, a handler with a parameter (P5); an external
    static with bytes, a static with one byte too few, a static of type
    `[u8]` reported once (P6); a relocation past the end, and one with an
    addend past its target (P7); a panic with a site when the panic
    function takes no parameter, one without a site in a runtime body when
    it takes one, a site in a local of another type, and a `comptime` body
    with a panic and no site accepted while the panic function takes one
    (P8);
  - a unit test in `src/mir/mod.rs`: a program with `core` validated
    before and after `leave_out`, both empty;
  - wiring of point 2: the unit test of step 1 in `src/query.rs` also calls
    `into_mir` and checks that the count of programs checked grew by one;
  - wiring of point 3: a unit test in `src/mir/mod.rs` calls `leave_out` on
    MIR built by hand whose kept body calls a body id past the end, and
    expects the validator's panic (`#[should_panic]` naming P2);
  - every existing test, which now validates the whole program at both
    points, `--emit=mir` dumps (after `leave_out`) and `erebos build`
    (after `into_mir`) included.
