# Plan: M5.1 MIR validation

ADRs: 0094, 0095
Base: 8ce05fa
Program on QEMU: no new program; every program of the tests, e2e on both
targets at `-O0` and `-O`, ui, the generated programs of ADR 0068 and the
snippets of ADR 0069, passes the validator at its three points (ADR 0095,
"When it runs"), since it runs in every build.
Out of scope:
- any change to the language: moves and `#[copy]` are M5.2, linear values
  M5.3, references M5.4, methods M5.5, peripherals M5.6, the move to
  references M5.7 (roadmap, "M5 steps"; ADR 0094 is accepted with this step
  so that M5.1 decides nothing the later steps must break, and implemented
  from M5.2);
- running the analyses of one body before evaluation: ADR 0094, from M5.2,
  which adds the first such analysis;
- new passes over MIR: none exists besides `leave_out`.

Before step 1: the `docs(adr)` commit that accepts ADR 0094 and 0095 also
sets the status line of the ADR 0094 amends, in its file and in the index
(`docs/adr/README.md`):
- 0033: `Accepted; amended by 0063 (the evaluator names HIR items by their
  ids only; `query` reaches every layer of the front end), 0094 (the
  analyses of one body run before that body is evaluated)`; index
  `Accepted, amended by 0063, 0094`.
The same commit holds the roadmap's edits written while planning: the M5
steps table, the decisions agreed for M5.2 to M5.7, the M5 pending decisions
per step, the work owed (the validator) removed, the deferred ideas on affine
and linear values and on typestate updated, and the status line.

Order: the rules of one body come first, wired at the end of MIR building
(1); the types (2) and the depth of `critical` blocks (3) add rules to the
same function; the program's rules and the two later points (4) need the
whole MIR. Each step runs the validator over every existing test through the
build, so a rule today's MIR breaks shows at that step.

A rule that today's MIR breaks (ADR 0095, last paragraph of "The rules of the
program"): if MIR building is wrong, the step fixes it, with a test that
fails without the fix, and records it in `Decisions`; if the MIR is right and
the rule is stated wrong, the step stops and the user is asked, since the
accepted ADR then needs an amending one.

## 1. feat(mir): validate the shape of each body
- Status: done
- Implements: ADR 0095, "What it is", "When it runs" (point 1), "How it
  fails", and rules S1 to S9.
- Changes:
  - `src/mir/validate.rs` (new): a `Violation` (the body's name, the block,
    the statement's index or the terminator, the rule's id such as `S5`,
    and a short text naming what is wrong); `check_body(&Body) ->
    Vec<Violation>`, which finds every violation without panicking and
    computes nothing through `Body::place_ty`; and the one function that
    panics with the list when it is not empty, the only `panic!` of the
    file. The rules match every variant of `Statement`, `Terminator`,
    `Rvalue`, `Operand`, `PlaceElem` and `AsmOperandKind` without `_`, so
    that a new variant fails to compile there (ADR 0095, "Consequences").
    No cascade and the fixed order of violations (ADR 0095, "What it is").
    Under `#[cfg(test)]`, a thread-local count of the bodies and programs
    checked, which the wiring tests read; nothing outside tests sees it.
  - `src/mir/mod.rs`: `mod validate;` and what the other layers call.
  - `src/mir/build.rs`: `Builder::finish` validates the body it returns,
    which covers `build_body` and `build_expr_body`, before `query` stores
    or evaluates it.
  - `tests/architecture.rs`: `PANICS` gains `src/mir/validate.rs` with 1,
    the panic ADR 0095 decides.
- Tests:
  - unit tests in `src/mir/validate.rs`: a helper makes a small valid body
    (two blocks, a parameter, an assignment and a `return`), which reports
    nothing; one test per rule S1 to S9 changes it to break that rule only,
    and checks that the violations are exactly one, naming the rule; S2 and
    S3 on an external and a naked body, S8 on a constant local written by
    an assignment, a call's destination, an `asm` output and `&raw mut`,
    and not written through a `Deref`;
  - a test that the panic lists every violation of a body that breaks two
    rules, in the fixed order (`#[should_panic]` with the expected text);
  - no cascade: a place naming a local that does not exist reports S7 only;
  - wiring of point 1: a unit test in `src/query.rs` builds a small program
    through `Queries` (`check_all`, `lower_all`) and checks that the count
    of bodies checked grew by the number of bodies built, `comptime` ones
    included;
  - every existing test, which now builds every body through the
    validator.
- Decisions:
  - `Violation` is `{ body: String, at: Location, rule: &'static str, text:
    String }` with `Location` one of `Body`, `Block(bb)`, `Statement(bb, i)`
    and `Terminator(bb)`: the plan's "block, statement or terminator" as one
    value that sorts. The fixed order is the key `(block + 1, position)` of
    `Location` (the body first, a block as a whole before its statements,
    the terminator last), then the rule id as a string; the sort is stable,
    so two violations of one rule at one place keep the order they were
    found in. The ordering by body index of the program is step 4's.
  - The one `panic!` is in `assert_valid(&[Violation])`, which takes a list
    so that step 4's `check_program` calls the same function and the file
    keeps its count of 1; `assert_valid_body(&Body)` is `check_body` then
    `assert_valid`. The message is `invalid MIR, a bug of the compiler
    (ADR 0095): N violations` and one line per violation, `` `name`,
    bb1, statement 2: S5: text ``. `PANICS` gains `src/mir/validate.rs` with
    1: no user input reaches it unless MIR building is wrong (ADR 0095, "How
    it fails").
  - The count of bodies checked is incremented in `check_body`, not in the
    function that panics, so that step 4's `check_program`, which runs
    `check_body` on every body (P1), counts them too; the test of point 1
    reads the difference around `lower_all`, before `into_mir`, which will
    validate the whole program.
  - No cascade, where two rules would report one fault: S3 checks only that
    a naked body has one block, no statement and an `asm` terminator, and
    that the `asm` has `noreturn` is S9's alone; with no block at all in a
    body that is not external, S2 speaks and S3 does not; S8 is skipped for
    a place whose local does not exist (S7); S1 reports a parameter count
    past the locals once, and `params()` is never called. A `Location::Body`
    S3 is for the number of blocks, `Block(bb0)` for the statements and
    `Terminator(bb0)` for the terminator.
  - S7 reports each name of a missing local (a place's base and each index
    in its projection are separate), since each is a fault of its own.
  - S8: a place is written when it is the destination of an assignment or of
    a call, an `out` or `inout` place of an `asm`, or the place of
    `&raw mut`; "through a pointer" is any `Deref` or `Offset` in the
    projection, as the ADR says. `&raw const` of a constant local is fine.
  - S9 checks the placeholders of an `asm` in a statement and in a
    terminator alike, and its operands' locals for S7/S8 too.
  - `Rvalue::AddressOf` is matched twice (`mutable: true`, then `false`),
    still without `_`, to apply S8 to the first.
  - `src/mir/mod.rs` re-exports `check_body`, `Location` and `Violation`
    (so that step 4 and later passes can call them) and, under
    `#[cfg(test)]`, `bodies_checked`; `Builder::finish` reaches
    `assert_valid_body` through `crate::mir::validate`, a private submodule
    of `mir` that `mir::build` may name as a descendant. `tests/architecture.rs`
    needs no change besides `PANICS`.
  - The wiring test of point 1 needs the HIR of a program in `query.rs`'s
    tests, and only `driver::front_end` made one, together with the rest of
    the pipeline. `front_end`'s first half became `to_hir` (same code, the
    early stops now `Err(FrontEnd)`), and a `#[cfg(test)] pub(crate) fn
    hir_of` returns `to_hir`'s HIR for a program in one file with `core`.
    Behaviour of the driver does not change. `hir_of` returns an `Option` so
    that the helper holds no panic (`PANICS` counts `cfg(test)` code outside
    a `mod tests`); the test unwraps it.
  - The wiring test builds a program with a constant, a function and one
    `comptime twice(K)` expression, and expects the bodies checked to equal
    `Mir::bodies.len() + 1`: every body of `core` and the program, which
    `into_mir` collects, plus the body of the `comptime` expression, which
    is run and dropped (`build_expr_body`).
  - S5 yields one violation per block named, not per terminator: a `Switch`
    with two cases past the end, or one that names `bb0` twice, has one
    violation for each.
  - A naked body that is also `external` goes through the S3 check, which
    reports "no block" when it has none, since S2 (which would speak for a
    non-external body with no block) accepts an external body with none.
    The case probably cannot be built (an external function has no body to
    be naked); the code decides it so that no body escapes both rules.
  - Violations of different rules at one location are ordered by string
    comparison of the rule id. That is right for S1 to S9; with ADR 0095's
    other letters it is alphabetical (`C`, `P`, `S`, `T`), and an id of two
    digits such as `S10` would sort before `S2`. Making it numeric was not
    done because no such id exists yet; the step that adds one changes the
    key. (From the review.)
  - The `Display` of `Location` is `bb1, statement 2` for a statement,
    `bb0, terminator` for a terminator, `bb1` for a block and `body` for the
    body; the `should_panic` test of the panic's message pins this format.
    (From the review.)
  - The test of S7 puts a missing local in every operand position: a call's
    arguments, the operands of `Unary`, `Binary` (each side), `Cast` and
    `Slice` (each part), `SliceAddress`, `&raw const`, the `In` and `InOut`
    inputs of an `asm` in a statement and in a terminator, `If.cond`,
    `Switch.discr` and the message of `AssertionFailed`, so that dropping
    the check of any of them fails a test. (From the review.)
  - Tests of S2 and S3 use an external and a naked body built by helpers; the
    unit tests of each rule check that the violations are exactly `[rule]`
    (`breaks_only`), and the body they change is the one `valid()` returns,
    with a constant local, a plain local and a `*mut u32` local so that
    S7/S8 cases need no extra setup.

## 2. feat(mir): validate the types of places, operands and rvalues
- Status: done
- Implements: ADR 0095, "Types": "fits", volatile places, and rules T1 to
  T9.
- Changes:
  - `src/mir/validate.rs`: the validator's own type of a place, which
    stops at the first projection that does not apply (T1) instead of
    panicking; whether a place is volatile, as `Builder::is_volatile`
    computes it; the type of an operand and of each rvalue; T2 to T9 in
    `check_body`. The type of a call's arguments and destination needs the
    callee, and waits for step 4 (P3).
- Tests:
  - unit tests per rule: T1 for each projection, applied to a type it does
    not apply to and out of range (`ConstIndex` at the length, a `Field`
    past the last, a `Payload` of a variant that does not exist, `Field`
    on a peripheral entry that is an array); T2, T3 and T6 to T9 each
    with one case, T9 with a `u64` input too; T4 rejecting a struct read
    through a volatile pointer, and accepting `*(*p).q` with `p` volatile
    and `q` not; T5 with one case per rvalue kind, and with ADR 0024's
    conversion accepted (`*mut T` assigned to a `*const T` place) and its
    reverse rejected, a pointer of another pointee rejected, a `Use` of a
    `*mut [u8]` into a `*const volatile [u8]` place and a `Slice` from a
    `*const [u8; 4]` into a `*mut [u8]` place accepted (as `Builder::cast`
    builds them), and a `Cast` of a slice rejected;
  - every existing test.
- Decisions:
  - A rule today's MIR broke, found by running the validator over the tests:
    T5 for `SliceAddress`. `Builder::cast` built `s as *mut u16` (a slice
    cast to a thin pointer of another pointee, which ADR 0031's table
    allows: "any thin pointer") as `SliceAddress` into a temporary of the
    target type, so the statement read `*const u8` and wrote `*mut u16`. The
    ADR states T5 for `SliceAddress` precisely ("the thin pointer to the
    elements of the slice in the place, with its mutability and volatility"),
    and `Rvalue::SliceAddress`'s own doc says the same, so the MIR was wrong,
    not the rule: `cast` now assigns the address to a temporary of
    `slice_address_ty()` and, when the target differs, casts that
    (`Rvalue::Cast`, a pointer to a pointer, which T5 accepts). Same type
    gives the same MIR as before (`s as *const u8`). The test is the new UI
    program `tests/ui/mir_slice_address_casts.ers` (`emit: mir`): a cast to
    the same type, to another pointee, to a pointer to an array, and from a
    volatile slice; without the fix the program panics in the validator, as
    do `typeck_slices.ers` and `typeck_slice_errors.ers` through
    `tests/architecture.rs`. The ADR's "Types" paragraph names the casts
    `Builder::cast` builds (`Use` for slice to slice, `Slice` for array
    pointer to slice) but not this one, which now is a `SliceAddress` and a
    `Cast`.
  - The validator's type of a place is a `Typed { ty, volatile }`, made by
    `Checker::place` in one walk that also reports S7 (base and indices),
    T1 and T2, so that every rule that needs a place's type asks `place`
    once per occurrence. `project` (T1) matches every `PlaceElem` on its own,
    and then the type inside, with no `_` over the projections, so that a new
    one fails to compile; `volatile_after` copies `Builder::is_volatile`'s
    rule and says so in its doc. `fits` is ADR 0095's "fits".
  - The walk stops at the first projection that does not apply (one T1 for
    the place, the rest is not looked at), but T2 is checked for every index
    local that exists, whatever became of the walk, since the local is
    another input than the type.
  - T1 reads `StructDef::fields`, `EnumDef::variants` and
    `PeripheralTypeDef::layout` through the `OnceLock`s (private fields of
    `mir`, reached from its child module) instead of the accessors that
    panic: a struct whose fields were never set, an enum whose variants were
    not, and a peripheral type with no layout are each a T1 violation of the
    projection. A peripheral type with no layout is a T1 because the entry's
    array-ness cannot be told, and "every body reaching a register is built
    after the layout is set" (`PeripheralTypeDef`).
  - T1's `Offset` rejects a pointer to `[T]` or to a peripheral type (the
    ADR's "sized type": a type with no size); `Deref` accepts any pointer.
  - T3 and T4 (`Checker::whole`) apply where the ADR lists them: an operand
    that is `copy`, the destination of an assignment or a call, an `asm`
    output place. Not to the place of `&raw`, `SliceAddress` or `SliceLen`,
    which read no value of the place's type (`SliceLen` "reads the slice").
    T3 is `!`, `[T]` and a peripheral type; T4 is `is_aggregate()`, which is
    what the ADR lists (array, struct, slice, enum with payloads).
  - No cascade, as a function of what each helper returns: `place` gives
    `None` when S7 or T1 fired, `whole` when T3 fired, and `operand` the
    same, so T5, T7, T8 and T9 are skipped for that input; a T4 does not
    hide the type (the place's type is right, only its volatile access is
    not). A T5 fault of the operands of an rvalue (a unary on a `bool`
    negated, a cast of an array, a slice with a pointer that is not thin) is
    reported once and the comparison with the destination is not made; a
    `Slice`'s length and its pointer are two inputs, so each reports.
  - T5 details the ADR leaves to the code: a comparison's operands "of one
    type up to fitting" is `fits` in either direction; a shift takes
    integers of any widths and has the left operand's type; a bitwise
    operation takes `bool` and the arithmetic ones do not; an enum with
    payloads and a peripheral type are not comparable; `Slice` accepts a
    destination whose element type is the pointer's pointee, or the element
    of the array it points to (so both forms of ADR 0031 and an array of
    arrays are accepted); `AddressOf` is compared without building the
    pointer type (no leak): the destination is a pointer to the place's
    type, not volatile, and `*const` if the address was taken with `&raw
    const`.
  - T6 applies to `AsmOperandKind::Const` as well as to `Const::Int`: it is
    an integer constant, built from one by `mir::build::asm`, and the code
    of the `asm` template prints its bits (`display_bits`).
  - T7 reports each case at fault, not the `switch`: a value above the
    width, or a repeated one (the second and later occurrences). A `bool`
    discriminant has width 1.
  - T8 accepts exactly `*const [u8]`, not volatile.
  - T9 is applied to the type of the operand, or of the place of an output,
    after T3 passed for it; `bool`, `()`, arrays, structs, enums, `u64`/`i64`
    and slice pointers are rejected, as the ADR's "integer of at most 32 bits
    or a thin pointer" says.
  - A call's arguments and destination are read like any operand and place
    (S7, T1 to T4, T6), and their types against the callee wait for step 4
    (P3), as the plan says.
  - The unit tests' `valid()` body grew locals (`_5: [u32; 4]`, `_6` a
    constant `*mut u32`, `_7: *const u32`, `_8: usize`, `_9: *mut` of a
    peripheral type with a layout, `_10: *mut [u32]`) so that the cases of
    S7 and S8 are well typed and still break only their rule; the ghost
    local is now `GHOST` (50), and the S6, S3 and S1 cases were adjusted for
    the same reason (S6's body no longer assigns the `!` place). `typed()`
    adds the locals the T5 to T9 cases read.
  - Tests of T1 go through a `Call` whose argument is the place (`reading`),
    since a call's types are not checked yet; T5 to T9 go through `assigning`
    (a new destination local of the wanted type) and the terminators. One
    test per rule, with each accepted form beside the rejected ones, plus a
    test of T1 not cascading and one of the other types not cascading.

## 3. feat(mir): validate the depth of `critical` blocks
- Status: done
- Implements: ADR 0095, "`critical` blocks", rules C1 to C3.
- Changes:
  - `src/mir/validate.rs`: a walk from `bb0` giving each block reached the
    stack of `critical_enter` locals open at its start, compared at every
    edge into it; blocks nothing reaches are skipped.
- Tests:
  - unit tests: valid bodies with nested blocks, a `break` leaving two
    blocks, a `return` inside one, a panic inside one, and an unreachable
    block with an unmatched exit; invalid ones for C1 (a block entered at
    depth 0 and 1, and a block entered at depth 1 through two different
    locals), C2 (an exit at depth 0, and an exit naming the outer local
    while the inner is open) and C3 (a `return` at depth 1);
  - every existing test, among them the ui and e2e programs of M4.3 and
    M4.5 with `critical` blocks.
- Decisions:
  - No rule C1 to C3 is broken by today's MIR: every existing test (ui, e2e
    on both targets, generated, rejected, fuzz, svd) passes the walk, so MIR
    building changed nowhere and the ADR's rules are right as stated.
  - The walk is `Checker::critical`, run after the per-block loop of
    `check_body` and before the sort, so its violations take their place in
    the fixed order. It is a worklist (a stack, successors pushed in the
    order of `Terminator::successors`) over `Option<Vec<Local>>` per block,
    the stack of open locals at its start. A block gets the stack of the
    first edge found into it; a later edge with another stack is a C1 and the
    block is not walked again, so one fault is one violation and nothing
    cascades into what follows the join. Which edge is "first" depends on the
    worklist's order, which is fixed; the unit test pins it for one case.
  - C1 is reported at the terminator of the block the disagreeing edge
    leaves (the edge is the thing compared), naming the target and both
    stacks, as `[_1, _3]`, outermost first.
  - Edges to `bb0` and to a block that does not exist are skipped: S5
    reported them.
  - C3 is reported at the `return`'s terminator when the stack is not empty.
    Only `Return` is C3; a `panic` or an `asm` at depth 1 is valid (nothing
    returns to close the block).
  - C2 and the recovery of the stack, so that one bad exit is one violation:
    at depth 0 it reports; an exit of a local open further down closes it and
    every block above it (the likely MIR fault is the missing exits of the
    inner blocks, and popping only the top would report again at the next
    exit and at the `return`); an exit of a local that is not open reports and
    closes nothing. A local that does not exist is S7's: C2 is not also
    reported for it unless the stack is empty (a fault of its own); when the
    stack is not empty such an exit neither reports nor pops (`None => {}`),
    so the ghost stays open, and `c2_does_not_repeat_a_missing_local` pins it
    as `["S7", "C3"]`. (From the review.)
  - `Location::Statement` for C2, `Terminator` for C1 and C3. Violations of
    different rules at one place are sorted by the rule's string, so a C2 and
    an S7 on one statement are listed `C2`, `S7`.
  - The stack is a `Vec<Local>`, compared by equality, not by depth: C1 asks
    for the same locals, and two paths with equal depths and different locals
    break it.
  - Existing unit tests that put a lone `critical_enter` or `critical_exit`
    in `valid()` (S7 and T2) now broke C3 or C2, since the body returns with
    the block open: they use an enter and its exit, and assert both
    violations (`["S7", "S7"]`, `["T2", "T2"]`) instead of one per statement.
    That a T2 on the enter and one on the exit are told apart is lost; both
    go through `critical_local`.
  - Tests: `flow` builds a body from `(statements, terminator)` pairs on the
    locals of `typed()`; one test of valid shapes (nested with a join,
    `break` out of two blocks in a loop, `return` after an exit, a panic at
    depth 1, a block re-entered by a loop after it was left, an unreachable
    block with an unmatched exit and with a `return` at depth 1), one test
    each for C1 (depths 0 and 1, two locals, a loop opening on every turn, no
    cascade after the join), C2 (depth 0, the outer local named, a local not
    open), C3, and one for a missing local not repeated as C2.

  - every existing test, which now validates the whole program at both
    points, `--emit=mir` dumps (after `leave_out`) and `erebos build`
