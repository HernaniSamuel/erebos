# Plan: M5.6 Ownership of peripherals

ADRs: 0115 (building on 0058, 0066, 0078, 0084, 0093, 0094, 0101, 0106, 0110,
0111, 0113, 0114)
Base: c132fc7
Program on QEMU: a UART owned by its handler, with the thread context sending
through it, on both targets at `-O0` and `-O`. The thread never names the UART:
it queues the bytes in a `static mut` ring inside `critical` and raises an
interrupt; only handlers name the UART, so the handler context owns it (ADR
0115).
- `tests/e2e/uart_owned_armv7m/`: `main.ers` with `an385.svd` and the
  `an385.ers` that `erebos svd` writes from it, copies of
  `uart_interrupt_armv7m/`'s. The entry function enables the line
  `Interrupt::Uart0Tx` (`core::arch::nvic_enable`) and interrupts; `send`
  queues a message in `critical` and, when the transmitter is idle, pends the
  line with `core::arch::nvic_pend` (an address in `core`, no peripheral). The
  handler at `Interrupt::Uart0Tx` sets up the UART on its first run
  (`bauddiv`, `ctrl` with `tx_en` and `tx_inten`; a `static mut` only the
  handler names records it), clears `intstatus.tx` and writes the next byte,
  counting the bytes sent; the thread waits in `critical` with
  `wait_for_interrupt` until the queue is empty and the last byte is out, and
  compares the count with the message's length. It exits through
  `board::exit`.
- `tests/e2e/uart_owned_riscv32/`: `main.ers` with a `virt.svd` that is
  `uart_interrupt_riscv32/`'s with the CLINT's `msip` register of hart 0 added
  (`0x0200_0000`), and the `virt.ers` generated from it. The thread sets up the
  PLIC inside `critical` (the handler claims, so `PLIC` is shared and rule 1
  applies), sets `mie.MEIE` and `mie.MSIE` by `asm`, and enables interrupts;
  `send` queues in `critical` and, when the transmitter is idle, writes
  `CLINT.msip = 1` in the same block. The handler at
  `Vector::MachineSoftware` clears `msip`, sets up the UART on its first run
  and starts the transmission (`ier.thri`); the handler at
  `Vector::MachineExternal` claims source 10 and serves the UART as
  `uart_interrupt_riscv32/` does. Both handlers are the handler context. It
  exits through `board::exit`.
- Both print `uart owned by its handler` and exit 0.
Out of scope:
- tokens for peripherals, a peripheral taken once, owners declared on
  handlers: rejected by ADR 0115;
- registers and clusters of one peripheral as separate units of the rule: not
  yet scheduled, addable without breaking programs (ADR 0115, as for borrows,
  ADR 0111);
- `replace` on statics, statics of linear types and any move of a value from
  one context to another: not yet scheduled (ADR 0115; ADR 0101 unchanged);
- an `impl` in another module than its type's (ADR 0113): the programs above
  call no function of a generated peripheral type, so M5.6 does not need it;
  it stays not yet scheduled;
- priorities and several cores: not in M5 (ADR 0094, 0115);
- `core` and the tests moved to references: M5.7.

- 0093: `Accepted; amended by 0110 (...), 0112 (...), 0115 (places naming a

planning (M5.6's pending decisions settled; the items not yet scheduled).

Order: the three programs that share a peripheral today are rewritten first
(1), with `critical` and the board's `exit`, which they compile with before
the check exists; the comparison of peripherals' bytes is corrected next (2),
in the borrow check that already uses it, so that the check (3) shares it as
ADR 0115 states it; the check then finds every program of the tests valid.
The program on QEMU (4) needs the check, so that its rejected variant has an
error. Each step gains a `Decisions:` list while it is built (`/build-step`),
for the choices it makes that this plan and the ADR do not dictate.

## 1. test(e2e): protect the peripherals that handlers share
- Status: done
- Implements: ADR 0115, "Programs that name peripherals directly"
- Changes:
  - `tests/e2e/uart_interrupt_armv7m/main.ers`: the setup of `UART0`
    (`bauddiv`, `ctrl`) inside `critical`.
  - `tests/e2e/uart_interrupt_riscv32/main.ers`: the setup of `PLIC` inside
    `critical`; the program's `exit` removed for `board::exit` (`use
    board::exit;`), so that `TEST` is named by nothing; the header comment
    says why. The write of the generated `Finisher` bit-field struct that this
    `exit` made stays covered by `tests/e2e/svd_virt/main.ers` and
    `tests/e2e/uart_fields/devices.ers`.
  - `tests/e2e/uart_loopback_riscv32.ers`: every access of the thread to
    `UART0` and `PLIC` inside `critical`, joined to the existing blocks where
    they are adjacent. Joining moves the instant a raised interrupt is taken
    to the end of the block, which the program's waits already expect; QEMU
    at both levels confirms it.
- Tests: the three programs keep their expected output and exit code on QEMU
  at `-O0` and `-O`; no other test changes. `uart_interrupt_riscv32/virt.ers`
  is not edited (it is generated and `tests/svd.rs` compares it).
- Decisions:
  - `uart_interrupt_armv7m/main.ers`: only `bauddiv` and `ctrl` go in the new
    `critical`; `nvic_enable` and `enable_interrupts` stay outside, as they name
    no peripheral (addresses in `core`). A comment on the block says why.
  - `uart_interrupt_riscv32/main.ers`: the board's `exit` takes `u32` where the
    removed one took `u16`; every call passes a literal, so none changes. `use
    virt::test::Finisher` and `TEST` leave the imports (nothing names them). The
    header comment gains the reason, as the plan asks.
  - `uart_loopback_riscv32.ers`: the two `if PLIC.claim != 0 { exit(..) }`
    checks cannot hold `exit` inside a `critical` block that the plan wants
    short, so the claim is read in `critical` into a `let` (`claimed`, `left`)
    and tested after it; the second read is joined to the block that clears
    `ier` and `mcr`, which it follows directly. The setup writes (`mcr`, `ier`,
    `thr`) form one block; the `thri` write is a block of its own, since only a
    wait (itself a `critical`) is adjacent to it. The entry function's blocks
    are not otherwise merged across `enable_interrupts` or the waits, to keep
    the order of the program as it was.
  - No `critical` is added around the `putc` calls: `board::putc` writes
    through a `const` pointer and names no peripheral.

## 2. fix(analysis): an empty peripheral meets no other
- Status: done
- Implements: ADR 0111 as worded ("bytes meet"), and ADR 0115, "Peripherals
  whose bytes meet are one device"
- Changes:
  - `src/analysis/borrows.rs`: `overlap` compares two peripherals with a
    function that is false when either range is empty (`p.0 < q.1 && q.0 <
    p.1` alone counts an empty range strictly inside another as meeting it).
    The function, `meet(p, q)` with `bytes(p)`, moves to
    `src/analysis/bits.rs`, so that step 3 uses the same one.
- Tests: unit tests of `meet` in `bits.rs`: ranges sharing a byte, adjacent
  ranges, one inside the other, an empty range strictly inside another, at its
  start and at its end, and two empty ranges at one address; a unit test in
  `borrows.rs` beside `peripherals_conflict_when_their_bytes_meet`, a borrow of
  an empty peripheral inside another's range in no conflict. No ui snapshot
  changes (no test declares an empty peripheral inside another's range;
  checked when built).
- Decisions:
  - `bytes` moves to `bits.rs` with `meet` and becomes private there: only
    `meet` is used outside, by `borrows.rs` now and `shared_statics.rs` in
    step 3.
  - `meet` states emptiness explicitly (`p.0 < p.1 && q.0 < q.1` before the
    overlap test) instead of relying on the arithmetic, so that the rule reads
    as ADR 0111's "bytes meet". A peripheral whose type has no layout yet has
    an empty range and so meets none, as `bytes` documented already.
  - `overlap` keeps its `p != q` guard: the same peripheral falls to the
    root-equality arm, so an empty peripheral is still one root with itself
    (the borrow test checks it), while `meet` alone says nothing about identity.
  - The unit tests of `meet` in `bits.rs` build their own peripherals (a type
    without registers and a layout of the wanted extent) rather than reuse the
    helpers of `borrows::tests`, which is private; every case is checked in
    both orders, since `meet` must be symmetric. They are four tests, by kind
    of case (sharing a byte, adjacent or distant, inside, empty).
  - The `borrows.rs` test builds its empty peripheral with the two registers of
    `device()` and an extent of 0, borrowed in both directions against a
    non-empty one, so the accesses reach the same register shapes as in
    `peripherals_conflict_when_their_bytes_meet`.
  - Checked: no ui snapshot changes (the full test run is unchanged).

## 3. feat(analysis): peripherals in the rule of shared statics
- Status: done
- Implements: ADR 0115, "Peripherals in the rule of ADR 0078",
  "Diagnostics"; ADR 0093 as amended
- Changes:
  - `src/analysis/shared_statics.rs`: a place names a static or a peripheral;
    `Scan::of` collects `Const::Peripheral(p)` operands next to statics; a
    context's `first` place is kept per static and per peripheral; a
    peripheral is shared with a context when that context reaches it or one
    that `bits::meet`s it; rules 1 and 2 report
    `analysis::unprotected-peripheral` and `analysis::unmaskable-peripheral`,
    with the title, the labels and the choice of the other place of ADR 0115;
    emitted after the statics of the same rule, by `BodyId`, block, statement
    and index in `Mir::peripherals`. `PeripheralDef` has no id: the index is
    the position in `Mir::peripherals`, found once per check by a linear
    search of it with `PeripheralRef`'s `PartialEq` (by pointer; it has no
    `Hash`, and none is added for this), and used as the peripheral's key.
    The module comment says it covers peripherals.
  - `src/analysis/mod.rs`: the module comment names ADR 0115.
  - `src/driver.rs`: `inserted_calls_reach_no_static_and_no_check` and
    `reset_names_no_static_mut` also find no `Const::Peripheral`;
    `the_walk_finds_a_check_and_a_static` also finds a peripheral in a function
    that names one (names updated to say so).
  - `tests/rejected.rs`: the two codes join the exemption of ADR 0093's, its
    reason naming ADR 0115 and the ui tests `shared_peripheral_*`.
  - `docs/reference.md`: the two codes in the table of diagnostic codes, next
    to `analysis::unprotected-static`.
- Tests (`tests/ui/`, `// emit: mir`, riscv32 unless named; each is a
  snapshot of the dump or the diagnostics):
  - `shared_peripheral_naming.ers` (rejected): rule 1 at each way of naming of
    ADR 0115's list, in the entry function and in a callee with its path.
  - `shared_peripheral_over.ers` (rejected): a peripheral `over` another, the
    thread naming one and the handler the other, both ways; the title and the
    label name the other peripheral. The device `A` with `B` and `C` over its
    halves, the thread naming `A` and `B` and a handler `C`: the thread's
    places of `A` are errors, those of `B` are not.
  - `shared_peripheral_unmaskable.ers` (rejected): a fault handler and the
    thread with the thread's access inside `critical`; two unmaskable
    handlers, both reported; a panic function writing a peripheral the
    thread writes, with a fault handler that has a check.
  - `shared_peripheral_nmi_thumbv7m.ers` (rejected): NMI and the thread.
  - `shared_peripheral_and_static.ers` (rejected): one statement naming a
    shared static and a shared peripheral, one error under each code.
  - `shared_peripheral_accepted.ers`: the accepted cases of ADR 0115's list,
    each in its own function or handler as the rules allow, `B` and `C` over
    the halves of `A` with `A` named by neither among them.
  - `shared_peripheral_typeck.ers` and `shared_peripheral_opt.ers`: the
    stage tests, as `shared_static_typeck.ers` and `shared_static_opt.ers`.
  - The unit tests of `src/driver.rs` above.
  - Every e2e, ui, generated (ADR 0068) and rejected (ADR 0069) program
    still passes: step 1 made the programs that share a peripheral obey the
    rule.
- Decisions:
  - A place is `Named::Static(StaticRef)` or `Named::Peripheral { index,
    peripheral }`, in the one `Place` and `Scan` of the module, rather than a
    second list of places for peripherals: a statement's places stay in one
    order (statics by id, then peripherals by index, as ADR 0115 asks for the
    label), and the walk of blocks, the depth of `critical` and the calls are
    done once. `Scan::of` takes `Mir::peripherals` for the index; an operand
    naming a peripheral that the list lacks (which the validator, P2, rejects)
    is not a place, instead of a panic, so `PANICS` is unchanged.
  - A `Context` gains `near` (by peripheral index: the first place naming that
    peripheral or one whose bytes meet it, found in the order of bodies and
    places, so a statement's lowest index wins as the ADR says) and `named`
    (whether some place names the peripheral itself). `near` is filled when the
    context is built, by comparing each place's peripheral with every entry of
    `Mir::peripherals` through `bits::meet` (`i == index` first, so an empty
    peripheral still matches its own name). The cost is places times
    peripherals, small for a program and for the largest generated module
    (the ESP32-C3's); no table of `meet` is kept.
  - The title and the other label read the context's two facts apart, as the
    ADR words them. The title says "reaches `X`, whose bytes meet it" only when
    the context never names the peripheral itself (`named` false); otherwise it
    says "reaches it too", even when the first place found is a meeting
    peripheral's, and then the other label still names that peripheral ("reaches
    `TWIN_VIEW` here, whose bytes meet `TWIN`'s"). `shared_peripheral_over.ers`
    has this case (`TWIN`), so it is a decision of a test and not an accident.
  - Rule 1 for peripherals needs no `thread` context: every body of the
    outside-`critical` search is in the thread context already, and `near` of
    the handler context says whether the peripheral is shared. Rule 1's early
    return is the handlers being empty or the handler context naming no
    peripheral.
  - `Other` (rule 2) gained the `Context` it came from, and `other_context`
    takes the function that finds a place in a context (statics: `first`;
    peripherals: `near`), so that the order thread, handler, other unmaskable
    contexts is written once; the unmaskable contexts are built once in
    `check` and passed to both rule 2 functions. The labels of the calls on a
    path moved to `path_labels`, with the text after the step as a parameter
    (", outside `critical`" for rule 1, nothing for rule 2): the texts are
    those of ADR 0093, so no snapshot of the statics changes.
  - Errors are emitted per rule, statics then peripherals (rule 1 statics, rule
    1 peripherals, rule 2 statics, rule 2 peripherals), and
    `Diagnostics::into_vec` orders them by primary label, as for statics.
  - Texts, where ADR 0115 gives them: the help of rule 1 is "put the access, or
    one call on the path to it, in a `critical` block, or leave the device to
    one context", that of rule 2 "leave the device to this handler, or reach it
    through a pointer from a `const`". The label on a place that is both
    contexts' own is the statics' ("reached here, outside `critical`, by the
    thread and by the handler ..."); a peripheral's other place that is the
    same place can only name the peripheral itself, so no wording for a meeting
    one is needed.
  - `driver.rs`: `Found` gains `peripherals` (`body: peripheral`), read from
    `Const::Peripheral` operands next to the statics, and the three tests are
    renamed to say it: `inserted_calls_reach_no_static_no_peripheral_and_no_check`,
    `the_walk_finds_a_check_a_static_and_a_peripheral`,
    `reset_names_no_static_mut_and_no_peripheral`. The program of the walk gets
    a function `drives` that writes a peripheral, so the new column can fail;
    the program of the reset test writes one from `main`, and the walk from
    `_start` must find `main: DEVICE`.
  - `tests/rejected.rs`: one `Exempt` for the two new codes, separate from the
    statics' (their reasons differ in the files that cover them), with the same
    reason as ADR 0093's.
  - Tests of `tests/ui/`: the plan's names and cases, with these choices.
    `shared_peripheral_naming.ers` gives each way of naming its own peripheral
    (14, one per way plus `CALLED`, reached by a callee) so each error has a
    title of its own; the handler writes `data` of each, since the unit of the
    rule is the whole peripheral; the method is `Device::restart`, whose body
    names nothing (a use of a reference), so the only place is at the call.
    `shared_peripheral_over.ers` adds the `TWIN` case above to the two
    directions and the `WHOLE`/`LOW`/`HIGH` case. `shared_peripheral_unmaskable.ers`
    adds to the plan's cases a fault handler naming a view `over` the device the
    thread names in `critical` (rule 2 with a meeting peripheral: its title
    and label differ from rule 1's). `shared_peripheral_and_static.ers` covers
    rule 1 with `DEVICE.data = COUNT` in the entry function and rule 2 with the
    same in a fault handler against the thread; the two operands are in
    separate MIR statements, so the test shows one error under each code for
    one source statement. `shared_peripheral_accepted.ers` declares `EMPTY` as
    `peripheral Nothing {}` `over FULL` and names it by `&raw mut EMPTY`
    (a peripheral with no register has none to write); the pointer from a
    `const` is `&raw mut CONSTED` of a peripheral named by nothing else.
    Their snapshots were read before being accepted; no existing snapshot
    changed.
