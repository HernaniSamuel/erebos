# Plan: M5.6 Ownership of peripherals

ADRs: 0115 (building on 0058, 0066, 0078, 0084, 0093, 0094, 0101, 0106, 0110,
0111, 0113, 0114)
Base: c132fc7
Program on QEMU: a UART owned by its handler, with the thread context sending
through it, on both targets at `-O0` and `-O`. The thread never names the UART:
it queues the bytes in a `static mut` ring inside `critical` and raises an
interrupt; only handlers name the UART, so the handler context owns it (ADR
0115).
- `tests/e2e/uart_owned_armv7m/`: `main.ers` with `an385.svd` and the
  `an385.ers` that `erebos svd` writes from it, copies of
  `uart_interrupt_armv7m/`'s. The entry function enables the line
  `Interrupt::Uart0Tx` (`core::arch::nvic_enable`) and interrupts; `send`
  queues a message in `critical` and, when the transmitter is idle, pends the
  line with `core::arch::nvic_pend` (an address in `core`, no peripheral). The
  handler at `Interrupt::Uart0Tx` sets up the UART on its first run
  (`bauddiv`, `ctrl` with `tx_en` and `tx_inten`; a `static mut` only the
  handler names records it), clears `intstatus.tx` and writes the next byte,
  counting the bytes sent; the thread waits in `critical` with
  `wait_for_interrupt` until the queue is empty and the last byte is out, and
  compares the count with the message's length. It exits through
  `board::exit`.
- `tests/e2e/uart_owned_riscv32/`: `main.ers` with a `virt.svd` that is
  `uart_interrupt_riscv32/`'s with the CLINT's `msip` register of hart 0 added
  (`0x0200_0000`), and the `virt.ers` generated from it. The thread sets up the
  PLIC inside `critical` (the handler claims, so `PLIC` is shared and rule 1
  applies), sets `mie.MEIE` and `mie.MSIE` by `asm`, and enables interrupts;
  `send` queues in `critical` and, when the transmitter is idle, writes
  `CLINT.msip = 1` in the same block. The handler at
  `Vector::MachineSoftware` clears `msip`, sets up the UART on its first run
  and starts the transmission (`ier.thri`); the handler at
  `Vector::MachineExternal` claims source 10 and serves the UART as
  `uart_interrupt_riscv32/` does. Both handlers are the handler context. It
  exits through `board::exit`.
- Both print `uart owned by its handler` and exit 0.
Out of scope:
- tokens for peripherals, a peripheral taken once, owners declared on
  handlers: rejected by ADR 0115;
- registers and clusters of one peripheral as separate units of the rule: not
  yet scheduled, addable without breaking programs (ADR 0115, as for borrows,
  ADR 0111);
- `replace` on statics, statics of linear types and any move of a value from
  one context to another: not yet scheduled (ADR 0115; ADR 0101 unchanged);
- an `impl` in another module than its type's (ADR 0113): the programs above
  call no function of a generated peripheral type, so M5.6 does not need it;
  it stays not yet scheduled;
- priorities and several cores: not in M5 (ADR 0094, 0115);
- `core` and the tests moved to references: M5.7.

Before step 1: the `docs(adr)` commit that accepts ADR 0115 also sets the
status lines of the ADRs it amends, in their files and in the index
(`docs/adr/README.md`), keeping each existing parenthesis:
- 0058: `...; amended by 0060 (...), 0061 (...), 0064 (...), 0066 (...), 0110
  (...), 0115 (a peripheral is checked across contexts)`; index `Accepted,
  amended by 0060, 0061, 0064, 0066, 0110, 0115`.
- 0078: `Accepted; amended by 0093 (...), 0115 (peripherals are seen by the
  check)`; index `Accepted, amended by 0093, 0115`.
- 0093: `Accepted; amended by 0110 (...), 0112 (...), 0115 (places naming a
  peripheral; two codes)`; index `Accepted, amended by 0110, 0112, 0115`.
- 0094: `Accepted; amended by 0110 (...), 0115 (a context owns what only it
  reaches; moves still do not cross contexts)`; index `Accepted, amended by
  0110, 0115`.
- 0110: `Accepted; amended by 0115 (a borrow of a peripheral names it)`;
  index `Accepted, amended by 0115`.
The same commit holds this plan and the roadmap's edits written while
planning (M5.6's pending decisions settled; the items not yet scheduled).

Order: the three programs that share a peripheral today are rewritten first
(1), with `critical` and the board's `exit`, which they compile with before
the check exists; the comparison of peripherals' bytes is corrected next (2),
in the borrow check that already uses it, so that the check (3) shares it as
ADR 0115 states it; the check then finds every program of the tests valid.
The program on QEMU (4) needs the check, so that its rejected variant has an
error. Each step gains a `Decisions:` list while it is built (`/build-step`),
for the choices it makes that this plan and the ADR do not dictate.

## 1. test(e2e): protect the peripherals that handlers share
- Status: done
- Implements: ADR 0115, "Programs that name peripherals directly"
- Changes:
  - `tests/e2e/uart_interrupt_armv7m/main.ers`: the setup of `UART0`
    (`bauddiv`, `ctrl`) inside `critical`.
  - `tests/e2e/uart_interrupt_riscv32/main.ers`: the setup of `PLIC` inside
    `critical`; the program's `exit` removed for `board::exit` (`use
    board::exit;`), so that `TEST` is named by nothing; the header comment
    says why. The write of the generated `Finisher` bit-field struct that this
    `exit` made stays covered by `tests/e2e/svd_virt/main.ers` and
    `tests/e2e/uart_fields/devices.ers`.
  - `tests/e2e/uart_loopback_riscv32.ers`: every access of the thread to
    `UART0` and `PLIC` inside `critical`, joined to the existing blocks where
    they are adjacent. Joining moves the instant a raised interrupt is taken
    to the end of the block, which the program's waits already expect; QEMU
    at both levels confirms it.
- Tests: the three programs keep their expected output and exit code on QEMU
  at `-O0` and `-O`; no other test changes. `uart_interrupt_riscv32/virt.ers`
  is not edited (it is generated and `tests/svd.rs` compares it).
- Decisions:
  - `uart_interrupt_armv7m/main.ers`: only `bauddiv` and `ctrl` go in the new
    `critical`; `nvic_enable` and `enable_interrupts` stay outside, as they name
    no peripheral (addresses in `core`). A comment on the block says why.
  - `uart_interrupt_riscv32/main.ers`: the board's `exit` takes `u32` where the
    removed one took `u16`; every call passes a literal, so none changes. `use
    virt::test::Finisher` and `TEST` leave the imports (nothing names them). The
    header comment gains the reason, as the plan asks.
  - `uart_loopback_riscv32.ers`: the two `if PLIC.claim != 0 { exit(..) }`
    checks cannot hold `exit` inside a `critical` block that the plan wants
    short, so the claim is read in `critical` into a `let` (`claimed`, `left`)
    and tested after it; the second read is joined to the block that clears
    `ier` and `mcr`, which it follows directly. The setup writes (`mcr`, `ier`,
    `thr`) form one block; the `thri` write is a block of its own, since only a
    wait (itself a `critical`) is adjacent to it. The entry function's blocks
    are not otherwise merged across `enable_interrupts` or the waits, to keep
    the order of the program as it was.
  - No `critical` is added around the `putc` calls: `board::putc` writes
    through a `const` pointer and names no peripheral.
