# Plan: M3.5 Second target

ADRs: 0073, 0074, 0075, 0076, 0077
Base: 099f48c
Program on QEMU: the e2e programs on both targets: every portable
program of `tests/e2e/` built for `riscv32imac-unknown-none-elf` and run
on QEMU `virt`, and built for `thumbv7m-none-eabi` and run on QEMU
`mps2-an385`, each at `-O0` and `-O`, with the same output and exit
code (ADR 0077, step 7).
Out of scope:
- exception handlers, the rest of the vector table, interrupts: M4
  (ADR 0074);
- inline assembly, and with it `__aeabi_uldivmod`/`__aeabi_ldivmod` for
  C code on thumbv7m: M4 (ADR 0074, 0076);
- Cortex-M0 (`thumbv6m-none-eabi`), floating-point units, big-endian
  and 64-bit targets: not planned (ADR 0073, 0074);
- conditional compilation: not planned (ADR 0077);
- emitting LLVM's 64-bit division for constant divisors on thumbv7m: an
  optimization for later (ADR 0076);
- running the ESP32-C3's generated module, or generating ARM SVD files:
  the ESP32-C3 stays a riscv32 build test (ADR 0070).

Before step 1: the `docs(adr)` commit that accepts ADR 0073 to 0077
also sets the status lines of the ADRs they amend, in their files and
in the index (`docs/adr/README.md`):
- 0010: `Accepted; amended by 0073 (riscv32 is the first target, not
  the only one; the target is chosen per build), 0077 (test programs
  stop QEMU through their board module)`; index `Accepted, amended by
  0073, 0077`;
- 0012: `Accepted; amended by 0030 (...), 0057 (...), 0074 (on ARMv7-M
  the reset entry is two words of a vector table before `_start`)`,
  keeping the existing text; index `Accepted, amended by 0030, 0057,
  0074`;
- 0020: `Accepted; amended by 0052 (...), 0076 (where LLVM would call
  a 64-bit division function with a convention C cannot write, code
  generation calls `core`'s)`; index `Accepted, amended by 0052, 0076`;
- 0030: `Accepted; amended by 0034 (...), 0051 (...), 0057 (...), 0074
  (the unwind tables of ARM objects are discarded)`; index `Accepted,
  amended by 0034, 0051, 0057, 0074`.
The same commit holds the roadmap's edit written while planning: the
M3.5 pending decision settled by ADR 0073 to 0077.

Order: the target becomes a description (1) and a choice (2) while
riscv32 is the only one, so that no behavior changes; 64-bit division
moves out of LLVM's hands (3) and `core` gains the EABI's memory
functions (4), both tested on riscv32; the e2e programs move their
machine into a board module (5), still on riscv32. Then the ARM target
(6) arrives with its ABI, startup and linker script, checked by
snapshots and ELF inspection, and finally runs every portable program,
the generated programs and the layout tests on QEMU (7). Each step
leaves every existing test passing.

## 1. refactor(target): one description per target
- Status: done
- Implements: ADR 0073, "One description per target" (riscv32 only).
- Changes:
  - `src/target.rs`: `Target` gains `name`, `arch: Arch` (one variant,
    `Riscv32`), `pointer_bits`, `widest_access_bits`, `stack_align`,
    `code_align`, `div64`; `RISCV32_VIRT` becomes `RISCV32IMAC` with
    the values of ADR 0073's table; `TARGETS: &[&Target]`, `DEFAULT`
    (riscv32) and `by_name(&str) -> Option<&'static Target>`.
    `POINTER_BITS`, `POINTER_BYTES` and `WIDEST_ACCESS_BITS` stay
    constants; `STACK_ALIGN` and `CODE_ALIGN` go, read from the target.
  - `src/driver.rs`: `front_end`, `dump` and `build` take a `&'static
    Target` (callers pass `DEFAULT` until step 2) and hand it to the
    front end, codegen and `link`.
  - `src/query.rs`, `src/query/hardware.rs`: the query context holds the
    target; `ty::misaligned-code` and `ty::stack-size` read
    `code_align` and `stack_align` from it. `src/memory.rs`: the doc
    comment names `stack_align`.
  - `src/link.rs`: `linker_script` takes the target; its header
    (`OUTPUT_ARCH`) and the attributes section of `UNLOADED` come from a
    `match` on `arch`; the stack's alignment from `stack_align`.
  - `src/codegen/mod.rs`: LLVM's initialization (`initialize_riscv`)
    and the reset entry (`start_stub`) chosen by a `match` on `arch`;
    `src/codegen/abi.rs`: `classify` takes the `Arch` and keeps
    riscv32's table in its one arm.
  - `tests/architecture.rs` is unchanged: `target` stays shared.
- Tests: unit tests in `src/target.rs`: every target in `TARGETS` has
  `pointer_bits == POINTER_BITS` and `widest_access_bits ==
  WIDEST_ACCESS_BITS`, names are unique, `by_name` finds each and
  refuses an unknown name. Every snapshot and every other test is
  unchanged, which is the proof that nothing moved.
- Decisions:
  - `RISCV32IMAC` is a `static`, not a `const`: `TARGETS` and `DEFAULT`
    hold references to it, and a test compares them by address
    (`std::ptr::eq`), which only a single static guarantees. `Target`
    derives `Debug`; `Arch` derives `Clone, Copy, Debug, PartialEq, Eq`.
  - Extra unit test beyond the plan's: `DEFAULT` is one of `TARGETS`.
    `by_name` is also tested for the empty name and for a different case
    (names are matched exactly).
  - The new parameter of `driver::dump`, `driver::build` and `front_end`
    is `target: &'static Target`, placed just before `opt` (after
    `stage` for `dump`, after `link` for `build`, after `stop` for
    `front_end`), so that the flags that describe the build stay
    together. Every test that calls `dump` or `build` passes
    `erebos::target::DEFAULT`; only the call sites changed, no
    expectation.
  - `src/main.rs` may name only `erebos::driver` (`tests/architecture.rs`,
    ADR 0063), so it cannot say `erebos::target::DEFAULT`. The driver
    re-exports it as `driver::DEFAULT_TARGET` (`pub use ... as`), which
    `main.rs` passes until step 2. Step 2 needs the names of `TARGETS`
    and `by_name` in `main.rs` too: it should reach them through the
    driver the same way (a function there that turns a name into a
    target or the error of ADR 0073), not by widening the architecture
    test.
  - `Queries` holds the target in a private field `target`, set by
    `Queries::new(hir, target)`; only `query/hardware.rs` reads it, for
    `code_align` and `stack_align`. The text of `ty::misaligned-code`
    and `ty::stack-size` is unchanged (the values are the same; they
    now come from the target).
  - `link::linker_script(map, target)`: the header (`OUTPUT_ARCH`) is a
    `match` on `arch`; `UNLOADED` was split into `UNLOADED` (symbol
    tables and `.comment`), the architecture's attributes section (a
    `match` in `unloaded(arch)`), then `UNLOADED_DEBUG`, which keeps the
    emitted order of the script byte for byte (the linker-script
    snapshots are unchanged). The `HEADER` constant is gone.
  - `codegen`: `lower` takes the `&Target` (for the ABI and the reset
    entry); `target_machine` matches on `arch` for LLVM's
    initialization; `start_stub(arch, entry)` dispatches to
    `riscv32_start_stub`, the old body unchanged. `abi::classify(arch,
    ty)` handles scalars, `()` and `!` for every architecture, and leaves
    aggregates to `classify_riscv32`, which is the old table; `FnAbi::of`
    takes the `Arch`. The unit tests of `abi.rs` keep calling a local
    `classify(ty)` that fixes `Arch::Riscv32`, to keep their text.
  - `pointer_bits` and `widest_access_bits` are fields only for the
    description and the unit test; nothing reads them yet (ADR 0073:
    the constants stay the one source). `div64` is likewise read from
    step 3 on; the compiler does not warn about unread pub fields.
  - No new `panic!`/`unwrap`/`expect`: `tests/architecture.rs`'s counts
    are unchanged.

## 3. feat(codegen): 64-bit division calls `core`
- Status: todo
- Implements: ADR 0076.
- Changes: `src/codegen/mod.rs`: in `rvalue`, `BinOp::Div` and
  `BinOp::Rem` on 64-bit integers, when the target's `div64` is false,
  build a call to `__udivdi3`, `__umoddi3`, `__divdi3` or `__moddi3`
  (the table of ADR 0076) with the C ABI's scalar passing, instead of
  `udiv`/`sdiv`/`urem`/`srem`; when it is true, as on riscv32, nothing
  changes. The callee is the module's function of that symbol,
  `core`'s; where a dump leaves `core` out (ADR 0052), the function is
  declared with the same signature. `rt/builtins.ers`: the comment of
  the division section says who calls them: LLVM where `div64` is true,
  code generation where it is false, and C code on riscv32.
- Tests:
  - the code path where `div64` is false cannot be reached from a
    target until step 6; a unit test in `src/codegen/mod.rs` lowers a
    body with the four 64-bit operations for a test description that
    copies riscv32's with `div64` false, and checks that the printed IR
    holds the four calls and no `udiv`/`sdiv`/`urem`/`srem` on `i64`.
    Step 6 adds the thumbv7m snapshot.
  - `tests/e2e/c_division64.ers` with a C file, `// targets:
    riscv32imac-unknown-none-elf` (ADR 0077's reason 2, a feature of
    the C side: clang calls libgcc's names): C code divides and takes
    the remainder of `u64` and `i64` values, which links only because
    `core` exports the four names (ADR 0076). The divisors are run-time
    values (parameters passed from Erebos), never constants, so that
    clang calls the four functions at `-O0` and at `-O2` alike; the
    test runs at both levels. Its header takes effect from step 5, when the
    harness learns to read it; until then every program runs on
    riscv32 only.
  - unchanged on riscv32: every snapshot, `tests/e2e/division64.ers`
    and the differential tests.

## 6. feat(target): thumbv7m-none-eabi
- Status: todo
- Implements: ADR 0074, "The target", "The reset entry", "The linker
  script"; ADR 0075.
- Changes:
  - `Cargo.toml`: inkwell's feature `target-arm` (no new dependency;

  - `src/target.rs`: `Arch::Armv7m` and `THUMBV7M` with ADR 0073's

  - `src/codegen/mod.rs`: `initialize_arm` for `Armv7m`; the reset entry
    of ADR 0074 (vector table words and `_start`) as module assembly.
  - `src/codegen/abi.rs`: the AAPCS classification of ADR 0075, with the
    natural alignment (fields' alignments without the aggregate's own
    `#[align(N)]`; 1 when `#[packed]`), and the new pass modes: `[N x
    i32]` / `[N x i64]` arguments, `byval` with an alignment, and
    `i8`/`i16`/`i32` returns; their lowering at definitions and calls
    in `src/codegen/mod.rs`. If layout does not yet expose the natural
    alignment, `src/layout.rs` gains it.
  - `src/link.rs`: for `Armv7m`, `OUTPUT_ARCH(arm)`, `.ARM.attributes`
    among the unloaded sections, `/DISCARD/` for `.ARM.exidx*` and
    `.ARM.extab*`.
  - `tests/common/mod.rs`: the clang flags of each target (ADR 0074),
    chosen by target name.
- Tests:
  - unit tests in `src/codegen/abi.rs` for the AAPCS table: every row of
    ADR 0075's context table as Erebos types (sizes 0, 1, 2, 3, 4, 5, 8
    with alignment 8, 64, 68, 72 with alignment 8, a `#[align(16)]`
    struct of words, a `#[packed]` struct, a slice, a struct holding a
    `#[align(16)]` struct).
  - ui snapshots with `// target: thumbv7m-none-eabi`: `--emit=llvm-ir`
    of a program passing and returning each of those aggregates (the
    IR forms must be clang's of ADR 0075), of 64-bit division (calls of
    ADR 0076), of the reset entry (`module asm`); `--emit=linker-script`
    of a `mps2-an385` memory map; `ty::misaligned-code` for a code
    origin of `0x100` (aligned for riscv32, not for thumbv7m) and
    `ty::stack-size` for a size that is a multiple of 8 but not of 16
    (accepted on thumbv7m, an error on riscv32, both snapshotted).
  - `tests/elf.rs`: its checks become per target: the stack's alignment
    (today `next_multiple_of(16)`) is the target's `stack_align`, and
    "`_start` is at the code's origin" becomes the target's reset
    entry. A program built for thumbv7m, read with `llvm-readelf`: the
    word at the code origin is `__stack_end`, the next is `_start | 1`,
    `_start` follows them in `.text.start`, no `.ARM.exidx` section is
    left, and ADR 0030's guarantees on the five startup symbols and
    ADR 0057's placement of code, data and stack hold.
  - `tests/c_layout.rs` and `tests/layout/`: run with each target's
    clang flags (ADR 0077, "Other tests on both targets").
  - `tests/reproducible.rs`: builds its programs for each target.
  - `tests/architecture.rs`: the IR invariants (no `nsw`/`nuw`, panic
    counts) also cover the thumbv7m snapshots; if they read snapshots
    by name, the new ones are included.
  - the 64-bit division snapshot with `// target: thumbv7m-none-eabi`
    and `// opt: both` shows the calls of ADR 0076 at both levels, and
    the same program's riscv32 snapshot keeps LLVM's division.
- Note on the size of this step: the AAPCS classification (ADR 0075)
  cannot be its own earlier commit, since without the `Armv7m` variant
  constructed by a target its code is dead and `clippy -D warnings`
  rejects it; and the target without it would pass aggregates with
  riscv32's rules. The step may be committed as one, its Decisions
  listing the parts.

  startup programs and the generated programs run on both targets at
  both levels; `aapcs_c` and the existing C programs (`c_abi`,

  aggregates of ADR 0075 against clang on QEMU. Any program that
  must stay riscv32-only here gets `// targets:` with its reason in
  Decisions; the reason must be one of ADR 0077's three (a device of
