# Plan: M5.11 Stack bound

ADRs: 0121 (a second panic stops), 0122 (`#[stack(N)]`), 0123 (the stack
bound); building on 0014, 0020, 0026, 0057, 0076, 0078, 0079, 0082, 0084,
0085, 0086, 0087, 0088, 0093, 0119, 0120
Base: 5b81efc
Program on QEMU: an e2e program whose stack fits, which measures what it used
and is checked against the bound, on both targets at `-O0` and `-O`; and the
same program built with a stack too small, rejected with
`analysis::stack-overflow` and the path that needs the most, on both targets
at both levels (`tests/elf.rs`).
Out of scope:
- priorities and nested maskable handlers (after M6; ADR 0123,
  Consequences);
- function pointers (deferred ideas; ADR 0123 says how they will fit);
- a hook for what a second panic does other than spin (ADR 0121,
  Consequences);
- unsafe attributes (ADR 0119, "What stays out"; ADR 0122);
- the findings of `docs/open-findings.md`: worked off between steps, not here.

Decided with the user while planning (2026-11-16):
- A guard inside the panic function stops a second panic, which spins with
  interrupts as they are (ADR 0121).
- A function the bound reaches that needs `#[stack(N)]` and has none is an
  error, not a default (ADR 0122).
- `#[stack(N)]` is a plain attribute, not under `unsafe` (ADR 0122).
- The bound is always on, on every `erebos build`, at the level built, and
  `--emit=stack` prints its report (ADR 0123).
- Handlers add up by kind: the deepest maskable one, every unmaskable one, and
  the faults that reach default handlers (ADR 0123, "Contexts and the total").
  The planner refined the user's "one default-handler path" into the faults'
  two entries (one before a panic, one inside the panic function), the
  maskable words without a handler, and thumbv7m's NMI without a handler,
  each of which the model allows; flagged to the user.
- The calls MIR does not show are assumed from every function to each
  inserted function, and an oracle in the tests checks the machine's calls
  against the graph (ADR 0123).
- `#[stack(N)]` on an `extern fn` counts everything it calls, Erebos callbacks
  included; a `sym` operand is an edge, so a cycle through assembly is
  rejected (ADR 0122, 0123).
- One step, the guard first.

Frame sizes come from LLVM's `"warn-stack-size"` warnings, which the planner
tried with LLVM 22's `llc` on both targets at both levels (ADR 0123,
Context); no dependency is added.

Where Erebos source lives (as in the M5.10 plan; each migration step searches
all of them): `rt/`, `tests/boards/`, `tests/e2e/`, `tests/ui/`,
`tests/svd/chips/`, the snippets of `tests/rejected.rs`, the programs
embedded in `tests/elf.rs`, `tests/e2e.rs`, `tests/svd.rs` and
`tests/fuzz.rs`'s corpus, the source `tests/common/generator.rs` writes, and
`tests/layout/`. Only the programs that `erebos build` builds reach the bound.

## Before step 1

ADRs 0121, 0122 and 0123 are accepted by the user, in a `docs(adr): accept

## 1. feat(codegen): stop a second panic in the panic function
- Status: todo
- Implements: ADR 0121
- Changes:
  - `src/codegen/mod.rs`: when it defines the body `Mir::panic`, code
    generation emits the guard before the body's first block: a volatile load
    of `__erebos_panicking` (an `i8` global, zero-initialized, so in `.bss`,
    private to the object), a branch to a block that branches to itself when
    it is not 0, and otherwise a volatile store of 1 and the body. The global
    is defined only when the panic function is (a dump that leaves `core` out
    still defines the panic function, so the IR shows it). The panic
    function's LLVM function gets `noinline` (ADR 0121, 0123), and no
    `mustprogress`, which no Erebos function has today.
  - `tests/e2e/panic_in_panic.ers` (both targets): the thread arms the timer
    (the CLINT's on riscv32 as `interrupt_clint.ers` does, SysTick on
    thumbv7m as `interrupt_systick.ers` does; the builder chooses whether the
    two are one program with per-target code in the board or two programs,
    and records the choice and its reason in Decisions) and
    enables interrupts, then fails a check. The panic function prints `first`
    and fails a check of its own; the timer's handler prints `stopped` and
    exits with 1.
  - `tests/e2e/fault_in_panic_riscv32.ers`, rewritten as ADR 0121 says: the
    first panic from a fault, the second from a check after the panic function
    enables interrupts and arms the timer.
- Tests: `tests/ui/panic_guard_llvm.ers` and `panic_guard_llvm_thumbv7m.ers`
  (the guard and the flag, a panic function with and without
  `&core::PanicInfo`); every LLVM IR snapshot that shows a panic function
  changes, and the update is reviewed for the guard alone; the two e2e
  programs at both levels. `tests/architecture.rs`'s count of codegen's
  panics and wrap flags is unchanged or updated with the reason.

## 5. feat(codegen): measure each function's frame
- Status: todo
- Implements: ADR 0123, "Frames"; ADR 0082 amended
- Changes:
  - `src/codegen/mod.rs`: for an object, after `lower`, every defined function
    gets `"warn-stack-size"="0"`; `emit_llvm_ir` does not add it.
    `emit_object` returns the frames with the object: a plain struct of
    numbers (`Vec<u64>` indexed by body, and the largest frame among the
    default handlers), defined in `codegen` and turned into plain arguments by
    the driver, so that `analysis` names nothing of `codegen`. A function
    `emit_frames` compiles to a memory buffer for `--emit=stack`.
  - `src/codegen/diagnostics.rs`: the collector also keeps the warnings whose
    text holds `stack frame size (N) exceeds limit (0) in function 'f'`, as
    `(f, N)`; every other warning, remark and note is dropped as before. The
    handler still neither panics nor allocates beyond what it does now for
    errors.
  - `src/codegen/vectors.rs`: the names of the default handlers it made, so
    their frames can be told apart.
  - A reported name that is no body's and no default handler's is
    `codegen::llvm` with ADR 0123's message.
- Tests: unit tests in `src/codegen/`: on both targets at both levels, a
  function with a 40-byte array local reports a frame of at least 40, a leaf
  without locals reports none, a naked function reports none; the warning's
  text read as LLVM 22 writes it (with and without the `<unknown>:0:0: `
  location prefix); a name LLVM made is reported. `tests/architecture.rs`:
  the list of `llvm_sys` names the handler uses, updated only if it needs a
  new one.

## 6. feat(analysis): bound the stack
- Status: todo
- Implements: ADR 0123, "Where it runs" to "Diagnostics", "What ADR 0120 left
  open"
- Changes:
  - `src/target.rs`: `Target::exception_frame` (64 on riscv32, 36 on
    thumbv7m), with the comment ADR 0123 gives.
  - `src/analysis/stack.rs`: the graph (edges in ADR 0123's order, inserted
    edges from every body outside the inserted closure), the check of the
    closure (only `core`'s bodies, never the panic function; otherwise a
    panic of the compiler, counted in `tests/architecture.rs`), the cycles on
    the graph without panic edges (ADR 0123, "Cycles"), the depth in two
    states memoized per (body, state), the four parts, the worst paths, the
    depth of every body for the report, and the three errors. The strongly
    connected components and the shortest cycle reuse
    `src/analysis/call_graph.rs`, whose `Edges::Calls` is extended (or a new
    variant added; the builder says which in Decisions) with `critical`,
    `sym` and inserted edges. One public function taking `&Mir`, the frames
    as plain numbers, `exception_frame`, the declared size (or none), and the
    diagnostics sink; it returns the report's data for step 7.
  - `src/analysis/mod.rs`: exports it.
  - `src/driver.rs`: `build` runs it on the whole MIR (`front_end` leaves
    `core` in when there is no stage to stop at, as it does today) after
    `emit_object` and before writing the linker script; an error discards the
    object and stops before the link.
  - Whatever `analysis::missing-stack` finds that step 4 missed, fixed in the
    same commit. An e2e or generated program that `analysis::stack-overflow`
    rejects (none is expected: the boards declare 1 MiB) is investigated in
    this commit: a provisional number of step 4 that is too large is lowered
    with its measurement; a real overflow is a finding about the program, put
    to the user before the declared size changes. Either way it goes in
    Decisions.
- Tests:
  - unit tests in `src/analysis/stack.rs` on MIR built from small programs,
    with frames given by the test (ADR 0123, "Tests", first bullet);
  - a test that the riscv32 `exception_frame` equals the trap entry's
    `#[stack(N)]`;
  - `tests/elf.rs`, on both targets at both levels: a program with a check, a
    handler and an aggregate copy, with a stack that fits, builds; the same with

    and an `extern fn`; `analysis::stack-cycle` for two naked functions that
    name each other with `sym`;
  - every e2e program and generated program still builds and runs.

## 8. test: check the stack bound against the machine
- Status: todo
- Implements: ADR 0123, "Tests", the oracles
- Changes:
  - `tests/common/mod.rs`: `llvm-objdump` found like `llvm-readelf`
    (`EREBOS_OBJDUMP`).
  - `tests/stack.rs`: for every e2e program, on both targets at both levels,
    `--emit=stack` and the built executable; every call and every jump to
    another function's symbol in `llvm-objdump -d` must be an edge of the
    report's lines, or leave a function with `#[stack(N)]` (naked, `asm`) whose
    number covers it. A function of the executable that is not in the report is
    an error of the test unless it is the compiler's (default handlers, the
    vector table) or C's.
  - `tests/e2e/stack_measured.ers` (both targets): at entry it fills the stack
    below its own frame with a pattern, down to `__stack_start`; it arms a
    timer whose handler preempts the path below; it runs a deep path (calls
    with array locals, one of 512 bytes, an aggregate copy) that ends in a
    failed check. The panic function counts how many bytes of the pattern
    were overwritten before it prints anything, then prints the count and
    exits.
  - `tests/e2e/stack_measured_fault.ers` (both targets, `takes-exceptions`):
    the same path, with the same 512-byte local, but ending in a fault
    (`unimp`, `udf`) that reaches a default handler and the panic function,
    which counts the same way and exits.
  - `tests/stack.rs` checks each number against the report's total (at most)
    and against 512 (at least, so a broken count fails), on both targets at
    both levels.
- Tests: the three above. A failure of the calls oracle points at a call the
  graph misses; the fix is an edge or a number, made in this commit.
