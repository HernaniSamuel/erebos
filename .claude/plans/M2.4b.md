# Plan: M2.4b Enum payloads

ADRs: 0039, 0040, 0041
Base: 8983540cea0ed2ff5f6bb45f0e219c6f7c950b24
Program on QEMU: a command decoder: messages with payloads, decoded from
bytes and dispatched with `match` (`tests/e2e/command_decoder.ers`,
step 5).
Out of scope:
- `Option(T)`, `Result(T, E)`, `?`, and whether `Result(u32, !)` is
  infallible (M2.5);
- a `PanicReason` for "enum value is no variant" (M2.6);
- struct and array patterns, range patterns, guards, `..` in payload
  patterns (not scheduled);
- moves of payload values: a binding copies (M5).

Before step 1: the `docs(adr)` commit that accepts ADR 0039 to 0041 also
sets the status lines of the ADRs they amend, in the files as
`Accepted; amended by NNNN (what changed)` and in the index
(`docs/adr/README.md`) in its style, `Accepted, amended by NNNN`:
- ADR 0023: amended by 0039 (an enum with payloads is an aggregate);
- ADR 0025: amended by 0039 (enums with payloads cross calls as
  aggregates);
- ADR 0032: amended by 0039 (no value of an enum with payloads is
  known);
- ADR 0034: amended by 0039 (payload values are memory);
- ADR 0035: amended by 0039 (an enum with payloads is not its integer);
- ADR 0036: amended by 0039 (a value of an enum with payloads is any
  bytes), 0040 (values no arm matches, at any position);
- ADR 0037: amended by 0040 (payloads and nested patterns, at most
  three missing values listed), 0041 (bindings in or-patterns);
- ADR 0038: amended by 0040 (the enums a `match` needs, per position,
  and when MIR building does not use a body).

## 1. feat: enum variants with payloads
- Status: done
- Implements: ADR 0039, all sections. A `match` on an enum with payloads
  stays `ty::match-type` until step 3.
- Changes:
  - `src/syntax/{ast,parser}.rs`: a variant's payload, one or more types
    in parentheses with an optional trailing comma, between its name and
    `= value`; `V()` is `parser::empty-payload`. In expressions, a path
    followed by arguments (parsed as a call's) is one node, a path and
    its arguments, which HIR lowering resolves, so that M2.6's
    `module::f(args)` reuses it; `Enum::Variant()` parses, and is a count
    error.
  - `src/hir/{mod,lower}.rs`: `EnumDef` variants get their payload types;
    `EnumTy` records whether the enum has payloads, so that type checking
    and layout tell the two kinds apart without a lookup;
    `ExprKind::Variant` carries its argument expressions, if written with
    parentheses (so that `E::V()` and `E::V` stay apart for the count
    check), visited by `Expr::walk`; `!` as a payload type is recorded as
    a `NeverPosition` for `ty::never-in-memory` and `[T]` as an
    `UnsizedPosition` for `ty::unsized`, as for struct fields, and the
    enum then counts as erroneous, as such a struct does.
  - `src/layout.rs`, `src/query.rs`: the layout of an enum with payloads
    by ADR 0039 ("Layout"): each variant a struct of the tag and its
    payload values, the enum the largest of them; per variant, the offset
    of each payload value; computed on demand like struct layouts, with
    the containment cycle generalized from structs to structs and enums
    with payloads (`ty::infinite-size` naming every type of the cycle) and
    `over_aligned` propagated from payload types, and `ty::too-large` for
    an enum whose rounded size exceeds `MAX_SIZE`, as for structs; `mir_ty` gives the MIR
    enum type (below, `src/mir`); `--emit=typeck` and `--emit=mir`
    list each enum with payloads with its size, alignment, and per
    variant its value and payload offsets.
  - `src/ty.rs`: `E::V(args)` checks the count
    (`ty::wrong-payload-count`, also for `E::V` naming a variant with a
    payload and `E::V(...)` or `E::V()` naming one without, in enums with
    and without payloads) and each argument
    against its payload type, as call arguments are, with the implicit
    conversions of ADR 0024 and 0031; the result is not a place
    (`ty::not-a-place`, `ty::not-assignable`); on an enum with payloads,
    `==`/`!=` are `ty::invalid-operand`, `as` from and to it
    `ty::invalid-cast`, `x.f` and `offset_of` `ty::no-fields`, and a
    whole read or write through a volatile pointer
    `ty::volatile-aggregate`; it is a valid field, element, parameter,
    return, constant and static type; `ty::aligned-in-packed` applies to
    it as to a struct.
  - `src/mir/{mod,build}.rs`: `mir::Ty::Enum(EnumRef)`, leaked like
    `StructRef`, whose definition holds the name, integer type, layout and
    per variant its value and payload `Field`s (set after it exists, as
    struct fields are, since a payload may point back to the enum);
    `is_aggregate` and `layout` include it; projections
    `PlaceElem::Tag` (the integer at offset 0) and
    `PlaceElem::Payload { variant, index }`, handled by `place_ty` and
    printed in dumps; building `E::V(a, b)` evaluates the arguments left
    to right, then writes each payload value and the tag into the result
    place; `E::V` of an enum with payloads writes only its tag. Enums
    without payloads stay `mir::Ty::Int` (ADR 0035).
  - `src/mir/build/known.rs`: no value of an enum with payloads is known.
  - `src/eval.rs`: both projections by offset, as fields; constants and
    statics of such enums keep unwritten bytes zero, as padding.
  - `src/codegen/{mod,abi}.rs`: both projections as byte offsets, as
    fields are (`codegen/mod.rs`, the `PlaceElem::Field` arm);
    `classify` treats the enum as an aggregate (ADR 0025), which
    `is_aggregate` already gives.
  - `tests/fuzz.rs`: snippets `A(u8) = 0`, `E::A(1)`.
- Tests:
  - ui (parse): one and several payload types, a trailing comma in a
    payload, `V()`, `= value` before the payload (rejected).
  - ui (typeck): the list in ADR 0039 "Conformance tests", ui (typeck),
    with `!` as a payload type also in an unused enum (reported once).
  - e2e (`tests/e2e/enum_payloads.ers`): `Msg::Write(f(), g())` evaluates
    its payload values left to right (a counter), at both optimization
    levels.
  - ui (MIR): MIR snapshots of building a variant with two payload
    values, of a variant without payload in an enum with payloads, and of
    the enum's layout in the dump.
  - layout against clang: `tests/layout/structs.{ers,h}` gain enums with
    payloads on `u8`, `u16` and `u32`, with payload values of alignment
    1, 2, 4 and 8 and a struct payload, against C unions of structs that
    start with the tag; `tests/c_layout.rs` reads the new enum lines of
    the `--emit=typeck` dump and compares size, alignment and every
    payload offset with `sizeof`, `_Alignof` and `offsetof` of the
    union's members.
  - LLVM IR snapshot (`codegen_enum_payloads.ers`): building a variant
    writes the tag and the payload values at their offsets, a variant
    without payload writes only the tag, a constant with zero bytes outside its
    variant, a `static mut` of zero bytes in `.bss`, parameters and
    returns in each ADR 0025 class.
  - e2e (`tests/e2e/enum_payloads_c.{ers,c}`): enums with payloads of
    each row of ADR 0025's table, including `enum E: u64 { A = 0,
    B(()) = 1 }` against `union { uint64_t tag; }` for the aligned pair,
    passed to and returned from C functions taking the C unions, and C
    calling Erebos functions taking and returning them, at both
    optimization levels. Without `match` yet, the Erebos side reads tag
    and payload bytes through a `*const u8` cast from `&raw const`.
  - differential test (`comptime_differential.{ers,c}`): variants of
    every kind built in constants and at run time, compared through
    their tag and payload bytes, read through a `*const u8`; the run-time
    values pass through a C identity on the C union, so LLVM cannot fold
    them.

## 2. refactor(ty): check matches by the usefulness of patterns
- Status: done
- Implements: no new behaviour; prepares ADR 0040 "Exhaustiveness" and
  "Dead arms".
- Changes:
  - `src/ty.rs` (or a new `src/ty/` submodule if `ty.rs` grows too
    large): replace `Coverage` and `coverage` with a usefulness check
    over rows of patterns (Maranget's algorithm): a pattern is a
    constructor (an integer or `bool` value, a variant with its sub-
    patterns, or every value) and an or-pattern of these; integer
    positions keep the value sets of today, so a `u64` column is never
    enumerated; enum positions count values that are no variant as
    their integer type's other values (ADR 0036), and exhaustiveness
    ignores them. It reports exactly the diagnostics of today: a dead arm
    once, with the earlier arm that covers it alone; each dead
    alternative when only some are; the missing variants in declaration
    order; the integer message of ADR 0037.
- Tests: every existing ui snapshot unchanged (the proof of no
  behaviour change; the cap of three witnesses comes in step 3); unit tests of the algorithm in `ty.rs` on rows of
  integer, `bool` and enum patterns, including a `u64` column with
  values near `u64::MAX` and all 256 values of a `u8`.

## 3. feat: match on enums with payloads, with nested patterns
- Status: done
- Implements: ADR 0040, all sections. A `let` inside an or-pattern stays
  `resolve::binding-in-or-pattern` until step 4, now at any depth.
- Changes:
  - `src/syntax/{ast,parser}.rs`: the pattern `Enum::Variant(p, ...)`,
    each `p` a pattern with alternatives, with an optional trailing
    comma; `Enum::Variant()` parses and is a count error.
  - `src/hir/{mod,lower}.rs`: `PatternKind::Variant` carries its
    sub-patterns, if written with parentheses; `PatternKind::Or` may
    appear at any position, flattened when nested directly in another
    or-pattern; `resolve::duplicate-binding` for one name bound twice in
    one pattern; the `resolve::binding-in-or-pattern` check covers nested
    or-patterns. `Pattern::binding`, which gives one local, gives way to
    the list of a pattern's bindings, each a local and its position,
    since `Msg::Write(let r: u8, let v: u16)` binds two.
  - `src/ty.rs`: enums with payloads accepted as scrutinees (step 1's
    `ty::match-type` snapshot on them changes); a variant pattern's count
    (`ty::wrong-payload-count`) and its sub-patterns checked against the
    payload types; `_` and `let` alone at struct, array, pointer, slice
    and `()` positions; `ty::constant-pattern-type` for a constant of any
    type but an integer, `bool` or an enum without payloads, reported
    alone; the usefulness check of step 2 extended to variants with
    sub-patterns; witnesses for `ty::non-exhaustive-match` found and
    ordered as ADR 0040 "Exhaustiveness" says, at most three shown, then
    "and N more" (no existing snapshot lists more than three); which
    enums a `match` needs, per
    position (ADR 0040), replacing today's `needs_values`, and the skip
    when one of them has a value that failed or repeats.
  - `src/mir/build.rs`: a `match` on an enum with payloads lowered as a
    decision tree: a `Switch` on `copy tmp.Tag` of the scrutinee's
    temporary, then, per variant, the arms that can match in order,
    testing payload positions through `tmp.Payload { .. }` projections
    with `Switch`es, a failed test going to the next candidate arm; a
    `let` at any position copies that position into its local; the
    default of a switch on an enum position goes to the arms matching it
    with `_` or `let`, or to `Panic(NoVariant)`, always, even when every
    value of its integer type is a variant (ADR 0036); `Unreachable` only
    at integer and `bool` positions whose every value is listed; the body
    is marked failed when an enum the `match` needs is in error, with or
    without a catch-all arm (ADR 0040, "Which enums a `match` needs"),
    replacing today's `enum_ok` test, which applies only without one.
    `tests/ui/mir_match_enum_values_errors.ers` changes with it: its
    comment that, with a catch-all, the shared value goes to the first
    arm becomes false, and its `comptime` asserts on `twice_or` gain one
    that would fail if the function were evaluated, so that the new rule
    is observed. Matches on integers, `bool` and
    enums without payloads keep their single switch.
  - `src/eval.rs`, `src/codegen/`: nothing new, beyond what step 1 and
    `Switch` already provide.
  - `tests/fuzz.rs`: snippets `E::A(_)`, `E::A(1 | 2)`.
- Tests: the list in ADR 0040 "Conformance tests", with:
  - ui (eval) and differential test in `comptime_differential.{ers,c}`;
  - e2e (`tests/e2e/enum_payloads_no_variant.ers`): a tag that is no
    variant and a nested `Mode` that is no variant, read through a cast
    pointer from a `static` byte array with `#[align(4)]`, as the ui
    (eval) test reads them, handled by `_` arms, and then making a
    `match` without catch-all panic (exit code), at both optimization
    levels.

## 4. feat: bindings in or-patterns
- Status: done
- Implements: ADR 0041, all sections.
- Changes:
  - `src/hir/lower.rs`: `resolve::binding-in-or-pattern` removed; the
    alternatives of an or-pattern, at any depth, are lowered with one
    shared scope of bindings: the first alternative declares a local per
    name, the others resolve their `let`s of the same name to it;
    `resolve::inconsistent-binding` for a name missing from an
    alternative or bound `mut` by only some, labelled as ADR 0041 says.
  - `src/hir/mod.rs`: step 3's list of bindings becomes one list per
    alternative, for MIR building.
  - `src/ty.rs`: every `let` of one name has the same type
    (`ty::mismatched-types` at the later one, with the help of ADR 0041).
  - `src/mir/build.rs`: each leaf of the decision tree knows which
    alternative matched, and copies that alternative's bound positions
    into the shared locals before jumping to the arm's single body block.
- Tests: the list in ADR 0041 "Conformance tests"; the existing ui
  snapshots of `resolve::binding-in-or-pattern` become
  `resolve::inconsistent-binding` or `ty::unreachable-pattern`, as
  ADR 0041 says for `let x: u8 | 3` and `let x: u8 | let x: u8`.

## 5. test(e2e): a command decoder
- Status: done
- Implements: the milestone program of M2.4b.
- Changes: `tests/e2e/command_decoder.ers`: a static byte string holds a
  stream of messages (a command byte, then its arguments); a decoder
  function reads one message from a slice and returns an
  `enum Decoded: u8 { Done = 0, Cmd(Cmd, usize) = 1, Bad(u8, usize) = 2 }`
  (the command and the bytes it took, or an unknown command byte), with
  `enum Cmd: u8 { Nop = 0, Led(bool) = 1, Write(u8, u16) = 2,
  SetMode(Mode) = 3, Clear(u8) = 4 }` and `enum Mode: u8` decoded with a
  `match` that has a `_` arm for unknown bytes; a dispatcher `match`es
  the commands with nested patterns (`Cmd::Write(0x10, let v: u16)`,
  `Cmd::SetMode(Mode::Run)`), an or-pattern binding
  (`Cmd::Write(let r: u8, 0) | Cmd::Clear(let r: u8)`), and prints each
  action over the UART with the `print` of M2.3b; a `comptime` block
  decodes a fixed message and asserts its result with a `match`; a
  `static mut` of type `Cmd` holds the last command, starting at
  `Cmd::Nop` (in `.bss`).
- Tests: the program itself, with its expected output and exit code, at
  both optimization levels.
