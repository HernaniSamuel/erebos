# Plan: M3.2 Peripherals

ADRs: 0058
Base: 583d00d
Program on QEMU: hello world through a UART and a test finisher declared
as peripherals (`tests/e2e/peripherals/`, step 6).
Out of scope:
- fields at bit positions, enums in registers, write-1-to-clear fields,
  reads with side effects and reset values (M3.3);
- register arrays, clusters, `derivedFrom`, and the check against a real
  chip's SVD file (M3.4);
- checking peripherals against the regions of the `memory` block
  (ADR 0058, alternatives);
- ownership of peripherals, so that only one part of the program reaches
  a device (M5, ADR 0021);
- fences, and ordering register accesses against ordinary ones (M4,
  ADR 0023);
- moving the existing e2e programs off volatile pointers: they keep
  compiling and keep testing ADR 0013 and 0023; only `hello.ers` and the
  milestone program use peripherals (step 6).

Before step 1: the `docs(adr)` commit that accepts ADR 0058 also sets the
status lines of the ADRs it amends, in the files as
`Accepted; amended by NNNN (what changed)`, appended to an existing
amendment list, and in the index (`docs/adr/README.md`) as
`Accepted, amended by ..., 0058`:
- ADR 0013: amended by 0058 (accesses through a pointer to a peripheral
  type are volatile without `volatile`, which is an error there);
- ADR 0023: amended by 0058 (a register reached from a peripheral is
  accessed volatile with no pointer on its path);
- ADR 0048: amended by 0058 (register offsets, register types in error
  and peripheral addresses are failed values).

The same commit holds the roadmap's edit to its M3 pending decisions
(access modes settled by ADR 0058; registers and peripherals sharing
addresses left to M3.3 or M3.4), written while planning.

Order: the items are parsed (1), resolved (2) and their values computed
and checked (3) before code that accesses registers is type checked (4)
and compiled (5). Until step 4 the type checker does not handle an
expression naming a peripheral, and until step 5 MIR building handles
neither such an expression nor `Ty::Peripheral` (`Queries::mir_ty`):
each stops there with a `todo!` naming the step that removes it. So the
ui tests of steps 2 to 4 that accept code are `emit: typeck` (or
earlier), which stops before `lower_all`, and none of them puts a
pointer to a peripheral type
in a constant, a static or a `comptime` block, which are built into MIR
and evaluated during type checking. The fuzz test (`tests/fuzz.rs`)
compiles every seed to LLVM IR, and `lower_all` builds every function
that type checks whatever errors other items have (ADR 0032), so from
step 2 until step 5 it leaves out the seeds that declare a peripheral
type or a peripheral; step 5 removes that filter. Code generation needs
no step of its own: registers become volatile accesses at constant
addresses.

## 1. feat(parser): parse peripheral types and peripherals
- Status: done
- Implements: ADR 0058, "Peripheral types and peripherals" (the grammar,
  the contextual words, `parser::local-peripheral`).
- Changes:
  - `src/syntax/ast.rs`: `Item::PeripheralType(PeripheralTypeDecl)`,
    holding its attributes, visibility, name, registers in source order
    and span; a `RegisterDecl` holds its visibility, access mode (`Read`,
    `Write`, `ReadWrite`), name, type, offset expression and span.
    `Item::Peripheral(PeripheralDecl)`, holding its attributes,
    visibility, name, type, address expression and span.
  - `src/syntax/parser.rs`: at the start of an item, the identifier
    `peripheral` followed by an identifier starts one of the two items:
    a `{` after the name makes a peripheral type, a `:` a peripheral.
    Inside them, `read`, `write` and `at` are recognized by their text,
    with the helpers M3.1 added (`word_at`, `at_word`); a register's
    name is the identifier just before `:`, so `read write: u8 at 0` is
    a `read` register named `write`. The lexer is unchanged. In a
    function body, `peripheral` followed by an identifier is
    `parser::local-peripheral`, and the item is parsed and dropped, like
    the other `parser::local-*`; at the depth of the items,
    `peripheral` followed by an identifier is a point where error
    recovery (`recover_to_item`) stops.
  - `src/hir/lower.rs`: skips both items for now; step 2 lowers them.
- Tests (ui):
  - `parse_peripheral.ers` (`emit: ast`): a peripheral type with each
    access mode, `pub` and private registers, two registers at one
    offset, a trailing comma, offsets naming constants; an empty
    peripheral type; registers named `read`, `write` and `at`
    (`read write: u8 at 0`, `write read: u8 at 1`); `pub` peripherals
    whose type is a name and a path, and whose address names a constant.
  - `parse_peripheral_errors.ers`: a register without an access mode,
    `write read x: u8` (the modes in the wrong order), a register
    without `at`, a missing `,` between registers, a peripheral without
    `at`, without its `;`, and `peripheral NAME;` without a type; each a
    `parser::unexpected-token` at the right token, with recovery
    reaching the next item.
  - `parse_local_peripheral.ers`: a peripheral type and a peripheral in
    a function body are `parser::local-peripheral`, and the item after a
    broken item-level peripheral type is still parsed.
  - `peripheral_names.ers` (`emit: typeck`): `peripheral`, `read`,
    `write` and `at` as names of locals, functions, fields, struct
    literals' fields and a module still compile, and `read(x)` and
    `write(x, y)` calls in a body are not items.
- Decisions:
  - The access mode is `ast::AccessMode` (`Read`, `Write`, `ReadWrite`),
    declared in `ast.rs` right after `RegisterDecl`, which uses it, and
    `Copy` like `Visibility`, so that step 2 can carry it into the HIR as
    is. (Reworded after review: the entry first placed it beside
    `Visibility`.)
  - The parser tells the two items apart in one method,
    `peripheral_item`, after `peripheral NAME`: `{` goes to
    `peripheral_type_decl`, `:` to `peripheral_decl`, anything else is
    "expected `{` or `:`" at that token (so `peripheral D;` points at the
    `;`), with a help naming both forms. The local item is parsed by the
    same method and dropped.
  - "The name is the identifier just before `:`" is implemented as: `read`
    or `write` is a mode word only when the token after it is not `:`
    (`at_access_word`). So `read: u8 at 0` is a register without a mode
    named `read`, reported as such; `write read x: u8` is a `write`
    register named `read`, and the error is "expected `:`" at `x`, the
    help saying the modes go `read write`, in that order. No special case
    for the reversed order: the help covers it, and `read` is a valid
    name there.
  - A missing access mode is reported at the token that stands where the
    mode should (normally the register's name), not right after the line
    before as `missing_token_span` would, as `memory_decl` does for a
    stray token; at the end of the file it falls back to the missing
    span.
  - The register list is a loop of its own rather than `brace_list`, so
    that a missing `,` between registers says "expected `,` or `}`"
    (`brace_list` says "expected `}`").
  - The errors on a register's own tokens, a missing access mode, `:`,
    `at`, and `,` or `}` after it, carry one help, `REGISTER_HELP` (a
    module constant, since `peripheral_type_decl` and `register` both
    use it): the form `ACCESS NAME: TYPE at OFFSET`, `pub`, the modes in
    order, the name before `:`, and `,` between registers. Errors from
    the shared parsers of the name, the type and the offset (`ident`,
    `ty`, `nested_expr`), as in `read write 5: u8 at 0`,
    `read a: 5 at 0` or `read a: u8 at ;`, carry no help, as in
    `memory_decl`. Likewise a peripheral's errors on `at` and `;` carry
    their own help with its form, and those of its type and address
    none. (Reworded after review: the entry first said every error
    inside a register carries the help.) A missing
    access mode is "expected `read` or `write`", without listing `pub` or
    `}`, which may also stand there.
  - A register's offset is parsed with `nested_expr` (inside braces, as a
    region's fields), a peripheral's address with `expr` (as a constant's
    value). A register's span runs from `pub` or its mode to the end of
    its offset; an item's span from `peripheral` (not `pub`, as for every
    item) to its `}` or `;`.
  - `parser::local-peripheral` says "`peripheral` items cannot be
    declared inside a function", as `parser::local-const` does, one
    message for both items, labeling the `peripheral` word.
  - `recover_to_item` stops at `peripheral NAME` only at the depth of the
    items, as at `memory {`; `parse_local_peripheral.ers` shows a
    peripheral inside a broken body being skipped, and
    `parse_peripheral_errors.ers` shows each broken item's recovery
    stopping at the next `peripheral`.
  - `hir/lower.rs` skips both items in `Items::collect` with a comment
    naming step 2; nothing else matched `ast::Item` exhaustively.
  - `peripheral_names.ers` keeps the locals named `read` and `write` in a
    function apart from the one calling `read(..)` and `write(..)`, so
    that the test does not depend on how a local and a function of one
    name interact in a call.

- Status: done
- Implements: ADR 0058, "Peripheral types and peripherals" (names,
  visibility, the type of a peripheral), the type positions of
  "Accesses" (a peripheral type is no type of a value, `volatile`
  pointers to one), and the first table of "What is checked".
- Changes:
  - `src/hir/mod.rs`: `PeripheralTypeDef` (path, name span, module,
    visibility, the modules it is reachable from as for structs, and its

    offset as a value computed at compile time in the scope of the

    name span, module, visibility, its `PeripheralTypeId`, type span,

    `Hir`, the program's then `core`'s. `Ty::Peripheral(PeripheralTypeId)`;
    `ExprKind::Peripheral(PeripheralId)`.
  - `src/hir/lower.rs`: both items in their module's one namespace
    (ADR 0049), so a name shared with any other item of the module is
    `resolve::duplicate-item`, and a built-in type's name

    another type (`resolve::unknown-type` stays for a name that names no
    type); attributes on either item as `resolve::misplaced-attribute`.
    A peripheral type written where a value would have it (every

    a pointer to a peripheral type, lowered as the pointer without it.
    A register's type is a new position of `never_in_memory` and
    `unsized_types` (`NeverPosition`, `UnsizedPosition`), so that `!`

    The `hir` dump shows both items.
  - `src/ty.rs`: reports the recorded positions as

- Tests (ui):
  - `resolve_peripheral.ers` (`emit: hir`): a peripheral type in a

    each item, and an attribute that does not exist),
    `resolve_peripheral_names.ers` (a peripheral type named as a struct,

  - `typeck_peripheral_by_value.ers` (`emit: typeck`): each position of

  - `typeck_volatile_peripheral.ers` (`emit: typeck`): `*mut volatile T`

- Decisions:
  - The type is `Ty::Peripheral(PeripheralTy)`, an id with the type's
    leaked path, like `StructTy`, rather than a bare `PeripheralTypeId`:
    types display on their own, and the new diagnostics name `Uart`.
  - `PeripheralDef::ty` is a `Ty`, `Ty::Peripheral` or `{error}`, rather
    than a `PeripheralTypeId`: a peripheral whose written type is no
    peripheral type has no id to hold, and a program may declare no
    peripheral type for a placeholder to name. Steps 3 and 4 take the id
    from `Ty::Peripheral` and skip `{error}`.
  - Both definitions hold their `path` and no separate name, as the plan
    lists; `RegisterDef::span` is the register name's span, as
    `FieldDef::span` is, beside `ty_span` and the offset's span.
  - `hir` re-exports `ast::AccessMode` (`pub use`), which step 1 made
    `Copy` to be carried into the HIR as is.
  - In each part (program, then `core`), peripheral types and then
    peripherals are lowered after the `memory` blocks, the last items
    added. Offsets and addresses are `Comptime::Value` bodies named
    `offset` and `address` in the dumps, through `comptime_usize` as a
    region's values; `check_all` already evaluates every such body, so an
    offset or address that fails to evaluate is reported from this step.
  - Where a peripheral type is allowed is judged in `Lowerer::ty`, after
    `named_ty` (which resolves a peripheral type anywhere): only at
    `Memory(Pointee)` and `Memory(Register)`. Every other position is
    recorded in `Hir::peripherals_by_value` (`PeripheralByValue`: span of
    the path, the type, an `UnsizedPosition`) and lowered as `{error}`;
    that includes the target of a cast, which is a position of `[T]`
    though the ADR's list does not name it. A register's type stays
    `Ty::Peripheral`, left to step 3's `ty::register-type`: the register
    is not among the ADR's positions, and one error there says what a
    register may be.
  - The ADR's "`comptime` value" has no written type (a `comptime`
    expression or block declares none), so nothing is recorded for it;
    the types of constants and statics are the typed values computed at
    compile time.
  - `volatile` on a pointer to a peripheral type is recorded in
    `Hir::volatile_peripherals` (`VolatilePeripheral`: the span of the
    whole pointer type, and the pointer as lowered, without `volatile`).
    Both new lists are cut at `core` through `CoreStart`, like
    `unsized_types`, and shown in the `hir` dump after it; the two item
    lists are shown after `memory`, `core`'s left out by module.
  - `ty::peripheral-by-value` says "`Uart` is a peripheral type, which no
    value has", labels "`Uart` as <position>" (the wording of
    `ty::unsized`, through a `position` helper now shared with
    `report_unsized_types`), and helps with `*mut Uart`.
    `ty::volatile-peripheral` says "a pointer to the peripheral type
    `Uart` cannot be `volatile`" at the pointer type, and its help gives
    the type to write. Both are reported in `check_all` right after
    `ty::unsized`.
  - `!` as a register's type gets a help of its own (`NeverHelp::Register`:
    a register is a `u8`, a `u16` or a `u32`) rather than the one
    suggesting `()`, which is no register type either.
  - `resolve::not-a-peripheral-type` is reported in `peripheral_of`:

    the written type with what it is ("a struct", "an enum", "a built-in
    type", "a pointer type", "an array type", "a slice type"), with a help
    on both forms. A path goes through `named_ty`, so a name of nothing
    and an item that is no type stay `resolve::unknown-type` (a
    peripheral named as a type, too: "a peripheral, not a type"); an
    applied type goes through `applied_ty`, so `Uart(u8)` is
    `resolve::type-argument-count`; the parts of a pointer, array or slice
    type are not lowered, since nothing in them makes it a peripheral
    type.
  - `resolve::duplicate-register` follows `resolve::duplicate-field`, at

  - The help listing the item kinds that share a namespace is
    `resolve::duplicate-item`'s (`resolve::duplicate-type` has none, so

    peripherals and ADR 0058, which changes nine snapshots (and the new
    `hir` dump fields two more).
  - `names_type` accepts a peripheral type, so that `Uart(u8)` says it
    takes no type arguments rather than that it is no type.
  - The placeholders until steps 4 and 5 are `todo!`s in
    `Checker::expr_kind` and `Checker::place_info` (so that `&raw P` and
    `P.r` stop there too), in MIR building's `expr_kind`, and in

  - The fuzz test leaves out, until step 5, the seeds that declare a

## 3. feat(typeck): compute and check peripheral types and peripherals
- Status: done
- Implements: ADR 0058, "Layout", "Failed values" and the second table
  of "What is checked".
- Changes:
  - `src/layout.rs`: the layout of a peripheral type: each register's
    offset, the extent (a `u64`, up to 2³²) and the alignment.
    Evaluated data, like the layouts of structs.
  - `src/query.rs`: computes each register's offset and each
    peripheral's address (`usize` values computed at compile time) and
    the layouts, and checks every peripheral type and peripheral of the
    program, used or not, as `check_memory_map` checks the map:
    `ty::register-type`, `ty::misaligned-register`,
    `ty::register-overlap` (once per pair, at the later register),
    `ty::misaligned-peripheral`, `ty::peripheral-out-of-range` (a
    peripheral ending exactly at 2³² is accepted) and
    `ty::peripheral-overlap` (once per pair, at the later peripheral in
    the order of ADR 0057). A check that needs a value that failed is
    skipped; a register whose type is wrong takes part in no other
    check, and a register type already in error is not also
    `ty::register-type`. A peripheral type with a failed offset or
    register type reaches a failed value, and a peripheral whose type
    reaches one or whose address failed is erroneous: the ADR 0048
    predicates (`needs_missing_layout`, `lacks_layout`) see both, so
    that a body naming them is not built into MIR.
  - `src/ty.rs`: the `typeck` dump lists each peripheral type with its
    registers' offsets, its extent and alignment, and each peripheral
    with its address and range.
- Tests (ui, `emit: typeck` where nothing is wrong):
  - `typeck_peripheral.ers`: the dump of a peripheral type with
    registers of the three widths, the RBR/THR pair at one offset, and
    two peripherals of it.
  - `typeck_peripheral_register_type.ers`: `u64`, `i32`, `usize`,
    `bool`, an enum, a struct and a pointer as a register's type.
  - `typeck_peripheral_misaligned_register.ers`: a `u32` at 2 and a
    `u16` at 1.
  - `typeck_peripheral_register_overlap.ers`: two registers at one
    offset with one mode; a `u32` at 0 and a `u8` at 2; `read write`
    with `read`; and accepted, a `read` and a `write` at one offset and
    overlapping in part; three registers sharing a byte give one error
    per pair.
  - `typeck_peripheral_misaligned.ers`, `typeck_peripheral_out_of_range.ers`
    (past 2³², ending exactly at it accepted, and a `u32` at
    `0xFFFF_FFFC` in a peripheral at 0, whose extent is 2³², accepted),
    `typeck_peripheral_overlap.ers` (two peripherals in one file; an
    empty peripheral type's peripheral overlaps nothing), and the
    directory test `typeck_peripheral_overlap_modules/` (two peripherals
    in two files, the error at the one in the later file).
  - `typeck_peripheral_failed_values.ers`: an offset, a register type
    and an address that fail are reported once each, and the checks
    that need them are skipped; a register of type `!` is not also
    `ty::register-type`. The cases that name a peripheral in a value
    (an address computed from a failed one, an address naming its own
    peripheral) need steps 4 and 5, and are in step 5's
    `eval_peripherals.ers`.
  - Step 3's error tests run the whole pipeline; as the "Order"
    paragraph says, none has a function, constant, static or
    `comptime` block mentioning a pointer to a peripheral type.
- Decisions:
  - `layout.rs` holds the rules as plain functions, as for enums:
    `register_width` (`u8`, `u16`, `u32` give 1, 2, 4; anything else
    `None`) and `peripheral_layout(&[(offset, width)])`, giving
    `PeripheralLayout { offsets, extent, align }`, with unit tests (the
    16550, an empty type, a register declared before one ending earlier,
    a `u32` at `0xFFFF_FFFC`). The layout keeps no widths: the register
    types give them. The extent is a `u64`; it is at most 2³² when the
    registers are aligned, and a misaligned one (a `u32` at
    `0xFFFF_FFFE`) can take it a few bytes past, which `u64` holds.
  - `Queries::peripheral_layout` computes a type's layout once, as a query
    item of its own (`Item::PeripheralLayout`), so that a layout needing
    itself would be `ty::cycle` ("the layout of `T` depends on its own
    value"), as a struct's. It is `None` when an offset failed or a
    normalized register type is no register type, and reports nothing:
    the register checks are in `check_peripheral_type`, run from
    `check_all`, so that what is reported does not depend on what asks
    for a layout first.
  - `peripheral_type_failed` answers "reaches a failed value" for the ADR
    0048 predicates; a type whose layout is being computed does not, as a
    struct already in `seen` does not for `lacks_layout`, so that an
    offset naming a pointer to its own type is no cycle. (Replaced in
    step 5 by the user's decision: such an offset is `ty::cycle`, in
    either order; see step 5's Decisions.)
    `peripheral_erroneous` adds a failed address and a type that is no
    peripheral type; `needs_missing_layout` collects every
    `ExprKind::Peripheral` of a body and asks it, while `lacks_layout`
    sees the peripheral type through the expression's type (step 5's
    tests reach both). `placed_peripheral` gives the address with the
    type's layout, for the checks and the dump.
  - When a register type that reaches a failed value stays silent (the
    user's decision, on a case ADR 0058 does not settle). Read literally,
    "a type reaching a failed value stays silent" would silence
    `read write own: *mut Regs` in `Regs`, whose type reaches the failure
    this very register causes, and two peripheral types whose registers
    only point to each other would both stay silent: a program in error
    with no diagnostic. The rule has two tiers. A peripheral type has a
    *base* failure (`peripheral_base_failure`) when an offset failed, or
    a register type is in error without a peripheral type: in error in
    itself (`!`, `[T]`, a failed length, a struct without a layout), or
    no register type and mentioning no peripheral type (`u64`, `bool`, a
    struct, `*mut u32`); "mentioning" looks behind pointers and into
    elements, fields, payload values and type arguments
    (`mentions_peripheral`), so that a cycle through a struct is no base
    failure either. The silent tier is transitive (from the review): a
    type's failure is *explained* when it has a base failure, or a
    register whose type, no register type, reaches an explained type
    (`explain_peripherals`, the least fixed point over every declaration,
    computed once for all types). So with `B { s: u64 }`,
    `A { r: *mut B }` and `C { t: *mut A }`, only `u64` is reported: `A`'s
    failure is `B`'s, already reported, and `*mut A` reaches a failed
    value already reported, which the ADR silences; a cycle that reaches
    a base failure is explained too. A register type reaching an
    explained type, as `*mut Failed` with `Failed`'s offset failed, stays
    silent, as the ADR says; one mentioning only types whose failure is
    not explained (`*mut Regs` in `Regs`, `Regs` by value, two types
    pointing only to each other, a pointer to such a type) is

## 4. feat(typeck): type-check register accesses
- Status: done
- Implements: ADR 0058, "Accesses" (places, access modes, `&raw`, a
  peripheral as a whole) and the third table of "What is checked" but
  for the codes of step 2.
- Changes:
  - `src/ty.rs`: a peripheral is a place of its peripheral type; a
    field access on a place of a peripheral type, from a peripheral or
    through a pointer, looks up a register (`ty::unknown-register`,
    `ty::private-register`, as fields are looked up and checked) and is
    a place of the register's type that carries its access mode and is
    volatile. A read of a `write` register is `ty::read-of-write-only`,
    a write of a `read` one `ty::write-to-read-only`, and a compound
    assignment checks both; writing through a `*const` pointer stays
    `ty::write-through-const`, and writing a `read` register through a
    `*const` pointer reports both. A peripheral, or `*u`, read, written
    or passed as a whole is `ty::peripheral-by-value`; `&raw mut *u` and
    `&raw const *u` are not. `&raw const P` and `&raw mut P` give
    `*const T` and `*mut T` without `mut` on the peripheral; `&raw` of a
    register is `ty::register-address`. Indexing a pointer to a
    peripheral type is `ty::peripheral-index`. Register visibility is
    that of fields (`Hir::field_visible`'s rule): seen through a
    peripheral only where its type is reachable. The `todo!` of step 2
    for an expression naming a peripheral goes.
- Tests (ui):
  - `typeck_peripheral_access.ers` (`emit: typeck`): reads, writes and
    a compound assignment of the modes that allow them, from a
    peripheral and through `*mut` and `*const` pointers; `&raw mut` and
    `&raw const` of a peripheral passed to a driver function; a `pub`
    register of a peripheral type of another module, through `use`; a
    register read in a condition, a `match` scrutinee and an expression
    statement; a private register used from a descendant module;
    `&raw mut *u`; a pointer made with `as` from an integer.
  - `typeck_peripheral_access_errors.ers` (`emit: typeck`): each code of
    the step: writing and compound-assigning a `read` register, reading
    a `write` one (in a `let`, an operand and an expression statement)
    and compound-assigning it, writing through `*const`, writing a
    `read` register through `*const` (both errors), a private register
    of another module's peripheral type, a `pub` register seen through
    a `pub` peripheral of a private peripheral type
    (`ty::private-register`), an unknown register, `&raw const` and
    `&raw mut` of a register, `u[1]` and `&raw mut u[1]`, and a
    peripheral and a `*u` used as values (a `let` initializer, an
    argument, an assignment).
- Decisions:
  - A peripheral is a place of its `PeripheralDef::ty` (`Ty::Peripheral`,
    or `{error}`, which makes everything after it silent), not `mut`
    (`immutable: None`, so `&raw mut P` passes) and reached through no
    pointer. A register is a place of its normalized type that keeps the
    base's mutability and pointer (so a `*const` base still gives
    `ty::write-through-const`), recorded in a new `PlaceInfo::register`
    (`Register`: the type's id and the register's index). A field of a
    register (only a register whose type is in error, a struct, has
    fields) keeps it, so its accesses are checked as the register's.
  - The access a place undergoes is passed to `access` and `place` as an
    `AccessMode`, reusing the register's mode type: `Read` for a read and
    for a pointer read to be indexed, `Write` for `=`, `ReadWrite` for a
    compound assignment. For a register, `access` checks the mode
    (`register_access`) and returns: the volatile checks
    (`ty::volatile-too-wide`, `ty::volatile-aggregate`,
    `ty::volatile-packed-field`) are not run for it, since step 3 checks a
    register's type once (`ty::register-type`), a valid one is a scalar of
    at most 32 bits, and no struct holds a peripheral, so no packed field
    leads to a register. That registers are volatile is not modeled in
    `PlaceInfo`: MIR building (step 5) takes it from the types.
  - The register's index goes into `Tables::fields`, the map of field
    indexes, read with `Tables::field` (documented as covering registers),
    so that step 5 finds the register without looking it up by name again.
  - `ty::read-of-write-only`: "the register `thr` of `Uart` is
    write-only"; `ty::write-to-read-only`: "... is read-only". Both label
    the place ("read here", "written here", or "read and written by this
    compound assignment") and the register's name ("declared `write`",
    "declared `read`"), with a help on what the mode allows and on
    declaring `read write`. A `read` register written through a `*const`
    pointer reports `ty::write-through-const` from the immutability check
    and `ty::write-to-read-only` from `access`, both.
  - `ty::unknown-register` and `ty::private-register` follow
    `ty::unknown-field` and `ty::private-field` (`unknown_register`,
    `private_register`), the type named by its path. The help of the first
    lists the registers visible in the body's module, each name once (a
    name declared twice was reported in step 2), or says that there are
    none or none is visible; the second has the private form (labeling the
    register) and the `pub` form (labeling the type, offering it with
    `pub` or `pub use`). Visibility is `Hir::register_visible`, beside
    `Hir::field_visible` in `hir/mod.rs`, with the same rule.
  - A peripheral or `*u` read whole (in `expr_kind`'s place arm, which now
    includes `ExprKind::Peripheral`) or written whole (in `place`) is
    `ty::peripheral-by-value`, checked beside the `[T]` case and like it
    returning `{error}`, so that a `let` initializer or an argument reports
    nothing more. The message is step 2's (now `peripheral_by_value`,
    shared), labeled "a device, read as a whole" (or "written", or "read
    and written" for a compound assignment), with a help on reaching
    registers one at a time and passing `&raw mut P` (`whole_peripheral`).
    As for `[T]`, writing a whole device returns before the immutability
    checks, so `*c = 0` through a `*const` pointer is only
    `ty::peripheral-by-value` (the user's decision, asked after this
    step's review: one error, not also `ty::write-through-const`).
  - `ty::peripheral-index`: "cannot index `*mut Uart`, a pointer to a
    peripheral type", at the pointer ("`Uart` has no size, so no stride"),
    with the help "a pointer to a peripheral type reaches one device,
    whose registers are reached as in `(*u).NAME`; for another device of
    type `Uart`, use a pointer to it", which says what to write instead
    without promising register arrays. It is checked before the pointee's
    layout, whose absence would otherwise be `ty::too-large`. The pointer
    itself is still read (its `access`). The place is `{error}`, so
    `&raw mut u[1]` reports only that. Indexing a peripheral or `*u`
    itself, `UART0[0]`, stays `ty::cannot-index`, and the peripheral is
    not also reported as read whole: a base of a peripheral type is not
    counted as read when indexed (other bases are, as before).
  - `ty::register-address`: "cannot take the address of the register
    `rbr` of `Uart`", at the place, labeled "a register", the help naming
    the mode the pointer would bypass and `&raw mut P`. It is checked
    first in `addr_of` and
    returns `{error}`, so `&raw mut (*c).r` through a `*const` pointer is
    not also `ty::address-of-immutable`.
  - `ty::no-fields` on a pointer to a peripheral type (`u.thr`) gets the
    help to dereference first that a pointer to a struct gets.
  - The `typeck` dump labels a field access whose base is of a peripheral
    type `register NAME` rather than `field NAME`.
  - Tests: the accepted test also has `u16` and `u32` registers, a
    compound shift, `&raw mut TIMER0 as *mut u8`, and `&raw const` of a

## 5. feat(codegen): access registers as volatile loads and stores

  - `tests/fuzz.rs`: removes `declares_peripheral` and its filter in
    `seeds`, added in step 2, so that the seeds declaring peripherals are
    fuzzed again.
- Tests:
  - `mir_peripherals.ers` (ui, `emit: mir`): a write, a read and a
    compound assignment from a peripheral and through a pointer.
  - `codegen_peripherals.ers` (ui, `emit: llvm-ir`, `opt: both`): one
    volatile store or load of the register's width at
    `address + offset` for a `u8`, `u16` and `u32` register, from a
    peripheral and through a pointer; a compound assignment as one load
    then one store; two reads of one register not merged; a read of
    RBR then a write of THR at the same address, in that order; a
    register write and a write through a volatile pointer kept in
    source order, both ways round; an access through a pointer made with
    `as` from an integer; no global emitted for a peripheral.
  - `mir_peripheral_failed_values.ers` (ui, `emit: mir`): functions
    naming a peripheral whose address failed, or reaching a peripheral
    type whose offset failed through a pointer, report nothing beyond
    the failed values' own errors, and the compiler does not panic.
  - `eval_peripherals.ers` (ui): a register read in a constant and a
    register written in a `comptime` block are
    `eval::volatile-access`; a `comptime` assertion that
    `&raw mut P as usize` is the peripheral's address passes, and a
    static initialized with `&raw mut P` is accepted; an address naming
    its own peripheral's address is `ty::cycle`; an address computed
    from a peripheral whose address failed reports nothing more, and
    that peripheral takes part in no overlap or alignment check.
- Decisions:
  - A peripheral type is `mir::Ty::Peripheral(PeripheralTypeRef)`, a
    leaked `PeripheralTypeDef` compared by identity as structs are: its
    path (as the HIR names it), its registers' names and types, and its
    layout, `layout::PeripheralLayout` re-exported by `mir` as `Layout` is.
    A register is the existing `PlaceElem::Field(index)` on it rather than
    a projection of its own: the index is the one step 4 records in
    `Tables::field`, the dump shows `(*_1).2` as for a field, and each
    match on projections gains one arm. Access modes are not in MIR, which
    checks none.
  - The layout is set after the type exists (a `OnceLock`, as a struct's
    fields): `peripheral_layout` sets it when it finishes, or
    `mir_peripheral_type` when it is done already, and the MIR type never
    asks for it: the type may be made for a struct's field or a static's
    type before its layout is computed, or while it is, and asking would
    start that computation, or report a cycle, from wherever the type is
    first needed. Only a register's offset needs the layout, and a body
    reaching a register has an expression of the peripheral type, whose
    layout `needs_missing_layout` computes before the body is built.
    `into_mir` asks for every layout, so that dumps and code generation
    find them all. (Rationale reworded after review: it first named an
    offset holding a pointer to its own type, which is now `ty::cycle`.)
  - Register types are taken from the written type, without normalizing
    or evaluating anything: `u8`, `u16` or `u32` as such, and anything
    else, reported and failing the layout, as `()`, which no body that is
    kept reaches.
  - A peripheral is `Const::Peripheral(PeripheralRef)`, a leaked
    `PeripheralDef` with its path, address, type and address type, shown
    `const peripheral UART0`. Its type is `*mut T`: a peripheral is not
    `mut`, but registers are written through it. A peripheral as a place
    is `_n = const peripheral P` then `(*_n)`, one temporary per
    occurrence, as `static_place` does for a static. `&raw const P` and
    `&raw mut P` are the operand copied into a temporary of the type
    checker's `*const T` or `*mut T` (the plan's "that operand"; both have
    one representation, as for `&raw` of what a slice points to), not
    `&raw (*_n)` as for a static. `ExprKind::Peripheral` in `expr_kind` is
    `unreachable!`: a peripheral read whole is a type error.
  - `Queries::mir_peripheral` takes the address and type with `expect`:
    `needs_missing_layout` keeps every body naming an erroneous
    peripheral out of MIR.
  - Registers are made volatile at the register projection, in codegen
    (`Address::volatile`) and in evaluation (`PlaceRef::volatile`), not
    when dereferencing a pointer to a peripheral type: every access
    through such a pointer reaches a register, and a register reached
    from a peripheral takes the same path.
  - In evaluation, the operand is `Pointer::Addr(address)`. The volatile
    check comes first in `access`, so a register read through a pointer
    made from an integer is `eval::volatile-access`, not
    `eval::invalid-access`. The register's offset is taken with `expect`
    (`PeripheralTypeDef::offset`), as codegen takes it: a body reaching a
    register is built only after its type's layout is computed (above).
    (From the review: this replaces a fallback to offset 0 for a layout
    not yet known, which the user's decision on self-referencing offsets
    below made unreachable; the reviewer's program that reached it is in
    `typeck_peripheral_offset_cycle.ers`, now `ty::cycle`.)
  - In codegen, the operand is the constant `inttoptr` of the address,
    and a register a `getelementptr` of its offset in bytes; nothing is
    emitted for a peripheral or a peripheral type.
  - The `mir` dump lists, after the structs and enums and before the
    statics, each peripheral type as
    `peripheral Uart { 0 rbr: u8 at 0x0, ... } // extent 6, align 1`
    (registers numbered as projections name them, offsets in hex as in
    the `typeck` dump) and each peripheral as
    `peripheral UART0: Uart at 0x10000000;`. `LeftOut` gains a mask for
    each, so `core`'s would be left out (it has none).
  - `driver::FrontEnd::Mir` now boxes the MIR: the two new lists made it
    large enough for clippy's `large_enum_variant`.
  - Tests: `mir_peripheral_failed_values.ers` also has a pointer to the
    failed type as a parameter, a local and a cast target, and a peripheral
    of that type; `eval_peripherals.ers` also reads a register through a
    pointer made from an integer (`VIA`), asserts the address held by the
    static `CONSOLE` at compile time, and makes `NEXT` a `Timer`, so that
    it would be misaligned as well as overlap `OTHER`. With `-O`, LLVM
    raises the alignment it records for constant addresses
    (`align 268435456`); the accesses keep their widths. The new
    snapshots have no `assertion_line`, as most do not.
  - An offset whose computation names its own peripheral type, through a
    pointer to it (`read status: u32 at (0x4 as *mut Regs) as usize`, or
    a local of type `*mut Regs` in the offset's block), is `ty::cycle`
    whatever the declaration or evaluation order, as a struct's field
    length naming a pointer to the struct is (the user's decision, asked
    after this step's first run and review). Step 3 had made a type whose
    layout is being computed count as not failed in
    `peripheral_type_failed`, so the outcome depended on the order: a
    cycle when `check_all` evaluated the offset first (through
    `needs_missing_layout` starting the layout, which needs the offset),
    accepted when something computed the layout first, as a constant
    declared earlier with a local of type `*mut Regs` does. Now
    `peripheral_type_failed` always asks for the layout, so a layout in
    progress is reported as a cycle by `start`, as `struct_layout`'s is
    from `lacks_layout`. The message names the item computed first ("this
    value depends on its own value", through the layout, or "the layout

    `typeck_peripheral_offset_cycle.ers` pins both orders, for a cast
