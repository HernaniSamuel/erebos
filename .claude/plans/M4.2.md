# Plan: M4.2 Startup in the language

ADRs: 0083
Base: 2123541
Program on QEMU: every e2e program boots through `core`'s `_start` on
both targets, at `-O0` and `-O` (step 2), including the startup tests of
ADR 0030 and a program whose entry function is in a module; a program
per target jumps back to its entry function through `sym entry`
(step 1).
Out of scope:
- handlers, the rest of the vector table, the riscv32 trap entry,
  `critical` blocks, whether `_start` masks interrupts on thumbv7m and
  the table's size and `code_align`: M4.3;
- reset code of the program, and statics in named regions or left
  uninitialized: deferred ideas of the roadmap (ADR 0083, 0057);
- ADR 0051 (line 40) and 0073 still describe `_start` as reserved or as
  the compiler's, citing ADR 0012: historical text of accepted ADRs,
  still true for the reservation; no status line changes.

Before step 1: the `docs(adr)` commit that accepts ADR 0083 also sets
the status lines of the ADRs it supersedes or amends, in their files and
in the index (`docs/adr/README.md`):
- 0012: `Superseded by 0083`, keeping the amendments in the line
  (`Superseded by 0083; was amended by 0030 (...), 0057 (...), 0074
  (...)`, with their existing text); index `Superseded by 0083`;
- 0030: adds `0083 (`_start` is `core`'s, read in `rt/arch/`, not in
  `--emit=llvm-ir`)` to its amendments; index adds `0083`;
- 0052: adds `0083 (the compiler knows `core::arch::_start` by path)`;
  index adds `0083`;
- 0057: `Accepted; amended by 0083 (on thumbv7m the reset entry is the
  vector table's section, then `_start`'s)`; index `Accepted, amended by
  0083`;
- 0074: adds `0083 (the vector table's words in `.vector_table`;
  `_start` is `core`'s)`; index adds `0083`;
- 0079: `Accepted; amended by 0083 (`sym entry`)`; index `Accepted,
  amended by 0083`.
The same commit holds the roadmap's edits written while planning: the
M4.2 pending decisions settled and the deferred idea of reset code of
the program.

Order: `sym entry` (1) exists before `core`'s `_start` uses it (2); the
documentation (3) follows. Every existing test passes after every step.

## 1. feat: `sym entry` names the entry function
- Status: done
- Implements: ADR 0083, "`sym entry`".
- Changes:
  - `src/syntax/ast.rs`, `src/syntax/parser.rs`: the operand `sym`
    takes the keyword `entry` in place of a path; the AST keeps which
    (`Sym(SymTarget)` with `Path(Path)` and `Entry(Span)`, or an
    equivalent), and its dump prints it.
  - `src/hir/mod.rs`, `src/hir/lower/expr.rs`: `hir::AsmSym::Entry`;
    the HIR dump prints `sym entry`.
  - `src/ty/asm.rs`: `AsmSym::Entry` is a valid `sym` (no
    `ty::asm-sym`), also in a naked function's body.
  - `src/mir/build/asm.rs`: `AsmSym::Entry` becomes
    `AsmSym::Body` of the entry function's body. Codegen needs no
    change: it writes the body's symbol.
- Tests:
  - ui: `asm_sym_entry_ast.ers` (`// emit: ast`), the operand parsed,
    plain and named (`main = sym entry`); `sym entry::x` is
    `parser::unexpected-token` at `::`;
    `asm_sym_entry.ers` (`// emit: llvm-ir`, riscv32) and
    `asm_sym_entry_thumbv7m.ers`, a function and a naked function whose
    `asm` holds `sym entry`, with the entry function in a module, so
    the template shows its path symbol (`app.main`); a MIR dump shows
    `sym` with the entry's name.
  - e2e: `sym_entry_riscv32.ers` and `sym_entry_armv7m.ers`
    (`// targets:` one each): the entry function counts its runs in a
    `static mut`; on the first it jumps to itself through `asm` with
    `sym entry` and `noreturn`, on the second it exits 0. Proves the
    symbol is the entry function's at run time.
- Decisions:
  - AST: `ast::SymTarget { Path(Path), Entry(Span) }` in `ast.rs`, and
    `AsmOperandKind::Sym(SymTarget)`; the span is the keyword's, kept
    for symmetry with the path's, though lowering does not read it. The
    parser eats `TokenKind::Entry` first and otherwise reads a path, so
    nothing follows `entry` and `sym entry::x` ends at `::` with the
    parser's existing "expected `,` or `)`" `parser::unexpected-token`,
    needing no new diagnostic. `asm_parse.ers`'s snapshot changes only in
    wrapping its two paths in `Path(..)`.
  - HIR: `AsmSym::Entry` has no payload, since the entry function's id
    is known only after every function is lowered (`find_unique` in
    `lower.rs`); the MIR builder reads `Hir::entry` (`self.q.hir.entry`),
    where MIR body ids are HIR function ids. The HIR dump is the derived
    `Debug`, so it shows `Sym(Entry)`, not the literal text `sym entry`
    the plan says; the plan's wording is loose, no printer was added.
  - `src/ty/asm.rs` needs no change: its arms match `Sym(_)` as valid
    and only `Sym(Other(..))` is reported, so `Entry` is accepted in a
    function and in a naked function's body (the naked check lets `Sym`
    through) with no code; the naked case is covered by a test.
  - Tests: one ui file per concern, as the harness takes one `// emit:`
    per file: `asm_sym_entry_ast.ers` (AST; operand plain, named, with a
    trailing comma, among other operands, after a path `sym`),
    `asm_sym_entry_errors.ers` (`sym entry::x`), `asm_sym_entry.ers`
    and `asm_sym_entry_thumbv7m.ers` (LLVM IR with the entry function
    `app.main` in a module; function, naked function and, on riscv32, a
    named operand), `asm_sym_entry_mir.ers` (MIR dump: `sym app.main`).
    The `named` function of the riscv32 file has no `out` operand,
    since `noreturn` allows no outputs (`ty::asm-options`).
  - The IR snapshots of the two ui files still carry today's `module
    asm` of `_start`, with `app.main`; step 2 removes it.
  - e2e: both programs use the root `main` (exits 3) as the decoy and the
    entry function in `mod app`, so a wrong symbol (the root's) shows
    as exit 3. The first run prints `1 `, the second `2\n`, so a jump
    that re-ran `_start` would also be seen: `static mut RUNS` would be
    zeroed again and the output would loop. The thumbv7m jump is
    `b.w`, as `asm_armv7m.ers` does; the riscv32 one `j`.

## 2. feat(rt): `_start` is a naked function of `core::arch`
- Status: done
- Implements: ADR 0083, "`_start` is a naked function of `core::arch`"
  and "The vector table on thumbv7m"; supersedes ADR 0012.
- Changes:
  - `rt/arch/riscv32.ers`, `rt/arch/armv7m.ers`: the private
    `#[export] #[naked] fn _start() -> !` of the ADR, with a comment
    saying what it does and why the steps are in that order; not in the
    `// portable:` list.
  - `src/hir/lower.rs`: `check_start` skips `core`'s items; its help
    says that `core::arch` defines `_start` (ADR 0083), and its doc
    comment names ADR 0083. `check_symbols` leaves out a program's item
    named `_start`, as it leaves out `__` names (`checked`), so a
    program's `_start` is one `resolve::reserved-name` and no
    `resolve::duplicate-symbol`. The compiler finds `core::arch::_start`
    through the binding of `arch` in `core`'s root namespace, then in
    the namespace of that module, as `core_item` finds `PanicInfo` in
    the root; `Hir` gains `reset: FnId` (an `unreachable!` when it is
    missing: a bug of the compiler; if `tests/architecture.rs`'s count
    for `src/hir/lower.rs` rises, say why in `Decisions`).
  - `src/mir/`: `Mir` gains `reset: Option<BodyId>`, the body of
    `_start`; `leave_out` drops it with `core` (`None` after it). The
    MIR dump prints nothing for it, since `_start` is never in a dump.
  - `src/codegen/mod.rs`: `start_stub` and its two functions go;
    the reset body, when present, is put in section `.text.start`; on
    thumbv7m the module asm is the vector table's four lines of the
    ADR, in `.vector_table`, and on riscv32 there is none. The
    remaining comments name ADR 0083, not 0012.
  - `src/link.rs`: on thumbv7m, `.vector_table : { KEEP(*(.vector_table)) }`
    first in the code's region, before `.text.start`; riscv32's script
    unchanged. Comments name ADR 0083.
  - Comments of tests that cite ADR 0012 for what `_start` does or who
    generates it now cite ADR 0083: `tests/ui/codegen_entry_name.ers`,
    `tests/ui/resolve_regressions.ers`, `tests/e2e/entry_in_module.ers`,
    `tests/e2e/startup_bss.c`, and any other a search for `0012` finds
    under `src/`, `rt/` and `tests/`.
- Tests:
  - ui: every LLVM IR snapshot loses the `module asm` of `_start`
    (riscv32: none left; thumbv7m: the four lines of the table);
    `target_thumbv7m_reset_entry.ers` comment rewritten to what it now
    shows; `target_thumbv7m_linker_script.ers` shows `.vector_table`;
    the snapshots of `resolve::reserved-name` for `_start` show the new
    help, and gain a case per kind (function, `extern fn`, `extern
    static`) if one is missing.
  - ELF (`tests/elf.rs`): on both targets at both levels, `_start` is a
    function symbol (`FUNC`) with a size above zero, so it is the naked
    function and not a label of module assembly; the existing checks of
    its address (`start_address`), of `reset_entry_alone` and of
    `thumbv7m_reset_entry` keep passing, the last reading the two words
    at the start of `.vector_table` at the origin, and `.text.start`
    at origin plus 8 (which holds while LLVM aligns the naked function
    to at most 8; if not, code generation sets its alignment, ADR 0083).
  - The reach of `tail` on riscv32: `startup_far_entry.ers`
    (`// targets: riscv32imac-unknown-none-elf`), a program with a naked
    function `pad` holding `asm(".space 0x180000", options(noreturn))`
    declared before its entry function, and a code region large enough;
    it boots and exits 0. An ELF test builds it at both levels and
    checks that the entry function's symbol minus `_start` exceeds
    `0x10_0000`, so the test fails rather than passes silently if the
    functions are emitted in another order (then move `pad` or the
    entry function, and record it in `Decisions`).
  - e2e: every program, on both targets, at both levels, unchanged;
    `startup_data`, `startup_bss` and `entry_in_module` among them.
- Decisions:
  - `_start` in `rt/arch/*.ers` is the ADR's text, with one comment above
    it that lists the four steps in order and why (stack first, since
    nothing before it may use the stack; the loops test their bounds before
    the first word; `.bss` before `.data` is only a convention, as neither
    reads the other; the jump reaches any address). The comment sits
    between the section header and the function, as the `__aeabi_*`
    functions' do. The thumbv7m copy comes before the EABI division
    section, after the fences: reset entry first, support functions after.
    The `sym entry` operand is implicit-positional (`{}`) on riscv32 and
    `{0}` twice on thumbv7m, as the ADR has them.
  - `check_start` takes `core_root` and keeps only items whose module is
    below it (the program's); `check_symbols`'s `checked` leaves out an item
    of the program named `_start` (a name test beside the `__` one). Both
    are the plan's; the help now reads "`core::arch` defines `_start`,
    which sets up the stack and jumps to the entry function (ADR 0083)".
  - `Hir::reset` is found through `core`'s root namespace: `arch`, then
    `_start` in the namespace of that module, with no visibility check, so a
    private `_start` is found. That adds two `unreachable!` to
    `src/hir/lower.rs` (5 -> 7 in `tests/architecture.rs`'s `PANICS`):
    `core::arch` not being a module, and the module having no function
    `_start`. No user input reaches either: `core` is the compiler's own
    source (`rt/core.ers` declares `pub mod arch;`, both files of
    `rt/arch/` define `_start`), and a program cannot change what `core`'s
    namespaces hold (a program's `mod arch` is in the program's root, not
    `core`'s). The `crate_in_core_is_core` unit test of `lower.rs` has a
    stand-in `core` of its own, so it gained `mod arch { fn _start() -> !
    { loop {} } }`.
  - `Mir::reset` is `Some` from `into_mir` and `None` after `leave_out`
    unconditionally (not computed from `left_out.bodies`), as `_start` is
    `core`'s and nothing a kept body calls names it; the `leave_out` unit
    test's `Mir` literal has `reset: None`.
  - Codegen: `RESET_SECTION` (`.text.start`) set with `set_section` on the
    LLVM function of `mir.reset` after the bodies are defined; the vector
    table is `vector_table(arch) -> Option<&str>` as module asm, set only
    when there is one (riscv32 sets no module asm at all). The table's four
    lines are the ADR's, with no `.thumb`/`.syntax`: `.word` needs no
    mode, and the Thumb bit comes from the linker, since LLVM marks `_start`
    `.thumb_func` and `STT_FUNC` when it defines it (the ELF test checks
    that the second word is `_start` with bit 0 set).
  - Linker script: `vector_table(arch, code)` in `src/link.rs` makes the
    thumbv7m line `.vector_table : { KEEP(*(.vector_table)) } > CODE` before
    `.text.start`'s, with a comment; riscv32's output differs only in the
    comment above `.text.start`, which now says "after the vector table
    where there is one (ADR 0083)". The overflow help's list of the code
    region's contents ("the reset entry, the code, ...") is unchanged: the
    table is part of the reset entry (ADR 0083 says the reset entry on
    thumbv7m is the two sections).
  - Snapshots: 64 changed. The LLVM IR ones lose the `module asm` (thumbv7m:
    keep the four lines, in `.vector_table`, beside the unchanged
    `.syntax`/`.thumb` removal); `target_thumbv7m_linker_script`,
    `link_memory` and `link_memory_shared` show the script's comment, and
    the first the `.vector_table` line; the five `resolve::reserved-name`
    ones for `_start` show the new help. Five HIR dumps (`resolve_bit_struct`,
    `resolve_field_modes`, `resolve_memory`, `resolve_peripheral`,
    `resolve_register_arrays`) shift the `FnId` of their value bodies by
    one: those bodies are numbered after every function, and `core` gained
    one (`_start`), so this is the expected consequence, not a change of
    the dumps' content.
  - Tests: `resolve_symbol_errors.ers` gained `mod v { extern fn _start();
    }` (the `extern fn` case was the one missing; `fn` and `extern static`
    were in `resolve_regressions`, `resolve_symbol_errors` and
    `resolve_static_errors`), its comment says why only `reserved-name`
    shows, and its snapshot confirms no `resolve::duplicate-symbol` for
    `_start` (the `mod v` is `v` since `e` is taken). In `tests/elf.rs`,
    `Symbol` gained `kind` (the `Type` column) and `check`, which
    `startup_ranges` and every `check_map` test run, asserts `_start` is
    `FUNC` with a size above zero on both targets at both levels, instead of
    a test of its own; `thumbv7m_reset_entry` reads the section headers of
    `.vector_table` (address 0, size 8) and `.text.start` (address 8) and the
    two words from the first; `the_entry_function_is_far_from_start` stages
    `tests/e2e/startup_far_entry.ers` with the board through
    `common::board::stage` and checks `main - _start > 0x10_0000` at both
    levels (it passes without moving `pad`: the functions are emitted in
    declaration order and `_start` is last, in its own section at the
    origin). `startup_far_entry.ers` prints `far` and exits 0, so the e2e
    run proves the jump reaches.
  - Comments naming ADR 0012 were rewritten in `tests/ui/codegen_entry_name.ers`
    (and `codegen_symbols.ers`, which said `_start` jumps to the entry
    function's symbol), `resolve_regressions.ers`, `entry_in_module.ers`,
    `startup_bss.c`, and `target_thumbv7m_reset_entry.ers`, which now says
    what it shows: only the vector table's words.
  - No `start_stub`: both stubs and their `entry`-name argument went; the
    `mir.entry` is no longer read by codegen, the symbol coming through
    `sym entry` in `core`'s template.

## 3. docs: document startup in `core` and mark M4.2 done
- Status: done
- Changes:
  - `docs/reference.md`: "Programs" (`entry fn` runs after `core`'s
    `_start`); "Inline assembly", the grammar and the table of
    operands (`sym entry`); "Symbols" (`_start` is defined by
    `core::arch` and reserved; `sym entry` names the entry's symbol);
    "Startup and memory" rewritten around `core::arch::_start` (ADR
    0083 in the heading, 0012 out), with where to read it and the
    reach of the jump; "Targets", the reset entry of thumbv7m
    (`.vector_table`, then `_start`); "`core`", the items of
    `core::arch` (`_start`, private, named by the compiler); the
    diagnostics table, if its text for `resolve::reserved-name` names
    ADR 0012.
  - `docs/roadmap.md`: M4.2 ✅ in the table, the status entry for M4.2
    done (what it delivered, what it left to M4.3), next M4.3.
- Tests: none; a documentation step. The gates run unchanged.
- Decisions:
  - The two stale statements named by the earlier review are fixed:
    "Startup and memory" no longer says `_start` is generated by the
    compiler and visible in `--emit=llvm-ir` (it says it is read in
    `rt/arch/`, since the dump leaves `core` out), and its heading now cites
    ADR 0030, 0057, 0083, not 0012; "Symbols" no longer cites ADR 0012 for the
    reservation of `_start`, and gives ADR 0083 as the reason, with the single
    `resolve::reserved-name` and no `resolve::duplicate-symbol`. A search of
    `docs/` (not the ADRs) for `_start` and `0012` found nothing else stale:
    `docs/open-findings.md` and `CONTRIBUTING.md` only name the symbol; the
    roadmap's older status entries (M2.3b, M3.5, M4.1, the pending decisions
    of M3.5) say what was true then and are history, left as written.
  - "Programs": `entry fn` says `_start` is `core`'s and that an `asm` may
    jump to it with `sym entry`; this is the one place outside "Inline
    assembly" that tells a reader the entry function can be jumped to, since
    "cannot be called" would otherwise read as absolute.
  - "Inline assembly": the grammar's `sym` takes `( path | "entry" )` and the
    operand table has a row for `sym entry`, not a paragraph, with its three
    rules (a keyword, nothing follows, `resolve::call-entry` does not apply).
    The row does not repeat that it is valid in a naked function: "naked
    functions" already allows `sym` operands.
  - "Startup and memory" keeps the four steps as before and says where
    `_start` is read, that the compiler names it by path, how the jump
    reaches (`tail` against the old `j`, `movw`/`movt` and `bx`), and that a
    program cannot run code before it (ADR 0083, "No reset code of the
    program"). The thumbv7m "reset entry" paragraph names the two sections,
    says the table's words are the compiler's `module asm` (the one thing the
    program's `--emit=llvm-ir` still shows) and `_start` the language's, and
    points the rest of the table to M4.3 instead of "M4".
  - "`core`": `_start` is described as a paragraph after the portable and
    specific items, not as an item of either list, since ADR 0083 says it is
    in no portable list and no program names it.
  - The linker script description says `.vector_table` is `KEEP`'d, as the
    script does, so that someone reading `--emit=linker-script` finds the
    word explained.
  - From the review: the roadmap's entry `**M4.2:** _start is a naked
    function of core::arch ...` under "Decisions already agreed for the later
    steps" is removed, as M4.1's was when it was marked done (a6d2332): the
    decision is carried out and recorded in the status entry. The reference's
    list of kinds of `_start` that are reserved now includes a plain
    `static` (`tests/ui/resolve_static_errors.ers`).
  - Roadmap: M4.2's status entry follows the form of M4.1's (what it
    delivered, then what is left), and the "Next" line points to M4.3. The
    pending-decisions entry for M4.2 (line 272) and the deferred idea were
    already written at acceptance, so they are untouched.
