# Plan: M2.4c Cost of `match`

ADRs: 0042, 0043
Base: 5171f20e6849585261770e09c750964233bd297a
Program on QEMU: matches whose code and checks grew exponentially in
M2.4b, built and run at both optimization levels and checked in a
`comptime` block (`tests/e2e/match_cost.ers`, step 4).
Out of scope:
- a limit on the cost of exhaustiveness checking, which stays exponential
  in the worst case (ADR 0043, "Consequences"); not scheduled;
- `match`es on integers, `bool` and enums without payloads, whose single
  switch is unchanged (ADR 0042);
- range patterns, guards, `..` in payloads (not scheduled);
- `Option` and `Result` (M2.5).

Before step 1: the `docs(adr)` commit that accepts ADR 0042 and 0043
also sets the status lines of the ADRs they amend, in the files as
`Accepted; amended by NNNN (what changed)` and in the index
(`docs/adr/README.md`) in its style, `Accepted, amended by NNNN`:
- ADR 0040: amended by 0042 (code generation), 0043 (witnesses listed
  without a count);
- ADR 0041: amended by 0042 (where a `let` is copied, and the first
  matching alternative binds).

The same commit carries the M2.4c row of `docs/roadmap.md`.

The two shapes of ADR 0042 "Context" are used throughout:

- **pairs(n):** `enum P: u8 { A(bool, ..., bool) = 0 }` with `2n`
  positions; for each `i < n`, one arm with `true` at positions `i` and
  `i + n` and `_` elsewhere;
- **ors(k):** `enum Q: u8 { A(u8, ..., u8) = 0 }` with `k` positions;
  arms whose positions are each `1 | 2 | 3`.

`tests/match_cost.rs` (created in step 1) generates programs of these
shapes as source text and runs them through `erebos::driver::dump`, as
`tests/ui.rs` does. Each case names its stage: the checks of steps 1 and
2 run to `Stage::Typeck`, which builds no MIR, so that they do not depend
on step 3; the size checks of step 3 run to `Stage::Mir`. Its sizes are
chosen so that the M2.4b compiler would take more than 2^30 steps on
them (pairs(32) has 2^32 witnesses; ors(32) tries 3^32 combinations),
while the fixed one takes milliseconds; the unit tests of
`src/ty/usefulness.rs` bound the steps exactly (step 2). The generator
also counts the patterns each program writes, as ADR 0042 "Conformance
tests" counts them.

## 1. feat(typeck): search at most four witnesses
- Status: done
- Implements: ADR 0043, all sections.
- Changes:
  - `src/ty/usefulness.rs`: `missing` takes the number of witnesses
    wanted and stops once it has found that many, at every depth: each
    recursive call is given the number still wanted, and a value's loop
    ends when none is. The order in which witnesses are found is
    unchanged (ADR 0040), so the result is a prefix of today's.
  - `src/ty.rs` (`coverage`): asks for four; shows the first three, and
    ends the list with "and more" when a fourth was found, in the message
    and the label; with three or fewer, `and_list` as today. The help is
    unchanged. The integer-scrutinee message is unchanged.
- Tests:
  - unit (`usefulness.rs`): on the `Msg` enum of the existing tests, the
    witnesses with a limit of 4 are the first four of those with a limit
    of 100, and a limit of 100 gives all five; pairs(40) without a `_`
    arm gives exactly four witnesses, the first being
    `P::A(true, ..., true, false, ..., false)`, `n` of each: ADR 0040
    examines `true` before `false`, and every arm is left until position
    `n`, where each `false` leaves fewer.
  - ui (typeck): `typeck_match_payload_coverage.ers`: its header comment
    ("then how many more") says "and more" instead; in its snapshot the
    three "and 2 more" become "and more", and no other diagnostic
    changes; new cases in the same file: exactly three witnesses (listed
    with "and", no "and more") and exactly four (three, "and more").
  - `tests/match_cost.rs` (new, `Stage::Typeck`): pairs(32) without a
    `_` arm reports one `ty::non-exhaustive-match` with three witnesses
    and "and more" (the M2.4b compiler enumerates its 2^32 witnesses).

## 2. perf(typeck): examine once the values the remaining arms do not tell apart
- Status: done
- Implements: no new behaviour; ADR 0040 "Exhaustiveness" and "Dead
  arms" as amended by ADR 0043, at a cost that no longer grows with the
  product of the or-patterns of an arm.
- Changes:
  - `src/ty/usefulness.rs`:
    - two values, or two alternatives, at one position are **alike**
      when specializing the rows by each gives the same rows, compared
      pattern by pattern by address (`std::ptr::eq`), and, in `useful`,
      the same remaining pattern. `expand` already shares the tail of a
      row among the rows of its alternatives, so the alternatives of one
      or-pattern that name values without payload are alike whenever the
      rows treat them alike;
    - `useful`, at an or-pattern: an alternative alike to an earlier one
      is not examined again, since its answer is the same;
    - `useful`, at `_` when every value is named: a value alike to an
      earlier one is skipped likewise;
    - `missing`: a value alike to an earlier one at the same position
      reuses that value's sub-witnesses, written with its own value in
      place, in the same order, so the witnesses and their order are
      those of ADR 0040; the limit of step 1 counts them as found;
    - the search state (`enums`, and a count of recursive calls) becomes
      one struct passed through `useful` and `missing`, so that the unit
      tests can bound the calls; `ty.rs` creates it per `match`.
  - The module comment says that values the rows do not tell apart are
    examined once, and that the worst case stays exponential
    (ADR 0043).
- Tests:
  - unit (`usefulness.rs`), each with the bound on recursive calls
    given, where M2.4b's search makes over 3^30 calls; "alike" compares
    only sibling values, so a sub-search is not reused across the tree,
    and the bounds are those of that rule:
    - ors(40), at most 10 · k calls (k = 40): a second arm equal to the
      first is not useful; with `4` in place of one position's or-pattern
      it is; an alternative `3` of the last position, after an arm with
      `1 | 2 | 3` there and the same elsewhere, is not useful;
    - ors(40) with one more position, a `bool`, last, at most 2 · k²
      calls (the branch of the unnamed value at each depth walks the
      positions left, about k²/2 calls in all): the rows
      `A(1 | 2 | 3, ..., 1 | 2 | 3, true)`, `A(_, ..., _, false)` and
      `A(_, ..., _, true)` leave no witness, and none of them is dead
      (no row of `_` alone stops the search early here);
    - two `u8` positions with distinct sub-patterns per alternative,
      `A(1 | 2, 5)` and `A(2, 6)`, where `1` and `2` are not alike: the
      witnesses are those of step 1, in the same order.
  - ui: every snapshot unchanged.
  - `tests/match_cost.rs` (`Stage::Typeck`): ors(32) with the arm
    written twice and a `_`
    arm reports one `ty::unreachable-pattern` labelled with the first arm;
    ors(32) followed by the same arm with `3 | 4` at its last position
    reports the alternative `3` as dead; the exhaustive three-row case
    above with 32 positions reports nothing.

## 3. fix(mir): test the arms of a match on an enum with payloads in order
- Status: done
- Implements: ADR 0042, all sections.
- Changes:
  - `src/mir/build.rs`: `decide`, `decision`, `Row`, `Test` and `Bind`
    give way to chains (ADR 0042 "The arms are tested in order"):
    - a `Switch` on `copy tmp.Tag` with a case per variant some arm
      names at the top, in the order first named; its default goes to the
      entry block of the first catch-all arm, or to a block with
      `Panic(NoVariant)`;
    - that entry block is built once, shared by the tag default and every
      chain: for a `let`, it copies the scrutinee's temporary into the
      arm's local, then jumps to the arm's block (replacing the
      `!tree && Binding` copy in `match_` for these `match`es);
    - per named variant, its chain: each top-level alternative naming the
      variant, in arm order, then the shared entry block of the first
      catch-all arm (ADR 0037: `_`, a `let`, or an or-pattern with a `_`
      alternative, as `Msg::Led(true) | _`), else a block with
      `Panic(NoVariant)`; each
      alternative is lowered by a recursive function taking the pattern,
      its position (`Vec<hir::PayloadStep>`, read with `position_place`),
      its type, and the block to go to on failure, leaving the current
      block where it passed; at the tag the variant was already switched
      on, so the alternative starts at its payload positions;
    - `_` emits nothing; `let` assigns its position to its local; a
      literal, constant or variant without payload is a `Switch` with one
      case to a new block and the failure block as default; a variant
      with payload switches on its tag (`PlaceElem::Tag` of its
      position), then lowers its payload positions; an or-pattern lowers
      each alternative with the next alternative's block as its failure,
      the last with the or-pattern's own failure, every passing
      alternative jumping to one join block, which becomes current;
      consecutive alternatives that are literals, constants or variants
      without payload are one `Switch` with a case per value to the join
      block;
    - when the alternative passes, a `Goto` to the arm's block, which
      holds the arm's expression once.
  - `src/mir/build.rs` doc comments of `match_` and the new functions
    describe the chains instead of the decision tree.
- Tests:
  - MIR snapshots, reviewed against ADR 0042: `mir_match_payloads.ers`,
    `mir_match_or_bindings.ers`, `mir_match_payload_errors.ers`,
    `eval_match_payload_no_variant.ers` (its diagnostics unchanged);
    LLVM IR snapshot `codegen_match_payloads.ers`, whose header comment
    is rewritten: chains instead of a tree, the `bool` with both values
    listed now ends its chain in the panic call.
  - new `tests/ui/mir_match_chains.ers` (`emit: mir`), for the ADR 0042
    cases not covered above: the tag default to a `_` arm and, without
    one, to the panic call; an or-pattern of values as one switch; an
    or-pattern of variants with payloads, as
    `Msg::SetMode(Mode::Run) | Msg::Pair(Mode::Run, _)` nested in a
    payload, both alternatives jumping to one block for the positions
    after it; a chain at a variant whose arms test only `bool` positions
    ending in the panic call; a `let` arm at the top reached from the tag
    default and from two chains through one entry block; an arm
    `Msg::Led(true) | _` ending the chain of another variant and taking
    the tag default; a `let` copied before a later test of its
    alternative fails.
  - `tests/match_cost.rs` (`Stage::Mir`): the MIR dumps of pairs(32)
    with a `_` arm, ors(32) with a `_` arm, and the three-deep or-pattern
    of variants of ADR 0042 "Conformance tests" have at most 4 × (p + v)
    blocks, counting `bbN:` lines, with p and v counted by the generator
    as that section defines them.
  - differential test (`tests/e2e/comptime_differential.{ers,c}`):
    functions over pairs(4) and ors(4), a nested or-pattern of variants
    with bindings, an arm `Msg::Led(true) | _`, and two overlapping
    alternatives binding one variable (`Pair(let a: u8, 7) |
    Pair(5, let a: u8)` on `Pair(5, 7)`, which binds 5), run at compile
    time and at run time on inputs that reach every arm, and that fail an
    arm at each of its positions.
  - e2e: every existing test passes, at both optimization levels, among
    them `command_decoder.ers`, `enum_payloads_no_variant.ers` and
    `enum_payloads_no_variant_tag.ers`.

## 4. test(e2e): matches whose code and checks grew exponentially
- Status: done
- Implements: the program on QEMU of M2.4c.
- Changes:
  - `tests/e2e/match_cost.ers`: pairs(16) with a `_` arm, ors(12) with
    two arms (the second with `4` at its last position) and a `_` arm,
    and an or-pattern of variants with payloads nested three deep that
    binds a value in each alternative; each `match` in a function; a
    `static` table of inputs, built with the variants, that reaches every
    arm, the `_` arms, and, for pairs(16), inputs with one `true` of each
    pair only; `main` prints, for each input, its index and the arm
    taken, through the `print` of M2.3b, then exits through the
    finisher; a `comptime` block asserts the arm taken for the same
    inputs.
- Tests: the program itself, with `expect-output` lines for every input
  and `expect-exit: 0`, at both optimization levels (`tests/e2e.rs`).
