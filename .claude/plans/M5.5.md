# Plan: M5.5 Methods

ADRs: 0113, 0114 (building on 0008, 0018, 0049 to 0051, 0058, 0079, 0094,
0097, 0102, 0105 to 0112)
Base: ba87a9c
Program on QEMU: the ring buffer and the UART drivers written as methods, on
both targets at `-O0` and `-O`:
- `tests/e2e/ring_methods.ers` (both targets): the ring of
  `ring_references.ers` with `impl Ring` in module `ring` (`Ring::new()`,
  `push(&mut self, b)`, `pop(&mut self)`, `count(&self)`, `is_full(&self)`)
  and methods that call others on their receiver (`fill(&mut self, text:
  &[u8])` calling `self.push(text[i])`, `drain(&mut self, n)`,
  `show(&self)`); fields read and written as `self.count` and
  `self.buf[at]`. `main` holds a `Ring` in a `let mut` and calls
  `buffer.fill(&b"references")`, `buffer.show()`, and lends `&mut buffer` to a
  free function `cycle(r: &mut Ring)` that calls `r.drain(3)` and
  `r.show()` through the reference. A last method by value,
  `into_count(self) -> usize`, consumes the ring. The output is that of
  `ring_references.ers`, with one more line for `into_count`.
- `tests/e2e/uart_methods_riscv32.ers`: the 16550 driver of
  `peripheral_references_riscv32.ers` as `impl Uart16550` (`ready(&self)`,
  `putc(&mut self, byte)` calling `self.ready()`, `write(&mut self, s:
  &[u8])` calling `self.putc(s[i])`), called `UART0.write(&b"...")`; and the
  PLIC's context cluster as `impl Context` (`set(&mut self, v)`, `get(&self)`),
  called `PLIC.ctx[0].set(3)` and `PLIC.ctx[1].get()`, with `Plic`'s own
  `set_second(&mut self, v)` calling `self.ctx[1].set(v)`.
- `tests/e2e/uart_methods_armv7m.ers`: the CMSDK UART driver of
  `peripheral_references_armv7m.ers` as `impl Cmsdk` (`init`, `ready`, `putc`,
  `write`), with a `let shared: &uart::Cmsdk = &UART;` and `shared.ready()`.
Out of scope:
- an `impl` outside its type's module, as for peripheral types generated by
  `erebos svd`: not yet scheduled; M5.6, which decides handles to
  peripherals, may need it (ADR 0113);
- two-phase borrows of the receiver (ADR 0114), volatile receivers, associated
  constants and types: not yet scheduled, each addable without breaking
  programs;
- functions of `Option`, `Result`, arrays and built-in types, and generic
  types: M6;
- getters returning a reference: references returned stay out of M5 (ADR
  0094; deferred ideas);
- `core` and the existing tests moved to methods: they keep their free
  functions (M5.7 measures what moves to references; methods are not
  required anywhere);
- methods in the generated programs of ADR 0068, which have only scalar
  types;
- `erebos svd`: it writes no function, so its output does not change.

Before step 1: the `docs(adr)` commit that accepts ADR 0113 and 0114 also sets
the status lines of the ADRs they amend, in their files and in the index
(`docs/adr/README.md`), keeping each existing parenthesis:
- 0008: `...; amended by 0024 (...), 0031 (...), 0105 (...), 0108 (...), 0114
  (`x.f()` borrows its receiver; fields and indexes through a reference)`;
  index `Accepted, amended by 0024, 0031, 0105, 0108, 0114`.
- 0049: `Accepted; amended by 0113 (a type before `::` names one of its
  functions; `use` of one rejected; `self`, `Self` and `impl` keywords)`;
  index `Accepted, amended by 0113`.
- 0050: `Accepted; amended by 0054 (...), 0059 (...), 0113 (the visibility of
  functions of a type)`; index `Accepted, amended by 0054, 0059, 0113`.
- 0051: `Accepted; amended by 0113 (the symbols of functions of a type)`;
  index `Accepted, amended by 0113`.
- 0102: `Accepted; amended by 0113 (a function of a type may be named `end`)`;
  index `Accepted, amended by 0113`.
- 0105: `Accepted; amended by 0108 (...), 0110 (...), 0114 (`r.f` and `r[i]`
  through a reference)`; index `Accepted, amended by 0108, 0110, 0114`.
The same commit holds this plan and the roadmap's edits written while
planning (M5.5's pending decisions settled; the items not yet scheduled).

Order: functions of a type (1) come first, called as `T::f(...)` only, so that
every later step has methods to call. Fields and indexes through a reference
(2) are independent of methods and come before the call syntax, so that the
tests of step 3 write method bodies as programs will (`self.count`). The call
`x.f()` (3) needs both. The programs (4) need 1 to 3. Step 1 spans the
lexer to the dumps; it stays one commit (review finding 13), since no part of
it has a program to test without the others: an `impl` that parses must be
lowered, and a function of a type must be callable to be tested. A diagnostic code gets,
in the step that adds it, its ui test, its snippet in `tests/rejected.rs`
(ADR 0069) and its row in the check tables of `docs/reference.md`; the prose
of the reference comes in the last step. Each step gains a `Decisions:` list
while it is built (`/build-step`), for the choices it makes that this plan and
the ADRs do not dictate.

## 1. feat: functions of a type
- Status: todo
- Implements: ADR 0113, all of it.
- Changes:
  - `src/syntax/token.rs`, `src/syntax/lexer.rs`: `impl`, `self` and `Self`
    keywords.
  - `src/syntax/ast.rs`: `Item::Impl` (the type's name, the functions, the
    span, with the attributes and `pub` kept so that lowering and the parser
    report them); `FnDecl` gains the receiver (`self`, `mut self`, `&self`,
    `&mut self`, with its span); `self` and `Self` are path segments named so,
    as `crate` and `super` are.
  - `src/syntax/parser.rs`: `impl Name { fns }` at item level; the receiver as

## 2. feat(ty): fields and indexes through a reference
- Status: todo
- Implements: ADR 0114, "Fields and indexes through a reference", and the
  changes to `ty::no-fields` and `ty::cannot-index` ("Diagnostic codes").
- Changes:
  - `src/ty/place.rs`: a field, an index and a range in an index whose base is
    of a reference type, any expression of one (ADR 0114, "Where a reference
    may be"), are checked as those of `(*base)`, with the place information
    the dereference gives (mutability, volatility, `via_ref`);
    `ty::no-fields` and `ty::cannot-index` arise for the referent's type, with
    a label saying it is reached through the reference, and their `(*r)` helps
    go. Raw pointers keep their errors and helps.
  - `src/ty/reference.rs`: the base of a field, an index and a range is a
    position of a reference, as the operand of `*` is.
  - `src/ty.rs`: `Tables` records the bases that are dereferenced so.
  - `src/mir/build.rs`: a `Deref` projection for such a base, so that the MIR
    of `r.f` is that of `(*r).f`.
  - `docs/reference.md`: the rows of `ty::no-fields` and `ty::cannot-index`
    lose the reference cases.
  - `docs/open-findings.md`: the M5.4b entry about the help of
    `ty::cannot-index` writing `(*r)[i]` for any reference is removed.
- Tests:
  - ui `reference_places.ers` (`--emit=typeck`) and its MIR twin
    `reference_places_mir.ers`: `r.f`, `r.f = v`, `r.f += v`, `r[i]`,
    `r[a..b]`, `&r.f`, `&mut r[i]`, `&mut r.buf[0..4]`, `len(&r.buf)`, a field
    of a field (`r.a.b`), through `&T`, `&mut T`, a reference to a slice
    (`s[i]`, `s[1..]`), a reference to a peripheral type (`u.thr = 1`) and a
    volatile reference; `(if c { &a } else { &b }).count`; a function writing
    `r.f` and one writing `(*r).f`, whose MIR is the same.
  - ui `reference_place_errors.ers`: `r.f = v` through a `&T`
    (`ty::write-through-const`); `r.missing` (`ty::unknown-field`); `r.f` with
    `r: &u32` (`ty::no-fields`, without the `(*r)` help); `r[i]` with `r:
    &u32` (`ty::cannot-index`); `p.f`, `p[i]` on a thin pointer to an array
    (pointer arithmetic, accepted, in the accepted file) and `s[i]` on a raw
    slice still as before.
  - ui `borrow_reference_places.ers`: the borrow check over `r.f`: `let a: &mut
    u8 = &mut r.buf[0];` then `r.count = 1` and a use of `a`
    (`analysis::borrow-conflict`, labels naming `(*r).buf[_]` or as the
    analysis names it).
  - existing snapshots that show `ty::no-fields` or `ty::cannot-index` for a
    reference (`reference_errors.ers`, `slice_reference_errors.ers`, and any
    the build finds) change; `tests/rejected.rs` snippets of those codes that
    use a reference are moved to a raw pointer or a scalar.

## 3. feat: method calls
- Status: todo
- Implements: ADR 0114, "The call `x.f(args)`", "Order, and the borrow
  check", "In MIR", the three new codes.
- Changes:
  - `src/syntax/ast.rs`, `src/syntax/parser.rs`: `ExprKind::MethodCall`
    (receiver, name, arguments) for `.name(` in postfix position; `.name`
    without `(` stays a field.
  - `src/hir/`: `ExprKind::MethodCall` (receiver, name and its span,
    arguments), lowered from the syntax; the walks of `hir/mod.rs` visit it.
  - `src/ty/`: a new `ty/method.rs`: the type of the receiver, one level
    through a reference, never through a raw pointer; the lookup among the
    functions of the type, with `ty::unknown-method`, `ty::not-a-method` and
    `ty::private-method`; the receiver made from the receiver place as
    `P`, `&P` or `&mut P`, checked by the code that checks those expressions
    (`ty/place.rs`), so that their codes come out unchanged; the volatile
    receiver help on `ty::mismatched-types`, the register help on
    `ty::register-address`, the `len(x)` help on `ty::unknown-method`; the
    base of a method call a position of a reference (`ty/reference.rs`); the
    arguments by the code of
    ordinary calls (`ty/expr.rs`), `ty::wrong-arg-count` without the
    receiver. `Tables` records the function and how the receiver is made. The
    other walks of `src/ty/` (reference positions, `linear.rs`, moves out of
    places, the dump) learn `MethodCall`.
  - `src/mir/build.rs`: the call with its receiver first: a `Ref` of the
    receiver place with the span of the receiver expression, or its value
    moved or copied, then the arguments, left to right.
  - `tests/rejected.rs`: snippets for the three new codes.
  - `docs/reference.md`: the check tables gain the three codes; the rows of
    `ty::mismatched-types` (the volatile receiver) and `ty::register-address`
    (a method on a register) their cases.
- Tests:
  - parser (ast) `parse_method_calls.ers`: `x.f()`, `x.f(a, b)`, `a.b.f()`,
    `x.f().g()`, `x.f()?`, `x.f()[i]`, and `x.f` still a field.
  - ui `method_calls.ers` (`--emit=typeck`) and its MIR twin
    `method_calls_mir.ers`: each receiver form called on a local, a `let mut`,
    a parameter, a field, an array element, a temporary (`&self` only and by
    value), a `&T` and a `&mut T` parameter, `(*r)`, a `static mut` inside
    `critical`, a peripheral and a cluster; `self.f()` inside methods of each
    receiver; a copy type by value through a reference; a linear value
    consumed by `t.wait()`; a bit-field struct's method by value on a
    register (one volatile read) and by each receiver on a local; a call on
    the value of an `if` of a reference type; the MIR of `r.push(1)` equal to
    that of
    `Ring::push(&mut *r, 1)` and of `x.push(1)` to `Ring::push(&mut x, 1)`.
  - ui `method_call_errors.ers`: `ty::unknown-method` (no such function; a
    field called, with the help; a type with no functions, `5.f()`; through a
    raw pointer, with the `(*p).f()` help; `s.len()` on a reference to a
    slice, with the `len(s)` help); `ty::not-a-method` with its help;
    `ty::private-method` from a sibling module, and a `pub` method called on a
    value of a type that is not reachable there (`m::make().f()`), in a
    directory program `method_calls_modules/`; a bit-field struct's `&self`
    method on a register (`ty::register-address`, with its help); `&mut self`

    `&T` and on a temporary (`ty::mut-borrow-of-immutable`); `self` by value

  - ui `method_call_borrows.ers`: `v.push(v.len())`, and a `&mut` receiver's

  - ui (LLVM IR) `codegen_method_calls.ers`: a method call and the explicit
