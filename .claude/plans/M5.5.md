the ADRs do not dictate.

  - Tokens `Impl`, `SelfValue` (`self`) and `SelfType` (`Self`); in a path
    they are first segments named so, through `keyword_segment`, as `crate`
    and `super` are, so `Self::new`, `Self { .. }`, `Self::Run` in a pattern

    expression and nowhere else (not in a type or a pattern); a `use` path may
    start with either and is judged when resolved.
  - `Parser::item` is split into `attrs_and_vis` and `item_after`, so that the
    functions of an `impl` take their attributes and `pub` as items do, and a
    non-function item inside one is parsed to its end and dropped after
    `parser::impl-item` (reported at its first token). A token that starts no
    item there is `parser::unexpected-token` ("expected `fn` or `}`"). Errors
    inside an `impl` recover as inside a module: the `}` at the depth of its
    items closes it (`module_depth`), and `impl` is a token where recovery
    stops.
  - `fn_decl` takes `in_impl`; the receiver is recognised by lookahead
    (`at_receiver`: `self`, `mut self`, `&self`, `&mut self`) as the first
    parameter only. Any receiver form elsewhere, or in a function outside an
    `impl`, is `parser::misplaced-self` ("can only be the first parameter of
    a function in an `impl`") and is parsed as a parameter `self: ()` so that
    the rest of the signature parses; the pipeline stops after the parser's
    errors. Every other form (`self: Ring`, `&volatile self`, `&&self`) is not
    a receiver and falls into the ordinary `parser::unexpected-token`.

    the parser through `misplaced_pub`, whose list gains `impl`) and the span.

    `params`; `hir::Fn::param_count` counts it, and `ReceiverKind` is
    re-exported by `hir`.

    `collect`, so its `FnId` follows the source like any function's (depth
    first, `core` last) and `bodies` needs no change; `Items::fn_owners`
    (`Owner::{Free, Type(Def), Skipped}`, parallel to `fns`) says what each is

    all items and `use`s are declared (the item may come after its `impl`).

- Decisions:
  - The base of `r.f`, `r[i]` and `r[a..b]` is typed by `place_info` as before
    and, when its type is `Ty::Ref`, replaced by `Checker::dereferenced`, which
    records the base's `ExprId` in `Tables::derefed` and returns the place
    `PlaceInfo::through_ref(r, base.span)`, the one `*base` gives. The type of
    the base expression itself stays the reference's (`expr_types` is
    unchanged), so every consumer that asks "what is the base" goes through
    `Tables::base_ty` (the referent when the base is dereferenced) or
    `Tables::is_derefed`. The marker is on the base, not on the parent, because
    each expression node occurs once in the tree and MIR building reaches the
    base through `place_then(base)`.
  - The base is not checked again as a value, as `*` does with its operand:
    the only places of a reference type are locals (a static of a reference
    type is `{error}`, a reference in memory is `ty::reference-position`), and
    reading a local reference reports nothing, so `place_info` has already done
    what `check` would.
  - `ty::no-fields` moves to `Checker::no_fields`, shared by `field` and the
    reference case; for a reference it is reported on the referent's type

- Decisions:
  - The syntax is `ast::ExprKind::MethodCall(base, name, args)`, made in
    `Parser::postfix` when the name after a `.` is followed by `(`; `hir`
    lowers it to `ExprKind::MethodCall { receiver, name, name_span, args }`
    with no resolution (the type decides, ADR 0114). `Expr::walk` visits the
    receiver, then the arguments.
  - Type checking lives in `ty/method.rs` (`Checker::method_call`). It types
    the receiver with `Checker::base`, the function that gives the base of a
    field its place, and when the type is a reference calls `dereferenced`, so
    the receiver is marked in `Tables::derefed` as the base of `r.f` is and
    MIR building reuses `place_then`'s `Deref`. The two are `pub(super)` now.
    `Tables::methods` (`ExprId -> FnId`, read by `Tables::method`) is the only
    new table: the receiver's form is the callee's own (`Fn.owner.receiver`).
    Nothing is recorded when the lookup fails (no function, no receiver,
    not visible); it is recorded before the receiver and the arguments are
    checked, so an error in either leaves it there (harmless: the pipeline
    stops before MIR). None either for a receiver of type `!` (MIR building
    evaluates the receiver and stops).
  - The receiver is checked by the code of the expression it stands for:
    `Checker::borrow` is split in two, `borrow` (finds the place) and
    `borrow_place` (the checks: `ty::bit-field-address`, `ty::register-address`
    by `has_address`, `ty::mut-borrow-of-immutable` for each `Immutable`,
    `ty::packed-field-address`), and `&self`/`&mut self` call `borrow_place`
    with the receiver place, a temporary's included (`PlaceInfo::temporary`).
    `self` and `mut self` call `access` for a read and report
    `ty::move-out-of-place` through `unmovable`, or `Unmovable::Reference` when
    the receiver is a reference, as `*r` would. A volatile place keeps what the
    read gives (one volatile access, or `ty::volatile-aggregate`). A `self`
    receiver of a peripheral type reports nothing at the call: the parameter's
    type was reported as `ty::peripheral-by-value`.
  - `ty::register-address` for a method on a register is reported by
    `register_receiver`, before `borrow_place`, with the title of the code's
    other cases and its own label and help; a bit field of a register is left
    to `borrow_place`, which reports `ty::bit-field-address` as for `&`. The
    volatile case (`volatile_receiver`) is `ty::mismatched-types` "expected
    `&Ring`, found `&volatile Ring`", from the reference `borrow_place` makes.
  - The lookup takes the first function of the type's `fns` named so (a
    duplicate was reported by name resolution). Order of the checks: no function
    (`ty::unknown-method`), no receiver (`ty::not-a-method`), not visible

    `pub` function needs the type reachable from the module of the call
    (`fn_visible`), which only a call on a value can break.

    struct, an enum or a peripheral type has functions" (a type that cannot),
    the list of its methods, or that it has none. `ty::not-a-method` labels the
    call and the declaration and writes `T::f(...)` with the function's path.
    `ty::private-method` names the function by path, labels the call and the
    declaration; for a private function the help is that of `resolve::private-item`

    here" and a help that no path in the calling module names the type.
  - Arguments go through `Checker::call_args` (the loop of `call`, now shared)

    call the arguments are checked against `{error}` (`unchecked_args`), so
    they are still typed and their own errors reported.

    arguments that are not simple is `operands`' own rule, applied to the
    receiver first, so the MIR of a method call is that of the explicit call

  - The dump labels a call `method <path> (<receiver form>)`, e.g. `method

  - `reference.rs` changes only its module comment, as step 2's decision says
