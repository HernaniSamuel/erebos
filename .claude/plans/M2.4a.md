# Plan: M2.4a Enums and `match`

ADRs: 0035, 0036, 0037
Base: 064dd5e8f0c0c62d67193dd43cf6c04fd0a09316
Program on QEMU: a state machine (`tests/e2e/state_machine.ers`, step 4).
Out of scope:
- enum variants with payloads, their layout and ABI, patterns nested in
  payloads, `let` inside or-patterns, and payloads of type `!` (M2.4b);
- `Option(T)`, `Result(T, E)` and `?` (M2.5);
- a `PanicReason` for "enum value is no variant", and `::` paths through
  modules (M2.6);
- range patterns and guards (not scheduled).

Before step 1: the `docs(adr)` commit that accepts ADR 0035 to 0037 also
sets the status lines of the ADRs they amend, in the files as
`Accepted; amended by NNNN (what changed)` and in the index
(`docs/adr/README.md`) in its style, `Accepted, amended by NNNN`:
- ADR 0023: amended by 0035 (an enum is a scalar);
- ADR 0032: amended by 0035 (enum variants are known), 0037 (arms a
  `match` never takes).

## 1. feat: enum items with explicit discriminants
- Status: done
- Implements: ADR 0035, all sections ("Declaration", "Naming a variant",
  "Operations", "Layout and calls"), except `match`.
- Changes:
  - `src/syntax/{token,lexer,ast,parser}.rs`: keyword `enum`; token `::`;
    enum items with `: Type` and variants `Name = expr`, separated by
    commas, trailing comma allowed, attributes before them;
    `parser::enum-without-type` and `parser::variant-without-value`; the
    path expression `Enum::Variant` (a primary expression).
  - `src/hir/{mod,lower}.rs`: an `EnumId` per enum in the single item
    namespace (`resolve::duplicate-item` with structs, constants, ...);
    `EnumDef` with its integer type and its variants; each variant's value
    lowered as a compile-time body (`Comptime::Discriminant(EnumId,
    index)`, whose return type is the enum's integer type, unlike
    `Comptime::Value`, which is `usize`); `hir::Ty::Enum`;
    `ExprKind::Variant(EnumId, index)`; `resolve::enum-type` for a type
    after `:` that is not an integer type; `resolve::duplicate-variant`,
    `resolve::empty-enum`, `resolve::unknown-variant`,
    `resolve::not-an-enum`, `resolve::unknown-type` for an unknown name
    before `::`, which is looked up among items only (locals ignored, as
    for struct literals); `Mode` alone reports what a struct name alone
    does; `#[packed]` and `#[align]` on an enum are
    `resolve::misplaced-attribute`.
  - `src/query.rs`: each discriminant's value on demand, with `ty::cycle`;
    `check_all` evaluates every discriminant, reports a failed one once
    and `ty::duplicate-discriminant` naming both variants, and records
    the enum as erroneous for step 3's checks; the layout of an enum is
    its integer type's; `--emit=typeck` and `--emit=mir` list every enum
    with its integer type and variant values, as they list struct layouts.
  - `src/ty.rs`: a variant has type `Enum` and is not a place
    (`ty::not-a-place` under `&raw`, `ty::not-assignable`); `==` and `!=`
    between values of one enum type, a literal operand checked against
    the enum (`ty::mismatched-types`, help suggesting a variant or
    `m as u8 == 3`); every other operator on enums is
    `ty::invalid-operand`; `as` from an enum to any integer type, nothing
    to an enum (`ty::invalid-cast`, help suggesting a `match` from the
    integer; a literal operand, `3 as Mode`, gives only this error), not
    to `bool` or a pointer; `x.f` and `offset_of` on an enum are
    `ty::no-fields`; enums are scalars for volatile accesses, so a `u64`
    or `i64` enum through a volatile pointer is `ty::volatile-too-wide`;
    enums are valid constant, static, field, element, parameter and
    return types.
  - `src/mir/{mod,build}.rs`: an enum is lowered to its integer type
    (`mir::Ty::Int`); a variant is `Const::Int` of its value; `as` from an
    enum is an integer cast from its integer type. MIR never sees enums,
    so `src/eval.rs` and `src/codegen/` need no change for this step, and
    a parameter or return value is extended by its integer's signedness
    as any integer is (ADR 0006).
  - `src/mir/build/known.rs`: a variant is known, with its value (amends
    ADR 0032), and so is `as` from one.
  - `tests/fuzz.rs`: snippets `enum E: u8 { A = 0 }`, `E::A`, `::`.
- Tests:
  - ui (parse): `enum E { A = 0 }`, `enum E: u8 { A }`, a trailing comma,
    attributes before an enum.
  - ui (resolve): `resolve::duplicate-variant`, `resolve::empty-enum`,
    `resolve::unknown-variant`, `resolve::not-an-enum` (a struct before
    `::`), an unknown name before `::`, a local named like the enum (does
    not hide it), `Mode` alone, an enum and a constant with one name
    (`resolve::duplicate-item`), `#[packed]` and `#[align(4)]` on an enum,
    `enum E: bool` and `enum E: Other` (`resolve::enum-type`).
  - ui (typeck): duplicate values written as literals and computed from a
    constant (`ty::duplicate-discriminant`); `= 1 / 0` (reported once);
    `= 300` in a `u8` enum and `= -1` in a `u8` enum (reported as
    `let x: u8 = 300;` and `let x: u8 = -1;` are today); a cycle between
    two variants' values (`ty::cycle`); `x as Mode` from a `u8` variable,
    `3 as Mode` (exactly one error), `Mode::Run as bool`,
    `Mode::Run as Other`, `Mode::Run as Mode` (`ty::invalid-cast`);
    `m == 3` (`ty::mismatched-types`); `Mode::Run < Mode::Off` and
    `Mode::Run + Mode::Off` (`ty::invalid-operand`); `&raw const
    Mode::Run`; `Mode::Run = x`; `m.f` and `offset_of(Mode, f)`; a `u64`
    enum read through a volatile pointer (`ty::volatile-too-wide`);
    accepted: `==`, `!=`, `as` to every integer type, `[u8; Mode::Run as
    usize]`, enums as fields, array elements, parameters, return values,
    constants and statics, `size_of(Mode)` and `align_of(Mode)`.
  - ui (MIR): `x >> (Mode::Run as u32)` with an out-of-range value is
    `ty::shift-out-of-range` (the variant is known).
  - LLVM IR snapshot (`codegen_enums.ers`): a variant as an immediate,
    `==` as `icmp`, an `i8` enum parameter `signext` and a `u8` one
    `zeroext`, a volatile store of a `u16` enum as one 16-bit store, a
    `static mut` of value 0 in `.bss`.
  - layout against clang: `tests/layout/structs.{ers,h}` gain a struct
    with enum fields on `u8`, `u16` and `i32`, whose C twin uses C23
    `enum E : uint8_t` and friends; `tests/c_layout.rs` compiles the
    header with `-std=c23` instead of `-std=c11`, and reads enums from the
    `--emit=typeck` dump if the struct lines alone do not suffice.
  - e2e (`tests/e2e/enums_c.{ers,c}`): passes a `u8` enum and an `i8`
    enum holding `-1` to a C function declared with C23 enums, gets them
    back, and C calls an Erebos function taking and returning one, at
    both optimization levels. The helper is compiled with the flags
    `tests/e2e.rs` uses for every C helper (`-std=c11 -Wall -Werror`),
    under which clang accepts C23 enum types; if that ever changes, the
    harness moves to `-std=c23` for all helpers.
  - differential test (`comptime_differential.{ers,c}`): `as` from enums
    on `u8`, `i8`, `u16` and `i32` to wider and narrower integers, and
    `==` on enums, at compile time and at run time; the run-time values
    come from new C identities on enums (`opaque_mode`,
    `opaque_level`, ...), so LLVM cannot fold them.

## 2. feat: match on integers and bool
- Status: done
- Implements: ADR 0037, "Syntax", "What can be matched" (integers and
  `bool`; until step 3 an enum scrutinee is `ty::match-type`), "Patterns"
  (all but variants), "Choosing an arm", "Typing", "Exhaustiveness"
  (integers and `bool`), "Dead arms", "When the checks run", "Values known
  at compile time", "Code generation".
- Changes:
  - `src/syntax/{token,lexer,ast,parser}.rs`: keyword `match`; tokens
    `=>` and `_` (no longer an identifier: `let _: u32`, `const _`, `_`
    as a parameter or expression are errors, `parser::unexpected-token`
    with a help saying `_` is the wildcard pattern); the `match`
    expression, block-like, its scrutinee parsed without struct literals
    as for `if`; patterns: `_`, `let name: T`, `let mut name: T`
    (`parser::let-without-type` without the type), integer and byte
    literals, `-` and an integer literal, `true`, `false`, a bare name,
    and `|` between alternatives; commas between arms, and an arm whose
    expression starts with a block-like expression ends with it, as
    statements do (`parser.rs`, the rule that `if c { } - 1` is not a
    subtraction).
  - `src/hir/{mod,lower}.rs`: `ExprKind::Match { scrutinee, arms }`, a
    `Pattern` type; a bare name resolves as an expression would: to a
    constant (kept), else `resolve::not-a-constant` (a local, parameter,
    static, function, struct or enum) or `resolve::unknown-name`; `let`
    declares a local of its written type, scoped to its arm; `let` as an
    alternative is `resolve::binding-in-or-pattern`; `Expr::walk` visits
    the scrutinee and the arms.
  - `src/ty.rs`: the scrutinee is checked with no expected type (so
    `match 3` is `ty::untyped-literal`) and must be an integer, `bool` or
    enum (`ty::match-type`); integer literals in patterns are checked
    against its type, byte literals are `u8`; a constant pattern and a
    `let` must have its type (`ty::mismatched-types`); arms typed as `if`
    branches are, with `!` arms fitting any type. Exhaustiveness and dead
    arms, as part of type checking: every pattern is a set of values of
    the scrutinee's integer (`bool` is {0, 1}), constants contributing
    their evaluated values, whatever they are; `ty::non-exhaustive-match`
    lists what is missing (`true`, `false`, or "a `_` or `let` arm" for
    integers); `ty::unreachable-pattern` is reported once per dead arm,
    pointing at the first earlier arm that covers it alone if one does,
    and once per dead alternative when only some alternatives of an arm
    are dead. A constant that fails to evaluate stops both checks for that
    `match`; a constant whose evaluation needs the function being checked
    is a `ty::cycle`.
  - `src/mir/{mod,build}.rs`: `Terminator::Switch { discr: Operand,
    cases: &'static [(u64, BasicBlock)], otherwise: BasicBlock }`,
    leaked like projections so terminators stay `Copy`, each case the
    value's bits masked to the scrutinee's width, as `Const::Int` holds
    them; MIR building evaluates the scrutinee once into a temporary (one
    read, ADR 0018), lowers each arm's patterns to cases (or to
    `otherwise` for a catch-all), copies the scrutinee into a `let`
    binding's local, and makes `otherwise` `Unreachable` when every value
    is listed. The MIR dump prints the switch.
  - `src/mir/build/known.rs`: with a known scrutinee, only the arm it
    selects is checked by ADR 0032's rules, and none when no arm matches
    (amends ADR 0032).
  - `src/eval.rs`: `Switch` jumps to the case equal to the value, or
    `otherwise`; one step, as any terminator.
  - `src/codegen/mod.rs`: `Switch` as an LLVM `switch`, its case values
    built from the masked bits at the scrutinee's width.
  - `tests/fuzz.rs`: snippets `match x { _ => {} }`, `=>`,
    `let n: u8 =>`, `_`.
- Tests:
  - ui (parse): arms with and without commas after blocks, a trailing
    comma, `0 => {}` followed by `-1 => {}` (two arms), `match` as a
    statement without `;`, a struct literal as scrutinee with and without
    parentheses, `let` without a name, `let n =>` without a type
    (`parser::let-without-type`), a missing `=>`, `let _: u32`,
    `const _: u32`, `_` as an expression.
  - ui (resolve): a bare name naming a static, a function, a struct, an
    enum, a local variable that shadows a constant (help:
    `let x: T => if x == NAME`), and nothing; `1 | let n: u8`; a `let n`
    arm whose `n` shadows a constant in that arm only, the constant
    usable in the next arm.
  - ui (typeck): scrutinees of type pointer, slice, struct, array, `()`,
    `!` and, until step 3, an enum (`ty::match-type`); `match 3`
    (`ty::untyped-literal`); a `u16` constant and `let n: u16` against a
    `u8` scrutinee; `300` against a `u8`; `-1` against a `u8`
    (`ty::negate-unsigned`); `b'q'` against a `u32`; `true` against an
    integer, `0` against a `bool`; non-exhaustive on `bool` (missing
    `false`) and on an integer; dead arms: `0` twice, `0` and a constant
    `ZERO`, an arm after `let n: u8`, `_ | 3`, `1 | 1`, `1 | 2` after `1`
    and `2` (one error for the arm), `_` after `true` and `false`; a
    constant that fails to evaluate used as a pattern (reported once); a
    cycle (`const C: u8 = f(0);` with `f` matching on `C`); accepted: all
    256 `u8` values without `_`, `let mut n: u8` assigned in its arm, arms
    of type `!` mixed with `u32` arms, a `match` whose arms are all `!`
    used as `!`, a `match` statement of type `()`, arms converting
    `*mut T` to an expected `*const T` and `*const [u8; 4]` to an
    expected `*const [u8]`, `-1` and `-128` against an `i8`, a byte
    literal against a `u8`.
  - ui (MIR): a `match` on a known constant with `1 / 0` in an arm it
    never takes (no error) and in the arm it takes
    (`ty::division-by-zero`); a function with a non-exhaustive `match`
    and a known `1 / 0` reports only the `match`; MIR snapshot of a switch
    with a catch-all, with `let`, and with every `bool` value listed
    (`otherwise` unreachable).
  - LLVM IR snapshot: the `switch` on a `u8`, an `i8` with negative cases
    and a `u64`; `match (*p).status` through a volatile pointer as one
    volatile load.
  - ui (eval): `match` at compile time on integers and `bool`, with
    constants, or-patterns and `let`.
  - differential test: functions matching `u8`, `i8`, `i32`, `u64` and
    `i64` values with literals (negative ones, `-128` on `i8`, values
    above `u32::MAX` on `u64`), constants, or-patterns and `let`, at
    compile time and at run time.
  - e2e (`tests/e2e/match.ers`): matches on integers and `bool`; the
    scrutinee runs once when it has a side effect (a counter); arms run in
    order, the first match wins, at both optimization levels.

## 3. feat: match on enums, with values that are no variant
- Status: done
- Implements: ADR 0037, "Patterns" (variants), "Exhaustiveness" (enums),
  "Dead arms" (enums); ADR 0036, all sections.
- Changes:
  - `src/syntax/parser.rs`, `src/hir/{mod,lower}.rs`: the pattern
    `Enum::Variant`, resolved as in expressions (`resolve::unknown-variant`,
    `resolve::not-an-enum`).
  - `src/ty.rs`: enum scrutinees accepted (the step 2 snapshot of
    `ty::match-type` on an enum changes); variant patterns against an enum
    scrutinee (a variant of another enum is `ty::mismatched-types`);
    exhaustiveness requires every variant or a catch-all, and
    `ty::non-exhaustive-match` lists the missing variants by name, in
    declaration order; for dead arms the values of an enum are all those
    of its integer type, so `_` after every variant is accepted while
    values that are no variant remain; a constant of the enum's type
    covers its value, a variant or not; a `match` on an enum recorded as
    erroneous in step 1 (a failed or duplicate value) skips both checks.
  - `src/mir/build.rs`: a value repeated across arms, possible only in
    such a `match` (two variants with one value), becomes one case, the
    first arm's, so a `Switch` never holds a value twice and arms keep
    their order (ADR 0037, "Choosing an arm").
  - `src/mir/{mod,build}.rs`: `PanicCause::NoVariant` ("enum value is no
    variant"); a `match` on an enum without a catch-all gets `otherwise`
    a block ending in `Panic(NoVariant)`, never `Unreachable`.
  - `src/eval.rs`: reaching that panic is `eval::panic` with the cause,
    like the other causes.
  - `src/codegen/mod.rs`: no range metadata or `assume` on loads of enums
    (none exist today; the IR snapshot pins it), the default of such a
    switch calls the panic function.
- Tests:
  - ui (typeck): non-exhaustive on an enum listing two missing variants
    in declaration order; a variant of another enum as a pattern; dead
    arms: a variant twice, a variant after a constant holding it;
    a `match` on an enum with a duplicate value reports only
    `ty::duplicate-discriminant`, also when a `comptime` block calls the
    function holding it (the build stops at the error, the evaluation
    takes the first arm when the `match` has a catch-all and fails silently without one, and nothing panics in the compiler); accepted: every variant without `_`,
    every variant and then `_`, a constant of type `Mode` holding a value
    that is no variant as a pattern next to every variant.
  - ui (eval): a compile-time `match` without a catch-all on a value that
    is no variant, read from a `static` of bytes through a cast pointer
    (`eval::panic` with the cause); the same `match` with `_` evaluates.
  - LLVM IR snapshot: a load of an enum without range metadata; the switch
    of a `match` without a catch-all whose default calls the panic
    function.
  - e2e (`tests/e2e/enum_values.ers`): bytes 0, 1, 3, 2 and 7 read through
    a `*const Mode` and a `*const volatile Mode`; a `match` with `_` sends
    2 and 7 there; `==` and `as` give their integers.
  - e2e (`tests/e2e/enum_no_variant.ers`): a `match` listing every variant
    on the byte 7 calls the panic function, observed through the exit
    code, at both optimization levels.
  - differential test: a `match` on enums at compile time and at run
    time, including an `i8` enum with a negative variant and a `_` arm
    reached by a value that is no variant.

## 4. test(e2e): a state machine
- Status: done
- Implements: the milestone program of M2.4a.
- Changes: `tests/e2e/state_machine.ers`: a state machine over an
  `enum State: u8` driven by a byte string of events (an `enum Event: u8`
  decoded from bytes with a `match` that has a `_` arm for unknown
  bytes), printing each transition over the UART through the `print` of
  M2.3b; the transition is a pure function, a `match` on the state nested
  with a `match` on the event; a `comptime` block runs that function over
  a fixed input and asserts the final state (it reads no `static mut` and
  prints nothing, which compile time forbids); a constant pattern (a
  command code) and an or-pattern appear; the `static mut` holding the
  state at run time starts at a variant whose value is 0 (in `.bss`).
- Tests: the program itself, with its expected output and exit code, at
  both optimization levels.
