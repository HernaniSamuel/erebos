Order: references go through every layer at once (1), since a reference that
type checks must reach MIR, evaluation and code generation, and none of them
can be built without the others' types. The positions a reference may not
take, and what may not be borrowed yet (2), are type errors before MIR gains
R1, which assumes them. The conversion `&mut T` to `&T` and lending at calls
(3) need the MIR borrow of step 1. The analysis (4) reads the borrows and
reborrows of steps 1 and 3. A diagnostic code gets, in the step that adds it,
its snippet in the catalog of ADR 0069 (`tests/rejected.rs`) and its row in
the check tables of `docs/reference.md`; the prose of the reference comes in
the last step. Each step gains a `Decisions:` list while it is built
(`/build-step`), for the choices it makes that this plan and the ADRs do not
dictate.

Between step 1 and step 4, references type check and run without the borrow
check, and between step 1 and step 3 a `&mut` passed twice is a use after a
move; the branch is merged only once step 7 is done.

## 2. feat(ty): where references may be, and what is not borrowed yet
- Status: done
- Implements: ADR 0105, "Where a reference may be", "What may be borrowed"
  (the two errors left to M5.4c); ADR 0107, R1.
- Changes:
  - `src/ty/` (a new `ty/reference.rs`, as `ty/linear.rs`):
    `ty::reference-position` at each written type that holds a reference
    where ADR 0105 forbids it (fields, payload values, array and slice
    elements, type arguments, `size_of` and the other layout queries, return
    types, statics, `extern static`s, constants, `comptime` parameters and
    `comptime T: type` arguments, pointees, referents), at a `mut` parameter
    and a `let mut` of a reference type; at the innermost expression whose
    type holds a reference below its top (an array literal of references,
    `&e`, `&mut e` and `&raw` of an `e` of a reference type), not again at
    the expressions above it; at a `critical` block's value and a `comptime`
    expression of a reference type; once per written type, at the outermost
    reference, as `ty::linear-array` is reported. The written types need spans: the mechanism of
    `Hir::array_types` (M5.3 step 2) or a list of its own.
  - `src/ty/place.rs`: `ty::reference-to-static-mut` for a borrow of a
    `static mut` or `extern static mut`, `ty::reference-to-volatile` for one
    through a volatile pointer or of a peripheral or a cluster.
  - `src/mir/validate.rs`: R1, through the types of locals, statics and
    returns, each definition once.
  - What step 1 lets through to MIR (a struct with a reference field, a static
    of one) must stop before MIR: `Queries::lacks_layout` (as M5.3 step 3 did
    for linear arrays), so that R1 never meets a type type checking rejected.
- Tests:
  - ui: `reference_position.ers` (every written position, each with its
    label; `&&u32`; `Option(&u32)`; a generic `comptime T: type` given
    `&u32`); `reference_position_bindings.ers` (`let mut r: &u32`, `mut r:
    &u32`); `reference_position_values.ers` (`[&a, &b]`, `&r`, `&mut r`,
    `&&x`, `*&r`, `&(if c { &a } else { &b })`, `&raw const r`,
    `(&raw const r) as *const u8`,
    each reported once, `critical { &x }`, `comptime &X`), none reaching the
    validator; `reference_not_yet.ers` (`&S` and `&mut S` of a `static
    mut`, of an `extern static mut`, `&*v` with `v: *mut volatile u32`, `&UART0`,
    `&PLIC.ctx[1]`); `references_accepted.ers` (`--emit=mir`: a reference in
    every position ADR 0105 allows, an `if`, a `match`, a block and a
    `loop` with `break &x` whose value is one, as an argument and an
    initializer, an `extern fn`, a `#[export]` and a
    `#[naked]` function taking references).
  - unit tests of the validator: R1 for a field, a payload value, a pointee,
    a static's type and a return type.
  - `tests/rejected.rs`: snippets for the three codes; `docs/reference.md`:
    their rows.
- Decisions:
  - Written types (`ty::reference-position`) are recorded by HIR lowering, in
    a list of its own, `Hir::reference_types` (`ReferenceType { span, ty,
    position }`, `ReferencePosition`), not by walking the AST later: the
    lowerer already holds the position of every type it lowers (`memory_ty`
    and `ty` take it), so a forbidden position is known where the reference
    is met, with no second walk and no list of spans to keep aligned with
    `Hir::array_types`. The list is left out of the HIR dump, as
    `array_types` is, and holds `core`'s too (it has no reference), so
    `CoreStart` has no index for it. `ReferencePosition` is `Memory(
    NeverPosition)`, `Return`, `MutParameter` and `MutVariable`; the positions
    allowed (`Variable`, `Parameter`) and the target of a cast, which is
    `ty::invalid-cast`'s, are not recorded.
  - "Once per written type, at the outermost reference": a reference in a
    forbidden position is recorded and the types inside it are not
    (`Lowerer::reference_reported`), so `&&u32` as a field is one error at the
    whole, `Option(&&u32)` one, while `&&u32` as a parameter is one error at the
    inner `&u32` (the outer is allowed, the inner is a referent), and `[[&u32;
    2]; 2]` one at the `&u32`. A reference that lowered to `{error}` (`&!`,
    `&[T]`) is not recorded, since its own error was reported. A `mut`
    binding is recorded through `Lowerer::binding_ty`, which parameters,
    `let`s and pattern bindings use: when the type written is a reference and
    the binding `mut`, `mut_binding` gives the position to the first
    reference met, which is the outermost. The span is the type's, not the
    `mut`'s; the help says to declare a new `let`.
  - Messages: `a reference cannot be {position}`, the position named as the
    other codes name theirs (`memory_position`: "the type of a field", "an
    array element", "a payload type", "a type argument", "the operand of
    `size_of`", "a return type", ...), with the new "the type of a `mut`
    parameter" and "the type of a `mut` variable"; the label is "`{ty}` is a
    reference". The help is one of five: statics and constants (a value
    computed at compile time is never a reference), layout queries (ask for
    `*const T`), a `mut` binding (bound once; declare a new `let`), a return
    type (no function returns one), and the general one (a reference is held
    by a parameter or a `let`; keep an address as a raw pointer).
  - There are no `comptime` parameters and no `comptime T: type` arguments in
    the language as built (ADR 0027 only sketches them), so those two
    positions of ADR 0105 have no code and no test; `Option(&u32)` and
    `size_of(&u32)` are the type arguments there are. A `comptime` parameter
    will need to say what it does with references when it is added.
  - Expressions (`Checker::report_made_references`, in `ty/reference.rs`, run
    by `check_fn` after `report_made_arrays`): an `Array` or `Repeat` whose
    element type is a reference; a `Ref` and an `AddrOf` whose operand has a
    reference type; a `Critical` and a `Comptime` expression of a reference
    type. Each rule reads only the expression and its operand's type, so the
    expressions above one reported are not reported, and `[[&a], [&b]]` is
    reported at its two inner arrays. An expression of type `{error}` is
    skipped (`&mut q` with `q` not `mut` is `ty::mut-borrow-of-immutable`,
    and cannot be anything else: a `mut` binding of a reference is itself
    rejected, so `&mut` of a reference is always an error already). The
    `critical` error is labeled at the block's tail (at the whole expression
    if it has none), the `comptime` one at the expression; their helps are
    their own. A type written and an expression that makes it are both
    reported (`let a: [&u32; 2] = [&x, &y];` has two errors, at two places),
    unlike `ty::linear-array`, which dedupes per type: ADR 0105 asks no such
    thing, and each place is one to change.
  - What stops before MIR, so that rule R1 never meets a type type checking
    rejected: `Queries::lacks_layout` counts a reference below the top of a
    type as lacking one (`lacks_layout_in`, used for a pointee, referent,
    element, field and payload value; the top of the type asked about is
    fine), which also catches `Option(&u32)` through its normalized payload;
    `needs_missing_layout` also leaves out a function that returns a
    reference, has a `mut` local of a reference type, or asks the layout of a
    reference with `size_of`, `align_of` or `offset_of` (building those would
    not break R1, but a layout query of a reference never gives a value). A
    constant or a static of a reference type is itself left out the same way
    (its function has the type as its return type), and a use of one has type
    `{error}` (`ExprKind::Const` in `ty.rs`, the `Static` place in
    `place.rs`), so that uses report nothing more and no body names a static
    of a reference type. The `unreachable!` of `Builder::const_operand` for
    `Ty::Ref` keeps its place and is now unreachable: a constant of a
    reference type has no value, its body being left out.
  - R1 in the validator (`Checker::reference_positions` for the locals,
    `reference_static` for the statics, `references_below` and
    `reference_part` for the walk): `_0` is not a reference
    (`Local::RETURN`); no local type reaches a reference, through arrays,
    slices, fields, payload values, pointees and referents, with the structs
    and enums looked into once per body (and once per program for the statics,
    a set of its own so that L3's and R1's walks do not hide each other); a
    static's type is not a reference, and when it is, that is the one
    violation, whatever the reference reaches. A reference found is not
    looked into further, and each one met is a violation (a struct with two
    reference fields is two). Tests: `r1_a_reference_is_only_the_type_of_a_local`
    (referent, element, slice behind a pointer, pointee, field, payload value,
    each definition once), `r1_no_body_returns_a_reference` (a reference, and a
    struct holding one), `r1_no_static_is_a_reference_or_reaches_one`.
  - `ty::reference-to-static-mut` and `ty::reference-to-volatile` are
    `Checker::not_borrowed_yet`, called by `borrow` after `has_address` and
    the slice check, before `ty::mut-borrow-of-immutable` (the more basic
    fault first). It must know that the path starts at a `static mut` with no
    pointer or reference between, so `PlaceInfo` gains `static_mut:
    Option<StaticId>`, set by `Static` and kept by fields and indexes, reset
    by `*` (a place through a pointer read from a `static mut` is the
    program's word, as any pointer is). The volatile case reads `PlaceInfo::via`
    (the last pointer on the path) and its `volatile` flag; a peripheral or a
    cluster is a place of type `Ty::Peripheral`, which `borrow` used to
    report as `ty::peripheral-by-value` (`whole_peripheral`, "borrowed as a
    whole"): that is now `ty::reference-to-volatile`, so the snapshot of
    `reference_errors.ers` changed in that error only. A register is
    `ty::register-address` first, as before. `static mut` is reported for any
    `&` or `&mut` of the static or of a field or element of it; `&raw` is
    unchanged. The help says to use `&raw` inside `critical` (ADR 0078, 0093)
    for the static, a pointer for a device, and the pointer itself for a
    volatile place.
  - The interim holes of step 1, each with the test that fails without its
    fix (checked by taking the fix out and running the compiler on the file):
    `&*v` with `v: *mut volatile T` is a validator violation (T5) at MIR
    building without the volatile branch of `not_borrowed_yet`
    (`reference_not_yet.ers`); `static mut` is the same file's snapshot (it
    passed type checking); a struct, `Option(&u32)` or a parameter that holds
    a reference below its top is R1 without `lacks_layout_in`
    (`reference_position.ers`, `argument`, `hold`); `fn pick() -> &u32` and
    the constant `KEPT` are R1 on `_0` without the return check of
    `needs_missing_layout` (`pick`, `KEPT`); `*HELD` is R1 (`*const &u32` in a
    local) without the `Static` guard (`read_static`); and `&KEPT` gives a
    second diagnostic without the `Const` guard (`read_constant`). The
    `const R: &u32 = &S;` of the plan panicked the compiler at
    `Builder::const_operand`: with R1 in place that panic is reached first as
    an R1 violation of the constant's own body when the return check is
    removed, and with the check not at all, the constant having no value;
    `read_constant` is the test.
  - Tests: `reference_position.ers` (`--emit=mir`, so that a missing guard
    panics; every position of the list apart from the two `comptime` ones,
    and the uses that would reach MIR), `reference_position_bindings.ers`
    (`mut` parameter, `let mut`, `&&u32`, and a pattern binding, which also
    has the match's own mismatch since a payload is never a reference),
    `reference_position_values.ers` (the arrays, `&r`, `&mut q`, `&&a`,
    `*&r`, `&(if ..)`, `&raw const r`, the cast, `critical`, `comptime`, each
    once; `&mut q` is `ty::mut-borrow-of-immutable`, above),
    `reference_not_yet.ers` (a `static mut`, an `extern static mut`, a field
    and an element of one, `&*v` and `&(*w).a` with volatile pointers, a
    peripheral, a cluster and a cluster array element, with the accepted
    `static`, `extern static`, plain pointer and `&raw`), `references_accepted.ers`
    (`--emit=mir`: a reference as an `extern fn`, `#[export]` and `#[naked]`
    parameter, the value of an `if`, a `match`, a block and a `loop` with
    `break`, an argument, an initializer, a cast). The three rows of
    `docs/reference.md` and the three snippets of `tests/rejected.rs` (`Items`,
    so that a base program's names do not clash).

## 3. feat(ty,mir): `&mut T` to `&T`, and `&mut` lent to calls
- Status: done
- Implements: ADR 0105, "Kinds, conversions, casts and comparisons" (the
  conversion); ADR 0106, "Calls" (lending); ADR 0107, "What MIR building
  writes" (lending, the conversion).
- Changes:
  - `src/ty.rs`: `coerces` accepts `&mut T` for `&T`, of the outermost
    reference only, with the conversion recorded where it happens, as
    `Tables::coercions` records ADR 0031's.
  - `src/mir/build*`: the conversion is `_t = &*q`; an argument that is a
    variable or a parameter of type `&mut T` is `_t = &mut *r`, `move _t`;
    `is_simple` false for it.
- Tests:
  - ui: `reference_lending.ers` (`--emit=mir`): `f(r); f(r);` and a `&mut`
    passed in a loop accepted, the reborrows in the dump; a `&mut` given to a
    function taking `&T`, as a variable, a parameter, `&mut x` and the value
    of an `if`; a `&mut` in an `if` passed to a call, moved; `let q: &mut T =
    r;` still a move (`analysis::use-after-move` on a later `r`).
  - ui: `reference_coercion_errors.ers` (`ty::mismatched-types` for a `&T`
    where a `&mut T` is expected and for a `&mut T` where a `&U` is).
- Decisions:
  - The conversion is recorded in `Tables::coercions` with the target type, as
    the slice one is, and `check` records it where `unsizes` did, through a new
    `shares(from, to)` (`&mut T` to `&T` of the same referent, of the
    outermost reference only, as the pointer ones are); `coerces` includes it, so every position that passes an expected
    type (arguments, `let`, the branches of an `if` and `match`, the tail of a
    block, `break`) converts, and a block, `if` or `match` converts inside, in
    its tail or branches, as for slices. MIR building tells the two
    conversions apart by the target type (`Ty::Ref` is `share`, the rest
    `array_slice`). The type dump already prints ` as {to}`.
  - `share` is `_t = &*q` with `q` the place of the operand converted: the
    variable or parameter itself, or the temporary holding a value. The
    operand read of a variable (`move _r`) is dropped, so `r` is not moved. An
    operand with no place (never a `&mut`) is returned unchanged rather than
    met with a panic, so the count of `src/mir/build.rs` in
    `tests/architecture.rs` does not change; the validator (T5) would reject
    the body.
  - Lending (`Builder::argument`): an argument that is `ExprKind::Local` of
    type `&mut T` and has no conversion is `_t = &mut *r`, `move _t`; it is
    done in `operands`, which a variant's payload also uses, but a payload
    holds no reference (step 2), so only calls lend. A `&mut` that is any
    other expression (an `if`, a block, a call's result, `&mut x`) is moved by
    the argument, as the plan says. A `let` of a variable is a move as before
    (`reference_lending_moved.ers`).
  - `is_simple` is a free function of the expression alone and cannot tell a
    variable of type `&mut T` from any other, so it is unchanged and
    `operands` asks `Builder::is_mut_variable` besides: a `&mut` variable
    argument (lent or converted to `&T`, both are a borrow) is not simple for
    the place arguments before it (`ordered` and `lent_after_place` in
    `reference_lending.ers`: `n` and `x.a` are read into a temporary before
    the borrow), and the borrow, a fresh temporary that nothing else writes, is
    never spilled to another (`_t = &mut *r; call f(.., move _t)`, with no
    `_u = move _t` between when a later argument is not simple).
  - `ty::mismatched-types` for a `&T` where a `&mut T` is expected gets a
    help, "a `&` reference never becomes `&mut`; borrow the place with `&mut`
    if it may be written", as `*const` to `*mut` has one. A `&mut T` where a
    `&U` is, or a raw pointer, has the plain message.
  - Tests: unit test `mut_references_coerce_to_shared` (`coerces` and `shares`:
    both directions, another referent, raw pointers, only the outermost);
    `reference_lending.ers` has the plan's cases (`twice`, `looped`, a
    variable and a parameter, a `&mut` lent then used, `&mut x` and the value
    of an `if` converted, `let q: &u32 = r;` then `*r` written, a `&mut` in an
    `if` moved to a call) and the argument order; `reference_lending_moved.ers`
    (not in the plan) has the `analysis::use-after-move` of a `let q: &mut T =
    r;` and of an `if` value, in a file of its own since a body with errors
    dumps no MIR; `reference_coercion_errors.ers` is `--emit=typeck`.
    `reference_comptime.ers` gained `lent()`: a `&mut` lent to two calls and
    converted to a `&` at compile time (7), so the evaluator runs the reborrow
    `&mut *r`. The snapshot of `references_mir.ers` changed in one line: its
    `write(c, ..)` now lends `c` (`_6 = &mut (*_3)`) where it moved it. The e2e
    `references.ers` is unchanged, and still valid: it passes each `&mut`
    once and reborrows by hand.

## 4. feat(analysis): the borrow check
- Status: done
- Implements: ADR 0106; ADR 0107, "The borrow analysis", "`check_body`".
- Changes:
  - `src/analysis/borrows.rs` (new): sites and paths, the forward analysis of
    what each reference local may hold, the backward liveness, the sites in
    use at each access, the conflicts and the errors, as ADR 0107 says; on
    `analysis::bits`.
  - `src/analysis/mod.rs`: `check_body` runs `moves::check`, then on a body
    that passed it both `borrows::check` and `linear::check`; the module
    comment names it.
- Tests:
  - unit tests in `borrows.rs`, on hand-built bodies as `moves.rs` and
    `linear.rs` have: a write while a shared borrow is used later, and after
    its last use; two mutable borrows held together; a read during a mutable
    borrow, and through it; disjoint fields, overlapping elements, a field
    and its struct; a reborrow keeping its base in use; a borrow held by one
    of two locals at a join; a use only round a loop; a borrow through a raw
    pointer giving no site; a call's arguments in use during the call and not
    at its result's write; an operand read after another's last use within
    one statement; a body with no `Ref` doing no work; the fixed point not
    depending on the order of blocks.
  - ui: `borrow_conflict.ers` (each row of ADR 0106's table: a read, a `&`,
    a write, a move, `end`, a `&mut` in conflict, with the borrow and the
    later use labelled; `f(&mut x, &x)`, `f(&mut x, &mut x)`, `f(&mut x,
    x.a)`; a reborrow then a use of its base; `&mut a[0]` with `&a[1]`; a
    borrow used in the next iteration of a loop; an `if` whose value may hold
    either borrow; `x.a` read while a copy of a reference to `x`
    (`let b: &mut .. = a;` moved, `let b: &T = a;` copied) is used later; a conflict with a lent argument and with a conversion, as
    their messages say); `borrow_accepted.ers` (the last-use cases of ADR
    0106, `f(x.a, &mut x)`, `f(&mut s.a, &mut s.b)`, `x = f(&x)`, `*r = 1`
    through the borrow, `&*p` with `p` raw, a borrow of an immutable static
    and of a byte string, paths that do not return); `borrow_const.ers` (a
    `comptime` function with a conflict, called from a `const`: the analysis
    error and nothing from evaluation, as `use_after_move_const.ers`);
    `borrow_and_linear.ers` (a body with both a conflict and a linear value
    not consumed: both reported); `borrow_after_move.ers` (a borrow of a
    moved place: only `analysis::use-after-move`).
  - `tests/rejected.rs`: a snippet for `analysis::borrow-conflict`;
    `docs/reference.md`: its row.
- Decisions:
  - `check_body` stops after the analysis of moves when it fails, and
    otherwise runs the borrow check and the analysis of linearity both (no
    `&&` between them), so a body reports the errors of each; the borrow
    check's come first, and the driver orders the diagnostics. The module
    comment of `analysis/mod.rs` names the borrow check.
  - `borrows.rs` reads each statement once into a `Stmt`: its `Access`es in
    the order of ADR 0099 (the operands left to right, then the place of the
    rvalue, then the destination), the `Def` (what a whole write of a local
    of a reference type makes it hold) and, for a call, the reference locals
    it receives. The forward analysis, the liveness and the pass that finds
    the faults all read that, so the three agree on what a statement does.
    Both fixed points take the order of the blocks as a parameter, as
    `moves::Flow::solve` does, for the test of order independence.
  - What a local holds is one `Bits` of sites per local of a reference type
    (`State`), and liveness is one `Bits` over those locals only: no other
    local holds a borrow (R1), so the others need neither. The sets are
    united at a join, and a transfer replaces the destination's set, so it is
    monotone.
  - The sites in use at an access (`Flow::in_use`) use the sets after the
    statement for the locals live after it (a local the statement writes
    holds its new value there, which is what a later read sees) and the sets
    before it for the locals its later accesses read, and for a call's
    arguments (they are read as the call runs). The site the access itself
    makes is left out, as ADR 0107 says. Every access of a call but the write
    of its result sees the arguments' sites, so `f(&mut x, x.a)` is a fault
    whether `x.a` is an operand of the call or a temporary read before it.
  - Paths: `Field(i)`, `Elem` (for `Index`, `ConstIndex`, `Element` and
    `ConstElement`) and `Deref` of a reference; a `Deref` of a pointer or an
    `Offset` ends the path (`None`). `Tag` and `Payload` are `Step::Other`,
    equal to themselves and to nothing else: no site has one (R3), so they
    never decide an overlap, and the rule is ADR 0106's alone: two paths from
    one root overlap unless they meet two different fields. A static has no
    path: its place is the `Deref` of the pointer of a `Const::Static`
    temporary. It conflicts with nothing, which is right while only a static
    that is never written can be borrowed (ADR 0105); M5.4c, which allows
    `static mut`, must give it one.
  - A write of a whole local of a reference type is an access like any other
    (`How::Assign`, path the local), and so conflicts with a borrow of `*r`
    in use, by ADR 0106's table. It cannot happen to a variable (a reference
    is never `mut`, step 2), and the temporaries that are written again are
    written in a fresh iteration, when nothing borrowed through them is live.
  - Raw pointers: an access whose place goes through one has no path, but is
    still kept when its base is a local of a reference type (`(*r).p` read
    before `*(*r).p`): `Access::reads` is what liveness needs, so it is
    recorded for every access that names the local, with or without a path.
  - Lending and conversion are told apart in messages by the shape of the
    MIR (`Flow::borrow_how`): `_t = &mut *r` with `_t` a temporary moved into
    a call as an argument and `r` a variable or parameter is `How::Lend`;
    `_t = &*q` with `q` of type `&mut` and `_t` a temporary is `How::Convert`
    (`q` may be the temporary that holds a value converted). MIR has no flag
    for them, so a hand-written `&mut *r` passed to a call is told as a lend
    and `&*q` as a conversion: they are the same borrow, with the same
    duration, and the words are right for both. A `let q = &mut *r;` is a
    plain borrow of `*r`, since its temporary is not an argument.
  - Messages (all `analysis::borrow-conflict`, at the access): "cannot use
    `x` while it is borrowed as mutable" (a copy, `SliceAddress`, `SliceLen`),
    "cannot take `&raw const` of `x` while it is borrowed as mutable",
    "cannot borrow `x` while it is borrowed as mutable", "cannot convert `r`
    to `&` while it is borrowed as mutable", "cannot assign to `x` while it is
    borrowed", "cannot take `&raw mut` of `x` while it is borrowed", "cannot
    move out of `x` while it is borrowed", "cannot end `x` while it is
    borrowed", "cannot borrow `x` as mutable while it is borrowed", "cannot
    lend `r` to this call while it is borrowed". The primary label says
    "used here", "address taken here", "borrowed here", "converted to `&`
    here", "assigned here", "moved here", "ended here", "borrowed as mutable
    here" or "lent to this call here". Each borrow in conflict is labelled
    "`x` is borrowed here", "`x` is borrowed as mutable here", "`r` is lent
    to this call" or "`r` is converted to `&` here", and its later use "the
    borrow is used later here" or "the borrow is used in the next iteration
    of the loop". The help is one: "end the borrow first: use the reference
    before this point, or take the value out into a `let` before borrowing it
    (ADR 0106)". A place with a temporary for its root is "this value", with
    no backquotes. The ADR lists some of the messages and leaves the rest to
    the step: the new ones follow their wording.
  - The later use (`Flow::later_use`) refines ADR 0107's rule, which cannot
    tell a read that comes after the access in the program from one that
    comes first in the source. The ADR picks, among the reads of a local that
    holds the site that the access reaches, the first that starts at or after
    the access's span, else the first of all, marked as in the next iteration
    of a loop. For `f(&mut x, &x)` the read of the first borrow is the call,
    whose span starts at `f`, before the access `&x`, so the rule would say
    "in the next iteration of the loop" for a program with no loop. So a read
    in the access's own block after it, and the reads of the call the access
    is an argument of (the call reads its arguments when it runs, after all
    are evaluated), count as ahead whatever their span; only a read that is
    neither, reached through a back edge, is marked. A read of a call is
    placed at the call's span, not at its argument's, so the label is at the
    call. Ties are broken by end, then by location, as ADR 0107 says.
  - `Builder` (`mir/build.rs`, `block_then`): the assignment of a `let` takes
    the span of its initializer. It took the span of the enclosing block, so
    `let n: u32 = x;`, which is a copy of a variable with no statement of its
    own before it, was a read labelled at the whole function. It is the one
    change outside `analysis/`; no snapshot changed with it (dumps leave
    spans out and no other diagnostic read that one).
  - A body with no site does no work, and one whose sites are all in blocks
    nothing reaches has none. `analysis/` still has no panic: the code

## Fixes found while building

- A bare `return` or `break` before a `,` did not parse: `.None => return,`
  gave `parser::unexpected-token: expected an expression, found ','`, though
  `docs/reference.md` and ADR 0037 show `State::Done => return,`. Cause:
  `Parser::at_expr_end` (`src/syntax/parser.rs`) listed `;`, `}`, `)`, `]`
  and the end of file as ending an expression, not `,`, so the keyword read
  the comma as the start of its value. Fix: `TokenKind::Comma` joins the list.
  What was checked:
  - `at_expr_end` has one caller, the `break`/`return` arm of `primary`. No
    other construct uses it.
  - A `,` cannot start an expression, so every program that has `return,` or
    `break,` was an error before (`expected an expression, found ','`) and
    parses now; no program that parsed changes meaning. No snapshot held that
    diagnostic, and none changed.
  - The commas that can follow such a keyword are those of match arms, call
    arguments, array elements and struct literal fields (the language has no
    tuples), and the `asm` operands, which take no `return`. The first four
    are in the ui test `parse_return_break_arms.ers`, with the forms that
    already worked (a value, `;`, `}`, `)`, `]`, and the last arm without a
    comma).

- `(*r).buf[(*r).head]` with `r: &mut Ring` was `analysis::use-after-move`
  ("use of moved value `r`", moved at the `(*r)` of the base, used at
  `(*r).head`), though ADR 0105 and 0106 accept it. Cause: `place_then` marks
  `later_writes` for an index that is not simple (ADR 0018), and
  `pointer_place` then stores the base pointer in a temporary with `_t = move
  r`, because `read` gives `Operand::Move` for a type that is not copy. A raw
  pointer or a `&T` is copied there, so only a `&mut` base was hit: the read,
  the write (`... = v`), `+=`, a field of a field (`(*o).ring.buf[(*o).ring.head]`)
  and `&mut (*r).buf[(*r).head]` all went through that one arm of
  `pointer_place` (`Deref`, the pointer-indexing arm and `slice_index` are its
  callers; a `&mut` can only reach the first). Fix: `pointer_place` returns the
  place of a variable of type `&mut T` as it is, whatever `later_writes` says
  (`Builder::is_mut_variable`, the test the lending of step 3 uses). The rule:
  `later_writes` exists because a variable may be assigned by code evaluated
  before the access, and a reference variable never is: it is bound once and
  `mut` is `ty::reference-position` (ADR 0094, 0105), so reading it late is
  reading it now. What was tried first, and why it is not the rule: the
  reborrow of step 3 (`_t = &mut *r`, then `(*_t).buf[_i]`) removes the move
  but keeps `*r` borrowed while the index reads `(*r).head`, so
  `analysis::borrow-conflict` rejects the same program (checked on the read,
  the write, `+=`, the nested forms and the borrow). This is not the rule of
  ADR 0107 "What MIR building writes" for lending, which only names arguments;
  the ADR does not say how a place is reached through a `&mut` variable
  while a later index is evaluated. What was checked:
  - The other spills of an operand: `Binary` and `Slice` spill integers and
    raw pointers; `operands` spills a call's arguments, and a `&mut` variable
    there is lent (`is_mut_variable` excludes it); the fallback of
    `place_then` and `spill` meet a `&mut` only as the value of an expression
    that is not a variable (a call's result, a block), a temporary or a move
    that is right. No other site moves a `&mut` variable by spilling it.
  - A `&T` base is a copy (`_2 = copy _1`) and was accepted; it is left as it
    is, so the snapshots that hold it do not change.
  - No existing snapshot changed.
  - Tests: ui `reference_index_through.ers` (`--emit=mir`): the read, the
    write, `+=`, the nested read and write, the borrow `&mut` and `&` of such a
    place, a `&` base and the reference used again after the access, so the

  - ADR 0107, "What MIR building writes", is amended by the user's decision (a
