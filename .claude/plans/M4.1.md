# Plan: M4.1 Inline assembly

ADRs: 0078, 0079, 0080, 0081
Program on QEMU: the thumbv7m board stops QEMU through `bkpt` written in
Erebos, so every e2e program on `mps2-an385` runs through inline
assembly (step 7); C code divides 64-bit values on both targets
(step 6); a program per target reads machine registers and moves values
through every kind of operand, and a portable program hands a
descriptor to a "device" across `core::arch::fence()` (step 8); each at
`-O0` and `-O`.
Out of scope:
- `_start` in `core`: M4.2 (it stays compiler-generated, ADR 0012);
- handlers, vector tables, `critical` blocks and masking interrupts:
  M4.3 (ADR 0078 is accepted with this step, so that M4.1 decides
  nothing it must break, and implemented from M4.3);
- external interrupts and the SVD's `<interrupt>`: M4.4;
- the check of shared statics: M4.5;
- finer fences (`fence w,o`, `dmb st`, `dsb`, `isb`) as items of
  `core::arch`: added by the step that needs one (ADR 0081);
- operand modifiers in placeholders (`{0:x}`), `inlateout`, ABIs other
  than C: not planned (ADR 0079).

Before step 1: the `docs(adr)` commit that accepts ADR 0078 to 0081
also sets the status lines of the ADRs they amend, in their files and in
the index (`docs/adr/README.md`):
- 0016: `Accepted; amended by 0079 (string literals exist, as the
  templates of `asm` only)`; index `Accepted, amended by 0079`;
- 0023: `Accepted; amended by 0031 (...), 0035 (...), 0039 (...), 0058
  (...), 0059 (...), 0081 (the compiler provides a compiler fence and a
  hardware fence)`, keeping the existing text; index adds `0081`;
- 0052: `Accepted; amended by 0056 (...), 0080 (`core` has a module
  whose file depends on the target)`; index adds `0080`;
- 0074: `Accepted; amended by 0080 (`core` defines `__aeabi_uldivmod`
  and `__aeabi_ldivmod`)`; index `Accepted, amended by 0080`;
- 0076: `Accepted; amended by 0080 (C code on thumbv7m divides 64-bit
  values through `core`'s `__aeabi_uldivmod` and `__aeabi_ldivmod`)`;
  index `Accepted, amended by 0080`;
- 0077: `Accepted; amended by 0079 (the thumbv7m board stops QEMU with
  inline assembly, without a C file; a program holding one target's
  assembly or naming an item of `core::arch` specific to one target
  lists only that target)`; index `Accepted, amended by 0079`.
The same commit holds the roadmap's edits written while planning: the M4
steps table, the decisions agreed for M4.2 to M4.5, the M4 pending
decisions and the status line.

Order: the expression is parsed (1), checked and built into MIR (2),
then generated (3), each with snapshots; naked functions (4) build on
all three. `core::arch` (5) and the EABI's division (6) use them inside
`core`; the board (7) and the milestone programs (8) use them on QEMU.
Steps 1 and 2 leave a temporary diagnostic where the next layer meets
an `asm` it does not handle yet, never a panic; each later step removes
the one before it. Every existing test passes after every step.

## 3. feat(codegen): generate inline assembly
- Status: todo
- Implements: ADR 0079, "Meaning", "Errors from the assembler", "Where
  it is checked and generated".
- Changes:
  - `src/codegen/mod.rs`: `InlineAsm` becomes an LLVM call of inline
    assembly (`Context::create_inline_asm`): the template rendered from
    the pieces, `$` escaped as `$$`, operand placeholders as `${N}` in
    LLVM's numbering (outputs, then inputs), `sym` pasted as the
    symbol, `const` as decimal; constraints `=&r` (`out`), `=r`
    (`lateout`), `r` (`in`), a tied input for `inout`, `{reg}` for an
    explicit register; `out(reg) _` an `=&r` output whose value is
    dropped (it appears in the template), `out("x") _` a `~{x}`
    clobber; `~{reg}` for each register `clobber_abi` covers that is no
    output, an explicit input among them tied to a dropped output;
    `~{memory}` unless `nomem` or `readonly`, `~{cc}` on thumbv7m
    unless `preserves_flags`; `sideeffect` unless `pure`, `alignstack`
    unless `nostack`; the call's memory attribute from `nomem` and
    `readonly`; inputs narrower than 32 bits extended to `i32` by their
    signedness and outputs truncated (ADR 0079, "Widths"); several
    outputs as a struct, stored to their places left to right;
    `noreturn` followed by `unreachable`. Items named by `sym` join
    `llvm.compiler.used`. The temporary `codegen::llvm` goes.
  - `src/codegen/mod.rs` (object emission) and `src/driver.rs`: a
    diagnostic handler on the LLVM context, through `inkwell::llvm_sys`
    (no new dependency), collects LLVM's errors instead of letting it
    exit. Object emission returns diagnostics instead of a `String`, so
    an error can carry the span of an `asm` from MIR. A message that
    starts with LLVM's inline assembly prefix (`<inline asm>`) is an
    assembler error: each `asm` of the program is then assembled alone
    in a scratch module with the same constraints, in source order, and
    each one the assembler rejects is one `codegen::asm` at its span
    with LLVM's message, however many copies of it the module held. A
    register allocation failure for an inline assembly constraint
    (LLVM's "could not allocate ... for constraint" and "couldn't
    allocate ... register for constraint" messages) is an inline
    assembly error too, found the same way. If none fails alone, one
    `codegen::asm` without a label carries LLVM's message; any other
    LLVM error stays `codegen::llvm`. A build
    without errors pays nothing for it.
- Tests:
  - ui (`emit: llvm-ir`, `opt: both`): `asm_codegen.ers` and
    `asm_codegen_thumbv7m.ers` show the constraint strings of every
    direction, an explicit register, `clobber_abi("C")`, each option,
    `sym`, `const`, `$` escaped, several outputs, and `noreturn`; at
    `-O`, a `pure` asm whose output is unused is gone and a plain one
    is kept.
  - `tests/e2e.rs` (harness tests): a program whose template has an
    unknown instruction fails to build with `codegen::asm` labelled at
    the `asm`, on both targets, and the process exits with the
    compiler's error status, not LLVM's; a function with a bad template
    called from three places at `-O` gives one report; a non-local label
    in a function inlined twice, at `-O` (at `-O0` nothing is inlined and
    it builds), gives the unlabelled `codegen::asm`; on thumbv7m, an
    `asm` with more `reg` operands than free registers gives
    `codegen::asm`.
  - `tests/elf.rs`: a program with one `asm` per target (`csrr` on
    riscv32, `mrs` on thumbv7m) is built and linked, and its `.text`
    holds the instruction, so the rendered template assembles. The
    programs that run on QEMU are step 8's.
