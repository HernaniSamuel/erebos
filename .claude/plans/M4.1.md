# Plan: M4.1 Inline assembly

ADRs: 0078, 0079, 0080, 0081, 0082
Base: bd0efcf
Program on QEMU: the thumbv7m board stops QEMU through `bkpt` written in
Erebos, so every e2e program on `mps2-an385` runs through inline
assembly (step 7); C code divides 64-bit values on both targets
(step 6); a program per target reads machine registers and moves values
through every kind of operand, and a portable program hands a
descriptor to a "device" across `core::arch::fence()` (step 8); each at
`-O0` and `-O`.
Out of scope:
- `_start` in `core`: M4.2 (it stays compiler-generated, ADR 0012);
- handlers, vector tables, `critical` blocks and masking interrupts:
  M4.3 (ADR 0078 is accepted with this step, so that M4.1 decides
  nothing it must break, and implemented from M4.3);
- external interrupts and the SVD's `<interrupt>`: M4.4;
- the check of shared statics: M4.5;
- finer fences (`fence w,o`, `dmb st`, `dsb`, `isb`) as items of
  `core::arch`: added by the step that needs one (ADR 0081);
- operand modifiers in placeholders (`{0:x}`), `inlateout`, ABIs other
  than C: not planned (ADR 0079).

Before step 1: the `docs(adr)` commit that accepts ADR 0078 to 0081
also sets the status lines of the ADRs they amend, in their files and in
the index (`docs/adr/README.md`):
- 0016: `Accepted; amended by 0079 (string literals exist, as the
  templates of `asm` only)`; index `Accepted, amended by 0079`;
- 0023: `Accepted; amended by 0031 (...), 0035 (...), 0039 (...), 0058
  (...), 0059 (...), 0081 (the compiler provides a compiler fence and a
  hardware fence)`, keeping the existing text; index adds `0081`;
- 0052: `Accepted; amended by 0056 (...), 0080 (`core` has a module
  whose file depends on the target)`; index adds `0080`;
- 0074: `Accepted; amended by 0080 (`core` defines `__aeabi_uldivmod`
  and `__aeabi_ldivmod`)`; index `Accepted, amended by 0080`;
- 0076: `Accepted; amended by 0080 (C code on thumbv7m divides 64-bit
  values through `core`'s `__aeabi_uldivmod` and `__aeabi_ldivmod`)`;
  index `Accepted, amended by 0080`;
- 0077: `Accepted; amended by 0079 (the thumbv7m board stops QEMU with
  inline assembly, without a C file; a program holding one target's
  assembly or naming an item of `core::arch` specific to one target
  lists only that target)`; index `Accepted, amended by 0079`.
The same commit holds the roadmap's edits written while planning: the M4
steps table, the decisions agreed for M4.2 to M4.5, the M4 pending
decisions and the status line.

Order: the expression is parsed (1), checked and built into MIR (2),
then generated (3), each with snapshots; naked functions (4) build on
all three. `core::arch` (5) and the EABI's division (6) use them inside
`core`; the board (7) and the milestone programs (8) use them on QEMU.
Steps 1 and 2 leave a temporary diagnostic where the next layer meets
an `asm` it does not handle yet, never a panic; each later step removes
the one before it. Every existing test passes after every step.

## 1. feat(parser): parse string literals and `asm` expressions
- Status: done
- Implements: ADR 0079, "`asm` expressions" (the grammar, string
  literals, the contextual words, `parser::string-outside-asm`).
- Changes:
  - `src/syntax/token.rs`, `src/syntax/lexer.rs`: a `String` token for
    `"..."`, with the escapes, errors and ASCII rule of byte strings
    (ADR 0031), sharing their code; the token keeps its unescaped bytes
    and the span of the literal. `asm` becomes a keyword.
  - `src/syntax/ast.rs`: `ExprKind::Asm(AsmExpr)`: the templates (each
    its bytes and span), the operands in order (`AsmOperand` with an
    optional name and a kind: `In { reg, expr }`, `Out { reg, late,
    place: Option<Expr> }` (`None` for `_`), `InOut { reg, expr, out:
    Option<Option<Expr>> }` (absent, `=> _`, `=> place`), `Sym(Path)`,
    `Const(Expr)`, `ClobberAbi(bytes, span)`), `AsmReg` (`Class(Ident)`
    or `Explicit(bytes, span)`), the options in order with their spans,
    and the span.
  - `src/syntax/parser.rs`: `asm` in `primary`; inside the parentheses
    the contextual words of ADR 0079 are recognized by their text, with
    the helpers M3.1 added; `options(...)` must be last. A `String`
    token anywhere else is `parser::string-outside-asm`, with a help
    showing `b"..."`; the parser skips the token and goes on. The AST
    dump prints every part.
  - `src/hir/lower.rs` (or the module that lowers expressions): an `asm`
    expression is reported as `resolve::asm-unsupported` ("inline
    assembly is not lowered yet") and lowered as an erroneous
    expression. Step 2 removes the code.
- Tests (ui):
  - `asm_parse.ers` (`emit: ast`): several templates; each direction,
    with and without a name, with `reg` and with a string; `inout` with
    no `=>`, with `=> _` and with `=> place`; `out(reg) _`; `sym` with a
    path; `const` with an expression; `clobber_abi("C")`; every option;
    trailing commas; an `asm` as a statement and as the tail of a block;
    escapes in a template.
  - `asm_parse_errors.ers`: a missing template, an unknown direction
    word, `options` not last, an unknown option word, a missing `)`, a
    positional operand after a named one, a named operand after an
    explicit register, a name on an explicit-register operand;
    each `parser::unexpected-token` at the right token, with recovery
    reaching the next statement.
  - `string_outside_asm.ers`: a string literal as a `let` initializer,
    an argument and an item-level token, each
    `parser::string-outside-asm` with the help; a malformed escape in an
    `asm` template is the byte string's error.
  - `asm_names.ers` (`emit: typeck`): `in`, `out`, `lateout`, `inout`,
    `sym`, `reg`, `options`, `nomem`, `pure`, `noreturn` and
    `clobber_abi` as names of locals, functions and fields still
    compile.
  - `asm_unsupported.ers` (`emit: hir`): the temporary
    `resolve::asm-unsupported`; deleted in step 2.
  - Unit tests in `src/syntax/lexer.rs`: the tokens `String` and `Asm`,
    `string_value`, and that a string literal's errors have the codes of a
    byte string's.
- Decisions:
  - The `String` token keeps only its kind and span, as `ByteString`
    does, and the parser decodes the bytes from the text with
    `lexer::string_value` (the plan said "the token keeps its unescaped
    bytes"): `Token` is `Copy` and the lexer already validated the
    literal, so no token needs to own a `Vec<u8>`; the AST holds the
    bytes, in `StrLit { bytes, span }`.
  - Byte strings and string literals share one scanner, `Lexer::quoted`,
    and one decoder, `quoted_value` (`byte_string_value` and
    `string_value` are its two entry points), so the escapes and the ASCII
    rule cannot drift apart. The codes are the byte string's:
    `lexer::invalid-byte` and `lexer::unterminated-byte-string`, with
    messages and labels saying "string literal" ("unterminated string
    literal", "invalid in a string literal") and a help for the
    unterminated case that points at `asm`'s several strings; no new
    lexer code, so the diagnostics table of step 9 changes only in the
    descriptions of those two rows.
  - `StrLit` has a hand-written `Debug` that prints its bytes as text
    (`bytes: "csrr {}, mcause"`), so that the AST dump is readable
    instead of one number per line; its bytes are empty when the lexer
    rejected the literal, as `unwrap_or_default` does for byte strings
    in HIR lowering (syntax errors stop the pipeline before HIR).
  - The AST (`src/syntax/ast.rs`): `AsmExpr { templates, operands,
    options }` (the span is the `Expr`'s); `AsmOperand { name, kind,
    span }`, whose span starts at the name; `AsmReg::Class(Ident)` for
    `reg` and `AsmReg::Explicit(StrLit)`; `ClobberAbi(StrLit)`; options
    as `AsmOption { kind: AsmOptionKind, span }`, the kind an enum with
    `AsmOptionKind::ALL`, the words of the options, for the parser and for
    step 2. The span of `options(`'s keyword is not kept: no check names
    it.
  - The `String` token's `describe()` is "string literal", and the
    keyword `asm` is "`asm`".
  - A string literal outside `asm` is `parser::string-outside-asm` in two
    places: `primary` reports it, skips the token and returns a
    placeholder expression (`ExprKind::ByteString(None)`), so that the
    rest of the statement parses and several are reported in one
    function; and `report_unexpected` and `report_unexpected_help`
    report it instead of `parser::unexpected-token` whenever the token
    they found is a string, which covers items, types, patterns and the
    rest without a case for each (recovery then skips it). Inside `asm`
    the arguments use their own `asm_expected`/`asm_expect`, so a string
    where `asm` does not take one (a second template after an operand,
    one in place of an operand's `)`) is an ordinary
    `parser::unexpected-token`: it is the one place where strings are
    valid.
  - `parser::string-outside-asm`: the message is "string literals exist
    only inside `asm`", the label "not valid here" on the literal, and
    the help shows `b"..."` and names ADR 0016, 0031 and 0079.
  - The parser recovers from an error inside `asm` locally
    (`recover_asm`): it skips to the `)` that closes the expression, or
    stops at a `;` or `}` outside the braces opened since the `asm`, even
    inside its parentheses
    (or the end of the file), and returns the partial `Expr`, so the
    statement around it parses and the next statement's errors are found
    ("recovery reaching the next statement"). Everywhere else in this
    parser an error skips to the next item; `asm` is where a long
    argument list and many near-identical statements make that costly.
  - Errors of the operands' order are reported and parsing goes on (no
    recovery needed): an operand out of its group is `parser::unexpected-token`
    with the label "comes too late" on the operand's first token (its
    name, or its direction word), and a name on an operand with an
    explicit register or on `clobber_abi` is the same code with the label
    on the name. Their messages do not use the "expected X, found Y"
    form, since the token is valid, only out of place. `sym` and `const`
    belong to the positional group, or the named one when they have a
    name.
  - Every error in the arguments of `asm` carries one help describing the
    grammar (`ASM_HELP`), except those with a more exact one (the group
    order, the name on an explicit register, and an operand after
    `options(...)`, whose message is "expected `)`").
  - A comma missing between two arguments is "expected `,` or `)`", the
    token after the last argument being neither; an empty `options()` is
    "expected an option".
  - A name is read as an operand's name when an identifier is followed by
    `=` at the start of an operand; `in`, `out` and the other words are
    then valid names (`in = in(reg) x`, in `asm_parse.ers`).
  - No new panic: `unwrap_or_default` is used where a lexer-rejected
    literal has no bytes; `tests/architecture.rs` is unchanged (the
    lexer's one `unreachable!` stays, now inside `quoted`).
  - `resolve::asm-unsupported` is reported in `src/hir/lower/expr.rs` at
    the whole `asm` expression, with the label "this `asm` expression"
    and a help saying it is parsed but not yet checked or generated; the
    operands are not lowered (no names are resolved inside), and the
    placeholder is `ExprKind::Unit`, as the other lowering failures use.
    Step 2 removes it.
  - Tests: `asm_parse_errors.ers` has one error per statement in one
    function, which also shows the local recovery; `string_outside_asm.ers`
    has the item-level token, the `let` initializer, an argument, an
    operand of a binary expression, and two malformed escapes in `asm`
    (one in a template, one in a register); an unterminated string is a
    unit test of the lexer instead (it also swallows the `;`, so a
    snapshot would show a cascade that says nothing about strings).
    `asm_names.ers` also shows every word as a local, a function, a
    parameter and a field, and `asm_parse.ers` has the words as the
    names of operands. Snapshots were accepted without the
    `assertion_line` that insta adds, as the existing ones have none.

## 2. feat(typeck): check `asm` expressions and build them into MIR
- Status: done
- Implements: ADR 0079, "`asm` expressions" (placeholders, directions,
  registers, types, `sym`, `const`, `clobber_abi`), "Meaning" (the
  options and their checks, `noreturn` as `!`), "Compile-time
  evaluation", "Where it is checked and generated" up to MIR.
- Changes:
  - `src/target.rs`: per `Arch`, the table of registers ADR 0079 names:
    each register's canonical name, its other names, whether the
    compiler reserves it, and whether `reg` may choose it; and the
    registers `clobber_abi("C")` covers. Data, beside the description
    (ADR 0073).
  - `src/hir/`: `ExprKind::Asm` with resolved operands: `sym` resolves
    its path as any path (`resolve::unknown-path` and the rest); places
    and expressions lowered as usual. `resolve::asm-unsupported` and its
    test go.
  - `src/ty/expr.rs` (and `src/ty/place.rs` for output places): the
    checks of ADR 0079 with the build's target: template placeholders
    parsed into pieces (text, operand index), `ty::asm-template` with a
    label on the placeholder (mapped back through the literal's escapes)
    or on the operand, and on a template byte outside `0x01`–`0x7F`;
    `ty::asm-register` (including `in` and `out` on one register, and
    outputs without an explicit register beside `clobber_abi`),
    `ty::asm-operand-type` (thin pointers only; a `const` of any integer
    type), `ty::asm-sym`, `ty::asm-options`; output places checked as
    assignment targets; operand values and `const` typed without an
    expected type; the expression's type `()` or `!`.
  - `src/mir/`: a statement `InlineAsm` (a terminator when `noreturn`,
    with no successor) holding the pieces, the operands (an operand
    value for `in`, a place for `out`, both for `inout`, a symbol for
    `sym`, a value computed at compile time for `const`, asked of the
    evaluator as array lengths are), the clobbered registers, the
    options and the span of the `asm` expression; the MIR dump prints
    them. MIR building evaluates the operands and output places left to
    right before the statement (ADR 0079, "Evaluation order"), so their
    checks come first, and the statement stores the outputs left to
    right. Places written by outputs count as assigned.
  - `src/eval.rs`: reaching `InlineAsm` is `eval::asm`.
  - `src/codegen/mod.rs`: temporarily, a function holding `InlineAsm`
    is reported as `codegen::llvm` ("inline assembly is not generated
    yet"); step 3 removes it.
- Tests (ui):
  - `asm_typeck.ers` (`emit: mir`): every operand form, its MIR; a
    `noreturn` asm as the tail of a function returning `!`; an `out`
    into a field and an array element; `const` naming a constant, a
    negative `i32`, a `u64`; a placeholder used twice; two outputs to
    one place (stored left to right); an output place `A[f()]` whose
    index check comes before the statement.
  - `asm_template_errors.ers`: a placeholder naming no operand, an
    unused operand, an explicit register in the template, an unmatched
    `{`, `{}` past the last positional operand, a placeholder after an
    escape (the label lands on it), two operands with one name, `\x80`
    and `\0` in a template.
  - `asm_register_errors.ers` and `asm_register_errors_thumbv7m.ers`
    (`// target: thumbv7m-none-eabi`): an unknown register, each
    reserved register by each of its names, a register named twice
    among inputs and among outputs, `in("a0")` with `out("a0")`
    (rejected) and with `lateout("a0")` (accepted), `out(reg)` beside
    `clobber_abi("C")` (rejected) and `out("a0")` beside it (accepted);
    and a riscv32 name on thumbv7m.
  - `asm_operand_errors.ers`: `u64`, `bool`, an enum, a bit-field
    struct, an array, a slice and a `*const [u8]` as operands; a literal
    without `as`, in `in` and in `const`;
    `out` into an immutable local and into a `static`; `inout ... =>`
    of two types; `sym` naming a constant, a struct and a module;
    `const` of a non-integer.
  - `asm_options_errors.ers`: `nomem` with `readonly`, `pure` without
    an output and without `nomem`/`readonly`, `noreturn` with an
    output, an option twice, `clobber_abi` twice and with `"D"`.
  - `asm_comptime.ers`: an `asm` reached by a constant's evaluation is
    `eval::asm`; the same function called at run time builds.
  - `asm_codegen_unsupported.ers`: the temporary `codegen::llvm`;
    deleted in step 3.
- Decisions:
  - **String literal offsets (a change to step 1's AST).** Type checking
    has no source text, and the label of a placeholder must land on its
    text through the escapes of the literal (`"\x7boops\x7d"`), so the
    parser keeps, in `StrLit::starts`, where each byte starts in the source
    (from the start of the literal) and the closing quote after them;
    `StrLit::span_of(from, to)` gives the span of some bytes, the whole
    literal when the offsets are unknown (a literal the lexer rejected,
    which stops the pipeline before this). The lexer's decoder gained
    `string_bytes`, sharing `quoted_value`'s code; `StrLit`'s `Debug` does
    not print the offsets, so step 1's AST snapshots are unchanged.
  - **Register tables** are in `src/target.rs`: `Target::registers` (a
    `Register` per register: `name`, `aliases`, `reserved`, `in_reg_class`),
    `Target::c_clobbers` and `Target::register_names` (the words of the
    help of an unknown name), plus `Target::register(name)`. The canonical
    name is the architecture's own (`x10`, `r0`), not the ABI's, so that
    `a0` and `x10`, `lr` and `r14` are one register wherever two are
    compared and in the MIR dump; whether LLVM spells a constraint
    `{x10}` or `{a0}` is step 3's to check. `fp` is `x8` on riscv32 and
    `r11` on thumbv7m (`r7`, the Thumb frame pointer, has only its own
    name); `sb`, `sl` and `ip` are aliases of `r9`, `r10` and `r12`.
    `in_reg_class` follows the registers LLVM's `r` constraint may pick
    (every unreserved register, `lr` included, on Thumb-2); nothing reads it
    yet but the unit tests, which check that no reserved register has it:
    it is the data the plan asked for, kept for step 3 and for the
    reference. `clobber_abi("C")` covers `x1`, `x5`-`x7`, `x10`-`x17`,
    `x28`-`x31` and `r0`-`r3`, `r12`, `r14`; the flags are no register an
    operand names, and step 3 adds `~{cc}` for them from `preserves_flags`
    alone. `Queries::target()` is new, for type checking and MIR building.
  - **HIR.** `ExprKind::Asm(Box<Asm>)` with `Asm`, `AsmOperand`,
    `AsmOperandKind`, `AsmReg` (`Class(span of reg)` or `Explicit(StrLit)`)
    and `AsmSym`; `StrLit`, `AsmOption` and `AsmOptionKind` are the
    parser's, re-exported as `AccessMode` is. `Expr::walk` descends into the
    operands, so every operand expression is typed, and every `const`
    operand is evaluated with the other `comptime` expressions (the walk of
    `query`).
  - **`sym` resolves where lowering can say what it names.** A function
    (the entry and the panic function too: nothing in the ADR keeps the
    address of either from a template) or a static is `AsmSym::Fn` or
    `Static`; any other item (a constant, a struct, a module, an enum, a
    variant, a peripheral) is `AsmSym::Other(what, span)` and the type
    checker reports it as `ty::asm-sym`, so that the plan's test of a
    module is `ty::asm-sym` and not `resolve::misused-module`. A name that
    does not exist is `resolve::unknown-name` ("cannot find ..."), with
    `lookup_path`'s own errors for the segments before the last, and a
    help saying what `sym` takes. A local of the same name is not looked
    at: `sym` takes an item.
  - **`const e` is lowered as `comptime e`**: the operand is an
    `ExprKind::Comptime` expression with an id of its own, built by the code
    `comptime` uses (`comptime_operand`, new). So MIR building asks the
    evaluator through `comptime_value` as for any `comptime`, a variable of
    the function, parameters included, is `ty::not-comptime` (the case of
    step 4's "parameter named in a `const` operand"; it stops the
    pipeline, so `asm_const_runtime.ers` is a file of its own), and an
    evaluation error says "this `comptime` expression". The latter is not
    exact for `const`, and is left as it is (one origin text, in `query`).
  - **Type checking is `src/ty/asm.rs`** (a new module of `ty`), with the
    result for MIR in `Tables::asms` (`AsmChecked`: the template as pieces
    and each operand's canonical register); `ty` defines its own
    `AsmPiece` because `mir` cannot use `ty` (only `mir::build` can, and
    converts). The expression has type `!` when `noreturn` is among the
    options, `()` otherwise. Order of the checks of one `asm`: the
    operands' expressions and types, the registers, the template, the
    options.
  - **Operand types** (`ty::asm-operand-type`): an integer of at most 32
    bits, a thin pointer; `u64`/`i64` and a pointer to a slice have their
    own help; `()`, arrays, structs, enums, bit-field structs and `bool` the
    general one. `{error}` and `!` are skipped (reported elsewhere, or
    unreachable). The two sides of `inout ... =>` are compared after
    both are checked, and are reported once, with both labels. An output
    into a bit field is `ty::asm-operand-type` ("a bit field cannot receive
    the output of `asm`"): it has no place in memory, MIR building would
    need the write of ADR 0059 after the code, and the ADR names no other
    way; storing in a variable first is the help. `inout` without `=>`
    whose expression is not a place is `ty::not-assignable` with a message
    of its own (the generic one says "assign"), and `inout` of a place is
    checked as a compound assignment (read and written).
  - **Registers** (`ty::asm-register`): the name is looked up with the
    target's table, written or canonical in the message (`zero` (`x0`)); an
    unknown name is labelled at the string, with the target's names in the
    help; a reserved one lists the target's reserved registers. Two
    operands on one register are reported at the later one, with the first
    it conflicts with: "two inputs" (an `in`/`inout` each), "two outputs",
    or "an input and an `out`" (a non-late output beside an input only); an
    output that is `lateout` beside an `in` is accepted, and `inout` beside
    `in` is two inputs. An output on `reg` beside `clobber_abi` is one
    diagnostic per output, labelled at the `reg` word and at the (first)
    `clobber_abi`. `in(reg)` beside `clobber_abi` is fine, as the ADR says
    only outputs.
  - **Templates** (`ty::asm-template`): each string is read alone and a
    line break is added between them, which is the same as joining them
    first, since a placeholder cannot cross a break. `{}` counts from its
    own counter, apart from `{N}`; `{name}` takes an identifier; anything
    else between braces (`{0:x}`, `{ }`, `{a-b}`) is "is no placeholder"
    with a help naming the forms, and a number too large for `usize` names
    no operand. A name that is a register of the target gets a help saying
    to write the register as text, which is the "explicit register in the
    template" case: an operand with a register has no number and no name, so
    the template cannot name it, and the error is that of a name no operand
    has. The unmatched `{` is the one with no `}` before the next `{`.
    Each byte outside `0x01`-`0x7F` is labelled at its own text. An operand
    left out of the template is not reported when the template already has
    an error of its own, since the placeholder that failed may be the one
    it was meant for; the second operand of a repeated name is not reported
    as unused either. The names of the operands are checked first, each
    repetition reported at the later name with the first.
  - **Options** (`ty::asm-options`): each rule is its own diagnostic, so
    `pure` without an output and `pure` without `nomem`/`readonly` are two;
    every output counts for `pure` and `noreturn`, `out(reg) _` and
    `inout ... => _` included; an option given twice, `clobber_abi` given
    twice and an ABI other than `"C"` (of any spelling) are reported at
    the second occurrence, or at the string.
  - **MIR.** The types are in `src/mir/asm.rs` (`InlineAsm` and the rest);
    the statement is `Statement::InlineAsm(Box<InlineAsm>)` and the
    terminator `Terminator::InlineAsm(&'static InlineAsm)`, leaked like
    projections so that `Terminator` stays `Copy`. The template is pieces
    (`Text` as the user wrote it, braces undoubled; `Operand(i)` by the index
    in `operands`, which has no `clobber_abi`: that is `clobbers`, the
    target's `c_clobbers` in canonical names when the operand is there,
    leaving to step 3 what to do with the ones an explicit operand names).
    An operand has `AsmReg::Any` or `Fixed(canonical)`; `const` is its bits
    and `IntTy`, as `Const::Int` has them, so the dump writes it
    `const -1_i32`; `sym` is `AsmSym::Body` or `Static`; the options are
    a struct of bools, `AsmOptions`. The dump is `asm("template with {0}",
    in(reg) copy _1, out("x10") _2, inout(reg) copy _3 => _4, sym f, const
    5_u32, clobber(...), options(...))`, the operands in order and the
    placeholders their indices; `{` and `}` in the text are doubled, the

- Decisions:
  - **Where the code lives.** The lowering of `asm` is `src/codegen/asm.rs`
    (a new file of `codegen`, so no table of `tests/architecture.rs` changes
    for it): `Plan` (the template, constraint string, inputs and outputs of
    one `asm`, computed from MIR alone), `call` (the LLVM call, shared by the
    program and the scratch modules), `FnCodegen::inline_asm` (an `impl` in
    the child module, which sees the private fields), `keep_symbols`,
    `diagnose` and `assembles`. `mod.rs` only calls them. The handler is
    `src/codegen/diagnostics.rs`, with the names of ADR 0082 and no others
    (`Collector`, `Severity`, `handle`); it has no row in `PANICS`.
  - **`PANICS`: `src/codegen/asm.rs` is 7, `mod.rs` stays 69.** Two are in
    `memory_attribute` (the IR it parses is a fixed text with an enumerated
    effect, and the attribute is there), one each in `call` for the call and
    for `extractvalue` (made only when the call returns a struct of its
    outputs), in `widened` and `narrowed` (a builder that is positioned, on
    integers of the types type checking allows), and in `assembles` (the
    return of the scratch function). No input of the user reaches one: the
    operands' types are checked by `ty::asm-operand-type` (an integer of at
    most 32 bits, or a thin pointer), and the template and the registers
    are strings that LLVM reads, never values the Rust code indexes.
  - **Errors of code generation are diagnostics.** `emit_llvm_ir` and
    `emit_object` return `Vec<Diagnostic>` (ADR 0082: "instead of a
    `String`"): `codegen::asm`, or `codegen::llvm` for everything else, the
    machine LLVM cannot create and the object it cannot write included
    (that one was `error: cannot write ...`, a bare line; the write of the
    linker script keeps that form in the driver). `build` renders them
    through `Diagnostics::into_vec`, so they come in source order and the
    unlabelled ones last. `emit_llvm_ir` also installs the handler and fails
    on a collected error: the errors of the assembler appear only when the
    object is written, but the rule of ADR 0082 is every `Context`.
  - **The handler.** `Collector::install(&self, &Context)` takes the
    collector by shared reference; the callers declare it before the
    `Context`. The callback takes `try_borrow_mut` instead of `borrow_mut`
    (an error found while a borrow is held is dropped rather than a panic
    in an `extern "C"` function), and collects only errors, as text. A unit
    test of the file shows that an assembler error reaches the collector
    instead of ending the process, and that two contexts each have their
    own.
  - **Constraints** (`Plan::new`, shown by `asm_codegen.ers` and
    `asm_codegen_thumbv7m.ers`): outputs first, in operand order, then
    inputs; `out` is `=&`, `lateout` `=`, `inout` an `=` output with its
    input tied by number, as for `reg` (`r`) and for an explicit register
    (`{x10}`); `out(reg) _` is a real output of a word whose value is
    dropped (its register is in the template), and `out("x") _` is
    `~{x}`. A pointer operand stays a `ptr` in the call, an integer is a
    word (`i32`), so an input is extended before the call by its own
    signedness and an output truncated by the place's type. An explicit
    input whose register the code loses (`clobber_abi` covers it, or an
    `out("r") _` or `lateout("r") _` names it) is tied to an extra output
    nothing reads, which comes after the user's outputs; a register an
    output names is not a clobber, and a clobber is not listed twice.
    `~{memory}` and `~{cc}` come last. The test of the plan for that case
    is `explicit` and `clobbers` in both files.
  - **Register names.** The canonical name (`x10`, `r0`) is what LLVM
    spells in `{...}`, but for `r14`: LLVM rejects `{r14}` on thumbv7m
    ("couldn't allocate output register for constraint '{r14}'", found by
    running it) and knows `lr`, so `llvm_register` maps it. `x10` and the
    other `r` numbers are accepted as they are.
  - **Memory attributes.** The encoding of `memory(...)` is LLVM's, so the
    attribute is taken from a parsed declaration that has it
    (`memory_attribute`) instead of its bits being written in the compiler.
    Every call is `nounwind`. `pure` has no `sideeffect` and is `willreturn`,
    with `memory(none)` for `nomem` and `memory(read)` for `readonly`, so
    LLVM may delete it when its outputs are unused; one that is not `pure`
    keeps `sideeffect`, and is `memory(inaccessiblemem: readwrite)` with
    `nomem` (it may not be removed or reordered with what else has an
    effect, but memory accesses move across it) and `memory(read)` with
    `readonly`. `nostack` removes `alignstack`; the options other than
    `noreturn` change nothing else. `noreturn` is the terminator: the call,
    then `unreachable`.
  - **`sym` and `const` in the text.** A `sym` is the name LLVM gives the
    function or static (`Body::name`, the static's name), taken from MIR, so
    the program and the scratch modules render one text. A `const` is
    `IntTy::display_bits`: decimal, signed by its type. `llvm.compiler.used`
    (`keep_symbols`) holds each item once, in order of first use, with
    appending linkage and the section `llvm.metadata`; it is not created
    without a `sym`, so no snapshot of a program without one changes.
  - **The errors of LLVM and which are an `asm`'s** (`is_asm_error`). Besides
    the `<inline asm>` prefix and the two "allocate ... for constraint"
    forms of the plan, LLVM 22 says "inline assembly requires more registers
    than available" when a `reg` operand finds none (the plan's case on
    thumbv7m; found by running it), so that form is an `asm` error too.
    Everything else is `codegen::llvm`.
  - **Finding the `asm`** (`diagnose`). Only when an error of an `asm` was
    reported: every `asm` of a body that is part of the program is
    assembled alone, each span once (so a function inlined into three places
    is one report, and so is an `asm` that is copied), in order of (file,
    start, end). The scratch module is one function whose parameters are the
    inputs, with the same constraints, the call kept (always `sideeffect`,
    and without memory attributes, as a `pure` call with no used output
    would never reach the assembler), assembled by the same machine, with a
    context and a collector of its own. If none fails alone, one unlabelled
    `codegen::asm` per distinct message, with a help that says LLVM found it
    in the whole object. A program with an `asm` error that also has others

  - **What `codegen::asm` says.** The message is LLVM's text as it is, with
    the instruction and the caret under it (`<inline asm>:1:2: unrecognized

  - **The exit status.** The plan says the process exits "with the

  - **Failed objects are discarded** in `emit_object` as well as by `build`
