- the findings of `docs/open-findings.md` in `src/analysis/borrows.rs`

- naming P5 in ADR 0095's status line (M5.7, left to the user).

Decided with the user while planning (ADR 0118 leaves both to the plan):
- **The cluster on thumbv7m** is the CMSDK dual timer of `mps2-an385`: two
  identical timers at `0x4000_2000`, `0x20` apart, declared by the program
  that uses them (ADR 0077's reason for a program's own devices). The board

Before step 1: nothing is accepted here. ADR 0118 is Accepted (`0407b99`),
and the status lines of the ADRs it amends, in their files and in the index,
were set by that commit. This plan is committed alone (`docs: plan M5.8`),
with the roadmap's M5.8 line of the pending decisions pointing to it.

Order: the validator (1) and the analysis (2, 3) come before the rule of type
checking (4), so that no commit accepts a program whose returned reference is
not checked: until step 4, type checking still rejects every reference return
type, and steps 1 to 3 are tested over hand-built MIR. Step 4 opens the rule
with every test a source file can now reach for the signature and the body;
step 5 adds the rule of `critical` blocks, which ADR 0118 keeps for the
argument of ADR 0094 and not for soundness (no returned reference holds a
borrow of a `static mut`, by step 2), so the commit between is sound; step 6
adds the snapshots of what callers see; step 7 the tests at compile time and in
LLVM IR. The programs (8) come before the migration (9), which needs the
feature whole; the recount (10) needs the migration; the documentation is last
(11). Each step gains a `Decisions:` list while it is built (`/build-step`).

A gap in the compiler that the tests of steps 4 to 7 show (ADR 0118 expects
none in MIR building, the evaluator and code generation, and this plan did not
build a reference result to check) is fixed in a commit of its own, `fix(mir)`,
`fix(eval)`, `fix(codegen)` or `fix(analysis)`, before the step whose test
found it, with that test; it is recorded under that step's `Decisions:`. A gap
that is a design decision stops the build for the user.

Every new diagnostic code gets its snippet in the catalog of ADR 0069
(`tests/rejected.rs`) and its row in the table of codes of
`docs/reference.md` in the step where a source file first reaches it (step 4;
step 5 for the case it adds to `ty::reference-position`),
as the earlier steps of M5 did; the rest of the reference is step 11's.

## 1. feat(mir): let a body return a reference, under R1 and R5
- Status: done
- Implements: ADR 0118, "In MIR and the validator"
- Changes: `src/mir/validate.rs`:
  - R1 (`reference_positions`): `_0` of a reference type is no longer a
    violation. `references_below` still runs on `_0` as on every local, so a
    return type that reaches a reference below its top (`&&T`, an array of
    references) stays R1.
  - R5 (new), once per body, external bodies included (an `extern fn` has a
    signature and no blocks), read from `Body::ret` and `Body::params()`: when
    the return type is a reference, at most one parameter has a reference
    type; when it is a `&mut`, that parameter exists and is a `&mut`; when no
    parameter is a reference, the return type is a shared reference that is
    not volatile. One violation per clause broken, named `R5`.
  - The module header lists R5 beside R1 to R4; the doc comments in
    `src/mir/` that say `_0` is never a reference follow.
- Tests: unit tests of the validator (ADR 0118, "Unit tests of the
  validator"):
  - R1 accepts `_0: &T`, `_0: &mut T` and `_0: &[T]`, and rejects `_0: &&T`
    and `_0` of an array of references; the existing test that expects R1 for
    a body returning a reference is rewritten to the new rule.
  - R5, one case per clause: two reference parameters; a `&mut` result with
    one `&` parameter; a `&mut` result with no reference parameter; a volatile
    `&` result with none. Accepted: each accepted row of ADR 0118's table (one
    `&` or `&mut` parameter with a `&T` result, one `&mut` with a `&mut T`,
    none with a `&T`), parameters that are no references counting for nothing
    (a raw pointer, a struct by value), a volatile result of a volatile
    parameter, and an external body.
  - No snapshot moves: no source reaches a body with a reference result yet.
- Decisions:
  - R5 is its own method, `Checker::reference_return`, run once per body
    after `reference_positions` and before `address_temporaries`, with the
    body as its location (`Location::Body`). It reads `Body::ret` and the
    parameters through `locals.get(1..=param_count)`, not `Body::params()`
    (which panics on a body short of locals, and the validator never calls
    what panics on bad input): such a body is S1's and R5 does not run on it.
    The existing `reference_positions` keeps its loop; only the `_0` branch
    went.
  - "One violation per clause broken" is read as one violation per fault, so
    that a single mistake does not cascade (ADR 0095): with two or more
    reference parameters R5 reports that clause alone, and does not also judge
    the `&mut` clause against a "that parameter" that is not one; a `&mut`
    result with no reference parameter breaks the second clause ("that
    parameter exists") and is one violation, not also the third (which is
    judged for a shared result, the volatile one). A volatile `&mut` with no
    parameter is likewise one. The cases the plan lists give the same
    violations they would under the other reading, one each.
  - A volatile result with one reference parameter is accepted whatever the
    parameter's volatility: ADR 0118's R5 constrains the volatile result only
    when no parameter is a reference. Type checking (step 4) is what ties a
    volatile result to a volatile parameter, as T5 does for any `Ref`.
  - The rule is read off `Body::ret`, not `locals[0]`: a body whose `_0`
    differs from `ret` is S1's, and judging the signature twice would be a
    cascade.
  - The message of each case names the type and, for the parameters, their
    local numbers (`_1`, `_2`) and types, so a failing build points at the
    signature without the body.
  - `r1_no_body_returns_a_reference` became
    `r1_a_body_returns_a_reference_at_its_top_only` (it keeps the struct that
    holds references, which is still one R1); the new tests use a helper
    `signature(ret, params, external)` that builds a body with no statements,
    so that the rules broken are the signature's alone.
  - Tests are split as R1 (`_0` at the top accepted, `&&T`, an array of
    references and the struct rejected), R5 (every row of the table and every
    clause, in one test, with external bodies through the same helper), the
    text and place of the violation, and the body short of locals (S1 alone).
  - The doc comments that said `_0` is never a reference were those of
    `reference_positions` and the module header (which now lists R5); none
    elsewhere in `src/mir/` says it. `src/query.rs` (`needs_missing_layout`)
    and `src/analysis/borrows.rs` still say it, and stay true until steps 2
    and 4 change what they describe.

## 2. feat(analysis): check what a call's result holds and what a body returns
- Status: done
- Implements: ADR 0118, "What a call's result borrows", "What a body may
  return", "The borrow analysis" (items 1 to 3), "Diagnostics"
  (`analysis::returned-borrow`)
- Changes: `src/analysis/borrows.rs`:
  - Item 1, in `collect` and `def_of`: the write of a call's result to a
    whole local of a reference type is `Holds::Copy` of the call's one
    argument of a reference type (`Stmt::args`, which R5 and P3 limit to one),
    and `Holds::Nothing` when the call has none. `apply` reads the argument's
    set from the state before the statement, which is the state before the
    call.
  - Item 2: `Terminator::Return` is an access that reads `_0` when `_0` has a
    reference type.
  - Item 3: after the fixed points, for each reachable block that ends in
    `Return`, every site in the set of `_0` at the terminator is classified by
    the root of its path: a first step `Deref` (the local is then of a
    reference type, by R1) is accepted; `Root::Static` of a static without
    `mut` is accepted; `Root::Local` without a first `Deref`, `Root::Static`
    of a `static mut` or `extern static mut`, and `Root::Peripheral` are
    `analysis::returned-borrow`.
  - The diagnostic: primary label at the site's `Ref` ("`x` is borrowed
    here", the existing naming of places), a label "returned here" at the
    write of `_0`, and a help by case: a local ("return the value, or a part
    of the reference parameter"); a local that holds a constant's data
    (`LocalDecl::constant`: declare a `static` to return a reference to it); a
    `static mut` or `extern static mut`; a peripheral or a cluster (borrow it
    in the caller and pass the reference in). One error per site and return,
    ordered by the span of the borrow, then of the return, and deduplicated as
    the conflicts are; they follow the body's `analysis::borrow-conflict`
    errors. `check` answers `false` when there is one.
  - "The write of `_0`" for the label: the last statement of the `Return`'s
    block that writes `_0` whole, and the terminator's own span when the block
    has none (hand-built MIR, or a later MIR that moves the write). For a body
    whose tail is an `if` or a `match`, that write is the one after the join,
    so "returned here" is at the whole `if` or `match`, not at the arm that
    borrows; the primary label is at the borrow, which is in the arm.
  - The analysis still does no work on a body without a site
    (`flow.sites.is_empty()`). `facts`, `call_borrows`, the checks of moves,
    linearity and shared statics do not change.
  - The module header says what a call's result holds and names the return
    check.
- Tests: unit tests over hand-built MIR (ADR 0118, "Unit tests of the borrow
  analysis", but the walk, which is step 3's):
  - a call's result takes its argument's sites, the site of the lending
    reborrow among them, and holds nothing without a reference argument; a
    write of the argument's place while the result is read later is a
    conflict, and after its last read is not;
  - the `Return` read of `_0`: with a `critical_exit` or an `End` between the
    write of `_0` and the `Return`, a write there of what `_0` borrows is a
    conflict;
  - the return check for each root: a field through the reference parameter,
    the parameter itself and a copy of it (accepted); a static without `mut`
    and a byte string (accepted); a named local, a by-value parameter, an
    unnamed temporary, a local holding a constant, a `static mut`, a
    peripheral and an element of one (rejected, each with its help); a
    reborrow of a local's borrow (`t = &local; _0 = &(*t)[..]`) and a call's
    result tied to one (rejected); a reference made through a raw pointer
    beside a site of the body (accepted), and the body of `counter`, `_0 =
    &*(&raw const COUNT)` with `COUNT` a `static mut`, which has no site and
    is accepted without the fixed points;
  - one site reaching two `Return`s is two errors, in order; one site
    reaching one `Return` by two paths is one;
  - `facts`: a site rooted at a static and held by a call's result is in use
    during a later call;
  - the fixed points do not depend on the order the blocks are visited in,
    with a call's result in the body.
- Decisions:
  - The code is in `src/analysis/borrows.rs` alone, as the plan says. Item 1:
    `def_of` lost its `Option<Rvalue>` (the `None` was the call's case) and
    a call has its own `call_def_of(dest, args)`, so that the two sources of
    a definition are two functions and not one with a parameter that means
    "a call" when absent; both start from a new `whole_ref(dest)` (the number
    of a whole local of a reference type). `call_def_of` takes the first of
    `Stmt::args`: R5 and P3 leave at most one for a callee that returns a
    reference, and a callee that does not has no reference destination.
  - Item 2: the `Return` terminator gets an `Access` built by hand, `How::Use`
    of `_0` with `reads: Some(_0)` and `path: None`, at the terminator's span.
    It has no path so that it can never be in conflict with a site of its own
    (it reads `_0`, it does not touch a place something is borrowed through);
    `access` would give it the path of the local. It is added only when `_0`
    has a reference type.
  - Item 3 is `Flow::returned_borrows`, called by `check` after
    `diagnostics`; the classification of a site is `Flow::refusal`, which
    answers with the message and the help or `None`. The state at a `Return`
    is the block's state at its start with the block's statements applied
    again (`apply`), as `faults` does, and not stored.
  - What the root decides, beyond the plan: a site with root `Root::Local`
    and a first step `Deref` is accepted, every other local site refused;
    `Root::Static` is refused when `StaticDef::mutable` (an `extern static
    mut` is one: `external` only picks the wording); `Root::Peripheral` is
    refused whatever its steps, a cluster or an element of a named peripheral
    included.
  - Messages (the plan fixes the code, the labels and the helps by case, not
    the words): the primary label is `site_label`, the label of the borrow
    analysis's own sites, so it reads "`x` is borrowed here", "`x` is borrowed
    as mutable here" or "this value is borrowed here". The message names the
    root and not the borrowed part (`x` for `&x.f`, `UART0` for
    `&UART0.data`), the part being in the label:
    - a named local: "cannot return a reference to `x`, a local of this
      function" (ADR 0118's sample); a parameter that is not a reference is
      one too;
    - a local the compiler keeps: "cannot return a reference to a temporary
      value of this function";
    - a local with `LocalDecl::constant`: "cannot return a reference to a
      constant, which has no address of its own";
    - a `static mut`: "cannot return a reference to `m::COUNT`, a `static
      mut`" (an `extern static mut` says so); a peripheral: "..., a
      peripheral".
    The helps: the local's is ADR 0118's sentence word for word ("return the
    value, or a part of the reference parameter"); the constant's: "declare a
    `static` to return a reference to it"; the `static mut`'s: "a returned
    reference cannot borrow a `static mut`: borrow it in the caller and pass
    the reference in, or return a raw pointer and write `&*p` where it is
    used" (the second way is ADR 0118's `counter`); the peripheral's: "borrow
    the peripheral or its cluster in the caller and pass the reference in".
    None cites an ADR, unlike `analysis::borrow-conflict`'s help, which does:
    ADR 0118's sample error has none.
  - "Returned here" is `Flow::returned_at`: the span of the last statement of
    the `Return`'s block that writes `_0` whole (an `Assign` or a `Call`
    destination), the terminator's span when there is none or the statement
    has no span.
  - Order: the errors are emitted after the conflicts' and sorted by the span
    of the borrow, then of the return, then by block and site number, so the
    order does not depend on the order the blocks are visited in. The sink
    (`Diagnostics::into_vec`) sorts everything by the position of the primary
    label afterwards, so what the user reads is in source order, a returned
    borrow before a conflict that comes later in the source. The plan's "they
    follow the body's `analysis::borrow-conflict` errors" holds for emission
    only; the test of a body with both (`a_returned_borrow_and_a_conflict_in_
    one_body_are_both_reported`) says so.
  - `check` answers `false` for a returned borrow as for a conflict, and
    still does no work on a body without a site, which is how `counter` is
    accepted (tested through `Flow::of(..).sites.is_empty()`).
  - Tests, over hand-built MIR in the `tests` module of `borrows.rs`, with
    three helpers: `returning` (a body whose `_0` and `ret` are a reference
    type), `returning_shared` (`fn f(p: &Pair) -> &u32` with a named variable
    `x`, a `let t`, temporaries and `extra` locals) and `diagnostics_of`,
    which, unlike `errors_of`, accepts both codes. The tests are split as the
    plan lists them: a call's result takes its argument's sites (read at the
    start of a following block) and holds nothing without one; the conflict
    with the argument's place before and after the last read; the `Return`
    read (with the contrast of a body returning nothing, the write moved
    before the write of `_0`, and no write between); the accepted roots in one
    table (the parameter's part, the parameter, a copy, a reborrow, a call
    tied to it, a static, a part of it, a byte string, a raw pointer beside a
    site); `counter` with no site; the refused roots in three tests (locals
    in the four ways a local is told apart, `static mut`/`extern static
    mut`/peripheral/element, a reborrow of a local's borrow and a call tied
    to one, with the call with no argument accepted); the label of the write;
    one branch among two; two returns and two paths; `facts` with a result
    that holds a static's site, and its contrast; the order-independence of
    the fixed points with a call in a loop.
  - No snapshot changes: no source reaches a body that returns a reference
    before step 4, and the existing unit tests of `analysis::borrow-conflict`
    pass unchanged (none has a call whose result is a reference).
  - The panics of `src/analysis/borrows.rs` are unchanged (none added).
  - The comment of `def_of` that said no call returns a reference is gone
    with the rewrite of that function; the header of the file says what a
    call's result holds and names the return check.

## 3. feat(analysis): label the call whose result holds a borrow in conflict
- Status: done
- Implements: ADR 0118, "The borrow analysis" (item 4), "Diagnostics"
  (`analysis::borrow-conflict`, changed)
- Changes: `src/analysis/borrows.rs`: for each site of an
  `analysis::borrow-conflict`, after the fixed points and only then, the walk
  of item 4: from the later use, backwards over the definitions of the local
  it reads, following a copy to the local copied, a reborrow to the local it
  was made through and a call's result to the call's reference argument, only
  where the value holds the site at the fixed point; each definition visited
  once; the nearest call on each branch, and of those the one with the lowest
  block, then statement index. The call found gets one more label. A walk that
  reaches the site's own `Ref` without meeting a call adds none. A conflict
  with no later use (a site in use only during the statement, as a call's
  arguments are) has no walk and no label.
- Tests: unit tests over hand-built MIR: the label through a copy, through a
  reborrow and at a join of two calls (each site labelled at its own call);
  two definitions of one local in one block (the later one is followed); a
  loop (the walk ends); the tie broken by block, then statement, whatever the
  order of visits; no label when the site is held without a call. The existing
  unit tests and snapshots of `analysis::borrow-conflict` do not change: none
  of them has a call that returns a reference.
- Decisions (taken while planning):
  - The label's text names no function: "the result of this call holds the
    borrow", at the span of the call. ADR 0118 writes "the result of `first`
    holds this borrow", but the analysis of one body is given one `Body`
    (`analysis::check_body`, ADR 0099), a call names its callee by a `BodyId`,
    which is an index into a program that is not assembled yet, and the
    analyses read nothing but MIR (ADR 0093). ADR 0118 lets the texts be
    reworded and fixes only the code and what is labelled, which this keeps;
    the span shows the call. Flagged to the user.
- Decisions (taken while building):
  - The code is in `src/analysis/borrows.rs` alone. The walk is
    `Flow::holding_call(later, site, before)`, called by `diagnostics` for
    each site of a fault right after the "used later" label, so the call's
    label follows it. `later_use` is now a wrapper of a new `later_read`,
    which answers with a `Later` (the span, whether it is a later iteration,
    and the location and the local of the read) instead of the span alone,
    because the walk starts from the read and not from its span;
    `calls_in_use` (the check across calls) still uses `later_use`
    unchanged.
  - The text is "the result of this call holds the borrow", at the span of the
    call statement (`Stmt::span`), as the plan decided. It is one label per
    site, after that site's "used later" label, so the labels of a fault read
    site by site.
  - The walk: a work stack of (local, block, index), where a read of `local`
    is looked for in the statements of `block` before `index` (the whole block
    for the end of a predecessor). The nearest definition of the local above
    is taken; none in the block sends the walk to each predecessor whose
    state at its end holds the site (predecessors are built from `successors`
    inside the function, which only runs on an error). A definition counts
    only when the state after it holds the site, as the plan says. A call's
    definition is recorded and ends its branch; a copy and a reborrow of a
    different site (`Holds::Site` with `through`) go on to the local they
    copy or borrow through; the `Ref` of the site itself, a `Ref` with no
    base reference and `Holds::Nothing` end the branch with no call. The
    visited sets are the definitions `(block, statement, local)` and the
    block entries `(block, usize::MAX, local)`, so a loop ends the walk. The
    answer is the call with the least `(block, statement)`.
  - A fault whose site has no later use has no walk (the `Option` of
    `later_read` is the guard), as the plan says.
  - Tests, in the `tests` module of `borrows.rs`, with the helpers `holders`
    (`x` and three `&mut u32`), `conflict_labels` (the labels of the only
    error, as text and start) and `at`: the label through a copy and through a
    reborrow; the nearest of two calls in a chain; the join of two calls (two
    sites, each at its own call); two calls on two arms with the arms
    numbered both ways (the lowest block, whatever the numbering); two
    definitions of one local in a block (the later one, and the earlier call
    not labelled); a loop where two locals are defined from each other (the
    walk ends and finds the call outside it); and no label when the site is
    held by a reborrow only, when the call was given another borrow, and
    when the call lends the borrow itself.
  - The plan says no existing unit test has a call that returns a reference;
    one has, `a_write_of_the_argument_while_the_result_is_read_later_is_a_
    conflict` (written in step 2), and its first case gained the new label,
    "the result of this call holds the borrow". It is the only existing test
    that changed. No snapshot changes: no source reaches a call that returns a
    reference before step 4.
  - The panics of `src/analysis/borrows.rs` are unchanged (none added).

## 4. feat(ty): return a reference tied to the one reference parameter
- Status: done
- Implements: ADR 0118, "The rule, read off the signature", "Functions with
  fixed callers", "Diagnostics"
- Changes:
  - `src/hir/lower/types.rs`, `src/hir/mod.rs`: a reference at the top of a
    return type is no longer recorded (`UnsizedPosition::Return` forbids
    none), and `ReferencePosition::Return` goes. What is inside it is lowered
    as before, so `-> &&T`, `-> Option(&T)`, `-> [&T; 2]` and `-> *const &T`
    are reported at the inner reference, as a referent, a type argument, an
    element and a pointee.
  - `src/ty/reference.rs`, called from `Checker::fn_` (`src/ty.rs`) for every
    item written as a function that declares a return type, `extern fn`,
    `#[export]` and `#[naked]` functions included: the table of ADR 0118.
    The `Fn`s that HIR makes for the value of a `const`, a `static`, an enum
    discriminant or a `comptime` expression (`Fn::comptime` is `Some`) are not
    judged: their type is not a return type, and a reference there stays
    `ty::reference-position` alone. `ty::reference-return`
    is at the return type, with a label at each parameter of a reference type
    (`self` written `&self` or `&mut self` among them), and the help of its
    case: two or more reference parameters; a `&mut` result with one `&`
    parameter; a `&mut` or volatile result with no reference parameter. A
    signature with an `{error}` type in it is not judged.
  - The helps and module comments that say no function returns a reference
    (`src/ty/reference.rs`, `MEMORY_HELP` and the header; `src/ty/method.rs`
    or `src/ty/place.rs` where they say it) say what holds now.
  - `src/mir/build.rs`: the write of `_0` has the span of the expression
    whose value it writes, the body's tail or the operand of `return`, so that
    "returned here" (step 2) points at it. Nothing else is expected to change:
    a call's result of a reference type is a temporary like any other, a
    receiver or a base that is a call's result is reborrowed through that
    temporary (ADR 0114, `pointer_place`), and the conversions at a return

## 5. feat(ty): reject a `return` of a reference out of a `critical` block
- Status: done
- Implements: ADR 0118, "`critical` blocks and contexts"
- Changes:
  - `src/ty/reference.rs`, `report_made_references`: each `return` whose
    value has a reference type and that has at least one `critical` block
    around it in its function is one `ty::reference-position`, at the value,
    with "the value of a `return` out of a `critical` block" and the help of
    the `break` case. It is one error per `return`, however many `critical`
    blocks it leaves.
  - `docs/reference.md`, the table of codes: `ty::reference-position`'s row
    gains the `return` out of a `critical` block.
- Tests: ui, rejected: a `return` of a reference inside a `critical` block,
  inside a `critical` block nested in another (one error), inside a loop
  inside the block, and the harmless `return first(&self.buf)` that ADR 0118's
  consequences name; accepted: the value computed inside the block and
  returned after it, and, in a function whose result is no reference, a
  `return` of a `u32` inside a `critical` block (the rule is on the type of
  the value, not on `return`).
- Decisions:
  - The rule is in `report_made_references` (`src/ty/reference.rs`), beside the
    `break` case it copies: when the walk meets a `critical` block it walks the
    block once more and records the id of each `return` with a value in a
    `returning` set (as `leaving` does for the `break`s); a `return` with a
    value whose type is a reference, and whose id is in the set, is the error.
    A set, not a depth count, so that a `return` inside two nested blocks is
    recorded twice into the same id and reported once, and because `walk` has
    no exit hook to decrement a depth. `Block::walk` has no notion of
    function, and a function body is walked on its own, so a `return` is only
    ever found in the `critical` blocks of its own function.
  - The value's type is read from the value (`tables.expr_ty(value.id)`), as
    the `break` case does, and not from the `return` expression (type `!`).
    For a byte string returned from `-> &[u8]` that is the type before the
    conversion, `&[u8; 6]` in the label; the rule is the same.
  - Text: message "a reference cannot be the value of a `return` out of a
    `critical` block" (ADR 0118's label sentence, in the `diagnostic(what)`
    form of the other cases), label at the value "`T` would outlive the
    critical section" (the `break` case's). The help is the `break` case's
    with the ADR 0118 added to the citation and "return a copy of what it
    refers to" for "break with a copy of what it refers to": the plan says "the
    help of the `break` case", and a help that says `break` under a `return`
    would mislead.
  - A `return` without a value, and one whose value is not a reference, are
    not judged; nor is a `return` after the block or in a block that is not
    `critical`.
  - Tests, as two files under `tests/ui/`: `returned_reference_critical_errors.
    ers` (`typeck`: the harmless `return first(&self.buf)`, a `&mut` one, the
    plain one, two nested blocks (one error), a loop and an `if` in the block,
    a `critical` in a loop, a byte string, two `return`s in one block (an error
    each), and a `return` inside a plain block inside a `critical` one) and
    `returned_reference_critical_accepted.ers` (`mir`, so the analysis also
    runs: the value computed inside and returned after, a `u32` returned from
    inside a block, a reference returned after a block that returns a number,
    and a reference returned from a block that is not `critical`). The accepted
    file is `mir` and the rejected one `typeck` because a type error stops the
    later stages, as in the other `reference_*` files.
  - `tests/rejected.rs`: a second `ty::reference-position` snippet (a
    `critical { return injected_s; }` function), since the catalog may repeat a
    code for a case of its own (`resolve::duplicate-item` does); the first
    snippet (a struct field) is kept. `docs/reference.md`: the row of
    `ty::reference-position` gained "the value of a `return` inside one"; the
    prose of "No reference leaves a `critical` block" is step 11's.
  - No snapshot of an earlier test moved, and no panic was added.
