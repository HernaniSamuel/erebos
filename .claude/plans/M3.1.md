# Plan: M3.1 Memory maps

ADRs: 0057
Base: 8add5cf
Program on QEMU: a program laid out as on a small board (64 KiB of
"flash", 16 KiB of RAM with a 2 KiB stack), checking where its code,
data and stack are (`tests/e2e/memory_map.ers`, step 7).
Out of scope:
- `peripheral` blocks and everything about registers (M3.2 to M3.4);
- the second target and the per-target description beyond what this step
  removes from `src/target.rs` (M3.5);
- placing statics in named regions, statics left uninitialized across a
  reset, and reading the map's values from code (roadmap, deferred ideas;
  ADR 0057);
- detecting a stack overflow at run time, which needs trap handlers (M4);
- moving `_start` into the language (M4, ADR 0012).

Before step 1: the `docs(adr)` commit that accepts ADR 0057 also sets the
status lines of the ADRs it amends, in the files as
`Accepted; amended by NNNN (what changed)` and in the index
(`docs/adr/README.md`) as `Accepted, amended by NNNN`:
- ADR 0012: amended by 0057 (`_start` at the origin of the code's region,
  the stack's top from the linker script, a declared stack);
- ADR 0030: amended by 0057 (the `memory` block replaces the fixed split
  of QEMU's RAM; the load image of `.data` is its run range when data
  shares the code's region).

Order: the block is parsed (1), resolved (2) and computed (3) before it
reaches the linker (4). Until step 6 a program without a block keeps the
fixed layout of ADR 0030, so that every test program can gain its block
in a commit of its own (5) before the block becomes required (6).

## 1. feat(parser): parse memory blocks
- Status: done
- Implements: ADR 0057, "The `memory` block" (the grammar, and
  `parser::local-memory`).
- Changes:
  - `src/syntax/ast.rs`: `Item::Memory(MemoryDecl)`, holding its
    attributes and visibility like other items, its regions (name,
    `origin` and `size` expressions, span) and its placements (`code`,
    `data`, or `stack` with its `size` expression; the region's name;
    span), in source order.
  - `src/syntax/parser.rs`: at the start of an item, the identifier
    `memory` followed by `{` starts a block, parsed by the ADR's grammar
    (a trailing comma after the last field is allowed; a `;` after
    `stack in R { ... }` is a `parser::unexpected-token`). Inside it,
    `region`, `origin`, `size`, `code`, `data`, `stack` and `in` are
    recognized by their text. The lexer is unchanged: these words stay
    identifiers. `pub memory` is a `parser::misplaced-pub`. In a
    function body, `memory {` followed by `region` and a name, or by
    `code`, `data` or `stack` and `in`, is `parser::local-memory`, and
    `memory {` is a point where error recovery (`recover_to_item`)
    stops.
  - `src/hir/lower.rs`: skips the item for now; step 2 lowers it.
- Tests (ui):
  - `parse_memory.ers` (`emit: ast`): a block with three regions, one of
    them holding nothing, the three placements interleaved with the
    regions, a trailing comma, and expressions naming constants.
  - `parse_memory_errors.ers`: fields out of order, a missing field, an
    unknown word, a missing `;`, a `;` after the stack's braces,
    `stack in R;` without a size, and `pub memory`; each a
    `parser::unexpected-token` or `parser::misplaced-pub` at the right
    token.
  - `parse_local_memory.ers`: a block in a function body is
    `parser::local-memory`, and an item after a broken block is still
    parsed (recovery).
  - `memory_names.ers` (`emit: typeck`): `memory`, `region`, `code`,
    `data`, `stack`, `size`, `origin` and `in` used as names of locals,
    functions and a module still compile, and `memory { data: 1 }`, a
    literal of a struct named `memory` in a body, is not a block.
- Decisions:
  - The AST keeps regions and placements in two lists (`regions`,
    `placements`), each in source order, as the step names them; the
    interleaving is still visible in the spans, which is all step 2's
    "second" needs. A `Placement` is a `PlacementKind` (`Code`, `Data`,
    `Stack { size }`), the region's `Ident` and a span from the keyword to
    the `;` or the stack's `}`; a `RegionDecl` spans `region` to its `}`;
    the block spans `memory` to its `}`.
  - `MemoryDecl` keeps `vis` as the plan says, although `pub` is always
    reported on it, like `FnDecl` for the entry function: `pub memory` is
    reported and the block still parsed with `Visibility::Pub`.
  - The words are recognized by three parser helpers, `word_at` (the
    text of an identifier token), `at_word` and `at_memory` (`memory`
    followed by `{`), plus `at_local_memory` for the body's longer
    lookahead. The lexer is untouched.
  - In a body, the local check is a guarded arm right after the `static`
    one, before the `mod` and `use` arms (it only matches an identifier,
    so it cannot shadow them) and before the expression statement, which
    it must precede; after the error
    the block is parsed and dropped, like the other `parser::local-*`.
    Its message: "a `memory` block cannot be declared inside a function",
    labeled "inside a function" at `memory`, with a help to move it out.
    As for `parser::local-const`, a `comptime` block's body gets the same
    message.
  - `recover_to_item` stops at `memory {` with no further lookahead, as
    the step says, so after an error in a body a later `memory { data: 1
    }` literal would be parsed as a block and give one more error; the
    stricter lookahead of `at_local_memory` would avoid that but would let
    recovery skip a broken item-level block.
  - Syntax errors in the block are `parser::unexpected-token` with a help
    giving the shape of what was being parsed: the block's entries, a
    region's fields in order, or a placement (one help for `code`/`data`,
    one for the stack with its size). A missing token or word is reported
    where `expect` reports it (`missing_token_span`); a word that starts
    no entry is reported at that word ("expected `region`, `code`,
    `data`, `stack` or `}`"), as `item` reports stray tokens. So a missing
    `size` is "expected `,`" at the region's `}`, fields out of order
    "expected `origin`" at `size`, a `;` after the stack's braces the
    stray-token error at `;`, and `stack in R;` "expected `{`" at `;`.
    Two helpers carry the help: `error_expected_help` and
    `report_unexpected_help`, with `expect_help` and `expect_word` over
    them.
  - `misplaced_pub` reports `pub memory {` with "`pub` does not apply to
    a `memory` block" and a help (no name, describes the whole program,
    ADR 0057).
  - `origin`, `size` and the stack's size are parsed with `nested_expr`,
    as enum variant values are, since the braces delimit them.
  - `parse_memory_errors.ers` puts `pub memory` first: recovery skips a
    `pub` after an error, so it would not be reported in a later
    position. Each other case is a block of its own, which also shows
    recovery stopping at `memory {`. `parse_local_memory.ers` covers the
    four starts of a local block (`region` and a name, `stack in`,
    `data in`, `code in`), recovery after a broken item-level block
    (the next function's `parser::local-const` is reported) and recovery
    from a broken function to a `memory` block (its error is reported).
    `memory_names.ers` has the struct literal both at the start of a
    statement, where the lookahead runs, and inside an expression, and
    needs an entry and a panic function to reach `typeck`. The struct
    `memory` has the fields `data` and `region`, so that both branches of
    the lookahead have a literal at the start of a statement that is not
    a block: `memory { data: 1, ... }` (`data` not followed by `in`) and
    `memory { region: 3, ... }` (`region` not followed by a name); the
    second came from the review.
  - `hir::lower` skips `Item::Memory` in `Items::collect`, the only
    exhaustive match over items.

## 2. feat(resolve): memory blocks in the HIR
- Status: done
- Implements: ADR 0057, "The `memory` block" (one per program, names,
  placements) and the first table of "What is checked".
- Changes:
  - `src/hir/mod.rs`: the program's memory map, if any: its regions
    (name, `origin` and `size` as values computed at compile time in the
    scope of the block's module, as `#[align(N)]` arguments are, spans)
    and its placements as region indices, with the stack's size.
  - `src/hir/lower.rs`: collects blocks from every module and reports
    `resolve::duplicate-memory`, `resolve::duplicate-region`,
    `resolve::unknown-region`, `resolve::duplicate-placement`,
    `resolve::missing-placement` (at the block),
    `resolve::stack-with-code`, `resolve::reserved-name` for a region
    named `INCLUDE`, and attributes on the block as
    `resolve::misplaced-attribute`, with "second" as the ADR defines
    it. The `hir` dump shows the map.
- Tests (ui): one snapshot per code above, including two blocks in
  different modules (the error at the one in the later file); a `hir`
  dump of a block in a module, whose values name a constant of that
  module; a `const RAM` beside `region RAM`, the constant used in the
  block's expressions (accepted); and `RAM` named in a function where
  only a region has that name (`resolve::unknown-name`).
- Decisions:
  - `Hir::memory: Option<MemoryMap>`, after `comptime_blocks` (and in the
    same place in the dump). A `MemoryMap` holds the block's span, its
    regions (`RegionDef`: name, name span, `origin` and `size` each as
    `(ArrayLen, Span)` like `#[align(N)]`, span from `region` to `}`), one
    `Placement` (region index, span) each for `code`, `data` and `stack`,
    and `stack_size: (ArrayLen, Span)`. The module is not kept: the values
    are already lowered in its scope, and nothing later needs it.
  - The map is `None` when a placement is missing or names no region, so
    that later layers get indices that always exist; lowering errors stop
    the pipeline before type checking, and only `--emit=hir` shows such a
    block, as `None`. A repeated region or placement keeps the first, and
    `stack-with-code` and `reserved-name` leave the map in place.
  - The values are lowered by `array_len`'s code, now
    `comptime_usize(expr, name)` with `array_len` calling it with
    `"length"`, so that the bodies are named `origin`, `size` and
    `stack_size` in the dumps instead of `length`. Every value is lowered,
    those of a repeated region or placement and of a second block too, so
    that errors in them are reported; the ones not in the map are bodies
    nobody refers to.
  - Blocks are gathered in `Items::collect` with their module
    (`Items::memories`, counted in `Counts`) and lowered in the program's
    pass, after its enums, so that their expression ids and value bodies
    come before `core`'s. Each block is checked on its own
    (`Lowerer::memory_decl`); `memory_map` then sorts the blocks by file
    and position, keeps the first and reports each other one. The sort is
    needed: a `mod board;` before the root's block gathers `board.ers`
    first, though its file comes later.
  - Spans: `duplicate-memory` points at the word `memory` of each later
    block ("another `memory` block"), labeling that of the first ("the
    first one"); `missing-placement` points at the word `memory`, one
    error per missing placement, with a help giving the line to add
    (`stack in REGION { size: SIZE }`). Placements are shown from their
    word to the region's name (`stack in RAM`), without the `;` or the
    stack's braces; `unknown-region` points at the name alone; the region
    checks at region names.
  - `stack-with-code` follows the ADR's "second": it points at the later
    of the two placements and labels the earlier, each labeled with what
    it places ("the stack, in `RAM`", "the code, in `RAM`"); it is checked
    only when both placements name the same existing region.
  - A placement naming no region still counts as placed: it is not also a
    `missing-placement`, and a later one of the same word is a
    `duplicate-placement` (both errors when that one names no region
    either). A placement naming a repeated region names the first.
  - `reserved-name` is for the exact name `INCLUDE` only, as the ADR
    writes it; `include` and `Include` are accepted (tested). Its label
    says it is a command of the linker script language.
  - Attributes go through `no_attrs` ("a `memory` block"): `align`,
    `packed` and `export` are `misplaced-attribute`, any other
    `unknown-attribute`, as for constants and enums.
  - Tests are one file per code, named `resolve_memory_*`, all
    `emit: hir` but the constant beside a region (`emit: typeck`, which
    shows the values typed and that the program gets past resolution).
    `resolve_memory_duplicate/` has the root's block, a block in
    `board.ers` gathered before it, and a third in an inline module after
    it: both later ones are reported against the root's. `resolve_memory`
    puts the block in an inline module whose private `KIB` the root cannot
    see, with the placements before and between the regions, so that the
    indices are not in source order. `resolve_ok`'s dump gains
    `memory: None`.

## 3. feat(typeck): compute and check memory maps
- Status: done
- Implements: ADR 0057, the second table of "What is checked".
- Changes:
  - `src/target.rs`: the stack alignment (16) and the code alignment (4)
    of riscv32.
  - `src/query.rs`: computes each `origin` and `size` as a `usize`, then
    checks `ty::empty-region`, `ty::region-out-of-range`,
    `ty::region-overlap`, `ty::misaligned-code` and `ty::stack-size`,
    from `check_all`, so that the errors come whatever stage stops the
    front end after type checking. A check that needs a value that
    failed is skipped.
  - `src/mir/mod.rs`: `Mir` carries the computed map (region names,
    origins, sizes and spans; which region holds code, data and the
    stack; the stack's size), the data the linker script is made of.
  - `src/ty.rs`, `src/mir/mod.rs`: the `typeck` and `mir` dumps show the
    computed map.
- Tests (ui):
  - one snapshot per `ty::` code; for `ty::region-overlap`, regions
    touching at one end (accepted), sharing one byte (rejected), and
    three regions overlapping pairwise (three errors); for
    `ty::region-out-of-range`, a region ending at `0xFFFF_FFFF`
    (accepted) and one ending at 2³² (rejected); for
    `ty::misaligned-code`, a code origin of `0x8000_0002`, and the same
    origin for a region holding only data (accepted); for
    `ty::stack-size`, 0, 8, `size + 16` for a region whose size is a
    multiple of 16, a stack exactly filling a region whose origin is
    `0x2000_0004` (too large once rounded up), and 24 in a region too
    small for it (reported as not a multiple);
  - a `size` of the wrong type (`ty::mismatched-types`) and an `origin`
    whose evaluation fails (an `eval::` error at the expression), the
    latter overlapping another region: no overlap or stack error
    follows;
  - `typeck` and `mir` dumps of a map whose values come from constants
    and a `comptime` function call.
- Decisions:
  - The alignments are constants, `target::STACK_ALIGN` and
    `target::CODE_ALIGN`, beside `POINTER_BITS`, rather than fields of
    `Target`: the front end has no `Target` at hand and uses the other
    target values the same way, "fixed while there is one target"; M3.5
    can move them.
  - `Queries::check_memory_map` runs in `check_all` right after every
    `Comptime::Value` body is computed, so that the type and evaluation
    errors of the block's values come first and the map's checks only
    read cached values. Order of its errors: per region in source order
    `empty-region` then `region-out-of-range`; then the overlaps, grouped
    by the later region (pairs `(0,1)`, `(0,2)`, `(1,2)`); then
    `misaligned-code`; then `stack-size`.
  - Skipping: a region's range needs its origin and size; overlap needs
    both ranges, `misaligned-code` the code region's origin, the stack's
    zero and multiple checks its size only, the fit check also its
    region's range. The checks are otherwise independent: an
    out-of-range region still takes part in overlaps, and an empty region
    holding the stack still gets the fit error (two true errors). An
    empty region overlaps nothing, by the range test itself.
  - Spans and wording: `empty-region` at the `size` expression ("a size
    of 0"); `region-out-of-range` at the region's name ("ends at
    0x100000000"); `region-overlap` at the later region's name labeling
    the earlier's, each "covers [lo, hi)", message "the regions `A` and
    `B` overlap", help giving the shared bytes ("the byte at X" or "N
    bytes from X"); `misaligned-code` at the code region's `origin`
    expression ("0x80000002 is not a multiple of 4"), labeling the `code
    in R` placement; `stack-size` at the stack's `size` expression, with
    three messages (size 0, "not a multiple of 16", "does not fit in the
    region `R`"), the last labeling the region's name with its end and
    the size with the rounded start and the end it reaches. Addresses are
    printed `{:#x}`, sizes in decimal.
  - The computed map is `mir::MemoryMap` (`regions: Vec<mir::Region>`
    with name, origin, size and the span of the name, where diagnostics
    about a region point, as in step 2; `code`, `data`, `stack` as region
    indices; `stack_size`), carried as `Mir::memory: Option<_>`, `None`
    without a block (until step 6 makes it required to build). It is a
    MIR type of its own, so codegen and the linker never see the HIR.
  - `Queries::memory_map` builds it, `None` without a block or when a
    value failed; `into_mir` expects it when the HIR has a block (no
    errors by then). The `typeck` dump prints that same value through
    `mir::MemoryMap`'s `Display`, so the two dumps share one format and
    `ty.rs` gains no formatter; with a failed value the dump is discarded
    with the errors anyway, so it is left out rather than shown with `?`.
  - Format: the block as written, values computed, placements in the
    order `code`, `data`, `stack`, first in both dumps (it concerns the
    whole program); the MIR dump follows it with a blank line, as its
    other sections are.
  - Tests are named `typeck_memory_*` (all `emit: typeck`, so that the
    errors are seen to come at type checking) and `mir_memory.ers`. Each
    `stack-size` case needs a program of its own (one stack per program):
    `_zero`, `_not_multiple` (8), `_too_large` (`0x1_0000 + 16` in a
    region of `0x1_0000`), `_rounded` (origin `0x2000_0004`) and `_both`
    (24 in a 16-byte region). The data-only origin `0x8000_0002` cannot
    share a program with the misaligned code origin (they would overlap),
    so `_misaligned_data` is a `typeck` dump at `0x8400_0002`, with a
    region holding nothing at an odd origin and a stack region at an odd
    origin that the stack fills exactly once rounded up (the boundary
    accepted). `_out_of_range` has `TOP` ending at `0xFFFF_FFFF` and
    `LAST` (`0xFFFF_FFFF`, size 1) ending at 2³², which touch; no other
    region can end at or past 2³² without overlapping them. `_overlap`
    also has an empty region inside another: only its `empty-region`.
    `_failed_values` has a `u32` size (`ty::mismatched-types`) on a
    region that would overlap `FLASH`, and an origin `0x8000_0000 + 4 /
    zero()` (`eval::panic`, division by zero, at the expression) on the
    stack's region, which would overlap `FLASH` and be too small for the
    stack: only the two errors. `resolve_memory_region_const`'s `typeck`
    snapshot gains the map.

## 4. feat(link): generate the linker script from the memory map
- Status: todo
- Implements: ADR 0057, "The linker script", and `link::region-overflow`.
- Changes:
  - `src/link.rs`: `linker_script` takes the computed map: `MEMORY` with
    every region under its name; an output section holding only
    `.text.start`, then `.text`, `.rodata` and the initial values of
    `.data`, in the code's region; a
    `.stack` section (`NOLOAD`, start aligned to the stack alignment,
    `__stack_start`, `size` bytes, `__stack_end`), then `.data` and
    `.bss` in their regions, `.data` without `AT>` when it shares the
    code's region; the rest as ADR 0030. A program without a map keeps
    the fixed layout until step 6, which also defines `__stack_start`
    and `__stack_end` (the top of RAM).
  - `src/codegen/mod.rs`: `_start` sets `sp` from `__stack_end`
    (`la sp, __stack_end`) instead of an immediate.
  - `src/driver.rs`, `src/main.rs`: `Stage::LinkerScript`
    (`--emit=linker-script`), after `mir`; `build` passes the map to
    `link`. When `ld.lld` reports sections that will not fit in a
    region, the driver reports one `link::region-overflow` per region,
    at its span, naming the first section that does not fit (the
    initial values of `.data` by that name) and the largest overflow;
    other linker errors are reported as today.
- Tests:
  - ui `link_memory.ers` and `link_memory_shared.ers`
    (`emit: linker-script`): the script of a map with a region holding
    nothing, and that of a map whose code and data share a region (no
    `AT>`).
  - ui: the LLVM IR snapshots that show `_start` change in its first
    instruction only.
  - `tests/elf.rs`: a program with a map: `_start` is at the code
    region's origin; `__stack_start` is the stack region's origin and
    `__stack_end` the start plus the size; `.data` starts at or above
    `__stack_end`; `__data_load` and every loaded section lie in their
    regions; the disjointness checks of ADR 0030 pass. One with a stack
    region whose origin is not a multiple of 16: `__stack_start` is
    rounded up. One whose code and data share a region: `__data_load`
    equals `__data_start`, and the checks of ADR 0030 other than
    disjointness pass. One whose code region starts at `0x8000_0004`,
    linked with an assembly or C object whose code section is aligned
    to 64: `_start` is still at `0x8000_0004`.
  - `tests/elf.rs`: building a program whose code and `.rodata` do not
    fit their region (one diagnostic, with the largest overflow), and
    one whose `.bss` does not fit beside its stack, fails with
    `link::region-overflow`; the rendered diagnostics are snapshotted.

## 5. test: declare the memory map in every program that is built
- Status: todo
- Implements: ADR 0057, "Consequences" (every program built declares a
  block).
- Changes: every root file of `tests/e2e/` (single files and the
  `main.ers` of each directory) and every program `tests/elf.rs` and
  `tests/reproducible.rs` build gains the block equivalent to the layout
  of ADR 0030: `IMAGE` at `0x8000_0000` and `RAM` at `0x8400_0000`, 64 MiB
  each, `code in IMAGE`, `data in RAM`, and a stack of 1 MiB at the start
  of `RAM`. The fixed addresses programs use are all in `IMAGE`, above
  the program, and stay valid. The block is copied into each program:
  a shared board module cannot be reached from the single-file programs
  and the program directories alike (ADR 0049); this goes in the step's
  Decisions.
- Tests: every e2e program passes at both optimization levels with its
  expectations unchanged; the ELF and reproducibility tests pass. That
  the fixed layout is no longer used by any of them is what step 6
  proves.
