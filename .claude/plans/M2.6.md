## 1. refactor(parser): paths in the syntax tree
- Status: done
- Implements: groundwork for ADR 0049, "Paths"; no change in what is
  accepted.
- Changes:
  - `src/syntax/ast.rs`: a `Path` (its segments, each an `Ident`, and
    its span) wherever an item is named: `TyKind::Named` and
    `TyKind::Applied`, `ExprKind::Name`, `Call`, `StructLit`, `Path`
    and `PathCall` (the last two merge into the path forms), and the
    path patterns. Locals stay single names.
  - `src/syntax/parser.rs`: parses the same programs as today; a path
    still has one segment, or two where an enum variant is written
    (`E::V`).
  - `src/hir/lower.rs`: reads the new nodes; resolution unchanged.
- Tests: every ui snapshot stays as it is except the `ast` dumps
  (`parse_*`), which show the new nodes; no other change. The step is a
  refactor: `cargo test` passing with only those snapshots changed is
  the proof.
- Decisions:
  - `ast::Path` is `segments: Vec<Ident>` (at least one) and `span`, the
    first segment's start to the last one's end. It has two helpers:
    `Path::single(ident)`, to build a path of one name, and
    `as_single()`, the name when the path is one, which the parser and
    `lower` use to tell a name from `Enum::Variant`.
  - The merged variants keep the names of the single-name forms:
    `ExprKind::Name(Path)` holds what were `Name` and `Path`,
    `ExprKind::Call(Path, args)` what were `Call` and `PathCall`, and
    `PatternKind::Name(Path)` what were the pattern `Name` and `Path`.
    `PatternKind::PathArgs(Path, patterns)` keeps its name, as patterns
    have no `Call`. Renaming more would only grow the `ast` dumps' diff.
  - Unchanged, as single names: locals (`let`, parameters, binding
    patterns), field names (`FieldInit`, `.field`, `offset_of`'s field),
    `.V` variants and every declared item's name.
  - The parser reads expression and pattern paths with one helper,
    `Parser::path`: a name, then at most one `:: name`. Types build
    `Path::single` directly, since a type path is one name in this step.
    What is accepted after a path stays as it was: `(` makes a call for
    any path, `{` a struct literal only after one name, and `(` in a
    pattern only after `Enum::Variant` (a bare name followed by `(` is
    still `parser::unexpected-token`). The `Option(..)::` help is still
    armed only after a call of the single name `Option` or `Result`.
  - The span of a `Name` expression is now its path's span, which for
    `E::V` is what `token.span.to(variant.span)` gave before.
  - `lower` dispatches on `path.segments.as_slice()`: `[name]` takes the
    old single-name route, `[enum, variant]` the old `Enum::Variant`
    route. Places where the parser makes only one name (types, struct
    literals, callees other than variants, `assert`, `len`, `slice`) go
    through a free function `one_name`, and any other shape is
    `unreachable!`, like the other parser-held invariants in `lower`.
    Step 2 replaces this dispatch with path resolution.
  - The named-type arm of `Lowerer::ty` moved into a new
    `Lowerer::named_ty(&Ident)`, so that the path is unwrapped once
    rather than in every match guard; its diagnostics are unchanged.
  - Snapshot review: a script checked that each of the 16 changed
    `parse_*` dumps, with every `Path { segments: [..], span }` unwrapped
    and the old `Path`/`PathCall` renamed `Name`/`Call`, equals the old
    dump, and that every path's span runs from its first segment to its
    last. insta added an `assertion_line` header to the new files; it
    was kept only in those whose old snapshot had it, so the headers do
    not change.

## 2. feat(resolve): inline modules, paths and item visibility
- Status: done
- Implements: ADR 0049, "Modules" (inline only), "Namespaces",
  "Paths", "Names in diagnostics and dumps" and the codes
  `parser::local-mod`, `resolve::unknown-path`,
  `resolve::misused-module`, `resolve::super-at-root` and the wider
  `resolve::not-an-enum`; ADR 0050, "Items" (without `pub use`), with
  `parser::misplaced-pub` and `resolve::private-item`.
- Changes:
  - `src/syntax/{token,lexer}.rs`: the keywords `mod`, `pub`, `crate`,
    `super` (`use` comes with step 5).
  - `src/syntax/{ast,parser}.rs`: `Item::Mod` with its name, `pub` and
    an inline body (a `mod name;` without body is parsed now and is
    `resolve::module-file` until step 4 loads it); `pub` on items, with
    `parser::misplaced-pub`, and `parser::unexpected-token` elsewhere;
    `mod` in a body, `parser::local-mod`; paths of any length starting
    with a name, `crate` or `super`.
  - `src/hir/{mod,lower}.rs`: a module tree, each module with one
    namespace of items and child modules; the flat maps of `lower` (one
    per kind of item) become lookups in the namespace of the module the
    code is in. Every item records its module, its visibility and its
    path for display. Path resolution follows ADR 0049; each segment is
    checked visible from the module of the use (ADR 0050).
    `resolve::duplicate-item` per module. The entry and panic functions
    are found in every module. Structs and enums display by path in
    diagnostics and in the `hir` and `typeck` dumps.
  - Symbols are unchanged in this step: two functions with one name in
    two modules are two LLVM functions, which LLVM tells apart by
    renaming one; step 3 names them.
- Tests:
  - ui (resolve) `resolve_modules.ers`: inline modules holding every
    kind of item, used by path from the root, from a child through
    `super` and `super::super`, and through `crate`; the same name in
    two modules; items referring to each other across modules in any
    order; paths in types, `Option(m::T)`, arrays, pointers, constants,
    statics, calls, struct literals, variants, patterns, `size_of`,
    `align_of` and `offset_of`.
  - ui (resolve) `resolve_module_errors.ers`: each code of this step;
    a name of the parent used without `super`; an unknown segment in
    each position, naming its module; a struct, a constant and `Option`
    before `::` (`resolve::not-an-enum`, the `.None` help kept); a
    module as a type, a value, a callee and a struct literal;
    `resolve::duplicate-item` in a module.
  - ui (resolve) `resolve_visibility_errors.ers`: a private item used
    from its module and a descendant (accepted) and from a sibling and
    the parent (rejected); a `pub` item of a private module reached
    from its grandparent's other child (rejected); `pub` on every kind
    of item; `pub entry fn`, `pub comptime`, and `pub` before a variant,
    a parameter and a `let`.
  - ui (typeck) `typeck_modules.ers`: diagnostics naming types by path
    (`expected uart::Config, found u32`).
  - ui (mir) `mir_modules.ers`: calls and statics across modules, and
    entry and panic functions in a submodule.
  - The structs of these tests whose literals cross modules are given
    no fields, or are built inside their module, so that step 6 does
    not change their meaning; step 6 updates any that remain.
- Decisions:
  - Syntax. `crate` and `super` are path segments, `ast::Ident`s named
    by their keyword, which no other name can be. `Parser::path` reads
    a name, `crate` or `super` first, then `:: name` any number of
    times, `super` again only in a run at the start (`a::super` and
    `crate::crate` are `parser::unexpected-token`, "expected
    identifier"). Types, expressions and patterns start a path at any of
    the three tokens. `{` makes a struct literal after any path
    (`uart::Config { .. }`), and `(` in a pattern makes `PathArgs` after
    a path of two segments or more, as before for `E::V(..)`.
  - `pub` is read in `Parser::item`, after the attributes, and stored as
    `ast::Visibility` (`Private`, `Pub`) in a `vis` field of every
    declaration with a name, `ModDecl` included; `ComptimeDecl` has
    none. `parser::misplaced-pub` points at `pub` ("`pub` does not apply
    to a `comptime` block" / "to the entry function", with a help to
    remove it) and parsing goes on, so the item is still in the AST.
    Every other place gets `parser::unexpected-token` from the parser as
    it was (`pub pub` is "expected an item, found `pub`").
  - `pub` is not a token `recover_to_item` stops at: the misplaced `pub`
    that caused an error (`enum E { pub A = 0 }`) would otherwise be met
    again and reported a second time; skipping a `pub` before a good item
    loses nothing, since errors stop the pipeline. `mod` is one.
  - `ast::ModDecl { attrs, vis, name, items: Option<Vec<Item>>, span }`,
    `items` `None` for `mod name;` (step 4 fills it). A body is read
    like the file, item by item with the same recovery. An unclosed body
    is `parser::unclosed-block`, as a block's. A `mod` in a function
    body is `parser::local-mod` at the keyword, and the declaration is
    then parsed and dropped, as `parser::local-const` does.
  - Recovery in a module's body (from the review): the parser counts the
    `{` left open by the tokens it has consumed (`Parser::depth`,
    updated in `bump`), and a module's body records the depth of its
    items (`module_depth`). `recover_to_item` also stops at a `}` at that
    depth, which closes the module: an error in its last item no longer
    skips the module's `}`, carries the items after it into it and
    reports a false `parser::unclosed-block`. A `}` at a deeper depth,
    such as a function body's, is still skipped, which stopping at any
    `}` would not do. Recovery at the top of the file is unchanged.
  - HIR: `ModuleId` (`ModuleId::ROOT` is 0), `hir::Visibility` and
    `ModuleDef { name, path, name_span, parent, vis }` in `Hir::modules`,
    the root first, then in the order the `mod`s are met, depth first.
    The root's name and path are empty and its `vis` is `Pub`. `Fn`,
    `ConstDef` and `StaticDef` gain `path` (for display), `module` and
    `vis`; their `name` stays the declared name, which MIR and codegen
    use as the symbol until step 3. `StructDef` and `EnumDef` gain
    `module` and `vis`, and their `name` (and `StructTy::name`,
    `EnumTy::name`) becomes the path, since a type has no symbol: every
    diagnostic and dump that shows a type shows its path without
    touching the type checker. Bodies run at compile time take the
    module they are written in and `Private` (nothing names them); their
    `path` is the constant's or static's, `m::E::V` for a variant's
    value, and `comptime` and `length` as before. An `Option(T)` or
    `Result(T, E)` instance is in the root module and `Pub`.
  - The namespaces stay in `lower.rs`, not in the HIR: no later layer
    needs them in this step. `Items` walks the AST once, depth first in
    the order written, giving each item its id and its module and
    filling each module's `HashMap<String, Entry>` (`Entry`: a `Def`,
    its visibility, its name's span, whether the runtime declared it).
    Ids therefore follow the source as before, and one-file programs
    keep theirs. `Lowerer::module` is set before each item is lowered;
    the per-kind maps are gone.
  - The runtime's items are gathered after the program's, into the root
    module, private. A submodule reaches them as `crate::memcpy` (or
    `super::`), not as `memcpy`: like any name of a parent. Step 7
    moves them into `core`.
  - The checks for reserved names (`assert`, `len`, `slice`, `__`, the
    runtime's names) and `resolve::duplicate-type` apply to every item
    and module of every module: built-in names are in every module
    (ADR 0049), and symbols do not change in this step, so a `fn
    memcpy` in a submodule would still clash with the runtime's.
  - A `mod` takes no attributes: `#[packed]` and `#[align]` on one are
    `resolve::misplaced-attribute` ("not allowed on a module"), any
    other `resolve::unknown-attribute`, through the `no_attrs` the other
    items use, in `Lowerer::mod_decl`.
  - `_start` (from the review): with the entry function in any module,
    a function of the same name declared before it, in another module,
    keeps that name in LLVM, which names the entry function `main.1`;
    `_start` jumped to `main`, booting the wrong function. Codegen now
    builds the start stub from the name of the LLVM function made for
    `mir.entry` (`get_name()`), so the program works now rather than
    being rejected until step 3, which gives the functions distinct
    symbols and makes the two names agree again.
  - `resolve::duplicate-item` is per module, the first declaration
    keeping the name, and is still pushed after lowering, so that at one
    position the order of diagnostics is the old one. Its help is the
    old one, unless one of the two is a module: "the items and modules
    of a module share one namespace (ADR 0049)".
  - Resolution is `Lowerer::lookup_path`, giving `Named::{Item(Def),
    Variant, Missing(module), Failed}`. It reports the errors of the
    segments before the last (and `resolve::unknown-variant` after an
    enum) and leaves a last segment that names nothing to its caller,
    which reports the error of its position. Locals are tried only for a
    single name other than `crate` and `super`, and never before `::`,
    as before. The built-in names (types, `assert`, `len`, `slice`) are
    tried only as a single name or the first segment: "in every module"
    is read as "seen from every module", so `m::u32` is an unknown type.
  - Diagnostics of paths:
    - `resolve::unknown-path`: "cannot find `a::nope`" (the path up to
      the segment), labelled at the segment "not found in module `a`"
      or "in the root module".
    - A last segment naming nothing keeps the code and message of its
      position, with the path as written (`unknown type `a::Nope``,
      "cannot find `a::NOPE`", "cannot find function `a::nope`",
      "unknown struct `a::Nope`"), labelled at the segment "not found in
      module `a`". A single name in the root module keeps its old label
      ("not found", "not a type", "not a struct"), so one-file programs
      read as before; in another module the label names the module.
    - When a single name, or the first segment of a path, names nothing
      but a module around the current one has it, the help says so and
      writes the path: "a module does not see the names of the modules
      around it: the `LIMIT` of the root module is written
      `super::LIMIT` here (ADR 0049)".
    - `resolve::not-an-enum`: "`Point` is neither a module nor an
      enum", labelled with what it is ("a struct", "a constant", "a
      built-in type", "a built-in function", "a variant" for
      `E::V::x`), help "`::` follows a module, to name one of its items,
      or an enum, to name one of its variants, as in `Mode::Run`
      (ADR 0035, 0049)". `Option::None` keeps its old message, label and
      help.
    - `resolve::misused-module`: "`a` is a module, not a type" (or "a
      value", "a function", "a struct", and in patterns "a constant" or
      "a variant"), labelled "a module", help "a module holds items, each
      named by a path through it, as in `a::name` (ADR 0049)".
    - `resolve::super-at-root`: "the root module has no parent", at the
      `super`, label "`super` of the root module", help on `crate`.
      `super::super` one level down reports the second `super`.
    - `resolve::private-item`: "`outer::helper` is private", labels "not
      visible here" at the segment and "declared here without `pub`" at
      the declaration, help "a private item of module `outer` is
      visible only there and in the modules inside it; declare it `pub`
      to use it elsewhere (ADR 0050)". Each segment is checked; the
      private item still resolves, so nothing else is reported about
      it.
    - An item of the wrong kind now says what it is: as a value "a
      struct, which is not a value" (like the existing "a function,
      which is not a value"; it was "not found"), as a callee "a
      constant, not a function", as a type "a constant, not a type", in
      a struct literal "an enum, not a struct" or "a variant, not a
      struct". The namespace lookup knows it, where the old per-kind
      maps did not.
    - In a pattern, a path of several segments resolves as in an
      expression: a variant or a constant (`a::LIMIT`); another item is
      `resolve::not-a-constant`, one naming nothing
      `resolve::unknown-name`. A path with patterns that names no
      variant (`a::C(p)`) is reported as `resolve::unknown-variant`,
      "`a::C` is not a variant", labelled "a constant, not a variant":
      no ADR code fits exactly, and this is the closest; the user chose
      to keep it.
    - `resolve::module-file`, until step 4 reads files: "the file of
      module `file` cannot be read", at the declaration, label "declared
      without a body", help that only inline modules are read so far.
  - ADR 0049 shows every item outside the root by its path in
    diagnostics and the `typeck` dump, where the plan names structs and
    enums: functions, constants and statics also display by `path`, in
    `ty.rs` (the dump, `ty::wrong-arg-count`, places, patterns),
    `query.rs` (what a body is, cycles) and the `eval::extern-call`
    message. `eval` messages about statics read the MIR static's name,
    the declared name in this step; they are left for step 3, which
    names MIR statics.
  - Existing snapshots that change: every `parse_*` dump (a `vis` line
    per declaration; the insta header kept as it was), `resolve_ok` (the
    module tree and the new fields), `resolve_enum_errors` and
    `resolve_match_errors` (`X::V` with an unknown `X` is now
    `resolve::unknown-path`, the wording of `resolve::not-an-enum`, and
    the labels of a struct and an enum used as values).
  - Tests: a parse error stops the pipeline before resolution, so the
    parser's codes cannot share a file with the resolver's:
    `parser::local-mod`, `parser::misplaced-pub` and `pub` before a
    variant, a parameter, a `let` and another `pub` are in a new
    `parse_module_errors.ers`, not in `resolve_module_errors.ers` and
    `resolve_visibility_errors.ers`, which keep the resolver's codes
    (`pub` on every kind of item, accepted, is in the latter). A new
    `parse_modules.ers` dumps the AST of `mod`, `pub` and paths starting
    with `crate` and `super`; the lexer has a `module_keywords` test.
    `resolve_modules.ers` is dumped at `typeck`, which shows every item
    and the type of every expression by path, compactly; it adds an
    `extern fn`, an `extern static` and a `comptime` block to the kinds
    of items, and does `offset_of` and the literal of a struct with
    fields inside the struct's module. `mir_modules.ers` gives no two
    functions one name, since the `mir` dump shows declared names until
    step 3.
  - Tests added after the review: `resolve_module_names.ers` (a module
    named like a built-in type and a built-in function, `__x` and a
    struct `bool` in a submodule, `#[packed] mod`, and each label saying

    type", "a constant, not a function", "an enum, not a struct", "a
    variant, not a struct", and `resolve::not-an-enum` "a built-in
    type" (`u8::MAX`) and "a built-in function" (`len::x`)); the unit

## 3. feat(codegen): symbols named by module paths
- Status: done
- Implements: ADR 0051, all of it.
- Changes:
  - `src/hir/{mod,lower}.rs`: each function and static gets its symbol
    (path joined by dots, nothing for the root module, with
    `#[export]` or `extern` its own name); the attribute `export`,
    without argument, on functions with a body and statics,
    `resolve::misplaced-attribute` elsewhere; `resolve::duplicate-symbol`

    name in the root module; `_start` reserved in every module. Until
    step 7, a program item named like a runtime function keeps the
    `resolve::reserved-name` of ADR 0020, and is not also reported as
    `resolve::duplicate-symbol`.
  - `src/mir/{mod,build}.rs`: `Body::name` and the name of a static are
    the symbol, so the `mir` dump shows `uart.init`; the doc comment
    saying Erebos does not mangle is updated (ADR 0051).
  - `src/codegen/mod.rs`: unchanged but for `_start` jumping to the
    entry function's symbol.
- Tests:
  - ui (codegen) `codegen_symbols.ers`: functions and statics of
    nested modules, root items, `#[export]` items in a submodule and in
    the root, an `extern fn` and an `extern static` declared in a
    submodule, a call between modules, the entry function in a
    submodule.
  - ui (resolve) `resolve_symbol_errors.ers`: `resolve::duplicate-symbol`
    for a root item against an exported one, two exported ones and one
    `extern fn` declared in two modules; `#[export]` on each item it
    does not apply to (but `use`, step 5) and with an argument; `mod
    llvm` in the root (rejected) and in a submodule (accepted); `fn
    _start` in a submodule, with and without `#[export]`.
  - `tests/elf.rs`: the symbol table of a program with modules holds
    `m.f`, `m.n.S` and an exported name.
  - e2e `export_c.ers` with `export_c.c`: C calls an `#[export]`
    function and reads an `#[export]` static of a submodule.
- Decisions:
  - HIR: `Fn::symbol: Option<String>`, `None` for a body run at compile
    time, which has no symbol, and `StaticDef::symbol: String`. `name`
    stays the declared name: `check_start` and the namespaces work on
    names, not symbols. The symbol is computed in `fn_decl` and
    `static_decl` by a free function `path_symbol`, the module's `path`
    with `::` replaced by `.` (no name contains `::`), then the name; the
    item's own name for the root module, `#[export]` or `extern`. The
    `resolve_ok` dump (the only full `hir` dump) shows the new field.
  - MIR: `Body::name` is the symbol; a body run at compile time, having
    none, is named by its HIR `path` (`comptime fn app::driver::COUNT`),
    which tells apart two bodies of one name in two modules and is the
    old name in the root module, so one-file dumps do not change. The
    name of a MIR static is set in `Queries::mir_static` (`query.rs`),
    where MIR statics are made, not in `src/mir/build.rs` as the plan
    says; `src/mir/build.rs` only names bodies.
  - `eval` messages about statics (`eval::static-mut`,
    `eval::extern-static`, `eval::read-only-write`,
    `eval::pointer-out-of-bounds`) left by step 2: they now name the
    static by its HIR path through a helper `Interp::static_name` (a byte
    string still by its bytes), since diagnostics show paths (ADR 0049)
    and the MIR name is now the symbol. A test was added for it,
    `eval_module_static_errors.ers`, which the plan does not list.
  - Codegen: `_start` jumps to `mir.body(mir.entry).name`, the entry
    function's symbol, again; step 2's `get_name()` is removed. Symbols
    are unique once `resolve::duplicate-symbol` passes, and functions are
    declared before any private data, so LLVM keeps every symbol as the
    function's name; the plan's bullet ("unchanged but for `_start`
    jumping to the entry function's symbol") is this revert.
    `codegen_entry_name.ers` now shows `j app.main` and `@app.main`, and
    it and `entry_in_module.ers` stay as regression tests, with their
    comments updated.
  - Attributes: `fn_attrs` (functions) and `static_attrs` (now returning
    the alignment and whether the static is exported) accept `export`;
    the shared `export_attr` reports an argument as
    `resolve::attribute-argument` at the argument ("`#[export]` takes no
    argument", "remove this", as `#[packed]`), and a second `#[export]` as
    `resolve::duplicate-attribute`. Every other item reports it through
    `no_attrs` or `struct_attrs` as `resolve::misplaced-attribute`:
    "`#[export]` applies only to functions and statics defined in the
    program", labelled "not allowed on an `extern fn`" (or "an `extern
    static`", "a struct", "an enum", "a constant", "a module", "a
    `comptime` block"), help "`#[export]` gives a function or static its
    own name as its symbol; an `extern` item always has its own name
    (ADR 0051)". An `extern fn` now names itself so in the labels of

    compile time still come after every other body, so the program's are
