# Plan: M2.6 Modules and panic information

ADRs: 0049, 0050, 0051, 0052, 0053
Base: 4199e84
Program on QEMU: a panic prints `division by zero at main.ers:12`
(`tests/e2e/panic_location/`, a program of several files, step 10).
Out of scope:
- glob imports, a prelude, `self::` paths, `use` of variants, finer
  visibilities such as `pub(crate)` (not scheduled; ADR 0049, 0050);
- moving `Option`, `Result`, `assert`, `len` and `slice` into `core`
  (M6, ADR 0045, 0052);
- internal linkage for private items and removal of unused functions
  (not scheduled; ADR 0030, 0051);
- warnings for private types in public signatures (with warnings,
  roadmap deferred ideas);
- the caller's location for a function that panics on behalf of its
  caller, as Rust's `#[track_caller]` (not scheduled);
- several packages or libraries besides `core` (not scheduled).

Before step 1: the `docs(adr)` commit that accepts ADR 0049 to 0053
also sets the status lines of the ADRs they amend, in the files as
`Accepted; amended by NNNN (what changed)` and in the index
(`docs/adr/README.md`) in its style, `Accepted, amended by NNNN`:
- ADR 0014: amended by 0053 (the panic function may take a
  `*const core::PanicInfo`);
- ADR 0020: amended by 0052 (the runtime functions move into `core`);
- ADR 0026: amended by 0051 (which functions C calls by their name);
- ADR 0029: amended by 0049 (one namespace per module);
- ADR 0030: amended by 0051 (the symbols of statics);
- ADR 0031: amended by 0053 (an `assert` message reaches the panic
  function);
- ADR 0035: amended by 0049 (the code for an unknown name before `::`);
- ADR 0036: amended by 0053 (the cause is `PanicReason::NoVariant`).

## 2. feat(resolve): inline modules, paths and item visibility
- Status: todo
- Implements: ADR 0049, "Modules" (inline only), "Namespaces",
  "Paths", "Names in diagnostics and dumps" and the codes
  `parser::local-mod`, `resolve::unknown-path`,
  `resolve::misused-module`, `resolve::super-at-root` and the wider
  `resolve::not-an-enum`; ADR 0050, "Items" (without `pub use`), with
  `parser::misplaced-pub` and `resolve::private-item`.
- Changes:
  - `src/syntax/{token,lexer}.rs`: the keywords `mod`, `pub`, `crate`,
    `super` (`use` comes with step 5).
  - `src/syntax/{ast,parser}.rs`: `Item::Mod` with its name, `pub` and

  - ui (resolve) `resolve_visibility_errors.ers`: a private item used
    from its module and a descendant (accepted) and from a sibling and
    the parent (rejected); a `pub` item of a private module reached

## 4. feat(driver): file modules
- Status: todo
- Implements: ADR 0049, "Modules": the files of `mod name;`, "Order"
  and `resolve::module-file`.
- Changes:
  - `src/driver.rs`: after parsing a file, every `mod name;` it holds
    is loaded by the rule of ADR 0049, recursively, into the module's
    body; files are added to the source map in the order of ADR 0049
    (depth first, in declaration order). The driver is the only layer
    reading files, so it reports `resolve::module-file`, at the
    declaration: a missing or unreadable file, a name that matches only
    when case is ignored (checked against the directory's listing), and
    `mod main;` naming the root file. Source names of module files, in
    diagnostics and later in panic locations, are relative to the root
    file's directory with `/`, so snapshots agree between Windows and
    Linux. Reading goes through a small loader, so that step 7 can
    serve `core` from the compiler binary, and tests from memory.
  - `dump` takes the root file's path and its text: the text is
    compiled (`tests/fuzz.rs` keeps passing text it made), the path
    locates module files.
  - `src/diag.rs`: a diagnostic may label spans in several files
    (`resolve::private-item`, `resolve::duplicate-symbol`,
    `resolve::unknown-variant` and others point at a declaration
    elsewhere); each label is rendered against its own file, and a span
    never joins two files.
  - `src/main.rs`: `--emit` passes the path.
  - `tests/ui.rs`, `tests/c_layout.rs`, `tests/reproducible.rs` and the
    other callers of `dump`: pass the path. `tests/ui.rs` also runs
    every `tests/ui/*/main.ers`, the root of a program of several files,
    snapshotted under its directory's name.
  - `tests/e2e.rs`: every `tests/e2e/*/main.ers` is a program, its
    headers in `main.ers`, `link-c` files relative to its directory,
    its work files named after the directory.
- Tests:
  - ui `resolve_file_modules/main.ers`: a module declared in the root
    file (`a.ers` beside it), in a module file (`a/b.ers`), and inside
    an inline module of the root (`c/d.ers`); items used across them.
  - ui `resolve_module_file_errors/main.ers`: a missing file, a
    `mod.ers`-style layout that is not found, a file whose name differs
    in case, and `mod main;`; each error names the path; a
    `resolve::private-item` whose labels are in two files.
  - e2e `modules/main.ers` with files in a subdirectory: calls,
    statics and constants across files print over the UART, at both
    optimization levels.
  - `tests/reproducible.rs`: a program of several files builds to the
    same bytes twice, from two different working directories.

## 8. feat: panic information
- Status: todo
- Implements: ADR 0053, all but the `assert` message (step 9): the
  panic function's parameter, `core::PanicInfo` and
  `core::PanicReason`, their data for every check, `ty::panic-param`.
- Changes:
  - `rt/core.ers`: `PanicInfo` and `PanicReason` as in ADR 0053, and a
    `comptime` block asserting the size, alignment and offsets the ADR
    gives.
  - `src/syntax/ast.rs`, `src/hir/{mod,lower}.rs`: the span of the
    token that performs each check (the operator of `/`, `%`, `/=`,
    `%=`, the `[` of an index, the `?`, the `match` and `assert`
    keywords), where the nodes do not keep it yet.
  - `src/hir/{mod,lower}.rs`: the ids of `core::PanicInfo` and
    `core::PanicReason`; a table of source files, in the order of
    ADR 0049, each with its name for panic locations (relative to the
    root file's directory, or `rt/...` for `core`) and the offsets where
    its lines start, so that later layers turn a span into a line and a
    column without the source text.
  - `src/ty.rs`: the panic function takes none or one parameter of type
    `*const core::PanicInfo`, `ty::panic-param` otherwise; the entry
    function keeps `ty::special-fn-params`.
  - `src/mir/{mod,build}.rs`: `PanicCause` maps to `PanicReason`;
    when the panic function has the parameter, each check's terminator
    passes the address of read-only data (`ConstData`, with a relocation
    to the file name) holding its `PanicInfo`, located by the table of
    ADR 0053. To keep snapshots and builds deterministic: one
    `PanicInfo` per check, not shared; the empty message is address 0
    with length 0; the file names are byte string statics created
    before any body is lowered, in file order, one for every file of the
    program and of `core` (whether a file holds a check is only known
    while building MIR, ADR 0032; at `-O` the unused ones are private
    and removed). Without the parameter, nothing is built and the message of an
    `assert` is still evaluated, as today. The MIR dump shows the
    location.
  - `src/codegen/mod.rs`: the call passes that pointer when the panic
    function has a parameter.
  - `src/eval.rs`: unchanged in behavior; reads the new terminator.
  - `tests/layout/structs.h` and `tests/c_layout.rs`: the C twin of
    `PanicInfo` with `_Static_assert`s of the size, alignment and
    offsets of ADR 0053; with the `comptime` block in `core`, both sides
    are checked against the same numbers (dumps leave `core` out).
- Tests:
  - ui (typeck) `typeck_panic_param.ers`: each wrong parameter list of
    ADR 0053; a handler in a module with `use core::PanicInfo;`; an
    explicit call building a `PanicInfo`.
  - ui (mir) `mir_panic_info.ers`: `/`, `%`, `/=`, `%=`, an index, an
    index through a slice, `a[i][j]`, `a / b / c`, `(a / b)`, an
    `assert` without message, a `match` without catch-all and a `?` on
    a tag that is no variant, each with its reason, line and column.
  - ui (mir) `mir_panic_no_info.ers`: a handler without parameter, an
    `assert` whose message calls a function, still called on the
    failing path.
  - ui (codegen) `codegen_panic_info.ers` with `// opt: both`: the
    read-only data and the call passing it; a file name stored once;
    `codegen_panic_no_info.ers`: a handler without parameter, no data,
    no argument.
  - e2e `panic_division.ers`, `panic_index.ers`, `panic_no_variant.ers`
    and `panic_index_module/main.ers` (the index check in a file of a
    subdirectory): each handler prints the reason, the file, the line
    and the column, at both optimization levels.
  - Every existing handler without a parameter: unchanged snapshots and
    end-to-end results.
