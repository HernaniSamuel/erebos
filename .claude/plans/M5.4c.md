## 1. feat(ty): no reference leaves a `critical` block by `break`
- Status: done
- Implements: ADR 0110, "No reference leaves a `critical` block".
- Changes:
  - `src/ty/reference.rs`: `report_made_references` walks with a flat
    closure that knows no enclosing expression; the `break` case needs a walk
    of its own (or the existing one extended) keeping a stack of the
    enclosing loops and `critical` blocks, so that a `break` (which targets
    the innermost loop, Erebos having no labels) knows whether a `critical`
    block lies between it and its loop. A `break` with a value of a reference
    type that leaves a `critical` block is the error at the value, labelled
    "the value of a `break` out of a `critical` block", with the help of the
    `critical` case.
  - `docs/reference.md`: the row of `ty::reference-position` in the check
    table gains the case.
- Tests:
  - ui `reference_break_critical.ers` (rejected): `loop { critical { break
    &x; } }` with `x` a local, `&mut x` and a reference parameter passed on;
    a `break` two `critical` blocks deep; `loop { critical { loop { break &x;
    } } }` accepted beside `loop { critical { break &x; } }` inside an outer
    `loop`, rejected. One error each, at the value.
  - ui `reference_break_critical_accepted.ers` (`// emit: mir`): a loop
    inside a `critical` block whose `break` gives a reference; a `break` out
    of the block with a value that is not a reference; the wait of ADR 0086
    (`break` with no value).
- Decisions:
  - The walk stays the flat `Block::walk` of `report_made_references`, with
    no stack. At each `critical` block it reaches (before the expressions
    inside it), the new `breaks_out_of` walks the block once and returns the
    `break`s whose target loop is not inside it; the ids go into a `leaving`
    set, and when the main walk reaches such a `break`, it reports it if the
    value is a reference. So the diagnostics stay in source order, and a
    `break` leaving several nested blocks is in the set once and reported
    once (a `break` leaves some block exactly when it leaves the innermost
    one, so the test of ADR 0110 and "leaves any" agree). The cost is one
    extra walk per `critical` block, quadratic only in the nesting depth of
    the blocks, which is small.
  - The check is on the type of the `break`'s value
    (`tables.expr_ty(value.id)`), not of the `break`; an `Error`-typed value
    is not a reference, so it reports nothing more.
  - The message is "a reference cannot be the value of a `break` out of a
    `critical` block", the way every other position of
    `ty::reference-position` is named in the message ("a reference cannot be
    ..."); the label, at the value, is the one of the `critical` tail case
    ("`T` would outlive the critical section"), and the help is that case's,
    with 0110 added to the ADRs named and "break with a copy of what it
    refers to" for its last clause. The plan's "labelled ..." is read as the
    position naming of the message, as ADR 0105's messages do.
  - Tests: `reference_break_critical.ers` has six errors, one per case: a
    local, `&mut` of one, a reference parameter, two blocks deep, the outer
    loop's `break` beside an accepted inner loop in the same block, and a
    loop between two blocks; the accepted cases of the same shapes, and the
    ones with no value, are in `reference_break_critical_accepted.ers`
    (`// emit: mir`, so that they also reach MIR), which also holds the
    `break` after a block and a nested loop inside a block.
  - `docs/reference.md`: only the check table's row changes here; the prose
    (line "So are the value of a `critical` block ...") waits for step 8, as
    the plan says.

## 2. feat(analysis): statics and peripherals as roots of the borrow analysis
- Status: done
- Implements: ADR 0111, "Statics and peripherals are roots"; ADR 0112, "Rules
  of the validator" (R4), "The borrow analysis".
- Changes:
  - `src/mir/validate.rs`: R4 for every body.
  - `src/analysis/borrows.rs`: a path's root is a local, a static or a
    peripheral; a place whose base is a temporary of R4 followed by `Deref`
    is rooted at its static or peripheral; `Field`, `Element` and
    `ConstElement` applied to a peripheral type are `Elem` steps, below a
    `Deref` of a reference too; two peripheral roots overlap when their byte
    ranges meet (the address and the extent from the type's layout),
    whatever their steps; labels name a static or a peripheral by its path
    with `::`; `Flow::asm` counts a `sym` of a `static mut` or an `extern
    static mut` as a write of the whole static.
- Tests:
  - unit tests of the validator: R4 (a `const static` assigned to a named
    local; a temporary of R4 written a second time; `&raw const _t` of one;
    `const peripheral` the same).
  - unit tests of the borrow analysis over hand-built MIR: a `&mut` site of a
    `static mut` and a write of it while in use (a conflict, labelled with
    the static's name); two sites at two registers of one peripheral (a
    conflict), and the same below a `Deref` of a reference to a peripheral
    type; a site of one peripheral and a write of another whose bytes meet it
    (a conflict) and of one whose bytes do not (none); a `sym` of a `static
    mut` while a site of it is in use (a conflict), of a `static` (none).
  - ui `borrow_static_immutable.ers` (`// emit: mir`, accepted): `&S` of a
    `static` and of a field, held while `S` is read and lent to calls.
  - every existing test passes unchanged: no program could borrow a `static
    mut` or a peripheral yet.
- Decisions:
  - R4 is a pass of its own, `Checker::address_temporaries`, run once per body
    after the other per-body rules (like `reference_positions`), not inside
    `statement`/`rvalue`: it needs the writes of a local across the whole body
    (a second write may come before or after the first). It collects, in block
    order, the writes of whole locals (an assignment, a call's destination, an
    `asm` output or in-out; a write through a projection is a write through
    the pointer, not of the temporary) and the `Ref`/`AddressOf` of a whole
    local, and reports each at the statement concerned: every write after the
    first, and every `Ref`/`AddressOf` of the temporary.
  - R4 also rejects an address assigned to a parameter or `_0`, besides a
    named local: the ADR says "a temporary (no name)", but a parameter is
    written by the caller, so the value the analyses would read it as is not
    the only one it holds. Parameters are named by MIR building, so nothing
    changes for real programs.
  - `Root` (a local, a `StaticRef` or a `PeripheralRef`) replaces `Local` in
    `Path`; both refs already compare by identity (a static by id). The
    temporaries of R4 are found once in `Flow::of` (`addresses`, over all the
    body's blocks, not only the reachable ones, since R4 holds for all) and
    `Flow::root` gives a place's root and how many projections it consumes (the
    first `Deref`). A temporary read as a value (`_u = _t`, `_t` itself) keeps
    the local as root, as the ADR says.
  - The bytes of a peripheral are `[address, address + extent)` from its
    type's layout, half-open, so two peripherals one right after the other do
    not meet; a type whose layout is not set counts as empty (MIR is only used
    once layouts are set, so this is not reachable; it avoids a panic in a
    hand-built test). Two roots that are the same peripheral are compared by
    steps, not by bytes, so that `ctrl` and `data` of one peripheral are the
    `Elem` vs `Elem` overlap and a peripheral named in two temporaries is one
    root.
  - A `Field`, `Element` or `ConstElement` is an `Elem` step when the type of
    the place before it is a peripheral type, tested with `place_ty` of the
    prefix, so it holds below a `Deref` of a reference and of an R4 temporary
    alike.
  - Names: a static or a peripheral is named by its symbol with the dots shown
    as `::`; `shown` moved from `shared_statics.rs` to `analysis/bits.rs` so
    both use it. A byte string, which has no path, keeps its name as written.
    A register of a peripheral type is named by its declared name
    (`UART0.thr`, `(*u).thr`) and an element of a register or cluster array
    by `name[_]`, instead of `.0` and `[_]` after the peripheral.
  - A `sym` is `How::Sym`, a write of the whole static (`Path` with no steps),
    pushed by `Flow::asm` after the outputs; `Access` and `Fault` gain
    `sym: Option<StaticRef>`, which the message names (`place` is a filler, the
    return slot, since a whole static has no place of its own). Message:
    "cannot pass `S` to `asm` as `sym` while it is borrowed", label "passed as
    `sym` here"; the site's label is the usual "`S` is borrowed here". The ADR
    leaves the wording to snapshots. A `sym` of a static without `mut`, and of
    a body, adds no access.
  - Tests: R4 is one validator test (`r4_...`) covering every case of the
    plan plus the named and parameter cases, a `Ref` of the temporary, a
    write through the pointer accepted, and the peripheral twin. The borrow
    analysis has four tests, one per concern (a static as a root, with fields
    of a static; registers of one peripheral, at the peripheral and through a
    reference and an element of an array; peripherals whose bytes meet or not;
    `sym`), each also checking the accepted neighbour (after the last use,
    another static or peripheral, `static` without `mut`). `borrow_static_
    immutable.ers` needs an `entry` and a `panic` function, as every program,
    and borrows a scalar, a struct, a field and an array element and the
    whole array; its snapshot shows the `Ref` of `(*_t)` rooted at the
    static.
  - `docs/reference.md` does not change: no diagnostic code, row or syntax is
    added (the `sym` conflict is `analysis::borrow-conflict`), and the prose
    waits for step 8.

## 3. refactor(analysis): share the walk of the call graph and the accesses of the borrow analysis
- Status: done
- Implements: ADR 0112, "The conflicts across calls" (steps 1 to 3, the
  parts that change no behaviour).
- Changes:
  - `src/analysis/`: the walk of the call graph (`Reach`, and what of `Scan`
    and `Call` it needs) moves out of `shared_statics.rs` into a module of
    its own, with the set of edges as a parameter (`Statement::Call` alone,
    or with `Terminator::Panic`); `shared_statics` asks for both, with its
    order and ties unchanged.
  - `src/analysis/borrows.rs`: exposes, for a body, its accesses with their
    kind, path and span, and the sites in use at each `Statement::Call`
    with their later uses, computed by the same fixed points as `check`.
- Tests:
  - every ui snapshot of `shared_static_*` unchanged (the walk's paths and
    ties).
  - unit tests of the exposed functions over hand-built MIR: the sites in use
    at a call that lends a borrow, and at one with a borrow held across it,
    with its later use; none at a call after the last use.
- Decisions:
  - The walk lives in `src/analysis/call_graph.rs`: `Site`, `Call` (with
    `check`, the `Terminator::Panic` edge), `Edges` (`Calls`,
    `CallsAndPanics`) and `Reach` (`search`, `reaches`, `path`, and `root`,
    which `Context::root` of `shared_statics` read off a private field
    before). The scan of a body (`Scan::of`, with its `critical` depth and its
    places) stays in `shared_statics`: it is that rule's, and the calls of
    `call_borrows` need no depth (reachable blocks in order, `Statement::Call`
    only, which is the same order). `Reach::search` and `path` take any
    `&[C]` with `C: AsRef<[Call]>`, so `Scan` (implementing it) and a plain
    `Vec<Vec<Call>>` both serve and no list of calls is copied. `shared_statics`
    passes `Edges::CallsAndPanics`, the only set it follows; "asks for both"
    is read as: the one module serves both sets, `Calls` being first used by
    step 4 (and by the unit test of `call_graph` here).
  - What `borrows` exposes is one function, `facts(body) -> Facts`, rather than
    two (accesses, calls in use): both start from `Flow::of`, so one call builds
    it once. `Facts.accesses` (`Touch`: kind, path, name, span) are the accesses
    with a path rooted at a static or a peripheral, over the reachable blocks,
    in block, statement and access order. `Facts.calls` (`CallUse`: block,
    statement, callee, span, and the `Held` sites) is filled only when the
    body makes a site rooted at one (the fixed points are not computed
    otherwise) and lists a call only when such a site is in use during it.
    `Held` carries kind, path, name, the span of its `Ref` and `later:
    Option<(Span, bool)>`; its `conflicts(how, path)` is ADR 0106's rule,
    shared with `Flow::conflicts` through the free `in_conflict`.
  - `name` is in `Touch` and `Held` because the place is named by the body
    that holds it (`Flow::name`), which step 4's messages cannot rebuild; the
    `sym` name is shared with `message` through `Flow::access_name`. The sites'
    labels are not exposed: step 4 words them.
  - "In use during a call" is a new `Flow::during_call`: what the locals live
    after the call hold, what its reference arguments hold, and what the write
    of its result reads (a `(*r).f = f()` keeps `r`'s sites). The existing
    `in_use` is not reused as is: it is per access, and a call with no
    reference argument has no access to ask from. Both share `live_holds`.
  - The later use is `later_use` called from a `Point { at: (block, statement,
    accesses.len()), after_call: true, whole_call: true }`: the call's own
    reads of its arguments are not a later use, while a read in a later
    statement, or in the next iteration of a loop (`round = true`), is. So is
    the write of the call's result when it goes through a reference (`(*r).f =
    f()` reads `r` after the callee returns): that is a use of the borrow after
    the call, which ADR 0112 item 3 asks for ("a later use when one is held
    after the call"), and the same as `during_call` already counts it as in
    use; `whole_call` makes `later_use` take the `after_call` accesses of the
    same statement as ahead (from the review: before, it was missed, and in a
    loop reported as the next iteration pointing at the call itself). Its span
    is the call's. `later_use` takes a `Point` (location, `after_call`,
    `whole_call`, span) instead of a `Fault`; a `Fault` makes its `Point`.
  - `How`, `Step`, `Root` and `Path` become `pub(super)` so the exposed types
    can name them. Items only step 4 reads (`Touch`, `Held`, `CallUse`,
    `facts`) carry `#[cfg_attr(not(test), expect(dead_code, ...))]`: the
    crate is a library and denies warnings, and step 4 removes the attributes.
  - Tests: five in `borrows` for `facts`: the accesses (a static, a field of
    a peripheral, a `sym`, a local's access and an unreachable block left out,
    spans); the calls (lent, held across with a later use, shared, with
    `conflicts`); the write of a call's result through the borrow (a later
    use, also in a loop, and none when the result goes to a local); none after
    the last use, for a site of a local, or in an unreachable block; and a loop
    (later use ahead, and `round`). `in_conflict` is private (review). Two in
    `call_graph`: a check is an edge only with `CallsAndPanics`, and the first
    path found is kept. The unchanged `shared_static_*` snapshots are the test
    of the move.
