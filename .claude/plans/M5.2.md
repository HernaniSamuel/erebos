# Plan: M5.2 Moves

ADRs: 0094, 0096, 0097, 0098, 0099
Base: 5619b93
Program on QEMU: pins in typestate, on riscv32 and thumbv7m at `-O0` and
`-O`: a pin taken from disabled to input to output by functions that consume
it, one struct per state, over a port simulated by `static mut` words (the
boards have no GPIO), its states printed over the UART; the wrong uses (a
disabled pin driven as an output, a pin used after its conversion) are ui
tests rejected with `analysis::use-after-move`.
Out of scope:
- linear types, M5.3; references, M5.4; methods, M5.5; ownership of
  peripherals and how a context comes to own what a static holds, M5.6
  (roadmap, "M5 steps");
- non-copy bindings inside nested or-patterns: an error here (ADR 0097),
  allowed later (roadmap, pending decisions);
- structs and moves in the generated programs of ADR 0068, which have only
  scalar types (roadmap, deferred ideas);
- `erebos svd`: it writes bit-field structs only, which are copy (ADR 0096),
  so its output does not change.

Before step 1: the `docs(adr)` commit that accepts ADR 0096 to 0099 also sets
the status lines of the ADRs they amend, in their files and in the index
(`docs/adr/README.md`):
- 0042: `Accepted; amended by 0098 (a `match` on a place of a non-copy type
  tests the place; a non-copy binding is moved at the end of its
  alternative)`; index `Accepted, amended by 0098`.
- 0063: `...; amended by 0070 (...), 0082 (...), 0093 (...), 0099 (the
  module `query` uses `analysis`)`; index `Accepted, amended by 0070, 0082,
  0093, 0099`.
- 0095: `Accepted; amended by 0098 (the operand `move` and the rules M1 to
  M4)`; index `Accepted, amended by 0098`.
The same commit holds this plan and the roadmap's edits written while
planning (the M5.2 pending decisions settled, the or-pattern restriction left
open, the generator's growth among the deferred ideas).

Order: the attribute and the kinds of types come first (1), since every later
step asks whether a type is copy. The checks of type checking that need no
flow (2, 3) come before MIR changes, so that MIR building never sees a move
out of a place ADR 0097 forbids, and ADR 0098's rule M3 holds from the step
that adds it (4). The analysis (5) relies on M1 to M3. Each step migrates the
tests it breaks, adding `#[copy]` only to the types that need it (ADR 0096,
"Consequences"), so that the other types stay non-copy and the tests exercise
moves. Migrating means every suite the gate runs, `tests/layout`,
`tests/boards` and the chips of `tests/svd` included: a step adds `#[copy]`
wherever a program of them breaks. A diagnostic code gets, in the step that
adds it, both its snippet in the catalog of ADR 0069 (`tests/rejected.rs`)
and its row in the check tables of `docs/reference.md`: the catalog's test
rejects a snippet whose code the reference does not list. The prose of the
reference comes in the last step.

## 1. feat(ty): the `#[copy]` attribute and the kinds of types
- Status: done
- Implements: ADR 0096, "The attribute", "Which types are copy", "The check
  of `#[copy]`".
- Changes:
  - `src/hir/lower/item.rs`: `copy` in `struct_attrs` and `enum_attrs` (for
    an enum with payloads), with no argument, once; on a bit-field struct, an
    enum without payloads and every other item, `resolve::misplaced-attribute`
    with `copy` in its `applies_to` table; the `unknown_attr` help lists it.
  - `src/hir/mod.rs`: `copy: bool` on `StructDef` and `EnumDef`.
  - `src/ty.rs` (or a file of `src/ty/`): whether a HIR type is copy, as ADR
    0096 lists, reading `Option`/`Result` through their arguments; the check
    of `#[copy]` declarations, `ty::copy-field-not-copy`, at the attribute,
    labeling each field or payload value and naming its type, with the help
    suggesting `#[copy]` on that type when it is a struct or an enum with
    payloads; run from `check_all` with the other checks of declarations.
- Tests:
  - ui: `copy_attribute.ers` (accepted on a struct, on an enum with payloads,
    with `#[packed]` and `#[align(N)]`; the layout dump unchanged);
    `copy_attribute_misplaced.ers` (on a bit-field struct, an enum without
    payloads, a function, a static); `copy_attribute_argument.ers`,
    `copy_attribute_duplicate.ers`; `copy_field_not_copy.ers` (a field of a
    non-copy struct, a payload of a non-copy enum, an array of one, an
    `Option` of one, two fields reported once each, the help).
  - `tests/rejected.rs`: a snippet for `ty::copy-field-not-copy` at item
    level; `docs/reference.md`: its row in the check tables.
- Decisions:
  - HIR carries `copy: Option<Span>`, not `copy: bool`, on `StructDef` and
    `EnumDef`: the error is "at the attribute", so the check needs its span.
    Step 4's MIR flag stays a `bool`. `None` also for `Option`/`Result`
    instances (`BuiltinEnum::def`) and for an enum without payloads, whose
    kind never reads the field.
  - `is_copy(&Queries, Ty)` and `report_copy_fields` live in the new
    `src/ty/copy.rs`, re-exported by `ty`, so that steps 2 and 3 call
    `ty::is_copy` from the checker. `is_copy` takes `&Queries` and needs no
    normalization: it reads `Applied` through its arguments, and an
    already-normalized `Option`/`Result` instance (known by
    `Queries::builtin_enum`) through its payload types. `!`, `[T]`, peripheral
    types and `{error}` answer `true`: they have no values to move, and
    answering `false` would only add errors after another one.
  - `ty::copy-field-not-copy` runs in `check_all` right after
    `report_volatile_peripherals`, before the layouts, so it comes with the
    other checks of declarations. It labels the attribute first ("declared
    copy here"), then the field's name (a field has no span for its type) or
    the payload value's type, with "`T` is not copy", `T` normalized
    (`[Handle; 4]`, `Option(Handle)`). One error per field or payload value,
    structs before enums, each in source order.
  - The help names the struct or enum with payloads that makes the type
    non-copy, found inside arrays and `Option`/`Result` arguments (so for
    `[Handle; 4]` it suggests marking `Handle`), and says to remove `#[copy]`
    from the declaring type otherwise. Every non-copy type contains such a
    type, so there is no help for another case. The search skips what is
    copy already (`Result(Token, Handle)` names `Handle`, with `Token`
    `#[copy]`); `copy_field_not_copy.ers` has the case (from the review).
  - The label of a payload value falls back to the attribute's span when the
    payload has no span (`payload.span.unwrap_or(attr)`); a declared enum's
    payloads always have one, so this is probably unreachable (from the
    review).
  - `#[copy]` reuses `flag_attr` (argument and duplicate errors as
    `#[export]`'s). On an enum, whether it has payloads is read from the
    declaration (`enum_attrs` takes it); without, it is
    `resolve::misplaced-attribute` labelled "not allowed on an enum without
    payloads". The `applies_to` text reads "structs, other than bit-field
    structs, and enums with payloads", and a help (ADR 0096's reason) is added
    for `copy` only. A bit-field struct, a function, a static, a constant, a
    module and the other items with `no_attrs` get the same error.
  - The `unknown_attr` help lists `#[copy]`, which changes four existing
    snapshots (`resolve_attribute_errors`, `resolve_memory_attributes`,
    `resolve_peripheral_attributes`, plus the `Hir` debug dump of
    `resolve_bit_struct` showing `copy: None`).
  - The layout dump (`ty/dump.rs`) does not show `#[copy]` (the plan asks it
    unchanged), so `copy_attribute.ers` proves acceptance and the unchanged
    layouts, not the flag. `copy_attribute_misplaced.ers` and the other
    attribute tests stop at `hir`, where the errors come from.
  - The row of `resolve::misplaced-attribute` in the reference's check table
    names `#[copy]`; the prose of the reference is step 7's.
  - `copy_field_not_copy.ers` also holds a `#[copy]` struct that is accepted
    (`Fine`), and `Token`, itself reported, used as a field of a `#[copy]`
    struct without a second error: the declaration decides, as ADR 0096 says.

## 2. feat(ty): no constant or repeat of a non-copy type
- Status: done
- Implements: ADR 0096, "Values computed at compile time", "Repeat
  expressions".
- Changes:
  - `src/ty.rs`: `ty::non-copy-constant` at the type of a `const` whose
    normalized type is non-copy, and at a `comptime` expression of a
    non-copy type; a static's initializer is not checked;
    `ty::non-copy-repeat` at `v` in `[v; N]` with `v` of a non-copy type,
    whatever `N`, with its help, unless `v` is a variant written without
    payload values.
  - The tests and e2e programs these reject: `#[copy]` on the types they
    need.
- Tests:
  - ui: `non_copy_constant.ers` (a `const` of a non-copy struct, of an enum
    with payloads, of an `Option` and an array of one; a `comptime`
    expression of one; a `comptime` function building and returning a
    non-copy value inside a `const` of a copy type, accepted; a static of a
    non-copy type, accepted); `non_copy_repeat.ers` (`N` of 0, 1 and 4; a
    copy struct accepted; `[.None; 32]` of an `Option` of a non-copy type in
    a `static mut`, accepted, and `[.Some(h); 2]`, rejected).
  - `tests/rejected.rs`: snippets for both codes; `docs/reference.md`: their
    rows.
- Decisions:
  - The three checks are methods of `Checker` in `src/ty/copy.rs`
    (`check_constant_copy`, `check_comptime_copy`, `check_repeat_copy`), next
    to `is_copy`, and called from `src/ty.rs`: the constant's from `fn_`
    (once per body), the others from the arms of `ExprKind::Comptime` and
    `ExprKind::Repeat` of `expr_kind`. Nothing was added to `src/ty.rs`
    beyond those three calls.
  - A `const` is checked on its body (`f.comptime == Some(Comptime::Const(_))`)
    through the normalized return type, and labelled at `f.ret_span`, which
    lowering sets to the written type of the constant: `ConstDef` has no
    `ty_span`, and a new HIR field was not needed. A static's body
    (`Comptime::Static`) is never checked, as ADR 0096 says.
  - Both constants and `comptime` expressions are `ty::non-copy-constant`; the
    message names the constant (`the constant `H` is of the non-copy type
    `Handle``) or says "a `comptime` expression cannot be of the non-copy type
    `T`". The label is "`T` is not copy". The check of a `comptime` expression
    uses the type of its operand, so the operand's own checks (`!` in memory)
    come first and an `{error}` operand reports nothing more (`is_copy` answers
    `true` for it). The type is returned unchanged, so the surrounding `let`
    reports no second error.
  - A body of a `const` or a `comptime` expression that is rejected here is not
    evaluated: `typeck_fn` returns `false` as for any other type error, so
    `comptime_value` and `const_value` do not run on it.
  - The helps start with `mark `T` with `#[copy]` if its values may be
    duplicated` (the culprit of step 1, now `mark_copy`, shared with
    `ty::copy-field-not-copy`), then `or declare a `static`, whose initializer
    may be of any type` for a constant, `or build the value at run time` for a
    `comptime` expression, `or list each element in an array literal` for a
    repeat (ADR 0096 gives the last).
  - `ty::non-copy-repeat` is reported at `v` before the length is computed, so
    it is reported whatever `N` is, and also when `N` fails to evaluate. The
    type tested is that of `v` itself (its own checked type), not the element
    type the context expects.
  - "A variant written without payload values" is `ExprKind::Variant` or
    `ExprKind::ContextVariant` whose arguments are `None` or an empty list
    (`E::V()`): nothing is duplicated either way. A variant of an enum
    without payloads is copy and never reaches the exception. A block or a
    parenthesis around the variant is not looked through (`[{ .None }; N]` is
    rejected): ADR 0096 names the variant itself.
  - The e2e, ui, `layout` and `boards` programs that broke got `#[copy]` and
    nothing else: in `tests/e2e` the structs of `aapcs_c.ers` (not `Empty`,
    which no constant uses), `Pair`, `Small` and `Packet` of
    `comptime_differential.ers`, `Descriptor` of `layout.ers`, `Taken` of
    `match_cost.ers`; in `tests/ui` the type of the constant in
    `codegen_consts`, `codegen_enum_payloads`, `eval_enum_payload_slices`,
    `mir_consts`, `resolve_modules`, `typeck_const_place_errors`,
    `typeck_const_places`, `typeck_context_variants`, `typeck_enum_payloads`
    and `typeck_match_payload_errors` (also its `Pair`). Their snapshots
    changed only by the lines moved down by the attribute and the byte offsets
    in the typeck dumps; no other output changed. `tests/layout`,
    `tests/boards`, the chips of `tests/svd` and the directory programs of
    `tests/e2e` needed nothing; `rt/` neither.
  - `non_copy_constant.ers` also has a `#[copy]` enum with payloads and an
    `Option` of one as accepted constants, a constant that is an `Option` of an
    array of non-copy type, a `comptime { ... }` block building a handle in a
    `let` and returning a `u32` (accepted), and a `static mut` array of a
    non-copy enum holding a handle in a payload (accepted).
    `non_copy_repeat.ers` has `[[Handle; 2]; 2]` (nested repeat), a repeat
    through a `const` length, an `Option` of copy accepted, and `static mut`
    repeats of `.None` with `N` of 0, 1 and 32 and of a payload-less variant of
    an enum with payloads. Both stop at `typeck`.
  - Snippets of `tests/rejected.rs` are at item level (`Items`), since a
    constant is an item and the repeat sits in a function the snippet brings;
    their types are named `InjHandle2` and `InjHandle3` so as not to depend on
    the snippet of step 1.

## 3. feat(ty): moves only out of locals, their fields and payloads
- Status: done
- Implements: ADR 0097, "What moves", "Places a value is moved out of",
  the or-pattern restriction under "`match` does not move its scrutinee",
  "Statics".
- Changes:
  - `src/ty.rs`, `src/ty/place.rs`: where a place expression is used as a
    value (`expr_kind`'s arm for `Deref`, `Index`, `Field`, `Static`), when
    its type is non-copy and its path reaches an array element, a pointer or
    a static, `ty::move-out-of-place` at the use, the message naming which;
    a place rooted in a temporary is not one; a place, or a block whose
    tail is one, discarded by an expression statement is not a use
    (ADR 0097, "What moves").
  - `src/ty/pattern.rs`: a binding of a non-copy type moves out of the
    scrutinee's place: the same error when the scrutinee is such a place;
    `ty::non-copy-binding-in-or-pattern` at a non-copy binding inside an
    or-pattern nested in a payload.
  - The tests and e2e programs these reject (`tests/e2e/options.ers`
    matches a static binding a `Point`): `#[copy]` where needed.
- Tests:
  - ui: `move_out_of_place.ers` (`a[i]`, `a[0]`, `*p`, `p[i]`, `(*p).f`,
    `(*s)[i]`, a static, a field of a static, each with its message; copy
    fields of each read without error; `*p = v` accepted; `f().x` accepted;
    a `match` on a static binding a non-copy payload rejected, binding a
    copy one accepted); `non_copy_binding_in_or_pattern.ers` (nested,
    rejected; top-level alternatives binding a non-copy value, accepted; a
    copy binding in a nested or-pattern, accepted);
    `move_out_of_place_discarded.ers` (`a[i];`, `(*p).f;`, `S;` and
    `{ (*p) };` as statements, with non-copy types, accepted: a discarded
    place is not read, ADR 0097); `move_out_of_static.ers` (a `static mut`
    of a non-copy type assigned whole, its copy field read, `&raw mut` of it,
    accepted; read whole, rejected); a `match` on a non-copy enum through a
    `*volatile` pointer, rejected as a volatile aggregate read, as today.
  - `tests/rejected.rs`: snippets for both codes; `docs/reference.md`: their
    rows.
- Decisions:
  - The path of a place is read syntactically after it is typed
    (`Checker::root`/`unmovable` in `src/ty/place.rs`, with `Unmovable` and
    `is_place`): `PlaceInfo.via` only knows the last pointer, not arrays or
    statics. From the root: a static is `a static`, a `Deref` and an index
    through a pointer or a slice place are `a place through a pointer`, an
    index of an array place rooted in a local or parameter is `an array
    element`; the first obstacle from the root wins (`S.items[0]` is a static),
    and a `Deref` ends the walk (`*S.p` is through a pointer). A `Field` or an
    array `Index` whose base is not a place expression, or whose root is a
    temporary (`f().items[i]`), is not an obstacle.
  - `ty::move-out-of-place` is reported in the arm of `expr_kind` that types
    `Deref`/`Index`/`Field`/`Static`, after `access`, and the arm still returns
    the place's type, so the `let` around it reports no second error. A place
    whose type is `{error}` is copy and reports nothing. The message is
    "cannot move a value of the non-copy type `T` out of {an array element | a
    place through a pointer | a static}"; the label at the use says "`T` is not
    copy, and this is {what}".
  - The set of places named but not read (`Checker::unread`, ids of
    expressions) holds the discarded places and the `match` scrutinee. A
    discarded place is found by `Checker::discard`, called for every
    expression statement (with or without `;`): the expression if it is a
    place, or the tail of a block or `critical` block, recursively. The check
    of the type is unchanged for them, so a discarded `*p` of a volatile
    aggregate is still `ty::volatile-aggregate`. A block whose tail is a
    place is discarded even when it has statements before (`{ let n = 1; *p };`).
  - The help is `suggest_copy` (in `src/ty/copy.rs`, re-exported): `mark `T`
    with `#[copy]`...` when `T` is a struct or a declared enum with payloads
    whose fields or payload values, normalized, are all copy, as ADR 0097 says
    (so an `Option(Handle)` or an array gets none, and the type containing a
    non-copy field gets none); otherwise "a non-copy value is moved out of a
    local, a parameter or their fields, and out of the payloads a `match` binds
    from them". It differs from `mark_copy` (step 2), which names the culprit
    inside any non-copy type, because there the declaration is what changes.
  - A binding of a non-copy type moves from the scrutinee: `match_` computes
    why the scrutinee place is unmovable once (`Checker::scrutinee`, set around
    each arm's pattern, restored after) and `binding_moves` reports in
    `Binding`, at the binding pattern, with a second label at the scrutinee
    ("this is {what}"). A scrutinee that is not a place, or a local, reports
    nothing. The scrutinee is put in `unread` so that `match SMSG { ... }`
    itself is not a move; the `match` on a place with no binding is accepted.
  - `ty::non-copy-binding-in-or-pattern` is found with `payload_depth`
    (raised around each payload sub-pattern in `variant_pattern`) and
    `nested_or` (the outermost or-pattern met at depth above 0, restored on
    leaving it). The alternatives of an arm are depth 0, so they are not
    nested; any binding below the nested or-pattern, at any depth, is reported
    once, at the binding, with a label on the or-pattern. A binding next to a
    nested or-pattern (`.Mixed(.A(_) | .B(_), let h: Handle)`) is accepted: the
    ADR restricts bindings inside it. The two errors of a binding that is both
    inside a nested or-pattern and moved out of a static are both reported.
  - Migration: `#[copy]` (nothing else) on `Cmd` (`command_decoder`), `Lamp`
    (`comptime_differential`), `Msg` (`enum_payloads_no_variant`,
    `enum_payloads_no_variant_tag`), `Header` (`layout`), `P`, `Q`, `N`, `N1`,
    `N2` (`match_cost`), `Mode` and `Point` (`options`) in `tests/e2e`; `Pair`
    in `critical_types` and `typeck_slice_index_errors`, `Msg` in
    `eval_match_payload_no_variant` and `typeck_enum_payload_errors`, `Header`
    in `typeck_packed_align`, `Point` in `typeck_struct_errors`, `S` in
    `typeck_structs` in `tests/ui`. The seven snapshots changed only by the
    lines and byte offsets the attribute moves (the `assertion_line` header of
    insta was dropped when accepting, as in the other snapshots).
    `tests/layout`, `tests/boards`, `tests/svd` and `rt/` needed nothing.
  - Tests: `move_out_of_place.ers` also holds uses the plan lists for the
    rule (arguments, a literal's fields, the returned value), the `if`
    and `{ *p }` that do read, and the volatile `match` (`volatile_match`);
    `move_out_of_place_discarded.ers` is only acceptance (stops at `typeck`),
    `move_out_of_static.ers` has `&raw mut DRIVER.handle` and a compound
    write too; `non_copy_binding_in_or_pattern.ers` has a nested case under
    `Option`. Snippets of `tests/rejected.rs` are at item level, with types
    `InjHandle4`/`InjHandle5`, `InjInner`, `InjOuter`.
  - No `PANICS` count changed: no `unwrap`, `expect` or `unreachable` was added.

    `ty::is_copy` reads for a struct) and `mir_enum` from `ty::is_copy` on the
    enum's type, which answers for `Option`/`Result` through their payload
    types. The tests' own types (validator, ABI) are copy unless a test says
    otherwise.
  - `Builder::read(place)` (the span of the expression being built) and
    `Builder::read_at(place, span)` are the one place where MIR building picks
    `copy` or `move`, by the type of the place; `temp`, `read_result` and every
    arm of `expr_kind` that read a whole place go through them. The type is
    computed without panicking (`try_projected_ty`): the place of code that
    cannot run, as `*p` with `p` of type `!`, has none and is read as a copy
    (the fuzz test found one). `Builder::spill` stores an operand in a temporary
    and keeps the span of a `move`, so that `f(a, g())` reports `a`, not the
    call; `temp_place` makes a temporary and returns its place, replacing the
    `match` on the operand `temp` returned in `place_then`, `pointer_place`,
    `static_place` and `slice_index`. That removed five `unreachable!`
    ("temporaries are places"): the `PANICS` count of `src/mir/build.rs` goes
    from 40 to 35.
  - A `match` on a non-copy enum with payloads whose scrutinee is a place
    expression (`Local`, `Static`, `Deref`, `Index`, `Field`: `is_place_expr`)
    computes the place with `place_at` (the scrutinee's span) and tests it in
    place. Any other non-copy scrutinee (a call, a block, an `if`) is read as
    before, into an unnamed temporary unless it is one, and tested there, so a
    `{ a }` scrutinee is `_t = move _a`. A copy scrutinee is copied as before
    (`#[copy]` enums included).
  - A binding of a non-copy type pushes `(local, place, span)` onto
    `Builder::moves` instead of assigning; `chain` drains it after `payload`
    returns, in the block that ends the alternative, before the jump to the
    arm. The span is the binding pattern's. A copy binding assigns where its
    position is reached, as ADR 0042 says. The `let` arm of `chains` reads the
    scrutinee with `read_at`, at the span of the `let` pattern.
  - A discarded place (`Builder::is_discarded`/`discard`) is an expression
    statement that is a place of a non-copy type, or a block or `critical`
    block whose tail is one, recursively; `block_then(block, discarded)` and
    `critical(block, discarded)` build such a tail with `place`, not read.
    Statements before the tail are built as usual. A place of a copy type is
    read, as ADR 0097 says. The `Critical` arm of `expr_kind` became
    `Builder::critical`, which the discarded case shares.
  - `[v; N]` of a non-copy element: when the array's element is a non-copy
    enum and `v` is a variant written without payload values
    (`payload_free_variant`: `E::V`, `.V`, `E::V()`), each element gets
    `a[i].tag = const k` through `fill_with`, which `fill` became (it takes the
    store as a closure). The tag is the variant's discriminant, `failed` set
    when it is unknown, as in `variant`. Every other repeat evaluates `v` once
    and copies it, as before; type checking admits no other non-copy `v`.
  - The validator's M1 to M3 are in `Checker::operand` (the place is typed
    first; M3 and M1/M2 are skipped when T1 rejects the place, and M1/M2 when
    T3 does); M3 is `move_place`, which names the first projection that is not a
    `Field` or `Payload`, or the read-only local. M4 is `copy_kinds`, run once
    per body after the blocks and at `Location::Body`, with a set of the
    definitions seen (by address), so a definition is reported once per body
    even through several locals, arrays and fields; pointers are not followed.
    A struct or enum whose fields are not set is skipped (the rules that read
    them are not reached either).
  - **Found in step 3, fixed here**: type checking accepted a move out of an
    element of an array that is a temporary's (`make().items[i]`), as "a part of
    a value", but ADR 0098's rule M3 and "type checking has rejected a move out
    of any place but a local followed by fields" do not allow a `move` with an
    `Index`, and ADR 0097 lists "an element of an array, by `a[i]` whatever `i`"
    as not movable. `Checker::root` (`src/ty/place.rs`) now answers
    `ArrayElement` for the element of an array whatever the array is rooted in,
    a temporary included; the fields of a temporary (`make().h`) stay movable,
    and a copy field read through an element (`make().items[1].n`) is accepted.
    `move_out_of_place.ers` moved that case to a rejected one (its snapshot
    changed by the error and the lines the comment moved) and the reference's
    row says so. Left to the planner: whether ADR 0097 should say it.
  - Snapshots changed, all read: `copy` to `move` of non-copy locals and
    temporaries (`asm_typeck`, `eval_statics`, `mir_context_variants`,
    `mir_enum_payloads`, `mir_structs`, `mir_try`, `eval_try`), and the
    matches on non-copy locals tested in place, with their copy and one local
    fewer (`mir_match_chains`, `mir_match_context_variants`,
    `mir_match_or_bindings`, `mir_match_payloads`, `mir_panic_info`,
    `eval_try`, and `codegen_match_payloads` where the `alloca` and `memcpy`
    of the scrutinee are gone). The `assertion_line` header of insta was
    dropped when accepting, as in the other snapshots.
  - Tests: `mir_moves.ers` and `mir_match_moves.ers` are as the plan lists,
    with `Handle`/`Pair`/`Slot` for the former; the latter has a `match` on a
    field of a parameter and on a call besides, and the `.Two(let h, 0)` /

    moving nothing. The zero-sized struct (`Idle {}`) and the arrays of an

    `[.Free; 4]` of `Slot` is a local, compared at compile time and on the
    target, and a static's initializer, checked on the target against its tags
    (3 and 5 are not zero, so an element whose tag was not written fails the
    exhaustive `match`); `[.None; 3]` of an `Option` of a non-copy struct the
    same way (a static's initializer is not read at compile time, so only its
    run-time answer is checked, against the value the tags give). No new e2e
