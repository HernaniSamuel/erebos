# Plan: M5.9 `unsafe`

ADRs: 0119 (building on 0007, 0015, 0019, 0020, 0021, 0026, 0027, 0030,
0058, 0068, 0069, 0079, 0080, 0086, 0093, 0105, 0117, 0118)
Base: 12b9758
Program on QEMU: every program of `tests/e2e/` migrated, with the same output;
and `unsafe_boundary.ers`, portable, on both targets at `-O0` and `-O`
(ADR 0077): a safe interface built on `unsafe fn` and `unsafe` blocks (a ring
over a static buffer reached through raw pointers, and a fill of a buffer
through an `unsafe fn` whose contract the safe wrapper upholds).
Out of scope:
- unsafe attributes, `unsafe` on types or `impl`, `extern fn` declared safe,
  a check of `enable_interrupts` against `critical` and handlers (ADR 0119,
  "What stays out"); no step takes them yet;
- generic bodies and function pointers: M6 and the deferred ideas owe what
  ADR 0119's Consequences list;
- moving raw pointers to references: ADR 0117's rule is unchanged, and this
  step does not move a declaration;
- the findings of `docs/open-findings.md`: worked off between steps, not here.

Decided with the user while planning (2026-11-15):
- `unsafe` before M6, as its own step after M5.8.
- The five unsafe operations: accesses and borrows through a raw pointer,
  `asm`, calls to an `extern fn` or a `#[naked]` function, accesses to an
  `extern static`, calls to an `unsafe fn`; `static mut` stays safe
  (ADR 0093).
- `&raw` through a raw pointer (address computation) stays safe.
- An `unsafe fn` body is not an `unsafe` block.
- An unused `unsafe` block is an error, `ty::unused-unsafe`.
- `core::arch::enable_interrupts` becomes an `unsafe fn`, called only from
  the entry function outside `critical`, or from an `unsafe fn` carrying the
  same contract (a review rule).
- A call to a `#[naked]` function needs `unsafe` (after the review: a safe
  naked function would let safe code run any assembly).

Order: the syntax first, accepted with no check (step 1); the check with only
the operation that no program writes yet, calls to an `unsafe fn` (step 2);
then one kind of operation per step, each with the migration of every program
that writes it, so that each commit builds and passes every test (steps 3 to
6); then the mechanical test over the migrated programs, the new program, the
count and the documentation.

Where Erebos source lives, for every migration step (each step greps all of
them for its operation, with the commands recorded under its Decisions):
`rt/`, `tests/boards/`, `tests/e2e/`, `tests/ui/`, `tests/svd/chips/`, the
snippets of `tests/rejected.rs`, the programs embedded in `tests/elf.rs`,
`tests/e2e.rs`, `tests/svd.rs` and `tests/fuzz.rs`'s corpus, the source
`tests/common/generator.rs` writes, and `tests/layout/` (structs only,
expected to need nothing; confirmed in step 5).

## 2. feat(ty): check `unsafe` blocks and calls to an `unsafe fn`
- Status: todo
- Implements: ADR 0119, "The rule" (operation 5, where the rule applies,
  expressions in error), "`unsafe { }`" (every block is used), "Where it is
  checked", "Diagnostic codes"
- Changes: `src/ty/unsafety.rs` (new), run on each typed body after typing,
  beside `linear.rs` and `reference.rs`, reading `q.tables.expr_ty`: the
  stack of `unsafe` blocks, the innermost marked used at each unsafe
  operation, `ty::unsafe-required` at an operation outside every block,
  `ty::unused-unsafe` at each block left unused (with the outer block's
  label when nested). Every `Fn` of HIR with a body is a root, run from
  `check_fn`, the bodies of every `Comptime` kind included. Coverage is
  lexical: a `comptime(..)` operand (`ExprKind::Comptime`, an `asm` `const`
  operand included) is an expression of its enclosing body, which
  `src/query.rs` evaluates from there without making a body of it, so the
  walk descends into it with the current stack of blocks. An operation on an operand or callee of
  erroneous type marks its block used and is never reported. Operations
  recognized in this step: calls to an `unsafe fn` (free, of a type,
  method), at run time and at compile time.
- Tests: ui tests: a call to an `unsafe fn` rejected outside a block and
  accepted inside; an `#[export] unsafe fn` called from Erebos; in an
  `unsafe fn` body, rejected without a block, with the help; a method call;
  a call in a `const` initializer, an item-level `comptime` block, an enum
  discriminant and an array length; a `comptime(..)` operand and an `asm`
  `const` operand holding a call to an `unsafe fn`, inside an `unsafe` block
  (accepted, checked once) and outside one (one error); an empty `unsafe` block, one with only
  safe operations, one nested in a used block with nothing of its own, two
  nested empty blocks (two errors); a call to an undefined function inside
  `unsafe` (one error, no `ty::unused-unsafe`); `return`, `break` and
  `continue` out of an `unsafe` block; `tests/rejected.rs` snippets for both
  codes. No program writes an `unsafe` yet, so none changes.

## 5. feat(ty): require `unsafe` for accesses through a raw pointer
- Status: todo
- Implements: ADR 0119, operation 1, "`core`" (the memory functions as
  `unsafe fn`)
- Changes: `src/ty/unsafety.rs` recognizes a read, write or borrow of a place
  reached through a raw pointer of any kind (thin, slice, volatile, to a
  peripheral type), and a method call whose receiver borrows one; `&raw` of
  such a place, `len`, `slice`, casts and comparisons stay safe. What each
  place goes through comes from the typed body (`src/ty/place.rs`).
  Migration, the largest of the step: `rt/builtins.ers` (`memcpy`,
  `memmove`, `memset` and the twelve `__aeabi_mem*` become `unsafe fn`,
  each with its `Safety:` comment, their calls to one another in blocks),
  the boards, the programs of `tests/e2e/`, `tests/svd/chips/esp32c3_main.ers`
  (`rx_byte`'s `(*uart).fifo`), the programs of `tests/svd.rs` and
  `tests/fuzz.rs`'s corpus that dereference, the ui tests and the snippets.
  The step cannot be split cleanly: blocks added before the check
  recognizes their operations would be `ty::unused-unsafe`, and the check
  without the blocks fails every program. It stays one commit, reviewed by
  directory (`rt/`, boards, `tests/e2e/`, `tests/ui/`, the rest).
- Tests: ui tests, one per form of operation 1 (`*p` read, `*p` written,
  `p[i]`, `(*p).f`, `(*s)[i]`, a range of `*s`, `&*p`, `&mut (*p).f`, a
  volatile pointer, a register through `*mut Uart`, `(*p).method()`, a
  returned `&*p` under ADR 0118); one per safe form (`&raw const p[i]`,
  `&raw mut (*p).f`, `len(s)`, `slice(p, n)`, `p as usize`, `*r` through a
  reference, a register of a peripheral static); an expression with two
  operations gives two errors. The e2e programs and `tests/svd.rs` pass.

## 7. test(rejected): removing an outer `unsafe` from an e2e program is rejected
- Status: todo
- Implements: ADR 0119, "Conformance tests" (`tests/rejected.rs`, the
  mechanical part); extends ADR 0069
- Changes: `tests/rejected.rs`: for each `unsafe` block of the programs of
  `tests/e2e/` that is not inside another `unsafe` block, the program with
  that one `unsafe` removed (the block kept) must be rejected with
  `ty::unsafe-required`. Nested blocks are skipped: removing their `unsafe`
  is rightly accepted. How the blocks and their nesting are found (a scan
  of the source for `unsafe` before `{`, skipping comments and `unsafe fn`,

- Tests: the new test itself; a block that nothing in it needs would make it
  fail, which `ty::unused-unsafe` should already have caught (a second
  oracle for that check).
