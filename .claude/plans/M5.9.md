# Plan: M5.9 `unsafe`

ADRs: 0119 (building on 0007, 0015, 0019, 0020, 0021, 0026, 0027, 0030,
0058, 0068, 0069, 0079, 0080, 0086, 0093, 0105, 0117, 0118)
Base: 12b9758
Program on QEMU: every program of `tests/e2e/` migrated, with the same output;
and `unsafe_boundary.ers`, portable, on both targets at `-O0` and `-O`
(ADR 0077): a safe interface built on `unsafe fn` and `unsafe` blocks (a ring
over a static buffer reached through raw pointers, and a fill of a buffer
through an `unsafe fn` whose contract the safe wrapper upholds).
Out of scope:
- unsafe attributes, `unsafe` on types or `impl`, `extern fn` declared safe,
  a check of `enable_interrupts` against `critical` and handlers (ADR 0119,
  "What stays out"); no step takes them yet;
- generic bodies and function pointers: M6 and the deferred ideas owe what
  ADR 0119's Consequences list;
- moving raw pointers to references: ADR 0117's rule is unchanged, and this
  step does not move a declaration;
- the findings of `docs/open-findings.md`: worked off between steps, not here.

Decided with the user while planning (2026-11-15):
- `unsafe` before M6, as its own step after M5.8.
- The five unsafe operations: accesses and borrows through a raw pointer,
  `asm`, calls to an `extern fn` or a `#[naked]` function, accesses to an
  `extern static`, calls to an `unsafe fn`; `static mut` stays safe
  (ADR 0093).
- `&raw` through a raw pointer (address computation) stays safe.
- An `unsafe fn` body is not an `unsafe` block.
- An unused `unsafe` block is an error, `ty::unused-unsafe`.
- `core::arch::enable_interrupts` becomes an `unsafe fn`, called only from
  the entry function outside `critical`, or from an `unsafe fn` carrying the
  same contract (a review rule).
- A call to a `#[naked]` function needs `unsafe` (after the review: a safe
  naked function would let safe code run any assembly).

Order: the syntax first, accepted with no check (step 1); the check with only
the operation that no program writes yet, calls to an `unsafe fn` (step 2);
then one kind of operation per step, each with the migration of every program
that writes it, so that each commit builds and passes every test (steps 3 to
6); then the mechanical test over the migrated programs, the new program, the
count and the documentation.

Where Erebos source lives, for every migration step (each step greps all of
them for its operation, with the commands recorded under its Decisions):
`rt/`, `tests/boards/`, `tests/e2e/`, `tests/ui/`, `tests/svd/chips/`, the
snippets of `tests/rejected.rs`, the programs embedded in `tests/elf.rs`,
`tests/e2e.rs`, `tests/svd.rs` and `tests/fuzz.rs`'s corpus, the source
`tests/common/generator.rs` writes, and `tests/layout/` (structs only,
expected to need nothing; confirmed in step 5).

## 1. feat(syntax): parse `unsafe` blocks and `unsafe fn`
- Status: done
- Implements: ADR 0119, "`unsafe { }`", "`unsafe fn`" (placement)
- Changes:
  - `src/syntax/token.rs`, `lexer.rs`: the keyword `unsafe`.
  - `src/syntax/ast.rs`: `ExprKind::Unsafe(Block)` beside `Critical`, with
    the same statement rule (no `;` needed); whether the function is
    `unsafe` on the function item, set for functions with a body only.
  - `src/syntax/parser.rs`: `unsafe {` as a primary expression, as
    `critical {` (`parser.rs` around 1910 and 2368); `pub? unsafe fn` at
    module level and in an `impl`; `parser::misplaced-unsafe` before
    `extern fn`, `entry fn`, `panic fn`, `interrupt fn`, `impl`, any other
    item, and `unsafe` in an expression not followed by `{`.
  - `src/hir/mod.rs` (`walk`, around 1798), `src/hir/lower/expr.rs`,
    `src/hir/lower.rs`: `ExprKind::Unsafe(Block)` and the function's
    `unsafe` in its HIR signature.
  - Every place that matches `Critical` treats `Unsafe` as a plain `Block`:
    `src/ty.rs` (around 466, 935, 985, 1015, 1323), `src/ty/linear.rs`
    (462), `src/ty/dump.rs` (421), `src/mir/build.rs` (482, 1058). Not
    `src/ty/reference.rs`'s special case of `Critical` (a reference cannot
    leave a `critical` block; it can leave an `unsafe` one).
- Tests: parser ui tests (`unsafe` block as a statement, as a tail, as a
  `let` initializer, nested; `unsafe fn` at module level, `pub`, in an `impl`,
  with `#[export]`, with `#[naked]`); one ui test per misplaced position;
  `unsafe { *p } = 1` rejected as an assignment to a block; a MIR snapshot
  showing the same body with and without `unsafe { }`; a `tests/rejected.rs`
  snippet for `parser::misplaced-unsafe`. Nothing is rejected yet for a
  missing `unsafe`, so no program changes.
- Decisions:
  - The flag is `is_unsafe: bool` on `ast::FnDecl` and `hir::Fn` (Rust's
    keyword rules out `unsafe`), not a new `FnKind`: `unsafe` is orthogonal
    to `Plain`/`Naked` (an `#[export]` or `#[naked]` function can be one), and
    `FnKind` is matched in many places that would each need to ignore it. The
    parser sets it only for `unsafe fn` with a body; before `extern fn`,
    `entry fn`, `panic fn` and `interrupt fn` it is reported and the function
    parses as without it. Every HIR `Fn` that is not a source function (the
    bodies of `comptime`, `const`, `static` and other values, and the stand-in
    for a skipped function of an `impl`) has `is_unsafe: false`.
  - `fn_decl` itself eats `unsafe`, so the module level and the `impl` share
    one path; the span of an `unsafe fn` starts at `unsafe`. `item_after`
    reaches `fn_decl` for `unsafe` followed by `fn`, `extern fn`, `entry`,
    `panic` or `interrupt` (`at_unsafe_fn`; `unsafe extern static` is not a
    function), and handles `unsafe` before any other item itself.
  - `parser::misplaced-unsafe` is reported at the `unsafe` keyword
    ("not allowed here"), as `parser::misplaced-pub` is at `pub`, with a help
    per case: `extern fn` (every call is already unsafe), entry, panic and
    interrupt (no Erebos code calls them), `impl` (`unsafe` goes on each
    function), and a generic help for the rest. After it the item is parsed as
    without `unsafe`, so the errors of the item itself still come out; at
    module level and in an `impl`, `unsafe` before a token that starts no
    item (`unsafe 1;`, `unsafe {}`, `unsafe unsafe fn`) is reported and
    returns an error to the recovery, with no second error for the token.
    In an `impl`, `unsafe extern fn` and `unsafe const` give both
    `parser::misplaced-unsafe` and `parser::impl-item`: both are true, and the
    second goes away only with the first.
  - `item_noun` is the table of "an `extern fn`", "a struct", ... that
    `impl_item` had inline; it is shared with `misplaced_unsafe` so that the
    two diagnostics name items the same way.
  - In an expression, `unsafe` not followed by `{` is one
    `parser::misplaced-unsafe` ("expected `{` after `unsafe`, found X", the
    label on the keyword) and an error returned to the recovery. That covers
    `unsafe fn` written inside a function body, whose help says an `unsafe fn`
    is declared at module level or in an `impl`. The recovery after it is the
    existing one: a local `fn` in a body leaves a stray `}` that is reported
    as "expected an item" (the snapshot shows it, as `fn` in a body does
    without `unsafe`).
  - `unsafe` joins `at_block_like` and `ExprKind::is_block_like`, so as a
    statement it needs no `;` and as a `match` arm no `,`, as `critical` does.
    `recover_to_item` stops at `unsafe` only when `fn` follows it, as it does
    for `interrupt`: an `unsafe { }` block inside a broken body is not an item.
  - `ty/reference.rs` is untouched, as the step says. `ty/place.rs`, the
    evaluator and `analysis/` needed nothing: `Unsafe` is added to the
    matches that list `Block` and `Critical` (`ty.rs`, `ty/linear.rs`,
    `mir/build.rs` for `is_discarded`, `discard` and the expression itself,
    `hir/mod.rs` `walk`); `ty/dump.rs` prints `unsafe`.
  - The token is `TokenKind::Unsafe`; the SVD generator escapes it with no
    change, since `src/svd/names.rs` reads `TokenKind::keyword`. No Erebos
    source in the repository used `unsafe` as a name (checked with a search
    of `*.ers` and `*.svd`).
  - `docs/reference.md` gains one row in the table of "Diagnostics" for
    `parser::misplaced-unsafe`, because `tests/rejected.rs`
    (`every_code_has_a_rule`) requires every code with a snippet to be there;
    the rest of the documentation stays in step 10.
  - 34 existing AST snapshots change by one line, `is_unsafe: false`, in each
    `FnDecl` (checked: no other difference). The new ui tests:
    `unsafe_parse` (AST: statement, `let` value, tail, operand, `match` arm,
    nested, around and inside `critical`; `unsafe fn` at module level, `pub`,
    `#[export]`, `#[export] pub`, `#[naked]`, in an `impl` with and without
    `pub` and `#[export]`, in a `mod`), `unsafe_parse_errors` (AST: one
    position per case in a single file, so that the recovery of each is
    shown not to disturb the next), `unsafe_assign` (the statement form
    `unsafe { *p } = 1;` is a parse error, as `critical { } = 1;` is) and
    `unsafe_assign_types` (the parenthesized form is `ty::not-assignable`, next
    to the same for a plain block), `unsafe_mir` (a function and a copy of it
    with `unsafe` blocks around the same statements, including `break`,
    `continue`, `return` and a block as the tail: the MIR of the two is
    identical, as the snapshot shows). The `tests/rejected.rs` snippets are
    one at item level (`unsafe extern fn`) and one in a body (`unsafe;`).
    `tests/fuzz.rs`'s corpus gains four fragments (`unsafe {`, `unsafe { 1 }`,
    `unsafe fn`, `pub unsafe fn f() {}`).
  - No `PANICS` count changes: the step adds no `unwrap`, `expect` or
    indexing that user input can reach.

## 2. feat(ty): check `unsafe` blocks and calls to an `unsafe fn`
- Status: done
- Implements: ADR 0119, "The rule" (operation 5, where the rule applies,
  expressions in error), "`unsafe { }`" (every block is used), "Where it is
  checked", "Diagnostic codes"
- Changes: `src/ty/unsafety.rs` (new), run on each typed body after typing,
  beside `linear.rs` and `reference.rs`, reading `q.tables.expr_ty`: the
  stack of `unsafe` blocks, the innermost marked used at each unsafe
  operation, `ty::unsafe-required` at an operation outside every block,
  `ty::unused-unsafe` at each block left unused (with the outer block's
  label when nested). Every `Fn` of HIR with a body is a root, run from
  `check_fn`, the bodies of every `Comptime` kind included. Coverage is
  lexical: a `comptime(..)` operand (`ExprKind::Comptime`, an `asm` `const`
  operand included) is an expression of its enclosing body, which
  `src/query.rs` evaluates from there without making a body of it, so the
  walk descends into it with the current stack of blocks. An operation on an operand or callee of
  erroneous type marks its block used and is never reported. Operations
  recognized in this step: calls to an `unsafe fn` (free, of a type,
  method), at run time and at compile time.
- Tests: ui tests: a call to an `unsafe fn` rejected outside a block and
  accepted inside; an `#[export] unsafe fn` called from Erebos; in an
  `unsafe fn` body, rejected without a block, with the help; a method call;
  a call in a `const` initializer, an item-level `comptime` block, an enum
  discriminant and an array length; a `comptime(..)` operand and an `asm`
  `const` operand holding a call to an `unsafe fn`, inside an `unsafe` block
  (accepted, checked once) and outside one (one error); an empty `unsafe` block, one with only
  safe operations, one nested in a used block with nothing of its own, two
  nested empty blocks (two errors); a call to an undefined function inside
  `unsafe` (one error, no `ty::unused-unsafe`); `return`, `break` and
  `continue` out of an `unsafe` block; `tests/rejected.rs` snippets for both
  codes. No program writes an `unsafe` yet, so none changes.
- Decisions:
  - `src/ty/unsafety.rs` is a pass of its own, not an `impl Checker` like
    `linear.rs` and `reference.rs`: it needs the stack of blocks and nothing of
    the checker's state, so it is `Unsafety { q, open, in_unsafe_fn }` and one
    entry point, `unsafety::check(q, f, body)`, called from `Checker::fn_`
    after `report_made_references` for every `Fn` with a body (so the
    `comptime` kinds, array lengths and the rest are roots, as the step
    says). `ty.rs` only gains `mod unsafety;` and that call.
  - The walk is its own recursion (`expr`, with `children_of` listing the
    direct sub-expressions in source order, blocks flattened), not
    `Expr::walk` (it cannot pop a block when it leaves it) nor
    `linear::operands_of` (it separates operands from blocks and loses
    order). `children_of` has no wildcard arm, so a new `ExprKind` has to be
    placed in it. `Unsafe` is in its match for exhaustiveness only; `expr`
    handles it before. A `comptime(..)` operand and an `asm` `const` operand
    are plain children, so they are visited once, under the blocks around them
    (the `unsafe_compile_time*` ui tests show one error or none, never
    two).
  - An `Operation` enum holds what a diagnostic says about the operation
    (`CallsUnsafeFn(path)` now), so that steps 3 to 6 add a variant each with
    its message, label and help, and the reporting and "mark the block used"
    logic stays in one place.
  - `ty::unsafe-required`: the message is "calling `unsafe fn PATH` needs an
    `unsafe` block", the label "this calls `unsafe fn PATH`" (the ADR's
    wording), with `PATH` the callee's HIR path (`Counter::make`,
    `inner::deep`). The label is the whole call expression for a free call
    (HIR keeps no span of the callee alone) and the method's name for a method
    call (`c.peek()` points at `peek`, so a chain `a.safe().unsafe_one()`
    does not underline the safe part). The help is one string, as `Diagnostic`
    allows one: the general advice, and inside an `unsafe fn` the sentence the
    ADR asks for ("the body of an `unsafe fn` is not an `unsafe` block, so it
    needs its own"). Which function it is in comes from `Fn::is_unsafe`.
  - `ty::unused-unsafe`: the message is "this `unsafe` block holds no unsafe
    operation", the primary label "nothing in it needs `unsafe`" on the
    keyword, and for a nested block a second label "inside this `unsafe`
    block" on the enclosing block's keyword (the enclosing one, whether or not
    it is used itself: two nested empty blocks are two errors, the inner with
    the label). The keyword's span is the first six bytes of the `unsafe`
    expression's span (`unsafe` starts it; step 1's parser guarantees that),
    since HIR keeps only the block's span.
  - Erroneous expressions (ADR 0119, "Expressions already in error": an
    operation whose operand or callee has an erroneous type). For a call, the
    operands are its arguments and, for a method call, its receiver; the callee
    of a free call is a `FnId` and is never erroneous. A call to an `unsafe fn`
    with an operand whose type is `Ty::Error` marks the block around it used
    and is not reported (review finding 1; the first version applied this to a
    method call with no method only). A method call with no entry in
    `tables.methods` (no method, a private one, an erroneous receiver: each was
    reported) is treated the same, whatever its callee would be, since it is
    not known. A call to a safe function with an operand in error is not an
    operation, so it marks nothing. A free call to a function that is not
    found is a lowering error (`resolve::unknown-function`), and lowering
    errors stop the pipeline before type checking, so there is no
    `ty::unused-unsafe` after it (`unsafe_unknown_function`). A merely
    mismatched argument (`plain(true)` for a `u32`) keeps its type, so the call
    stays an operation and is reported outside a block
    (`unsafe_after_errors`, `wrong_argument`). `operand_in_error` in the same
    test has an argument in error and a receiver in error, each for a free
    call and a method call, inside and outside a block: only the operand's
    `ty::unknown-method` comes out. Steps 3 to 6 apply the same rule to
    dereferences and the other operations through their operand's type.
  - Ordering: diagnostics are sorted by their primary label, so the pass
    reports on the way down without sorting; an unused block is reported when
    it is left (after its contents), which the sort hides.
  - No new panic: the pass uses no `unwrap`, `expect` or indexing (a `pop` of
    the stack it just pushed to is an `if let`), so no `PANICS` count changes.
  - Step 1's tests `unsafe_assign_types` and `unsafe_mir` wrote `unsafe`
    blocks that hold no unsafe operation (a raw dereference is not one yet),
    which `ty::unused-unsafe` now rejects, so they changed: each block gains
    a call to `unsafe fn touch()`. For `unsafe_assign_types` that is all (the
    tail `*p` and the write stay). For `unsafe_mir`, `without_block` cannot
    omit the blocks (the calls need one), so it keeps each `touch()` in a
    block of its own and the other statements outside, while `with_block`
    groups them under the blocks: a block lowers flat, so the MIR of the two
    bodies is identical (checked by comparing the two functions of the new
    snapshot, line by line), which is still what the test claims. Step 5 can
    drop `touch()` from both when `*p` is itself the unsafe operation. Their
    snapshots changed accordingly; no other existing snapshot changed.
  - New ui tests (all `// emit: typeck`): `unsafe_call_accepted` (free
    function, `#[export]`, function of a type, method, a module's, from an
    `unsafe fn` through its own block, one block over two calls, nested blocks
    each with a call, `return`/`break`/`continue` out of a block, inside and
    around `critical`, as an `if` condition and a `match` arm),
    `unsafe_call_errors` (each of those forms without a block, two calls in one
    expression, a call next to a block, `unsafe fn` bodies with and without
    their own block, a branch of an `if` next to a covered one),
    `unsafe_compile_time` and `unsafe_compile_time_errors` (a `const`
    initializer, an item-level `comptime` block, an enum discriminant, an
    array length, a `comptime` operand, an `asm` `const` operand; covered by
    a block and not), `unsafe_unused` (empty block, only safe operations,
    nested without its own, two nested empty blocks, an outer block whose
    operation is in the inner, blocks holding only `break`, `continue` and
    `return`, an operation through an `if` inside the block, `critical`
    inside), `unsafe_after_errors` (a method that is not found inside and
    outside a block, a mismatched argument inside and outside),
    `unsafe_unknown_function` (the lowering error). The accepted and the
    rejected programs are separate files because a program with errors
    snapshots only the errors, which would hide an accepted form.
  - `tests/rejected.rs`: `ty::unsafe-required` is an `Items` snippet (an
    `unsafe fn` and a function that calls it) and `ty::unused-unsafe` a
    `Statements` one (`unsafe {}`), both at `Mir` like the neighboring `ty`
    snippets. `docs/reference.md` gains the two rows in "Diagnostics", after
    `ty::naked-body`, because `every_code_has_a_rule` requires it; the rest
    of the documentation stays in step 10.
  - Found, as asked: `unsafe fn f();` (no body, no `extern`) sets `is_unsafe`
    in `fn_decl` and then `self.block()` fails at the `;` with
    `parser::unexpected-token` ("expected `{`, found `;`"), the same error
    `fn g();` gives, and the whole `FnDecl` is dropped with the error, so the
    flag is dropped with it. Nothing reaches HIR and no second diagnostic
    comes out; no change to the parser, no test added.

## 3. feat(ty): require `unsafe` for `asm`
- Status: done
- Implements: ADR 0119, operation 2, "Naked functions" (the body), "`core`"
  (the safe functions of `core::arch`)
- Changes: `src/ty/unsafety.rs` recognizes `asm` outside a `#[naked]` body;
  `src/ty/asm.rs`: an `unsafe` block as a naked body stays `ty::naked-body`,
  with a help "remove the `unsafe` block: `#[naked]` is the mark".
  Migration of every `asm` outside a naked body (see "Where Erebos source
  lives"): `rt/arch/riscv32.ers` and `rt/arch/armv7m.ers` (the functions of
  `core::arch`, `__critical_enter` and `__critical_exit` keep safe
  signatures, with an `unsafe` block and a soundness comment around each
  `asm`), `tests/boards/thumbv7m-none-eabi.ers`, the programs of
  `tests/e2e/`, the programs embedded in `tests/elf.rs` (around 1511) and
  `tests/e2e.rs` (around 257), the ui tests and the snippets of
  `tests/rejected.rs` (the `eval::asm` snippet keeps a block, so that its own
  code is the one reported).
- Tests: ui tests: `asm` rejected outside a block, accepted inside, accepted
  as a naked body without a block, `ty::naked-body` with the help with one;
  `asm` at compile time inside a block keeps its error. The e2e programs run
  with the same output.
- Decisions:
  - `asm` is `Operation::Asm` in `src/ty/unsafety.rs`, beside
    `CallsUnsafeFn`, as step 2 planned: message "`asm` needs an `unsafe`
    block", label "this `asm`" (the ADR's wording) on the whole `asm`
    expression, and a help that says why (it can write any register or any
    memory) and that a `#[naked]` body needs no block. In an `unsafe fn` the
    sentence about its body not being a block is added, as for calls.
  - The naked exemption is in `unsafety::check`, not in `Operation`: for a
    function of kind `Naked`, an `asm` that is a direct statement or the tail
    of the body is visited for its operands only, never as an operation. Every
    such `asm` is exempt, not only the first: a second one, or one with the
    wrong operands, is `ty::naked-body`'s error already, and a
    `ty::unsafe-required` on top would be an error caused by an error. An
    `asm` nested deeper in a naked body (in an `if`, say) is not exempt: the
    body is malformed there too, and the nested `asm` is a real `asm` outside
    a naked body's own. This needed `block_exprs` (the statements and tail of a
    block, in order) out of `children_of`, where it was a local function.
  - Operand in error (step 2's rule, applied): an `asm` whose operand
    expression (`in`, `inout`, an `out` place, `const`) has type `Ty::Error`
    marks its block used and is not reported (`operand_in_error` in the new
    `unsafe_asm_errors.ers`, inside and outside a block: only the operand's
    `ty::unknown-method` comes out, and no `ty::unused-unsafe`). The operands
    are listed by `children_of`, so the walk and the test cannot disagree; the
    `asm`'s own type (`!` or `()`) is never an error.
  - `ty::naked-body` for an `unsafe` block as the body: in
    `Checker::naked_body`, any statement or tail that is an `unsafe` block gets
    the label "an `unsafe` block, not needed on a naked function" in the
    "is not one `asm` expression" error (instead of "not an `asm` expression"),
    and the help becomes "remove the `unsafe` block: `#[naked]` is the mark
    (ADR 0119); " followed by the usual help. The message is unchanged (the body
    is indeed not one `asm`). The help is not conditioned on the block holding
    an `asm`: an `unsafe` block of any content is the same mistake. The `asm`
    inside the block is covered, so the body gives no `ty::unsafe-required`;
    an empty block would also give `ty::unused-unsafe`, which is true and is
    not tested.
  - The migration wraps each `asm` statement, and only it, in `unsafe { }`,
    not the statements around it (ADR 0119: a block marks the operation). In
    `rt/` and `tests/boards/`, each block has a `Sound:` comment, as the ADR
    asks of those directories; `enable_interrupts`' says that calling it in
    `critical` or a handler is the caller's to avoid (it becomes an `unsafe fn`
    in step 6). In `nvic_disable` the block holds the `dsb`/`isb` `asm` only:
    the `*word = ...` beside it is step 5's. The programs of `tests/e2e/`, the
    ui tests and the Rust snippets have no comments (the ADR exempts test
    programs). A statement on one line stays on one line, `unsafe { asm(..); }`,
    so that the line numbers of every snapshot and test that names a line stay
    put; a statement on several lines becomes a block of several lines, with
    the `asm` indented by four. The inside of a `format!` string in `tests/e2e.rs`
    and `tests/elf.rs` writes the braces twice.
  - A tail `asm(..., options(noreturn))` (no `;`) becomes
    `unsafe { asm(...) }`, the value of the block being the `asm`'s, so that
    the function still ends in a `!` expression (`sym_entry_*`, the last line
    of `asm_*` e2e programs, `asm_typeck.ers`).
  - How every `asm` was found, as the plan asks (no file is left out by a
    search that sees only part of the repository):
    - `\basm\s*\(` over `{rt,tests}/**/*.{ers,rs,svd}` (the Grep tool): 99
      files; `\basm\b` over the same: 106 files (the seven more name `asm` in
      comments or as a word: `asm_names.ers`, `chip_interrupts_no_handler_thumbv7m.ers`,
      `target_thumbv7m_reset_entry.ers`, `critical_comptime.ers`,
      `tests/architecture.rs`, ...). `git ls-files '*.ers'` outside `tests/`
      and `rt/`: none. `src/`: `grep asm src/driver.rs src/svd` finds one
      source string, in a `#[naked]` function (exempt), and the SVD
      generator writes none. `tests/svd.rs`, `tests/svd/chips/`,
      `tests/fuzz.rs`, `tests/common/generator.rs` and `tests/layout/` hold no

- Implements: ADR 0119, operation 1, "`core`" (the memory functions as
  `unsafe fn`)
- Changes: `src/ty/unsafety.rs` recognizes a read, write or borrow of a place
  reached through a raw pointer of any kind (thin, slice, volatile, to a

  `memmove`, `memset` and the twelve `__aeabi_mem*` become `unsafe fn`,

  `tests/fuzz.rs`'s corpus that dereference, the ui tests and the snippets.
  The step cannot be split cleanly: blocks added before the check
  recognizes their operations would be `ty::unused-unsafe`, and the check
  without the blocks fails every program. It stays one commit, reviewed by
  directory (`rt/`, boards, `tests/e2e/`, `tests/ui/`, the rest).
- Tests: ui tests, one per form of operation 1 (`*p` read, `*p` written,
  `p[i]`, `(*p).f`, `(*s)[i]`, a range of `*s`, `&*p`, `&mut (*p).f`, a
  volatile pointer, a register through `*mut Uart`, `(*p).method()`, a
  returned `&*p` under ADR 0118); one per safe form (`&raw const p[i]`,
  `&raw mut (*p).f`, `len(s)`, `slice(p, n)`, `p as usize`, `*r` through a
  reference, a register of a peripheral static); an expression with two
  operations gives two errors. The e2e programs and `tests/svd.rs` pass.
- Decisions:
  - One variant joins `Operation` in `src/ty/unsafety.rs`, as step 2 planned:
    `RawPointer(Access)`. `Access::gerund` (new) gives the verb of the message
    for it and for `ExternStatic`, which had the same `match` inline.
  - What is an access through a raw pointer, read from the types the checker
    recorded (`tables.expr_ty`), not from the syntax: `Deref(e)` whose operand
    `e` has type `Ty::Ptr` (any kind: thin, slice, volatile, to a peripheral
    type), and `Index(base, i)` whose base has type `Ty::Ptr` (`p[i]`). A
    `Deref` of a reference is safe (`*r`). `Field` and `Subslice` are not
    operations themselves: they pass the access down to their base, so
    `(*p).f = 1` is one write at `*p`, `(*s)[i]` is one access at `*s`, and
    `&(*s)[1..3]` one borrow at `*s`. The operand of a `Deref` and the base and
    index of `p[i]` are read as values (`self.expr`), so `**pp` is two reads,
    `(*(*n).next).value` two reads, and `c_cursor[0] = 1` on an `extern static`
    pointer is a read of the static and a write through the pointer (step 4
    passed the write down to the static: it would have said "writing `extern
    static`"; `unsafe_pointer_errors.ers` `write_through_c_static` pins the
    corrected pair).
  - A base of reference type is read, not given the access (`place_base`): the
    place `r.f`, `r[i]`, `r[a..b]` is `(*r).f` (ADR 0114) and touches what the
    reference refers to, not `r`. It matters when `r` is itself read from a place
    (a `*q` of type `&T` would otherwise be reported as written).
  - How the place is touched comes from the expression around it, the rule of
    step 4 with the same `Access` set: an assignment target `Write`, a compound
    assignment target `Update` ("reading and writing"), `&` and `&mut` `Borrow`,
    a method receiver `Borrow` when the method takes `&self` or `&mut self` and
    `Read` for `self`, the operand places of an `asm` as `asm_operands` says
    (`in` reads, `out` writes, `inout` both, `inout(..) v => place` writes
    `place`), every other expression `Read`. `&raw const` and `&raw mut` pass
    `None`: no operation, but the pointer inside is still read (`&raw const
    (*(*n).next).value` reads `(*n).next`). `unsafe_pointer.ers` and
    `unsafe_pointer_errors.ers` (`updates`, `borrows`, `methods`, `asm_operands`)
    pin one message for each.
  - `ty::unsafe-required`: the message is "VERBing through a raw pointer needs
    an `unsafe` block" ("reading", "writing", "reading and writing",
    "borrowing"), the label is the ADR's "this dereferences a raw pointer"
    whatever the verb (the verb is in the message, as for `extern fn`), and
    the span is the `Deref` expression (`*p`, `(*pair)`, which includes the
    parentheses) or, for `p[i]`, the whole `Index`. So `(*pair).b = 3` points at
    `(*pair)`, and `(*s)[i]` at `(*s)`. The help says what the compiler cannot
    check and that `&raw`, `len`, `slice` and casts need no block.
  - Expressions in error (step 2's rule, applied): a `Deref` whose operand has
    type `Ty::Error` marks its block used and is not reported, for `&raw` too (a
    pointer in error may be a reference, and the block should not be called
    unused on top of the error); the pointer of `p[i]`, the index and the
    expression itself having type `Ty::Error` (`ty::slice-pointer-index`,
    `ty::peripheral-index`) do the same for an index, and an index or a range
    of a pointer (`Subslice`, always an error) or of a base in error marks the
    block used. The index counts as an operand because the address depends on it
    (step 4's reading: what the operation's own address depends on). The value
    written (`*p = expr_in_error`, `p[1] += expr_in_error`) is not an operand
    (the user's decision of step 4): the write is reported outside a block and
    inside only the value's error comes out. `operand_in_error` and
    `value_in_error` in the errors test show each, inside and outside a block.
  - A field of a pointer (`p.a`, `u.ctrl` with `u: *mut Uart`) is
    `ty::no-fields`, which was reported: `place_base` marks the block around it
    used and reports nothing, as for an index or a range of a pointer (review
    finding 1: the first version gave a `ty::unused-unsafe` after the
    `ty::no-fields` for `unsafe { p.a }`). `field_of_a_pointer` in the errors
    test shows both forms, inside and outside a block: only `ty::no-fields`
    comes out.
  - A pointer of type `!` (`*diverges()`) is neither an operation nor an error:
    `through_pointer` computes no place for it. Outside a block nothing is
    reported; inside one the block is `ty::unused-unsafe` (`never_pointer`).
  - The pass adds no panic: no `unwrap`, `expect` or indexing. No `PANICS`
    count changes (`tests/architecture.rs` passes).
  - Method: the compiler is the oracle, as in steps 3 and 4. `rt/` and the
    boards first (every build compiles `rt/`, so its sites show in every

    scratchpad stages each program as the harness does (a copy of the board
    beside it, one target for `*_riscv32` and `*_armv7m`, both otherwise) and
    runs `erebos build X --emit=typeck --target T`, printing each
    `ty::unsafe-required` and `ty::unused-unsafe` with the line, column and the
    length of the label. Before: 357 sites in 77 programs (143 writes, 143
    reads, 63 borrows, 4 reads and writes through a raw pointer, and 4 calls of
    `core::memcpy`, `memmove` and `memset`, now `unsafe fn`); after: none. For
    `tests/ui/`, `cargo test --test ui` listed the failing snapshots and the
    sites were read from the `.snap.new` files (441 sites in 135 programs; 137
    snapshots failed, 2 of them for lines of `rt/builtins.ers` only:
    `resolve_core`, `resolve_extern_errors`). A second script wrapped the
    single-line sites; the 13 sites it left (7 in `tests/e2e/`, 6 in
    `tests/ui/`) were edited by hand: the list elements of `print.ers` and

## 7. test(rejected): removing an outer `unsafe` from an e2e program is rejected
- Status: done
- Implements: ADR 0119, "Conformance tests" (`tests/rejected.rs`, the
  mechanical part); extends ADR 0069
- Changes: `tests/rejected.rs`: for each `unsafe` block of the programs of
  `tests/e2e/` that is not inside another `unsafe` block, the program with
  that one `unsafe` removed (the block kept) must be rejected with
  `ty::unsafe-required`. Nested blocks are skipped: removing their `unsafe`
  is rightly accepted. How the blocks and their nesting are found (a scan
  of the source for `unsafe` before `{`, skipping comments and `unsafe fn`,
  tracking braces) is decided while building and recorded.
- Tests: the new test itself; a block that nothing in it needs would make it
  fail, which `ty::unused-unsafe` should already have caught (a second
  oracle for that check).
- Decisions:
  - How the blocks and their nesting are found: `tokens` in
    `tests/rejected.rs` turns the source into words, single punctuation
    characters and literals, skipping `//` comments, `/* */` comments (which
    nest, as in the lexer) and the contents of strings and character
    literals (a backslash escapes the next character; a character literal
    ends at the line's end if unclosed), so that an `unsafe` or a brace in
    them is not seen. `outer_unsafe_blocks` walks the tokens with a stack of
    open braces, each marked "is the brace of an `unsafe` block". A `{`
    whose previous token is the word `unsafe` opens a block (so `unsafe fn`,
    `unsafe extern` and `unsafely` are not blocks, and a comment between
    the keyword and the brace does not matter); it is outer when no open
    brace on the stack is an `unsafe` block. The body of an `unsafe fn` is a
    brace marked false, so a block in it is outer, as ADR 0119 says (the
    body is not an `unsafe` block). A scan of tokens and not a parse because
    the test works on the program as text, like `statement_boundaries`; the
    parser's AST would also hide the block's byte offset.
  - The `unsafe` is removed by overwriting the six letters with spaces
    (`without_unsafe`), not by deleting them: every line and column stays,
    so the diagnostics and the reported line (the line of the removed
    `unsafe`) refer to the file as it is. The block is kept, as the plan
    and ADR say; the program compiles as a plain block.
  - Programs: the root file of each program of `tests/e2e/` only
    (`programs_in("e2e")`, the loop of `base_programs` made a function and
    shared by it). The other files of a program with modules
    (`panic_location/parse/digits.ers`, with 3 blocks, and the like) are not
    scanned: `dump` takes the root text and reads the modules from disk, so
    a changed module would need its own harness, for 3 blocks in all of
    `tests/e2e/`; left out and recorded here.
  - Targets: each program is built for the targets its `// targets:` header
    names, or for both, the same set the e2e test runs it on, taken from
    `common::qemu::expectation` (so the header is parsed in one place). A
    portable program is thus checked twice, which is intended: the
    operations of a block can differ in `core` per target (the `rt/arch`
    files), and a portable program compiles to the same thing on both
    anyway. The board is inlined with `with_board` for that target, as the
    other tests do.
  - Stage: `Stage::Mir`, like the `ty::` snippets of the catalog (the last
    stage an erroneous program reaches), so a panic of MIR building or of
    the validator on the program without the `unsafe` also fails the test.
  - The program without the `unsafe` is not first compiled as it is: it is a
    valid e2e program (the e2e tests build it), and if it were not, the
    removal would be rejected for another reason and reported as "was not
    reported" with the diagnostics. Two failure messages: "was accepted"
    (the removal gave a program; the block was not needed, or nested in
    spirit) and "`ty::unsafe-required` was not reported" with the rendered
    diagnostics. Each names the file, the line of the `unsafe` and the
    target.
  - No environment variables and no random choice: every outer block of
    every program is tried (the test is not a sample, since the cost is
    bounded and the result is deterministic). It takes about 33 s in a debug
    build for 116 programs and 1,358 removals (a program counted once per
    target), in parallel with the other tests of the file. Floors in the
    test (100 programs, 1,000 removals) fail it if the scan stops finding
    the blocks, so that it cannot pass by checking nothing; the numbers are
    the ones found when the step was written.
  - Result: the first run passed with no failure and no change to a program:
    every outer block of `tests/e2e/` is needed, so `ty::unused-unsafe` and
    this test agree (the second oracle the plan asked for).
  - Tests: `outer_unsafe_blocks_are_found` (a function and a block in an
    `unsafe fn`; blocks in a line comment, a nested block comment, a string
    and a character literal that are not seen; `'\''`; an outer block with
    two blocks nested in it, one inside an `if`; `unsafely`; a comment
    between `unsafe` and `{`; `unsafe fn f() {}` is none),
    `without_unsafe_keeps_the_block_and_the_positions`, and
    `a_removal_that_is_not_rejected_is_reported` (the check can fail, as for
    the catalog: a block nothing needs is "was accepted", a block whose
    removal gives another error is "was not reported", and a real

  - `CONTRIBUTING.md` and `docs/reference.md` are not touched; the
