Order: references to slices go through every layer at once (1), since a type
that checks must reach MIR, evaluation and code generation; it brings places
of type `[T]` with `Index`, which the conversion (2) and sub-slices (3) build
on. The conversion (2) adds `ConstSubslice`, which sub-slices of arrays with
known bounds (3) reuse. The program (4) needs all three. Each step that adds a
projection extends the validator, the borrow analysis, the analyses of moves
and linearity, the check of shared statics, code generation and the evaluator
in the same commit, so that no layer meets a projection it does not know. A
diagnostic case gets, in the step that adds it, its ui test and, where it
changes a row, its row in the check tables of `docs/reference.md`; the prose
of the reference comes in the last step. No code is new (ADR 0108), so
`tests/rejected.rs` gains no snippet unless a step's `Decisions` say why. Each
step gains a `Decisions:` list while it is built (`/build-step`), for the
choices it makes that this plan and the ADRs do not dictate.

    says so") and which would otherwise report one fault twice, and a
    projection other than `Index` on one is T1. So the plan's "U1 (a `copy` of

    reports each use. `ref_place` (R3) already allowed `Index`.

    `from > to`, on a `[T]`), R3 (a `Ref` whose place has `ConstSubslice`
    accepted).
  - e2e: `tests/e2e/slice_references_c.ers` gains a call with `&buf` and
    `&b"..."` converted.
- Decisions:
  - Type checking: `unsizes` (`ty.rs`) gained the reference arm beside the
    pointer one, so `coerces`, `check` and the `coercions` table treat
    `&[T; N]` to `&[T]` and `&mut [T; N]` to `&mut [T]` or `&[T]` as ADR 0031's
    conversion; the table holds the target type, and MIR building tells the
    conversions apart by the source type (a reference to an array, and a
    target that is a reference to a slice), since `share` (`&mut T` to `&T`)
    has the same shape. `len` of a reference to an array records no
    conversion: MIR building writes the constant, as ADR 0109 says. The help
    of `len`'s `ty::mismatched-types` now says "a pointer or a reference to an
    array" (`typeck_slice_errors.ers`'s snapshot changed by that line only).
  - A literal under `&` where a `&[T]` is expected (`Checker` `Ref` arm):
    the referent `[T]` is no longer passed as the type expected of the
    value, because no value has it and an array literal checked against it
    was `ty::mismatched-types`; the array under `&` is typed on its own and
    converts. So `&[1 as u8, 2, 3]` converts, and `&[1, 2, 3]` is
    `ty::untyped-literal`, as it is where no type is expected. Not in the
    plan; it follows from the conversion being in every position of ADR 0024.
  - MIR building: the conversion is made in `Builder::expr` before the
    expression is built, since the direct form (`place[0..N]` for `&place` and
    `&mut place`) must replace the `Ref` of `place`, not follow it
    (`unsize_reference`). `Builder::borrowed_place` is the old body of the
    `Ref` arm (the place, or a variable of its own for a value), shared by the
    arm and the conversion. The indirect form takes `q` from the operand
    `expr_kind` gives (a variable or parameter is its own place and is not
    moved: no statement uses the operand), else a temporary; so a `&mut [T;
    N]` variable converted, as an argument or not, is lent by the `Ref` and
    `argument`/`is_mut_variable` needed no change beyond a comment. The
    mutability of the `Ref` is the target's, so `&mut buf` converted to a
    `&[T]` is a shared `Ref` of `buf[0..N]`. `len` of a reference to an array
    evaluates the operand for its effects and gives `usize_const(N)`;
    `len(&buf)` therefore leaves a `Ref` temporary nobody reads (a dead
    borrow, harmless to the analysis). A cast `r as *const [u8]` with
    `r: &[u8; 4]` needed no code: `Builder::cast` already goes through
    `*const [u8; 4]` and `array_slice`.
  - `PlaceElem::ConstSubslice(from, to)` is dumped `[0..4]` after its base
    (`_1[0..4]`, `(*_1)[0..4]`), as the plan says. It was added to the
    exhaustive matches that name every projection (the validator's M3, L1,
    R3, `project`; the borrow analysis's `path`), and to the projection tables
    of `mir/mod.rs` and `mir/build.rs`. No other analysis names projections.
  - Validator: T1 for `ConstSubslice(from, to)` accepts an array with `from <=
    to <= N` (empty at the length included) giving `[T]`, and says what is
    wrong for a bound past the length, `from > to`, a `[T]` and anything that
    is no array; the `Subslice` form of a `[T]` is step 3's. R3 allows it. U1
    needed nothing more: T1 already refuses any projection but `Index` (and,
    from step 3, the subslices) on a `[T]`. Tests: `t1_const_subslice_applies_
    to_an_array_within_its_length` and `r3_the_place_of_a_ref_may_be_a_const_
    subslice_of_an_array` (which also pins R2 through a shared reference and
    T5 on the element type).
  - Evaluator and code generation: the length of a place of type `[T]` is
    now an enum in both (`eval::Length`, `codegen::Length`): `Stored` (the
    slice it was reached through, step 1's) or `Known(to - from)` for a
    `ConstSubslice`, which has no slice in memory to read. The address of a
    `ConstSubslice` is the base's plus `from` times the element's size. The
    plan's "`ConstSubslice` in the lowering of `[T]` places" is these two
    arms; the panics counted in step 1 are unchanged.
  - Borrow analysis: `ConstSubslice` is `Step::Elem` in `path`. `borrow_how`
    recognizes a `Ref` of `(*q).ConstSubslice(0, N)` with `q` of type `&[T; N]`
    and the same `N`, into an unnamed temporary: lent to this call when it is
    mutable, `q` is named and the temporary is passed to a call (the existing
    rule), else two new `How` variants, `ConvertSlice` (shared) and
    `ConvertSliceMut` (mutable, `mutable()` is true and it `writes()`), whose
    message and label are "cannot convert `q` to a slice while it is borrowed
    as mutable" / "cannot convert `q` to a mutable slice while it is borrowed",
    "converted to a slice here", and the site label "`q` is converted to a
    slice here". Two variants and not one because the shared one is a read and
    the mutable one is a `&mut` borrow in the table of ADR 0106. A shared
    conversion from a `&mut [T; N]` is "converted to a slice here" and not
    "converted to `&` here" (ADR 0109: the array case wins). A written
    `&(*r)[0..N]` has the same MIR and is told the same, as ADR 0109 says.
  - Naming: `name()` writes a `ConstSubslice(0, N)` of an array of `N`
    elements as the array itself, so that `&buf` converted is "`buf` is
    borrowed here" (ADR 0108, 0109) and not "`buf[_.._]`"; any other
    `ConstSubslice` is `[_.._]` after its base. Step 3's `&buf[0..N]` written
    over a whole array will read the same way; revisit there if that should
    differ.
  - `docs/reference.md`: only the row of `analysis::borrow-conflict` in the
    check tables changed (the conversion of a reference to an array to a
    `&[T]` among the reads, and a `&mut [T; N]` converted to a `&mut [T]`
    among the `&mut` borrows); the prose of "The error" lists the two new
    messages, and is left for step 5 with the rest of the prose.
  - Tests: the plan's three ui files are `slice_reference_conversion.ers`,
    `slice_reference_conversion_errors.ers` and `slice_borrows_conversion.ers`
    (the first has no error, as ui files with an error print only errors;
    the in-position cases are `places`, `variables`, `positions`, `empty`,
    `lengths` and `cast`; the `if`, `match` and block values are in
    `positions`, and the `&mut [T; N]` variable lent and usable after the call
    in `variables`). One file is added
    that the plan does not list, `slice_reference_conversion_comptime.ers`
    (`--emit=mir`, like step 1's comptime file), because the evaluator gained
    `ConstSubslice`: a byte string, a `&[u8; 4]` variable and a `&mut [u8; 3]`
    converted to a `&mut [u8]` and written, whose values (294, 24, 6) show in
    the folded sums. `ty.rs`'s unit test `array_references_coerce_to_slice_
    references` pins `coerces`/`unsizes`. The e2e program gains four
    outputs: `&buf` (54), `&b"abc"` (294) and `&b""` (0) to the C side, and
    `&words` to the `#[export]` function (600000).
  - No panic count changed: the first draft raised `src/mir/build.rs` by an
    `unreachable!`, which was removed by passing the target's mutability
    instead of re-matching it.
