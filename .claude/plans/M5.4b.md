# Plan: M5.4b Slices behind references

ADRs: 0108, 0109 (building on 0031, 0105, 0106, 0107)
Base: 68ad363
Program on QEMU: a driver writing and filling buffers passed as `&[u8]` and
`&mut [u8]`, on riscv32 and thumbv7m at `-O0` and `-O`
(`tests/e2e/slice_driver.ers`): a module `uart` with `write(bytes: &[u8])`,
writing each byte through the board's `putc`; a module `fmt` with
`fill(out: &mut [u8], b: u8)`, `copy(dst: &mut [u8], src: &[u8])` and
`decimal(n: u32, out: &mut [u8]) -> usize` (the digits written at the end of
`out`, returning where they start); a module `frame` with
`checksum(bytes: &[u8]) -> u32` and `encode(payload: &[u8], out: &mut [u8])
-> usize`, which writes the payload's length in decimal, `:`, the payload,
`;` and its checksum in decimal into `out`, each part through a sub-slice of
`out` (`&mut (*out)[at..]`, `&(*digits)[start..]`). `main` encodes byte
strings passed as `&b"..."` into a `[u8; 32]` lent as `&mut line`, writes
`&line[..n]`, fills the rest with `fill(&mut line[n..], b'.')` and writes a
part of it, encodes an empty payload (`&b""`), and holds a `&mut [u8]` to a
buffer that it lends to calls in a loop and reads through the same reference
converted to `&[u8]`. The wrong uses (two `&mut` sub-slices of one buffer in
one call, a write to the buffer while a `&[u8]` of it is used later, `len(s)`
while a reborrow of `*s` is in use) are ui tests.
Out of scope:
- splitting a `&mut [T]` in two halves in use together (ADR 0108,
  "Splitting"): deferred ideas, with returning a reference;
- `base[..]` and `base[a..=b]`: errors, which can be lifted later (ADR 0108);
- `assert` with a `&[u8]` message: M5.7's pending decisions (ADR 0108, "What
  does not change");
- references to slices through a volatile raw slice, to `static mut`, to
  peripherals: `ty::reference-to-volatile` and `ty::reference-to-static-mut`
  until M5.4c;
- `core` and the tests moved from raw slices to references: M5.7. Tests that
  write `slice(&raw const ..., n)` keep it, except where a step below
  replaces it to test a range;
- slices in the generated programs of ADR 0068, which have only scalar types;
- `erebos svd`: it writes no function, so its output does not change.

The same commit holds this plan and the roadmap's edits written while
planning (M5.4b's pending decisions settled; the split under deferred ideas;
`assert`'s message under M5.7).

Order: references to slices go through every layer at once (1), since a type
that checks must reach MIR, evaluation and code generation; it brings places
of type `[T]` with `Index`, which the conversion (2) and sub-slices (3) build
on. The conversion (2) adds `ConstSubslice`, which sub-slices of arrays with
known bounds (3) reuse. The program (4) needs all three. Each step that adds a
projection extends the validator, the borrow analysis, the analyses of moves
and linearity, the check of shared statics, code generation and the evaluator
in the same commit, so that no layer meets a projection it does not know. A
diagnostic case gets, in the step that adds it, its ui test and, where it
changes a row, its row in the check tables of `docs/reference.md`; the prose
of the reference comes in the last step. No code is new (ADR 0108), so
`tests/rejected.rs` gains no snippet unless a step's `Decisions` say why. Each
step gains a `Decisions:` list while it is built (`/build-step`), for the
choices it makes that this plan and the ADRs do not dictate.
