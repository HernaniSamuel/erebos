# Plan: M4.5 Shared statics checked

ADRs: 0093
Base: 8facbcd
Program on QEMU: programs with handlers checked: every e2e program with a handler builds
through the check; `critical_race` and `uart_interrupt` on both targets are those that
share statics, a helper called in `critical` and in the handler among them. Rejected
programs are ui tests.
Out of scope:
- accepting accesses before `enable_interrupts`, or after the last interrupt: ADR 0078
  lets a later step accept more; no step takes it yet;
- raw pointers and peripherals across contexts: M5 (ADR 0078);
- function pointers: the step that adds them (ADR 0078);
- handlers in the generator of ADR 0068: its programs have no source of interrupts; no
  step takes it yet;
- whether MIR analyses run before compile-time evaluation: M5 (roadmap).

Before step 1: the `docs(adr)` commit that accepts ADR 0093 also sets the status lines of
the ADRs it amends, in their files and in the index (`docs/adr/README.md`):
- 0063: `Accepted; amended by 0070, 0082 and 0093 (the tables gain the module
  `analysis`)`, keeping the wording of its other amendments; index adds `0093`;
- 0078: `Accepted; amended by 0093 (a `&raw` evaluated at compile time names no static)`;
  index `Accepted, amended by 0093`.
The same commit holds the roadmap's edit written while planning: M4.5's pending decisions
settled.

Order: the programs obey the rule (1) before the check can reject them (2). Rule 1 comes
with the layer because the layer has nothing to report without a rule; rule 2 (3) reuses
its searches. The guard on inserted calls (4) needs nothing from them but stands on the
reading of ADR 0093, "What is a call". Every existing test passes after every step. From
step 2 to step 5, `docs/reference.md` lists the new codes while its prose still says the
rule is not checked; step 5 rewrites that prose with the whole check in place.

In every step: if the count of `unreachable!` or `expect` for a file in
`tests/architecture.rs` rises, say why in `Decisions`, and only then raise it. A new file
needs a row only if it has any. No user input may reach one: a MIR the check cannot read is
an internal invariant, a program is not.

The check changes no generated code: a program it accepts compiles to the same bytes as
before.

## 1. test(e2e): the programs that share a static obey the rule
- Status: done
- Implements: ADR 0093, the table in "Context" and the end-to-end part of "Conformance
  tests". No compiler change.
- Changes:
  - Rule 1, each read in the thread context in `critical`, each expected output
    unchanged:
    - `tests/e2e/irq_disabled_armv7m.ers`: `RUNS` in the waiting loop and at the end; the
      `compiler_fence` before the first read goes, since the block is a fence;
    - `tests/e2e/irq_handler_in_module_armv7m.ers`: `RUNS` at the end;
    - `tests/e2e/irq_pended_armv7m.ers`: `RUNS` before `enable_interrupts` and at the
      end, `IPSR`, `ENABLED`;
    - `tests/e2e/irq_unpended_armv7m.ers`: `RUNS`, as in `irq_disabled`;
    - `tests/e2e/pendsv_returns.ers`: `RUNS` when printed;
    - `tests/e2e/uart_interrupt_armv7m/main.ers`, `uart_interrupt_riscv32/main.ers`:
      `SENT`.
  - Rule 2, the way out of ADR 0093: `tests/e2e/nmi_returns.ers` and
    `tests/e2e/svcall_returns.ers` name no static in the handler or the thread. Each
    static becomes `static mut COUNT: u32 = 0;`, and the name the program already uses
    becomes the constant: `const RUNS: *mut volatile u32 = &raw mut COUNT as *mut volatile
    u32;` in `nmi_returns`, `const CALLS: ...` in `svcall_returns`, read and written
    through it, with a comment naming ADR 0093. The `critical` in `nmi_returns`' loop
    goes: it protects nothing from an NMI, and a volatile read is not cached.
  - `tests/ui/interrupt_codegen_thumbv7m.ers`: the `svc` handler writes a `static mut` of
    its own; the snapshot gains that static.
- Tests: the programs above, with their outputs unchanged, at both levels; the snapshot
  above. A read now in `critical` delays a pending interrupt to the block's exit: where a
  program expected the handler to have run before that read, it waits first, in the form
  it already uses; any such change goes under `Decisions`. The check does not exist yet,
  so the proof that they obey it is step 2's and 3's full run.
- Decisions:
  - Each rule 1 read is `let x: u32 = critical { STATIC };` followed by the test on the
    local, not a `critical` around the whole `if`: the value is copied before the exit
    (ADR 0086), the block holds one read, and the `exit(n)` calls stay outside it. The
    local is named after the static (`runs`, `sent`; `before`, `ipsr`, `enabled` in
    `irq_pended`, where `runs` and `ipsr` are not otherwise taken).
  - `irq_pended_armv7m`: the read before `enable_interrupts` is in `critical` as the
    plan says (interrupts are masked there, so the block changes nothing at run time);
    the three reads at the end are three blocks, one per static, each followed by its
    own test, so the order of the exit codes 6, 7, 8 is the one it had.
  - `irq_disabled_armv7m` and `irq_unpended_armv7m`: the loop's `compiler_fence` goes (the
    block is a fence). The pending interrupt in these loops is disabled or unpended, so
    no handler is delayed to a block's exit and no program needed a new wait: no
    `wait_for_interrupt` was added anywhere.
  - The reads at the end of `irq_disabled`, `irq_unpended`, `irq_handler_in_module` and
    `irq_pended` come after a loop that left `critical` on `RUNS != 0`, so the handler has
    already run; the new block cannot change what they see.
  - `pendsv_returns`: `RUNS` is read once into `runs` before `putc`, so the digit printed
    is the value read in `critical`.
  - `nmi_returns`, `svcall_returns`: the new `static mut COUNT` and the constant keep the
    name the program used (`RUNS`, `CALLS`), so the uses change only by a `*`. The
    comment above them names ADR 0093 and says why the access is `volatile`; the NMI
    loop reads `*RUNS` each time, which is why its `critical` goes. Accesses are
    `*RUNS += 1` through the volatile pointer, read-modify-write, which is safe here: a
    single writer (the handler) and a reader that only looks.
  - `interrupt_codegen_thumbv7m.ers`: the new static is `CALLS`, declared next to `TICKS`
    at the crate root, and `svc` writes `super::CALLS = 1` (it wrote `TICKS = 0`, which
    `tick` and `pend` also write, hence rule 2 on the SVCall handler); the stored value
    is 1 so that the snapshot's store differs visibly from the old one. Only this
    snapshot moved: the `@CALLS` global in both optimization levels and the store in
    `svc`.
  - The snapshot was moved over the `.snap` with its `assertion_line` header dropped,
    as in the other snapshots.
  - No panic count moved: no compiler file changed.

    snapshot moves. Read-only ways to visit the operands and `asm` of a statement and of a
    terminator, next to `Body::for_each_operand`, which takes `&mut`; each matches every
    variant with no `_`, so that a new operand kind fails to compile here.
  - `src/query.rs`: `handlers()` fills `kind`: from `target.vector(name)` for a variant
    of `Vector`, `Maskable` for one of the chip's list.
  - `src/analysis/mod.rs`: the layer, with `pub fn check(mir: &Mir, diags: &mut

  - `src/lib.rs`: `pub mod analysis`.

  - `tests/architecture.rs`: `("analysis", &["mir"])` in `LAYERS`, and `analysis` in

  - `docs/reference.md`: the row of the code in the table of "Diagnostics", which
    `tests/rejected.rs` reads.
  - `tests/rejected.rs`: `EXEMPT` gains `analysis::unprotected-static`, with the reason of
    ADR 0093, "Conformance tests".
- Tests, all ui at `// emit: mir`, on riscv32 unless named:
  - `shared_static_naming.ers`: read, write, compound assignment, `&raw`, `sym`, an
    `extern static mut`, in the entry function and in a callee: each one error.
  - `shared_static_path.ers`: a path of two calls labels both; a function called inside

  - `shared_static_modules/main.ers`, with a module file: the path crosses files, each
    file its own snippet; names written with `::`.
  - `shared_static_flow.ers`: `critical` in one branch; accesses after `break`,
    `continue`, `return` and `?` left a block, and after its end; each proves the depth is
    walked, not read off the text.
  - `shared_static_same_place.ers`: a helper both contexts call, outside: one label,
    saying both.
  - `shared_static_panic.ers`: the panic function naming a static, reached by a check
    outside `critical`; the label on the check; the handler reaching it by a check too.
  - `shared_static_panic_core_thumbv7m.ers`: the check on the path is in `core::arch`, the
    `assert` of `nvic_address`, reached through `nvic_enable`; each line shows.
  - `shared_static_chip_thumbv7m.ers`: a handler at a variant of the chip's list counts
    as handler context.
  - `shared_static_race.ers`: `tests/e2e/critical_race_riscv32.ers` with `critical` removed,
    the race that end-to-end test shows being real.
  - `shared_static_typeck.ers`, `// emit: typeck`: a program that breaks the rule has a dump.
  - `shared_static_opt.ers`, `// emit: llvm-ir`, `// opt: both`: it reports the same error
    at both levels.
  - `shared_static_accepted.ers`: a block around the place, around a call on the path,
    nested; a recursion entered inside; `while !critical { DONE } {}` and the wait of ADR
    0086; two maskable handlers sharing; a handler's own static, the thread's own; a

    named only by `sym`; an `#[export]` function nothing in the program calls. The dump
    shows it passed.
  - `shared_static_accepted_pointers.ers`: a raw pointer from a `const`, from `comptime`

    a panic function naming a static in a program with no handler, as ADR 0085 lets it.
  - The full suite: all e2e programs with handlers build, so that step 1's rewriting
    is proved for rule 1, and the generated programs and bases of `tests/rejected.rs` pass.
- Decisions:
  - Read-only visitors live in `src/mir/mod.rs` as methods on the types that own the
    variants: `Statement::visit_operands` and `asm`, `Terminator::visit_operands`, `asm`
    and `successors`, and `InlineAsm::inputs` in `src/mir/asm.rs`. `visit_operands`
    includes the inputs of an `asm` (statement or terminator), so a caller reads `asm`
    only for its `sym` operands. `successors` was not in the plan: the walk over blocks
    needs it and `Terminator` had no such method (codegen walks blocks in order, not by
    edge). Every `match` names every variant, no `_`. The existing `operand_values_are_the_inputs`
    unit test also checks `inputs`.
  - `Handler::kind` is filled in `Queries::handlers` from the same `target.vector(name)`
    lookup that gives the word (one lookup returns `(word, kind)`); a variant of the chip's
    list is `Maskable` (ADR 0089). The mir unit-test table gets `Maskable`. No dump shows
    it, so no snapshot moved.
  - Where the check runs: in `front_end` right after `into_mir`, and an error returns
    `FrontEnd::Failed` before `leave_out`, so `--emit=mir` prints no dump (ADR 0093).
  - `src/analysis/mod.rs` has only `check`, which calls `shared_statics::check`; the layer
    is the place where M5's analyses join it.
  - Each body is scanned once into places and calls (`Scan`), and the searches work on the
    scans alone. A scan is a forward walk over `(block, depth)` pairs; each statement and
    terminator is keyed by `(block, index)` with the terminator at `statements.len()`, so
    the order is block, then statement, as ADR 0093 asks for "first". An item is outside
    when any visit has depth 0. `CriticalExit` at depth 0 saturates instead of
    underflowing: MIR building never emits it, and a panic here would be one more for
    `PANICS`. External bodies, `comptime` bodies and bodies with no blocks scan as empty.
    A statement with two places for one static is one place (sorted by static id, dedup).
  - An edge is a `Statement::Call` or a `Terminator::Panic` (to `Mir::panic`, flagged as a
    check); `CriticalEnter`/`CriticalExit` (which have no callee in MIR) and `sym` of a
    body are not edges, as ADR 0093 says.
  - The searches are a breadth-first `Reach::search` with a queue; `found[body]` holds the
    root it started from and the call it came through. The path of a label is that
    chain reversed. Rule 1's second search passes `outside_only` and follows calls with
    `outside` set; a root is always `found`.
  - Rule 1 runs only when the program has a maskable handler. The handler context is the
    one search from all maskable handlers in the order of `Mir::handlers`. Unmaskable
    handlers are left out of it (ADR 0093), so until step 3 a thread and an NMI sharing
    a static is accepted.
  - The label on the other context's place is the first place by body, block, statement
    among the bodies the handler search reached, computed once per static in a
    `HashMap` while the bodies are walked in id order. The handler it names is the root
    of the search that reached that body. When that place is the primary's own, the
    primary label reads `reached here, outside `critical`, by the thread and by the
    handler `X``, and there is no second label.
  - The texts are those of ADR 0093's example (message "S is reached outside critical in
    the thread context, and a handler reaches it too"; primary "reached here, outside
    critical"; a call "called here, outside critical"; a check "this check may call the
    panic function, outside critical"; the other place "the handler H reaches it here";
    the help of the example), with the backticks of the example. Labels are pushed primary first, then the path from the context to the place, then
    the other place (the diagnostics renderer orders the snippets, not the labels).
    Names are the symbol with `.` written `::`.
  - `if let Some(..) = first.get(..) else { continue }` rather than indexing, and no
    `unreachable!` or `expect` in `src/analysis`: no row in `PANICS`, and no count moved.
  - `docs/reference.md`: the row sits after the `eval::` rows and before `codegen::`, in
    the order of the pipeline. `tests/rejected.rs`: `EXEMPT` has its own entry for the
    code, worded after the `ty::interrupt-return` one.
  - Tests (riscv32 unless named; `shared_static_*.ers`). Each is its own snapshot:
    - `naming` has the six forms in the entry function and in `callee`, 12 errors in one
      snapshot, so each form is seen with and without a path.
    - `path`: one static per case (`DEEP` two calls, `BOTH` inside and outside, `LOOPED`
      recursion, `MANY` several places). `early` is defined before the handler and
      called by it, so that the label at `early`'s place shows "first by body", not "first
      found".
    - `modules/` has `main.ers`, `drivers.ers` (the call and the place) and `handlers.ers`
      (the handler, which reaches `drivers::COUNT` by `super::`): three files, three
      snippets, and `drivers::COUNT` in the message.
    - `flow`: one static per case, each with an access inside the block and one after
      it. Only `break` and the block's end make the "after" access discriminate (the
      access is reachable only once the block is left); `return` and `?` are tested in the
      form "an access after the block, on the path that did not leave", and `continue` is
      not tested apart: after `continue` the next iteration starts at depth 0 anyway.
    - `same_place`, `panic` (the same place in the panic function, hence one label that says
      both), `panic_core_thumbv7m` (the three steps of the path, two of them in `core`,
      whose snippet is the 30 lines around `nvic_address`; this snapshot moves with
      `rt/arch/armv7m.ers`), `chip_thumbv7m`.
    - `race`: `critical_race_riscv32.ers` without `critical`; `exit` and `putc` are stubs
      in the file because ui programs have no board, and the message printed is shorter.
      Five errors.
    - `typeck` (`// emit: typeck`: has a dump) and `opt` (`// opt: both`: the same error at
      `-O0` and at `-O`).
    - `accepted`: every case of the plan in one program (a static is shared when two
      contexts name it; `OWN` is a maskable handler's and `MINE` the thread's). The
      forms `while !critical { DONE } {}` and the wait of ADR 0086 are in `main`.
    - `accepted_pointers`: the pointer from a `const`, from a `comptime` block in a
      function, from a `static`'s initializer, and one taken in `critical` and used
      outside.
    - `accepted_panic` and `accepted_panic_no_handler`: two files, since one program cannot
      both have a handler and have none.
    - `accepted_panic_inside` (from review): the thread reaches the panic function only
      through checks inside `critical` (a division in a block, and a call in a block to a
      function that divides), the panic function names a shared static with no block, and
      a handler reaches it through a check outside; the program passes. Treating a check as
      always outside makes it fail (tried by hand). `panic`'s comment points to it.
  - A statement that names two different shared statics yields two errors with the same
    primary span, one per (place, static), as intended (from review).
  - No existing snapshot moved, and every e2e program with handlers builds through the
    check; the generated programs and the bases of `tests/rejected.rs` pass.
  - Step 4's guard (a change to `core` that makes an inserted call reach a check) is not
    part of this step, as the plan orders.
