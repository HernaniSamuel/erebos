# Plan: M4.5 Shared statics checked

ADRs: 0093
Base: 8facbcd
Program on QEMU: programs with handlers checked: every e2e program with a handler builds
through the check; `critical_race` and `uart_interrupt` on both targets are those that
share statics, a helper called in `critical` and in the handler among them. Rejected
programs are ui tests.
Out of scope:
- accepting accesses before `enable_interrupts`, or after the last interrupt: ADR 0078
  lets a later step accept more; no step takes it yet;
- raw pointers and peripherals across contexts: M5 (ADR 0078);
- function pointers: the step that adds them (ADR 0078);
- handlers in the generator of ADR 0068: its programs have no source of interrupts; no
  step takes it yet;
- whether MIR analyses run before compile-time evaluation: M5 (roadmap).

Before step 1: the `docs(adr)` commit that accepts ADR 0093 also sets the status lines of
the ADRs it amends, in their files and in the index (`docs/adr/README.md`):
- 0063: `Accepted; amended by 0070, 0082 and 0093 (the tables gain the module
  `analysis`)`, keeping the wording of its other amendments; index adds `0093`;
- 0078: `Accepted; amended by 0093 (a `&raw` evaluated at compile time names no static)`;
  index `Accepted, amended by 0093`.
The same commit holds the roadmap's edit written while planning: M4.5's pending decisions
settled.

Order: the programs obey the rule (1) before the check can reject them (2). Rule 1 comes
with the layer because the layer has nothing to report without a rule; rule 2 (3) reuses
its searches. The guard on inserted calls (4) needs nothing from them but stands on the
reading of ADR 0093, "What is a call". Every existing test passes after every step. From
step 2 to step 5, `docs/reference.md` lists the new codes while its prose still says the
rule is not checked; step 5 rewrites that prose with the whole check in place.

In every step: if the count of `unreachable!` or `expect` for a file in
`tests/architecture.rs` rises, say why in `Decisions`, and only then raise it. A new file
needs a row only if it has any. No user input may reach one: a MIR the check cannot read is
an internal invariant, a program is not.

The check changes no generated code: a program it accepts compiles to the same bytes as
before.

    `tests/e2e/svcall_returns.ers` name no static in the handler or the thread. Each
    static becomes `static mut COUNT: u32 = 0;`, and the name the program already uses
    becomes the constant: `const RUNS: *mut volatile u32 = &raw mut COUNT as *mut volatile

  program expected the handler to have run before that read, it waits first, in the form
  it already uses; any such change goes under `Decisions`. The check does not exist yet,
  so the proof that they obey it is step 2's and 3's full run.
- Decisions:
  - Each rule 1 read is `let x: u32 = critical { STATIC };` followed by the test on the
    local, not a `critical` around the whole `if`: the value is copied before the exit
    (ADR 0086), the block holds one read, and the `exit(n)` calls stay outside it. The
    local is named after the static (`runs`, `sent`; `before`, `ipsr`, `enabled` in
    `irq_pended`, where `runs` and `ipsr` are not otherwise taken).
  - `irq_pended_armv7m`: the read before `enable_interrupts` is in `critical` as the
    plan says (interrupts are masked there, so the block changes nothing at run time);
    the three reads at the end are three blocks, one per static, each followed by its
    own test, so the order of the exit codes 6, 7, 8 is the one it had.
  - `irq_disabled_armv7m` and `irq_unpended_armv7m`: the loop's `compiler_fence` goes (the
    block is a fence). The pending interrupt in these loops is disabled or unpended, so
    no handler is delayed to a block's exit and no program needed a new wait: no
    `wait_for_interrupt` was added anywhere.
  - The reads at the end of `irq_disabled`, `irq_unpended`, `irq_handler_in_module` and
    `irq_pended` come after a loop that left `critical` on `RUNS != 0`, so the handler has
    already run; the new block cannot change what they see.
  - `pendsv_returns`: `RUNS` is read once into `runs` before `putc`, so the digit printed
    is the value read in `critical`.
  - `nmi_returns`, `svcall_returns`: the new `static mut COUNT` and the constant keep the
    name the program used (`RUNS`, `CALLS`), so the uses change only by a `*`. The
    comment above them names ADR 0093 and says why the access is `volatile`; the NMI
    loop reads `*RUNS` each time, which is why its `critical` goes. Accesses are
    `*RUNS += 1` through the volatile pointer, read-modify-write, which is safe here: a
    single writer (the handler) and a reader that only looks.
  - `interrupt_codegen_thumbv7m.ers`: the new static is `CALLS`, declared next to `TICKS`
    at the crate root, and `svc` writes `super::CALLS = 1` (it wrote `TICKS = 0`, which
    `tick` and `pend` also write, hence rule 2 on the SVCall handler); the stored value
    is 1 so that the snapshot's store differs visibly from the old one. Only this
    snapshot moved: the `@CALLS` global in both optimization levels and the store in
    `svc`.
  - The snapshot was moved over the `.snap` with its `assertion_line` header dropped,
    as in the other snapshots.
  - No panic count moved: no compiler file changed.

  - Read-only visitors live in `src/mir/mod.rs` as methods on the types that own the

    scans alone. A scan is a forward walk over `(block, depth)` pairs; each statement and
    terminator is keyed by `(block, index)` with the terminator at `statements.len()`, so
    the order is block, then statement, as ADR 0093 asks for "first". An item is outside
    when any visit has depth 0. `CriticalExit` at depth 0 saturates instead of
    underflowing: MIR building never emits it, and a panic here would be one more for
    `PANICS`. External bodies, `comptime` bodies and bodies with no blocks scan as empty.
    A statement with two places for one static is one place (sorted by static id, dedup).
  - An edge is a `Statement::Call` or a `Terminator::Panic` (to `Mir::panic`, flagged as a
    check); `CriticalEnter`/`CriticalExit` (which have no callee in MIR) and `sym` of a
    body are not edges, as ADR 0093 says.

    root it started from and the call it came through. The path of a label is that
    chain reversed. Rule 1's second search passes `outside_only` and follows calls with
    `outside` set; a root is always `found`.

    one search from all maskable handlers in the order of `Mir::handlers`. Unmaskable
    handlers are left out of it (ADR 0093), so until step 3 a thread and an NMI sharing
    a static is accepted.
  - The label on the other context's place is the first place by body, block, statement
    among the bodies the handler search reached, computed once per static in a
    `HashMap` while the bodies are walked in id order. The handler it names is the root
    of the search that reached that body. When that place is the primary's own, the
    primary label reads `reached here, outside `critical`, by the thread and by the
    handler `X``, and there is no second label.
  - The texts are those of ADR 0093's example (message "S is reached outside critical in
    the thread context, and a handler reaches it too"; primary "reached here, outside
    critical"; a call "called here, outside critical"; a check "this check may call the
    panic function, outside critical"; the other place "the handler H reaches it here";
    the help of the example), with the backticks of the example. Labels are pushed primary first, then the path from the context to the place, then
    the other place (the diagnostics renderer orders the snippets, not the labels).
    Names are the symbol with `.` written `::`.
  - `if let Some(..) = first.get(..) else { continue }` rather than indexing, and no
    `unreachable!` or `expect` in `src/analysis`: no row in `PANICS`, and no count moved.
  - `docs/reference.md`: the row sits after the `eval::` rows and before `codegen::`, in

    - `typeck` (`// emit: typeck`: has a dump) and `opt` (`// opt: both`: the same error at
